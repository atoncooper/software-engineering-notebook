## 21.2 章节简介

大厂容器化流水线是工业级 CI/CD 的集大成者,日均构建 10万+次,从代码提交到生产部署 5-30min 完成。本章深度剖析 5 家代表性大厂的流水线架构:

1. **阿里 Aone**: 模板化 + 云原生,日均 10万构建

3. **Netflix Spinnaker**: 金丝雀 + Kayenta 自动分析
4. **Google**: Bazel 严格依赖图 + Buildbuddy
5. **Microsoft/Azure**: Azure DevOps + GitHub Actions

每家都包含: 架构图、关键设计、性能数据、可借鉴实践。

### 21.3.2 流水线模板

**模板化是 Aone 的核心**:

```yaml
# Java 应用模板(pipeline.yaml)
stages:
  - name: 代码检查
    jobs:
      - template: java-lint   # 公共模板
  - name: 单元测试
    jobs:
      - template: java-test
        params:
          coverage: 80
  - name: 构建
    jobs:
      - template: java-build
        params:
          jdk: 17
          maven: 3.9
  - name: 镜像构建
    jobs:
      - template: docker-build
        params:
          registry: registry.cn-hangzhou.aliyuncs.com
          multi-arch: true
  - name: 安全扫描
    jobs:
      - template: security-scan
        params:
          cve_severity: HIGH,CRITICAL
          sbom: true
          sign: true
  - name: 部署 staging
    jobs:
      - template: ack-deploy
        params:
          cluster: staging
          namespace: myapp-staging
          strategy: canary
          canary_percent: 10
  - name: 部署生产
    jobs:
      - template: ack-deploy
        params:
          cluster: prod
          namespace: myapp-prod
          strategy: canary
          canary_steps: [5, 25, 50, 100]
          auto_rollback: true
```

**模板库管理**:
- 200+ 标准模板
- 按语言(Java/Go/Python/前端)分类
- 按场景(Web/微服务/定时任务)分类
- 版本化(模板变更走 PR)

### 21.4.2 Bazel 严格依赖图

**为什么用 Bazel**:

```
传统构建(Maven/Gradle):
  - 全量构建: 25min
  - 增量构建: 仅按文件改动,无法跨模块

Bazel:
  - 严格依赖图: 知道每个目标的依赖
  - 增量构建: 仅构建受影响目标
  - 远程缓存: 跨机器共享
  - 远程执行: 跨机器并行
```

**BUILD 文件示例**:

```python
# BUILD
load("@rules_java//java:defs.bzl", "java_binary", "java_library")

java_library(
    name = "common-lib",
    srcs = glob(["src/main/java/com/example/common/**/*.java"]),
    deps = [
        "@maven//:guava",
        "@maven//:slf4j_api",
    ],
)

java_binary(
    name = "myapp",
    srcs = glob(["src/main/java/com/example/app/**/*.java"]),
    deps = [":common-lib"],
    main_class = "com.example.app.Main",
)
```

**远程缓存**(Buildbuddy):

```bash
# .bazelrc
build --remote_executor=grpcs://buildbuddy.internal:443
build --remote_cache=grpcs://buildbuddy.internal:443
build --disk_cache=
build --spawn_strategy=remote
```

**收益**:
- 全量构建: 25min → 8min
- 增量构建: 8min → 90s
- 缓存命中率: 95%+

### 21.4.3 关键设计

**1. 多语言支持**:
```python
# 同一 monorepo 内多语言
# BUILD 文件统一管理
java_binary(name = "java-app")
go_binary(name = "go-app")
py_binary(name = "py-app")
ts_bundle(name = "frontend")
```

**2. 远程执行**:
```
开发者机器
    │
    ▼ bazel build
Buildbuddy(调度)
    │
    ├─► Worker 1(Java 编译)
    ├─► Worker 2(Go 编译)
    └─► Worker 3(Python)
    │
    ▼ 结果汇总
返回开发者
```

**3. 镜像构建优化**:
```python
# rules_oci(Bazel 镜像规则)
oci_image(
    name = "myapp-image",
    base = "@distroless-java17",
    tars = [":app-tar"],
    entrypoint = ["java", "-jar", "app.jar"],
)

oci_push(
    name = "push",
    image = ":myapp-image",
    repository = "registry.bytedance.net/myapp",
    tags = ["v1.2.3"],
)
```

## 21.5 Netflix Spinnaker

### 21.5.1 架构概览

```
        开发者
          │
          ▼
    ┌─────────────┐
    │ Jenkins     │  ← CI 构建
    └──────┬──────┘
           │
           ▼
    ┌─────────────┐
    │ Spinnaker   │  ← CD 编排
    │ Orca        │
    └──────┬──────┘
           │
    ┌──────┴──────┐
    │             │
    ▼             ▼
 Bake(烘焙)   Deploy(部署)
 Rosco         Clouddriver
 └ 镜像构建    └ K8s/AWS
           │
           ▼
    ┌─────────────┐
    │ Kayenta     │  ← 金丝雀分析
    └─────────────┘
```

### 21.5.2 金丝雀部署流程

```
1. Bake
   └ 构建镜像(类似 Packer)

2. Deploy to Stage
   └ 部署 1% 流量到新版本

3. Manual Judgment(可选)
   └ 人工审批

4. Canary
   ├ Deploy 5%
   ├ Monitor 5min
   ├ Deploy 25%
   ├ Monitor 10min
   ├ Deploy 50%
   └ Monitor 10min

5. Kayenta Analysis(自动)
   ├ 收集指标(v1 vs v2)
   ├ 异常检测(ML)
   ├ 通过 → 继续
   └ 失败 → 自动回滚

6. Deploy to Production
   └ 100% 流量

7. Enable
   └ 完成发布
```

### 21.5.3 Kayenta 自动分析

**原理**:
```
v1(稳定版)指标 ──┐
                  ├─► Kayenta
v2(金丝雀)指标 ──┘    │
                       ▼
                  ┌──────────┐
                  │ 统计分析 │
                  │  - 均值  │
                  │  - 方差  │
                  │  - 异常  │
                  └────┬─────┘
                       │
                       ▼
                  ┌──────────┐
                  │ 评分     │
                  │ PASS/FAIL│
                  └──────────┘
```

**指标对比**:
- 错误率: v2 < v1 × 1.05
- 延迟 P99: v2 < v1 × 1.10
- CPU/内存: v2 < v1 × 1.20

**异常检测**:
- 自动学习基线
- 识别异常波动
- 减少误报

### 21.5.4 关键设计

**1. 多云部署**:
```yaml
# Spinnaker 同时部署到 AWS/Azure/GCP
stages:
  - deploy_aws:
      clusters: [us-east-1, us-west-2]
  - deploy_azure:
      clusters: [eastus, westeurope]
  - deploy_gcp:
      clusters: [us-central1, europe-west1]
```

**2. 红黑部署(蓝绿)**:
```
Red(新版本) ── 待命,无流量
Black(老版本) ── 100% 流量

切换:
Red ── 100% 流量
Black ── 待命,可回滚
```

**3. 自动回滚**:
```yaml
rollback:
  trigger:
    - metric: error_rate
      threshold: 0.01    # 1%
    - metric: latency_p99
      threshold: 500ms
  action: rollback
```

### 21.6.2 Google 内部构建规模

**Borg 内部数据**:
- 源码: 20亿+ 行

**关键设计**:

**1. Hermetic Build(封闭构建)**:
```python
# 所有依赖明确声明,不依赖环境
java_binary(
    name = "myapp",
    srcs = [...],
    deps = [
```

**3. Content-Addressable**:
- 缓存键 = 内容 hash

### 21.7.2 流水线示例

```yaml
# azure-pipelines.yml
trigger:
  branches: [main, develop]
  tags: [v*]

stages:
  - stage: Build
    jobs:
      - job: Build
        pool:
          vmImage: ubuntu-latest
        steps:
          - task: Docker@2
            inputs:
              command: build
              Dockerfile: Dockerfile
              tags: |
                $(Build.Repository.Name):$(Build.BuildId)
                $(Build.Repository.Name):latest
          - task: Docker@2
            inputs:
              command: push
              containerRegistry: $(dockerRegistryServiceConnection)
              tags: |
                $(Build.Repository.Name):$(Build.BuildId)

  - stage: Scan
    dependsOn: Build
    jobs:
      - job: Scan
        steps:
          - task: AzureContainerRegistry@1
            inputs:
              command: scan
              repository: $(Build.Repository.Name)
              tag: $(Build.BuildId)

  - stage: DeployStaging
    dependsOn: Scan
    jobs:
      - job: Deploy
        steps:
          - task: KubernetesManifest@0
            inputs:
              action: deploy
              kubernetesServiceConnection: staging-aks
              namespace: staging
              manifests: |
                k8s/staging.yaml
              containers: |
                $(registry)/$(Build.Repository.Name):$(Build.BuildId)

  - stage: DeployProd
    dependsOn: DeployStaging
    condition: startsWith(variables['Build.SourceBranch'], 'refs/tags/v')
    jobs:
      - job: Deploy
        steps:
          - task: KubernetesManifest@0
            inputs:
              action: deploy
              kubernetesServiceConnection: prod-aks
              namespace: prod
              strategy: canary
              percentage: 10
              manifests: k8s/prod.yaml
```

### 21.7.3 GitHub Actions 集成

Microsoft 收购 GitHub 后, GitHub Actions 与 Azure DevOps 深度集成:

```yaml
# .github/workflows/deploy.yml
name: Deploy to Azure

on:
  push:
    tags: [v*]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: azure/login@v1
        with:
          creds: ${{ secrets.AZURE_CREDENTIALS }}

      - uses: azure/setup-kubectl@v3

      - name: Deploy to AKS
        run: |
          az aks get-credentials --resource-group my-rg --name my-aks
          kubectl set image deployment/myapp app=registry/myapp:${{ github.ref_name }}
          kubectl rollout status deployment/myapp
```

### 21.8.1 大厂流水线对比

### 21.8.2 共性特征

**1. 极致缓存**:
```
本地缓存 → 远程缓存 → 远程执行
   │         │           │
   ▼         ▼           ▼
单机复用  跨机共享   分布式并行
```

**2. 模板化**:
- 200+ 标准模板
- 业务专注代码,流程走模板
- 模板版本化

**3. 安全门禁**:
- CVE 扫描(HIGH/CRITICAL 阻断)
- 镜像签名(Cosign)
- SBOM 生成
- 准入控制(Kyverno)

**4. 自动化**:
- 自动测试(单测+集成+E2E)
- 自动部署(金丝雀)
- 自动回滚(指标异常)
- 自动恢复(节点故障)

**5. 可观测**:
- 全链路追踪(代码→镜像→部署)
- 实时大盘(构建/部署/告警)
- 历史可查(审计合规)

## 21.9 工业实践启示

### 21.9.1 大厂都做的事

1. **模板化**: 通用流程抽模板
2. **远程缓存**: 跨团队共享
3. **金丝雀**: 全部生产走金丝雀
4. **自动回滚**: 指标驱动
5. **供应链安全**: 签名 + SBOM + 准入
6. **可观测**: 全链路追踪

### 21.9.2 小厂可借鉴

**1 年内可做**:
- GitHub Actions / GitLab CI 模板
- BuildKit 远程缓存
- Trivy 扫描
- 金丝雀(简单版)

**3 年内可做**:
- Bazel 增量构建
- ArgoCD GitOps
- Argo Rollouts 金丝雀
- Cosign 签名 + Kyverno 准入

**长期追求**:
- 全链路可观测
- 自动化运维
- 混沌工程
- AI 辅助发布

### 21.9.3 避免的坑

1. **不要造轮子**: 用开源(Bazel/ArgoCD/...)
2. **不要全盘照搬**: 量力而行,渐进式
3. **不要忽视文化**: 工具重要,流程和文化更重要
4. **不要过度自动化**: 简单场景手动更快
