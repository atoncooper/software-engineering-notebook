## 5.1 线性表查找

### 5.1.1 顺序查找

逐个比较,时间 $O(n)$。

**适用**:无序表、链表。

**ASL (成功)** = $\dfrac{1+2+\dots+n}{n} = \dfrac{n+1}{2}$

**ASL (失败)** = $n + 1$ (查完整个表 + 哨兵)。

**优化**:
- **监视哨**:在 0 位置放关键字,从后向前查,免去越界检查;
- **有序表顺序查找**:失败 ASL = $\dfrac{n+1}{2}$ (查到比 key 大就停);
- **按频率排序**:高频记录放前面,降低成功 ASL。

### 5.1.2 折半查找 (二分)

仅适用**有序顺序表** (链表不行,因无法 O(1) 随机访问)。

```c
int BinarySearch(int A[], int n, int key) {
    int low = 0, high = n - 1;
    while (low <= high) {
        int mid = (low + high) / 2;   // 向下取整
        if (A[mid] == key) return mid;
        else if (A[mid] > key) high = mid - 1;
        else low = mid + 1;
    }
    return -1;
}
```

**判定树**:折半查找过程对应一棵**平衡二叉树** (形态由 mid 取法决定)。

**深度**:$\lfloor \log_2 n \rfloor + 1$。

**推导**:判定树是平衡的,前 $\lfloor \log_2 n \rfloor$ 层是满的,最后一层可能不满;深度上界即 $\lfloor \log_2 n \rfloor + 1$。

**ASL (成功)** ≈ $\log_2(n+1) - 1$。

**ASL (失败)** ≈ $\log_2 n$ (到外部节点)。

**时间** $O(\log n)$。

> **真题陷阱**:
> 1. mid 取整方式 (向下/向上) 影响判定树形态,但深度不变;
> 2. 折半查找**必须顺序存储** (链表无法 O(1) 随机访问);
> 3. 折半查找**必须有序**;
> 4. **判定树的中序遍历** = 有序表;
> 5. **判定树不一定是完全二叉树** (但是平衡二叉树)。

### 5.1.3 分块查找 (索引顺序查找)

把表分成若干块,**块间有序** (第二块所有元素 > 第一块最大值),**块内无序**。

- **索引表** (块最大值 + 起始下标) 按块有序,可折半查找;
- **块内**顺序查找。

**ASL** = 索引查找 ASL + 块内查找 ASL。

设分 $b$ 块,每块 $s$ 个元素,$n = b \times s$:
- **顺序索引**:$ASL = \dfrac{b+1}{2} + \dfrac{s+1}{2} = \dfrac{s^2 + 2s + n}{2s}$
  - 最优 $s = \sqrt{n}$,ASL ≈ $\sqrt{n} + 1$;
- **折半索引**:$ASL \approx \log_2(b+1) + \dfrac{s+1}{2}$

## 5.2 树形查找 (BST/AVL/B/B+)

### 5.2.1 BST 与 AVL

详见 [[03-树与二叉树]] §3.7。

**要点**:
- BST:左 < 根 < 右,查找 $O(\log n)$ ~ $O(n)$;
- AVL:平衡 BST,查找严格 $O(\log n)$;
- 高度 $h < 1.44 \log_2(n+2)$。

### 5.2.2 B 树定义

m 阶 B 树 (multi-way balanced search tree) 满足:
1. 每节点至多 m 棵子树 (m-1 个关键字);
2. **根非叶时至少 2 棵子树**;
3. **非根非叶节点至少 $\lceil m/2 \rceil$ 棵子树** (即至少 $\lceil m/2 \rceil - 1$ 个关键字);
4. 节点关键字数 $k$ 满足 $\lceil m/2 \rceil - 1 \leq k \leq m - 1$;
5. **所有叶节点在同一层** (平衡);
6. 节点内关键字有序,且 $k_i$ 分隔 $k_i$ 左右子树的关键字范围。

**关键字范围** (n 个关键字,n+1 棵子树):

| 节点类型 | 子树数 | 关键字数 |
|----------|--------|----------|
| 根 (非叶) | $2 \leq s \leq m$ | $1 \leq n \leq m - 1$ |
| 内部节点 | $\lceil m/2 \rceil \leq s \leq m$ | $\lceil m/2 \rceil - 1 \leq n \leq m - 1$ |
| 叶子 (失败节点) | 0 | 0 |

**例**:5 阶 B 树,非根内部节点子树数 $3 \leq s \leq 5$,关键字数 $2 \leq n \leq 4$。

### 5.2.3 B 树插入

1. 找到目标叶子位置插入;
2. 若插入后关键字数 > m - 1 (即 $\geq m$),**分裂**:
   - 取中间关键字 (第 $\lceil m/2 \rceil$ 个) 上移到父节点;
   - 左右两半作为新节点;
3. 若父节点也上溢,递归分裂,直至根;
4. **根上溢则新建根**,B 树长高 (唯一长高方式)。

**5 阶 B 树插入示例** ($m = 5$,关键字数上限 4,分裂位置 $\lceil 5/2 \rceil = 3$):

插入序列 $\{1, 3, 5, 7, 9, 11, 13, 15, 17\}$:

```
插入 1, 3, 5, 7:        [1 | 3 | 5 | 7]   ← 4 个关键字,未超
插入 9:                  [1 | 3 | 5 | 7 | 9]  ← 5 个,上溢!
分裂:第 3 个 (5) 上移,左右两半:
                          [5]
                         /   \
                     [1|3]  [7|9]
插入 11, 13:
                          [5]
                         /   \
                     [1|3]  [7|9|11|13]   ← 4 个,未超
插入 15:
                          [5]
                         /   \
                     [1|3]  [7|9|11|13|15]  ← 5 个,上溢!
分裂:第 3 个 (11) 上移:
                          [5 | 11]
                         /   |   \
                     [1|3] [7|9] [13|15]
插入 17:
                          [5 | 11]
                         /   |   \
                     [1|3] [7|9] [13|15|17]   ← 3 个,未超
```

### 5.2.4 B 树删除

#### 5.2.4.1 删叶子关键字

1. 若删后关键字数 $\geq \lceil m/2 \rceil - 1$,直接删;
2. 否则 (下溢):
   - **借兄弟**:兄弟够借 (兄弟关键字数 $> \lceil m/2 \rceil - 1$),父下来,兄上去;
   - **合并**:兄弟不够借 (兄弟关键字数 $= \lceil m/2 \rceil - 1$),与兄弟 + 父节点中分隔关键字合并;
3. 若父下溢,递归处理,直至根 (根下溢且无关键字则删除根,B 树变矮)。

#### 5.2.4.2 删非叶关键字

用**直接前驱** (左子树最右) 或**直接后继** (右子树最左) 替换,转化为删叶子 (前驱/后继必在叶子节点)。

### 5.2.5 B+ 树

m 阶 B+ 树:
1. 每节点至多 m 棵子树,非根至少 $\lceil m/2 \rceil$ 棵;
2. **所有关键字都在叶子**,内部节点只存索引 (索引值 = 子节点中最大或最小关键字);
3. **叶子通过指针相连**形成有序链表;
4. 内部节点关键字 = 子节点中最大 (或最小) 关键字;
5. 内部节点关键字数 = 子树数 (而非 B 树的子树数 - 1)。

**B+ vs B 对比**:

| 对比项 | B 树 | B+ 树 |
|--------|------|-------|
| 关键字存储 | 内部 + 叶子 | 仅叶子 |
| 叶子链表 | 无 | 有 (双向链表) |
| 查找路径 | 任何节点都可能命中 | 必到叶子 |
| 范围查找 | 需中序遍历 | 顺着叶子链表 |
| 内部节点关键字数 | $n$,$n+1$ 子树 | $n$,$n$ 子树 |
| 磁盘友好 | 一般 | 更好 (内部更小,可放更多索引) |

> **真题陷阱**:
> 1. B+ 树内部节点关键字会在叶子**重复出现** (作为索引和实际记录);B 树不重复;
> 2. B 树关键字在内部节点 = 实际记录;B+ 树内部节点 = 仅作索引,实际记录在叶子;
> 3. B+ 树适合数据库索引:范围查找高效 (沿叶子链表),内部节点小,磁盘 IO 少。

### 5.2.6 B 树高度

含 n 个关键字的 m 阶 B 树高度 $h$ 满足:

$$
\log_m(n+1) \leq h \leq \log_{\lceil m/2 \rceil}\left(\frac{n+1}{2}\right) + 1
$$

**推导**:
- **下界** (每个节点最多 m-1 关键字,即 m 子树,n 个关键字最多对应 $m^{h-1}$ 叶子):$n+1 \leq m^h$ → $h \geq \log_m(n+1)$;
- **上界** (每个节点最少 $\lceil m/2 \rceil$ 子树):$n+1 \geq 2 \lceil m/2 \rceil^{h-1}$ → $h \leq \log_{\lceil m/2 \rceil}\left(\dfrac{n+1}{2}\right) + 1$。

## 5.3 散列表

### 5.3.1 哈希函数

| 方法 | 公式 | 适用 |
|------|------|------|
| 直接定址 | $H(k) = a \cdot k + b$ | 关键字连续,无冲突 |
| 除留余数 | $H(k) = k \mod p$ | 最常用,$p$ 取不大于表长的最大素数 |
| 数字分析 | 取关键字若干位 | 关键字位数多,分布已知 |
| 平方取中 | $H(k) = (k^2)$ 中间几位 | 关键字分布未知 |
| 折叠法 | 分段叠加 | 关键字位数多 |

**除留余数法** p 的选择:
- p 取**素数** (不大于表长 m),减少冲突;
- p 不取 2 的幂 (因 $k \mod 2^i$ 只看低 i 位,低 i 位易聚集)。

### 5.3.2 冲突处理

#### 5.3.2.1 开放定址法

冲突时按规则探查下一空位。

**线性探测**:
$$
H_i = (H(k) + i) \mod m, \quad i = 1, 2, \dots, m-1
$$
- 优点:简单,能探查全表;
- 缺点:**聚集** (primary clustering) 严重——同义词和非同义词都聚集在连续位置;
- 探查序列遍历整个表。

**平方探测** (二次探测):
$$
H_i = (H(k) + i^2) \mod m \quad \text{或} \quad (H(k) - i^2) \mod m, \quad i = 1, 2, \dots
$$
- 优点:减少聚集;
- 缺点:**不能探查全表**,只能探查到约 $m/2$ 个位置;
- 表长 $m$ 取 $4k+3$ 形素数时**可探查到一半**位置。

**双散列**:
$$
H_i = (H(k) + i \cdot H_2(k)) \mod m
$$
- 探查序列遍历全表,$H_2(k)$ 与 $m$ 互质;
- 优点:聚集最少;
- 缺点:需计算两次哈希。

**伪随机探测**:
$$
H_i = (H(k) + d_i) \mod m, \quad d_i \text{ 是伪随机序列}
$$

#### 5.3.2.2 链地址法 (拉链法)

同哈希值的关键字用单链表挂在桶上。

- 优点:无聚集;删除简单;α 可 > 1;
- 缺点:需要额外指针空间;
- 适合频繁插入删除。

#### 5.3.2.3 再哈希法

冲突时用第二个哈希函数重新计算,直到不冲突。计算开销大,实际少用。

#### 5.3.2.4 建立公共溢出区

冲突关键字统一存入溢出表,顺序或链式查找。

### 5.3.3 装填因子

$$
\alpha = \frac{\text{记录数 } n}{\text{表长 } m}
$$

- 散列表查找效率**取决于 α**,而非 n 或 m 单独;
- α 越小,冲突越少,查找越快,但空间浪费;
- 链地址法 α 可 > 1;开放定址 α 必须 < 1。

**ASL 与 α 关系** (近似):
- 线性探测:成功 ASL ≈ $\dfrac{1}{2}\left(1 + \dfrac{1}{1-\alpha}\right)$;
- 平方探测:成功 ASL ≈ $-\dfrac{1}{\alpha} \ln(1-\alpha)$;
- 链地址:成功 ASL ≈ $1 + \dfrac{\alpha}{2}$。

### 5.3.4 ASL 计算 (必考)

**成功 ASL**:对每个已存关键字,求其**探查次数** (找到该关键字所需的比较次数),取平均 (除以记录数 n)。

**失败 ASL**:对每个可能的哈希值 $H(k) \in \{0, 1, \dots, m-1\}$,求"探查到空位"的次数,取平均 (除以表长 m)。

> **真题陷阱 (极高频)**:
> 1. **失败 ASL 的分母是表长 m** (哈希函数值域),不是记录数 n!
> 2. 成功 ASL 的分母是 n (实际记录数);
> 3. 不同探查方式下,"探查次数"的计算口径略有差异:
>    - 线性探测:首次比较也算 1 次,继续探查每次 +1;
>    - 链地址法:链上第 i 个节点比较 i 次。

#### 5.3.4.1 线性探测 ASL 完整示例

**表长 11,哈希函数 $H(k) = k \mod 11$,线性探测,插入关键字 $\{1, 13, 25, 4, 6\}$**

| 关键字 | H(k) | 探查序列 | 探查次数 | 最终位置 |
|--------|------|----------|----------|----------|
| 1 | 1 | 1 | 1 | 1 |
| 13 | 2 | 2 | 1 | 2 |
| 25 | 3 | 3 | 1 | 3 |
| 4 | 4 | 4 | 1 | 4 |
| 6 | 6 | 6 | 1 | 6 |

**散列表**:[_, 1, 13, 25, 4, _, 6, _, _, _, _]

**成功 ASL** = (1+1+1+1+1)/5 = **1.0**

**失败 ASL**:对每个 $H(k) \in \{0, 1, ..., 10\}$,探查到空位的次数:
- $H(k)=0$:位置 0 空,探查 1 次;
- $H(k)=1$:位置 1 → 2 → 3 → 4 → 5 (空),探查 5 次;
- $H(k)=2$:位置 2 → 3 → 4 → 5 (空),探查 4 次;
- $H(k)=3$:位置 3 → 4 → 5 (空),探查 3 次;
- $H(k)=4$:位置 4 → 5 (空),探查 2 次;
- $H(k)=5$:位置 5 空,探查 1 次;
- $H(k)=6$:位置 6 → 7 (空),探查 2 次;
- $H(k)=7$:位置 7 空,探查 1 次;
- $H(k)=8$:位置 8 空,探查 1 次;
- $H(k)=9$:位置 9 空,探查 1 次;
- $H(k)=10$:位置 10 空,探查 1 次。

**失败 ASL** = (1+5+4+3+2+1+2+1+1+1+1)/11 = **22/11 = 2.0**

#### 5.3.4.2 链地址法 ASL

**同例,改用链地址法**:

桶 1: 1 → NULL
桶 2: 13 → NULL
桶 3: 25 → NULL
桶 4: 4 → NULL
桶 6: 6 → NULL
其他桶:NULL

**成功 ASL**:每个关键字探查 1 次 (在链头),ASL = 5/5 = **1.0**

**失败 ASL**:每条链探查次数 = 链长度 + 1 (走到 NULL):
- 桶 0: 0+1 = 1
- 桶 1: 1+1 = 2
- 桶 2: 1+1 = 2
- 桶 3: 1+1 = 2
- 桶 4: 1+1 = 2
- 桶 5: 0+1 = 1
- 桶 6: 1+1 = 2
- 桶 7-10: 0+1 = 1 (各 1)

**失败 ASL** = (1+2+2+2+2+1+2+1+1+1+1)/11 = **16/11 ≈ 1.45**

### 5.3.5 散列表实现

```c
// 开放定址 (线性探测)
typedef struct {
    int key;
    bool occupied;
} HashCell;

typedef struct {
    HashCell cells[M];
    int size;
} HashTable;

int Hash(int key) { return key % M; }

void Insert(HashTable &H, int key) {
    int idx = Hash(key);
    int i = 0;
    while (H.cells[idx].occupied) {
        i++;
        idx = (Hash(key) + i) % M;
    }
    H.cells[idx].key = key;
    H.cells[idx].occupied = true;
    H.size++;
}

bool Search(HashTable H, int key, int &cmpCnt) {
    int idx = Hash(key);
    int i = 0; cmpCnt = 0;
    while (H.cells[idx].occupied || i == 0) {
        cmpCnt++;
        if (H.cells[idx].occupied && H.cells[idx].key == key) return true;
        if (i == M) return false;
        i++;
        idx = (Hash(key) + i) % M;
    }
    return false;
}
```

```c
// 链地址法
typedef struct Node {
    int key;
    struct Node *next;
} Node;

Node *buckets[M];

void Insert(int key) {
    int idx = Hash(key);
    Node *s = (Node *)malloc(sizeof(Node));
    s->key = key; s->next = buckets[idx];
    buckets[idx] = s;
}

bool Search(int key, int &cmpCnt) {
    int idx = Hash(key);
    cmpCnt = 0;
    for (Node *p = buckets[idx]; p; p = p->next) {
        cmpCnt++;
        if (p->key == key) return true;
    }
    return false;  // cmpCnt = 链长度
}
```

## 5.4 真题陷阱与高频考点

1. **折半查找判定树形态**:由 mid 取整方式决定,但深度恒为 $\lfloor \log_2 n \rfloor + 1$;判定树是平衡二叉树,但不一定是完全二叉树。
2. **折半查找存储要求**:必须顺序存储且有序,链表不行。
3. **B 树关键字范围**:m 阶非根内部 $\lceil m/2 \rceil - 1$ 到 $m-1$;根 $1$ 到 $m-1$。
4. **B 树分裂**:取第 $\lceil m/2 \rceil$ 个上移。
5. **B 树根的高度变化**:只有根分裂才长高 (新建根);删除导致根空则变矮。
6. **B+ 树叶子链表**:便于范围查找;B+ 树内部节点关键字在叶子重复出现。
7. **散列失败 ASL 分母**:**表长 m**,不是 n!
8. **线性探测聚集**:同义词 + 非同义词都聚集 (primary clustering)。
9. **平方探测表长**:取 $4k+3$ 素数可探查到一半位置,不能探查全表。
10. **装填因子**:决定散列性能,链地址可 > 1;开放定址 α < 1。
11. **B 树 vs B+ 树**:B 关键字在内部 + 叶子;B+ 只在叶子;B+ 叶子有链表。
12. **B 树插入分裂向上传播**:可能导致连锁分裂直至根,根分裂使树长高。
13. **B 树删除借兄弟条件**:兄弟关键字数 $> \lceil m/2 \rceil - 1$ 才能借;否则合并。
14. **折半查找 vs 二叉排序树**:折半判定树静态 (表固定),BST 动态 (可插入删除)。

## 5.5 典型真题精解

### 2016 选择:B 树节点关键字范围

**题**:5 阶 B 树中,非根内部节点至少有几个关键字?

**解**:m=5,非根内部节点至少 $\lceil m/2 \rceil - 1 = \lceil 2.5 \rceil - 1 = 3 - 1 = 2$ 个;至多 $m-1 = 4$ 个。

**答**:2 个。

### 2017 综合:散列表线性探测 ASL

**题**:表长 11,哈希函数 $H(k) = k \mod 11$,线性探测,关键字 $\{6, 17, 28, 39, 50, 61\}$,求成功 ASL 和失败 ASL。

**解**:
- $H(6)=6$,位置 6,1 次;
- $H(17)=6$,冲突,探查 7,位置 7,2 次;
- $H(28)=6$,冲突,6→7→8,位置 8,3 次;
- $H(39)=6$,冲突,6→7→8→9,位置 9,4 次;
- $H(50)=6$,冲突,6→7→8→9→10,位置 10,5 次;
- $H(61)=6$,冲突,6→7→8→9→10→0,位置 0,6 次。

**成功 ASL** = (1+2+3+4+5+6)/6 = **21/6 = 3.5**

**失败 ASL**:对每个 $H(k) \in \{0..10\}$:
- $H(k)=0$:0 已占 → 1 (空?不,0 已被 61 占),探查 0→1 空,2 次;
- $H(k)=1$:1 空,1 次;
- $H(k)=2$:2 空,1 次;
- $H(k)=3$:3 空,1 次;
- $H(k)=4$:4 空,1 次;
- $H(k)=5$:5 空,1 次;
- $H(k)=6$:6→7→8→9→10→0→1 空,7 次;
- $H(k)=7$:7→8→9→10→0→1 空,6 次;
- $H(k)=8$:8→9→10→0→1 空,5 次;
- $H(k)=9$:9→10→0→1 空,4 次;
- $H(k)=10$:10→0→1 空,3 次。

**失败 ASL** = (2+1+1+1+1+1+7+6+5+4+3)/11 = **32/11 ≈ 2.91**

### 2018 选择:B+ 树叶子链表作用

**题**:B+ 树的叶子节点通过指针相连,主要作用是?

**解**:便于**范围查找**——找到范围下界后,沿叶子链表顺序扫描即可,无需回到根。也支持顺序遍历 (顺序查找)。

**答**:支持范围查找和顺序遍历。

### 2019 选择:折半查找判定树深度

**题**:有序表有 100 个元素,折半查找判定树深度?

**解**:$\lfloor \log_2 100 \rfloor + 1 = 6 + 1 = 7$。

**答**:7。

### 2020 算法:散列表构造与查找 (链地址法)

**题**:用链地址法实现散列表,支持插入和查找,写出代码。

**解**:见 5.3.5 链地址法代码。关键点:
1. `buckets[M]` 数组,每个桶一个链表头指针;
2. 插入用头插法 O(1);
3. 查找沿链表顺序比较;
4. ASL 计算时探查次数 = 链上比较次数。

### 2022 选择:平方探测表长选择

**题**:平方探测定址,表长应取?

**解**:平方探测能探查到的位置数有限,最多 $\lceil m/2 \rceil$ 个。要探查到一半以上位置,需表长 $m = 4k+3$ 形素数 (如 7, 11, 19, 23)。

**答**:$4k+3$ 形素数。

### 2024 综合:B 树插入分裂

**题**:3 阶 B 树,依次插入 $\{10, 20, 30, 40, 50, 60\}$,画出最终 B 树。

**解**:3 阶 B 树关键字数 1~2,子树数 2~3,分裂位置 $\lceil 3/2 \rceil = 2$。
- 插 10, 20:根 [10|20],未超;
- 插 30:[10|20|30] 上溢,第 2 个 (20) 上移,根 [20],子树 [10] [30];
- 插 40:进右子树 [30|40];
- 插 50:右子树 [30|40|50] 上溢,40 上移到根 [20|40];
- 插 60:进 [50|60] (右子);
- 最终:
```
        [20 | 40]
       /    |    \
    [10]  [30]  [50|60]
```

**答**:如上图。

## 5.7 易混淆点深辨析

| 易混点 | 辨析 |
|--------|------|
| B 树 vs B+ 树 | B 关键字在内部+叶子;B+ 只在叶子,内部节点仅作索引 |
| B 树根 vs 内部节点 | 根至少 2 子树 (1 关键字);内部至少 $\lceil m/2 \rceil$ 子树 ($\lceil m/2 \rceil - 1$ 关键字) |
| 成功 ASL vs 失败 ASL | 分母不同 (n vs m);探查口径不同 (找到 vs 到空位) |
| 线性 vs 平方探测 | 平方减少聚集但不能探查全表;线性能探查全表但聚集严重 |
| 链地址 α vs 开放定址 α | 链地址 α 可 > 1;开放定址 α 必须 < 1 |
| 折半判定树 vs 完全二叉树 | 折半判定树是平衡二叉树,但不一定是完全二叉树 |
| 折半查找 vs BST 查找 | 折半静态 (表固定);BST 动态 (支持插入删除) |
| B 树插入 vs 删除 | 插入从叶子开始,可能向上分裂;删除可能借兄弟或合并,可能向下传播 |
| 平方探测 +i² vs ±i² | 双向平方探测 (±i²) 能探查更多位置 |
| ASL 公式 vs 实际值 | ASL 公式是期望值;实际 ASL 需按具体冲突序列计算 |

## 5.8 延伸知识

### 5.8.1 红黑树 (概念)

详见 [[03-树与二叉树]] §3.14.1。AVL 的近似平衡版本,插入/删除最多 3 次旋转,适合频繁修改场景。

### 5.8.2 跳表 (Skip List)

多层链表,期望 $O(\log n)$ 查找。Redis 的有序集合用跳表。

### 5.8.3 布隆过滤器 (Bloom Filter)

用 k 个哈希函数 + 位数组,支持"可能存在"和"一定不存在"两种判断。空间极小但有误判率。

### 5.8.4 一致性哈希

分布式存储的哈希方案,节点增删时只影响相邻区间。用于分布式缓存 (如 Memcached)。

### 5.8.5 B* 树

B+ 树变体,非根节点至少 $\lceil 2m/3 \rceil$ 满时不必分裂,空间利用率更高。

## 5.10 本章习题

1. 折半查找有序表 $\{7, 10, 13, 16, 19, 22, 25, 28, 31\}$,查找 22 的比较序列?
   - **答**:low=0, high=8, mid=4 (19) < 22 → low=5;mid=6 (25) > 22 → high=5;mid=5 (22) 命中。比较序列:19, 25, 22。

2. 5 阶 B 树,非根内部节点最多几个关键字?最少几个子树?
   - **答**:最多 $m-1 = 4$ 个关键字;最少 $\lceil m/2 \rceil = 3$ 个子树。

3. 表长 13,哈希函数 $H(k) = k \mod 13$,链地址法,关键字 $\{10, 23, 36, 49, 62\}$,求成功 ASL。
   - **答**:H(10)=10, H(23)=10, H(36)=10, H(49)=10, H(62)=10。全部冲突在桶 10。
   - 链:62 → 49 → 36 → 23 → 10 (假设倒序插入);
   - 各关键字比较次数:62 比 1 次,49 比 2 次,36 比 3 次,23 比 4 次,10 比 5 次;
   - 成功 ASL = (1+2+3+4+5)/5 = 3.0。

4. 为什么失败 ASL 的分母是 m 而非 n?
   - **答**:失败查找对应"任意哈希值 $H(k)$",哈希函数值域有 m 个 (0 到 m-1),故分母为 m。n 是已存记录数,与失败查找无关。

5. B+ 树为何更适合数据库索引?
   - **答**:① 叶子链表支持范围查找 (WHERE x BETWEEN a AND b);② 内部节点小 (仅索引),可放更多索引,减少磁盘 IO;③ 所有记录在叶子,等值查找路径稳定 (必到叶子)。
