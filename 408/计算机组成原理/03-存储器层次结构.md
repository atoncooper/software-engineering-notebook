## 3.1 存储器分类与层次结构

### 3.1.1 分类

| 维度 | 类型 |
|------|------|
| 存储介质 | 半导体、磁表面、光 |
| 存取方式 | 随机 (RAM)、顺序 (SAM)、直接 (DAM)、相联 (CAM) |
| 可改写 | ROM (只读)、RAM (读写) |
| 易失性 | 易失 (RAM)、非易失 (ROM、磁盘、SSD) |
| 作用 | 寄存器、Cache、主存、外存 |

### 3.1.2 层次结构

```
寄存器     ← 最快 (ns级)、最小 (KB)、最贵
  ↓
Cache L1   ← 1-2 个周期
  ↓
Cache L2   ← 10 个周期
  ↓
Cache L3   ← 40 个周期
  ↓
主存       ← 100-200 个周期
  ↓
SSD        ← μs 级
  ↓
磁盘       ← ms 级
  ↓
磁带       ← 最慢、最大、最便宜
```

**层次原理**:基于**局部性原理** (Locality)。

#### 3.1.2.1 局部性原理

- **时间局部性** (Temporal Locality):最近访问过的数据,短期内可能再次访问;
  - 例:循环变量、栈顶;
- **空间局部性** (Spatial Locality):访问某地址后,其邻近地址可能被访问;
  - 例:数组顺序访问、指令顺序执行。

**应用**:
- Cache 利用时间局部性 (缓存最近数据);
- Cache 块预取利用空间局部性 (一次取一整个块)。

### 3.1.3 层次结构的设计目标

- **命中率**接近 1 (上层几乎都能命中);
- **平均访问时间**接近最快层;
- **平均价格**接近最便宜层;
- **容量**接近最大层。

## 3.2 SRAM 与 DRAM

### 3.2.1 对比

| 对比项 | SRAM (静态) | DRAM (动态) |
|--------|-------------|-------------|
| 存储元件 | 触发器 (6 晶体管) | 电容 (1 晶体管) |
| 是否刷新 | **否** | **是** (电容泄露) |
| 速度 | 快 (ns 级) | 慢 (10ns 级) |
| 集成度 | 低 (6T/cell) | 高 (1T/cell) |
| 功耗 | 大 (持续通电) | 小 (静态低) |
| 成本 | 高 | 低 |
| 易失性 | 易失 | 易失 |
| 用途 | **Cache** | **主存** |

### 3.2.2 DRAM 刷新

电容存储电荷会随时间泄露,需定期刷新 (再生)。刷新以**行**为单位,通过读出再写入恢复电荷。

#### 3.2.2.1 三种刷新方式

| 方式 | 描述 | 死时间 | 存取周期 | 优劣 |
|------|------|--------|----------|------|
| **集中刷新** | 一段时间内集中刷新所有行 | **有** (刷新时不读写) | 不变 | 突发死时间,适合实时性低场景 |
| **分散刷新** | 每个存取周期后刷新一行 | **无** | **变长 2 倍** (一半存取一半刷新) | 无死时间但吞吐降 |
| **异步刷新** | 每隔一段时间刷新一行 (各次刷新分散) | **几乎无** (仅一行死时间) | 不变 | **最常用**,平衡 |

**死时间** (Dead Time):刷新期间无法读写的时间。

**集中刷新示例**:DRAM 1024 行,刷新周期 2 ms,每次刷新一行 0.1 μs,集中刷新总时间 = 1024 × 0.1 μs = 102.4 μs。这 102.4 μs 内无法读写。

**异步刷新示例**:DRAM 1024 行,刷新周期 2 ms,每隔 2ms/1024 ≈ 1.95 μs 刷新一行。每次刷新仅 0.1 μs 死时间,分散均匀。

> **真题陷阱**:
> 1. **刷新与读出不同**:刷新以"行"为单位,按行地址刷新;读出以"单元"为单位;
> 2. **刷新不需要数据线**,内部读出再写入;
> 3. **刷新周期**:典型 2 ms (即每 2 ms 必须刷新所有行一次);
> 4. **异步刷新最常用**,因平衡死时间与吞吐。

### 3.2.3 ROM 系列

| 类型 | 全称 | 特点 |
|------|------|------|
| 掩膜 ROM | Mask ROM | 出厂写入,不可改 |
| PROM | Programmable ROM | 可一次编程 (熔丝) |
| EPROM | Erasable PROM | 紫外擦除重写 |
| EEPROM | Electrically EPROM | 电可擦除 (字节级) |
| Flash | Flash | 块擦除,SSD、U 盘核心 |

**Flash**:
- **NOR Flash**:随机读取快,适合存代码 (BIOS);
- **NAND Flash**:容量大,顺序读快,适合大容量存储 (SSD、U 盘)。

## 3.3 主存编址与扩展

### 3.3.1 编址

- **按字节编址**:每个字节一个地址 (最常见);
- **按字编址**:每个字 (16/32/64 位) 一个地址。

**地址线位数 = log₂(容量)**,数据线位数 = 字长。

**示例**:1 GB 主存,按字节编址,需地址线 30 位 ($2^{30} = 1$ GB)。

### 3.3.2 存储器扩展

#### 3.3.2.1 位扩展 (增加字长)

并联多片,共用地址线,数据线分别连接。

**示例**:用 4 片 1K×4 位芯片组成 1K×16 位存储器——4 片并联,共用 10 位地址,4 片各出 4 位,共 16 位数据。

#### 3.3.2.2 字扩展 (增加容量)

串联多片,片选信号选择哪一片工作。

**示例**:用 4 片 1K×8 位芯片组成 4K×8 位存储器——4 片串联,地址高 2 位作片选 (2-4 译码器),低 10 位作片内地址。

#### 3.3.2.3 字位同时扩展

最常用,组合上述两种。

**示例**:用 8 片 1K×4 位芯片组成 4K×8 位存储器——4 组 (字扩展) × 2 片 (位扩展),每组 2 片并联成 1K×8,共 4 组串联。

### 3.3.3 译码器

**74LS138 (3-8 译码器)**:3 位地址输入,8 路片选输出。

**地址范围计算**:
- 16 位地址线,64 KB 主存;
- 一片 8 KB 芯片,占地址 13 位 (8K = 2^13);
- 高 3 位作片选,8 片分别对应地址段 0000H-1FFFH, 2000H-3FFFH, ..., E000H-FFFFH。

> **真题陷阱**:
> 1. **CPU 地址线数与存储器地址空间对应**;
> 2. **片选逻辑决定地址范围**——同一芯片在不同片选下地址范围不同;
> 3. **位扩展不增加地址,只增加数据宽度**;
> 4. **字扩展增加地址,数据宽度不变**。

## 3.4 Cache

### 3.4.1 作用

利用局部性,在 CPU 与主存间加一层高速缓存,**提高平均访问速度**。

- 容量小 (KB-MB);
- 速度快 (与 CPU 同量级);
- 透明 (程序员不可见);
- 由硬件管理。

### 3.4.2 三种映射

#### 3.4.2.1 直接映射 (Direct Mapped)

**公式**:
$$
\text{主存地址} = \text{主存字块标记 (Tag)} + \text{Cache 行号} + \text{行内地址}
$$

**规则**:每个主存块只能映射到固定 Cache 行 $\text{主存块号} \mod \text{Cache 行数}$。

**示例**:主存地址 32 位,Cache 32 KB,每行 64 B:
- Cache 行数 = 32 KB / 64 B = 512 = $2^9$;
- 行内地址 = $\log_2 64 = 6$ 位;
- Cache 行号 = $\log_2 512 = 9$ 位;
- 主存字块标记 = 32 - 9 - 6 = **17 位**。

```
| 主存字块标记 (17) | Cache 行号 (9) | 行内地址 (6) |
```

**特点**:
- 命中查找:只需比较固定行的 Tag,速度快;
- **块冲突严重**:特定主存块只能到固定行,即使其他行空闲;
- **不需替换算法** (一个主存块只有一个可能位置);
- 适合大容量 Cache。

#### 3.4.2.2 全相联映射 (Fully Associative)

**公式**:
$$
\text{主存地址} = \text{主存字块标记 (Tag)} + \text{行内地址}
$$

**规则**:任一主存块可映射到任一 Cache 行。

**示例**:32 位主存地址,Cache 每行 64 B:
- 行内地址 = 6 位;
- 主存字块标记 = 32 - 6 = **26 位**。

```
| 主存字块标记 (26) | 行内地址 (6) |
```

**特点**:
- 命中查找:需与**所有** Cache 行标记比较 (相联存储);
- **块冲突少** (空间利用率高);
- **需替换算法** (LRU/FIFO);
- 适合小容量 Cache。

#### 3.4.2.3 组相联映射 (Set Associative)

**公式**:
$$
\text{主存地址} = \text{主存字块标记 (Tag)} + \text{组号} + \text{行内地址}
$$

**规则**:Cache 分组,主存块映射到固定组 $\text{主存块号} \mod \text{组数}$,组内任一行。

**示例**:32 位地址,Cache 32 KB,每行 64 B,8 路组相联:
- Cache 行数 = 512;
- 组数 = 512 / 8 = 64 = $2^6$;
- 组号 = 6 位;
- 行内地址 = 6 位;
- 主存字块标记 = 32 - 6 - 6 = **20 位**。

```
| 主存字块标记 (20) | 组号 (6) | 行内地址 (6) |
```

**特点**:
- 命中查找:组内所有行比较 (8 路需 8 次比较);
- **块冲突较少** (组内有多个候选);
- **需替换算法** (组内 LRU);
- 折中方案,主流 CPU 用 8-16 路组相联。

#### 3.4.2.4 三种映射对比

| 映射 | 命中查找 | 块冲突 | 替换算法 | 命中率 | 适用 |
|------|----------|--------|----------|--------|------|
| 直接 | 一次比较 | 严重 | 不需 | 较低 | 大容量 |
| 全相联 | 全表比较 | 少 | LRU/FIFO | 高 | 小容量 |
| 组相联 | 组内比较 | 较少 | LRU/FIFO | 中 | 主流 |

### 3.4.3 替换算法

| 算法 | 描述 | 优缺点 |
|------|------|--------|
| **LRU** (最近最少使用) | 替换最久未访问的 | 命中率最高,实现复杂 (需计数器) |
| **FIFO** (先进先出) | 替换最早进入的 | 简单,有 Belady 异常 |
| **随机** | 随机替换 | 硬件最简单,命中率波动 |
| **LFU** (最不经常使用) | 替换访问次数最少的 | 计数器,长期偏置 |

**Belady 异常**:FIFO 在增大 Cache 时命中率反而下降 (LRU 不会)。

### 3.4.4 写策略

#### 3.4.4.1 写命中策略

| 策略 | 描述 | 优劣 |
|------|------|------|
| **全写法** (写直达, Write Through) | 同时写 Cache 与主存 | 一致性好,带宽高,写慢 |
| **写回法** (Write Back) | 只写 Cache,设脏位,替换时写回 | 速度快,但脏数据风险,复杂 |

#### 3.4.4.2 写缺失策略

| 策略 | 描述 | 适用 |
|------|------|------|
| **写分配** (Write Allocate) | 写缺失时先调入 Cache 再写 | 配合写回法 |
| **不按写分配** (No-Write Allocate) | 写缺失时直接写主存,不调入 | 配合全写法 |

#### 3.4.4.3 常用组合

- **全写法 + 不按写分配**:简单,一致性好;
- **写回法 + 写分配**:快速,常用 (现代 CPU 主选)。

### 3.4.5 命中率与平均访问时间

**命中率**:
$$
h = \frac{\text{命中次数}}{\text{总访问次数}}
$$

**缺失率**:$1 - h$。

#### 3.4.5.1 顺序访问 (Cache 缺失再访问主存)

$$
t_a = h \cdot t_c + (1 - h) \cdot (t_c + t_m)
$$

- $t_c$ = Cache 访问时间;
- $t_m$ = 主存访问时间;
- Cache 缺失时,先访问 Cache (未命中),再访问主存,共 $t_c + t_m$。

#### 3.4.5.2 同时访问 (Cache 与主存同时启动)

$$
t_a = h \cdot t_c + (1 - h) \cdot t_m
$$

- Cache 命中:取消主存访问,耗时 $t_c$;
- Cache 缺失:用主存结果,耗时 $t_m$。

**示例**:Cache $t_c = 1$ ns,主存 $t_m = 100$ ns,命中率 $h = 0.95$:
- 顺序访问:$t_a = 0.95 \times 1 + 0.05 \times 101 = 0.95 + 5.05 = 6.0$ ns;
- 同时访问:$t_a = 0.95 \times 1 + 0.05 \times 100 = 0.95 + 5 = 5.95$ ns。

### 3.4.6 Cache 设计考量

- **块大小**:大块利用空间局部性,但缺失代价高;
- **相联度**:高相联度命中率好但功耗大、延迟高;
- **写策略**:写回法 + 写分配主流;
- **多级 Cache**:L1 小快,L2 中,L3 大共享;
- **包含性**:L3 包含 L2 包含 L1 (inclusive),或互斥 (exclusive)。

## 3.5 虚拟存储器

### 3.5.1 作用

- **扩大可用内存**:借助磁盘作"扩展内存";
- **隔离进程地址空间**:每进程独立虚拟地址;
- **简化内存分配**:连续虚拟地址可对应离散物理页;
- **保护**:页表项有权限位,防止越界。

### 3.5.2 页式虚拟存储

#### 3.5.2.1 地址结构

- **虚拟地址** = 虚页号 (VPN) + 页内偏移 (Offset);
- **物理地址** = 实页号 (PFN) + 页内偏移 (Offset);
- **页内偏移** 不变 (页大小固定)。

**示例**:32 位虚拟地址,4 KB 页:
- 页内偏移 = $\log_2 4096 = 12$ 位;
- 虚页号 = 32 - 12 = 20 位;
- 虚拟地址空间 = $2^{32}$ B = 4 GB;
- 虚页数 = $2^{20}$ = 1M 页。

#### 3.5.2.2 页表

页表:虚页号 → 实页号 + 控制位。

**页表项** (PTE) 内容:
- **实页号** (PFN):物理页号;
- **有效位** (Valid):页是否在内存;
- **修改位** (Dirty):页是否被写过;
- **访问位** (Accessed):最近是否访问 (用于 LRU);
- **权限位**:读/写/执行;
- **缓存禁止位**:是否绕过 Cache。

#### 3.5.2.3 地址变换

1. 虚地址 → 虚页号 + 页内偏移;
2. 查页表得实页号;
3. 实页号 + 页内偏移 = 物理地址。

**无 TLB 时,每次访存需 2 次内存访问**:1 次查页表,1 次取数据。

### 3.5.3 TLB (Translation Lookaside Buffer)

**TLB = 页表的 Cache**,存放最近访问的页表项。

#### 3.5.3.1 TLB 结构

- 通常**全相联或组相联**;
- 容量小 (64-512 项);
- 速度极快 (1 周期)。

#### 3.5.3.2 TLB 命中

- 无需访存查页表;
- 直接得到实页号,组合成物理地址;
- 总访存次数 = 1 (取数据)。

#### 3.5.3.3 TLB 缺失

- 访存查页表;
- 若页表项有效位 = 1 (页在内存):取实页号,填入 TLB;
- 若页表项有效位 = 0 (缺页):**缺页中断**,从磁盘读入。

### 3.5.4 多级页表

#### 3.5.4.1 单级页表的问题

32 位地址,4 KB 页,页表项 4 B:
- 虚页数 = $2^{20}$ = 1M;
- 页表大小 = 1M × 4B = **4 MB**;
- 每进程 4 MB 页表,占用大量内存。

#### 3.5.4.2 二级页表

把虚页号拆为"一级页号 + 二级页号"。
- 一级页号:目录项,指向二级页表;
- 二级页号:实际页表项;
- **未使用的二级页表可不分配**,节省空间。

**访存**:无 TLB 时,**3 次访存**:
1. 查一级页表得二级页表基地址;
2. 查二级页表得实页号;
3. 取数据。

#### 3.5.4.3 多级页表 (64 位)

64 位地址常需 4-5 级页表,访存次数更多。现代 CPU 用 TLB 缓解。

### 3.5.5 段式与段页式

#### 3.5.5.1 段式虚拟存储

- 按程序逻辑分段 (代码段、数据段、栈段);
- 段长可变;
- **段表**:段号 → 段基址 + 段长 + 属性;
- 优点:逻辑清晰,便于共享保护;
- 缺点:外部碎片 (段间空隙),分配困难。

#### 3.5.5.2 段页式

- 先分段,段内再分页;
- **段表 + 页表**;
- 无 TLB 时:**3 次访存** (查段表 + 查页表 + 取数据);
- 兼具段式逻辑性和页式无碎片。

## 3.6 TLB/Cache/Page 关系

### 3.6.1 访问流程

CPU 给出**虚拟地址**,按以下顺序访问:

```
1. TLB 查虚页号
       │
       ├── 命中 → 实页号 (不访存)
       │
       └── 缺失 → 查页表 (访存一次)
                    │
                    ├── 有效位 = 1 → 实页号,填 TLB
                    │
                    └── 有效位 = 0 → 缺页中断 → 磁盘 I/O → 填页表 → 填 TLB
                    
2. 实页号 + 页内偏移 = 物理地址

3. 物理地址查 Cache
       │
       ├── 命中 → 取数据 (不访存)
       │
       └── 缺失 → 访问主存取数据 (可能填 Cache)
```

### 3.6.2 各种缺失组合

| TLB | Page | Cache | 访问次数 | 含义 |
|-----|------|-------|----------|------|
| 命中 | 命中 | 命中 | 1 (Cache) | 最佳:仅访问 TLB + Cache |
| 命中 | 命中 | 缺失 | 2 (Cache + 主存) | TLB + 主存取数据 |
| 缺失 | 命中 | 命中 | 2 (页表 + Cache) | 访问页表 + Cache |
| 缺失 | 命中 | 缺失 | 3 (页表 + 主存) | 访问页表 + 主存取数据 |
| 缺失 | 缺失 | 缺失 | 多次 + 磁盘 I/O | 缺页中断,最慢 |

> **真题陷阱**:
> 1. **TLB 缺失未必缺页**——页表里可能有效位 = 1,只是 TLB 没缓存;
> 2. **Page 缺失 (缺页) 必引发缺页中断**,从磁盘读入;
> 3. **Cache 缺失不引发中断**,只是访问主存;
> 4. **Cache 用物理地址** (现代 CPU 多用物理地址索引 Cache,称 PIPT);
> 5. **TLB 与 Cache 关系**:TLB 在 Cache 之前 (虚拟地址 → TLB → 物理地址 → Cache)。

### 3.6.3 写策略与脏位

- **页表项修改位** (Dirty):页被写过 (写回策略下需写回磁盘);
- **Cache 行脏位**:Cache 行被写过 (替换时写回主存);
- **TLB 脏位**:TLB 项是否修改 (实页号变化时需写回页表)。

### 3.6.4 虚拟 Cache vs 物理 Cache

| 类型 | 索引用地址 | 优劣 |
|------|-----------|------|
| **VIPT** (虚拟索引物理标记) | 虚拟地址索引,物理地址比较 | 速度快,但需处理别名 |
| **PIPT** (物理索引物理标记) | 物理地址 | 简单,但需先 TLB |
| **VIVT** (虚拟索引虚拟标记) | 虚拟地址 | 最快,但同名空间问题 |

## 3.7 真题陷阱与高频考点

1. **SRAM 不需刷新,DRAM 需要**:电容存储电荷会泄露;
2. **异步刷新最常用**:无死时间,分散刷新;
3. **直接映射块冲突严重**:特定主存块只能到固定行;
4. **组相联**:兼顾直接映射与全相联,主流 CPU 用;
5. **全写法带宽高**:写主存频繁,但一致性好;
6. **写回法 + 写分配**:常用组合,脏位记录;
7. **平均访问时间公式**:$t_a = h t_c + (1-h)(t_c + t_m)$ (顺序);
8. **TLB 缺失未必缺页**:页表里可能有效;
9. **缺页中断**:Page 缺失引发,需磁盘 I/O;
10. **Cache 缺失不引发中断**:只访问主存;
11. **多级页表访存**:二级 3 次,无 TLB 时;
12. **TLB 用全相联或组相联**:容量小,查找快;
13. **页内偏移不变**:虚实地址变换不改变页内偏移;
14. **Cache 用物理地址索引** (现代 CPU);
15. **局部性原理**:时间 (缓存) + 空间 (块预取);
16. **Belady 异常**:FIFO 有,LRU 无;
17. **DRAM 刷新以行为单位**:不是单元。

## 3.8 典型真题精解

### 2016 综合:Cache 三种映射地址划分

**题**:主存地址 32 位,Cache 32 KB,每行 64 B,求直接映射、全相联、2 路组相联的地址划分。

**解**:
- Cache 行数 = 32K / 64 = 512 = $2^9$;
- 行内地址 = $\log_2 64 = 6$ 位。

**直接映射**:
- Cache 行号 = 9 位;
- 标记 = 32 - 9 - 6 = 17 位;
- 划分:Tag(17) + 行号(9) + 偏移(6)。

**全相联**:
- 标记 = 32 - 6 = 26 位;
- 划分:Tag(26) + 偏移(6)。

**2 路组相联**:
- 组数 = 512 / 2 = 256 = $2^8$;
- 组号 = 8 位;
- 标记 = 32 - 8 - 6 = 18 位;
- 划分:Tag(18) + 组号(8) + 偏移(6)。

### 2017 选择:DRAM 刷新

**题**:下列关于 DRAM 刷新的说法,错误的是?
A. 集中刷新有死时间
B. 分散刷新无死时间但存取周期变长
C. 异步刷新最常用
D. 刷新以单元为单位

**解**:刷新以**行**为单位,不是单元。

**答**:D。

### 2018 综合:TLB + Cache 推演

**题**:CPU 访问虚拟地址 0x12345678,TLB、Cache、Page 各种缺失组合下的访问次数。

**解**:
- **全命中**:TLB 命中 → 物理地址 → Cache 命中,1 次访问 (Cache);
- **TLB 命中,Cache 缺失**:TLB 命中 → 物理地址 → Cache 缺失 → 主存,2 次 (Cache + 主存);
- **TLB 缺失,Page 命中,Cache 命中**:查页表 (1) → 物理地址 → Cache 命中 (1),2 次;
- **TLB 缺失,Page 命中,Cache 缺失**:查页表 (1) → 主存取数据 (1),3 次;
- **TLB 缺失,Page 缺失**:查页表 → 缺页中断 → 磁盘 I/O → 主存,多次 + 磁盘。

### 2019 选择:写策略组合

**题**:下列写策略组合最常用?

A. 全写法 + 写分配
B. 写回法 + 不按写分配
C. 写回法 + 写分配
D. 全写法 + 不按写分配 (但写入少)

**解**:常用组合是:
- 全写法 + 不按写分配 (简单一致);
- **写回法 + 写分配** (快速,主流)。

**答**:C (写回法 + 写分配,现代 CPU 主选)。

### 2020 综合:平均访问时间

**题**:Cache $t_c = 2$ ns,主存 $t_m = 80$ ns,命中率 90%,求顺序访问和同时访问的平均时间。

**解**:
- 顺序访问:$t_a = 0.9 \times 2 + 0.1 \times (2 + 80) = 1.8 + 8.2 = 10$ ns;
- 同时访问:$t_a = 0.9 \times 2 + 0.1 \times 80 = 1.8 + 8 = 9.8$ ns。

**答**:顺序 10 ns,同时 9.8 ns。

### 2022 综合:多级页表访存次数

**题**:二级页表,无 TLB,访问一个数据需几次访存?

**解**:
1. 查一级页表 (1 次访存);
2. 查二级页表 (1 次访存);
3. 取数据 (1 次访存)。

**答**:3 次访存。

### 2024 综合:Cache 行大小推算

**题**:主存地址 32 位,直接映射 Cache,主存字块标记 20 位,Cache 行号 7 位,求每行大小、Cache 总大小。

**解**:
- 行内地址 = 32 - 20 - 7 = 5 位;
- 每行大小 = $2^5 = 32$ B;
- Cache 行数 = $2^7 = 128$;
- Cache 总大小 = 128 × 32 B = 4 KB。

**答**:每行 32 B,Cache 总大小 4 KB。

## 3.10 易混淆点深辨析

| 易混点 | 辨析 |
|--------|------|
| SRAM vs DRAM | SRAM 触发器不刷新 (Cache);DRAM 电容刷新 (主存) |
| 集中 vs 异步刷新 | 集中有死时间;异步几乎无 |
| 直接 vs 全相联 vs 组相联 | 冲突严重程度:直接 > 组相联 > 全相联 |
| 全写法 vs 写回法 | 前者同时写主存 (一致性好);后者只写 Cache (快) |
| 写分配 vs 不按写分配 | 前者调入再写;后者直接写主存 |
| 命中率 vs 缺失率 | 缺失率 = 1 - 命中率 |
| TLB 缺失 vs 缺页 | TLB 缺失未必缺页 (页表可能有效) |
| Cache 缺失 vs 缺页 | Cache 缺失只访问主存;缺页要磁盘 I/O |
| 页式 vs 段式 | 页式定长无碎片;段式变长有外部碎片 |
| 一级 vs 二级页表 | 一级 2 次访存;二级 3 次访存 |
| 顺序 vs 同时访问 | 顺序 $h t_c + (1-h)(t_c+t_m)$;同时 $h t_c + (1-h) t_m$ |
| FIFO vs LRU | FIFO 有 Belady 异常;LRU 无 |

## 3.11 延伸知识

### 3.11.1 NUMA (非一致内存访问)

多 CPU 系统中,每个 CPU 有本地内存,访问远端 CPU 内存慢。操作系统需 NUMA 感知调度。

### 3.11.2 Cache 一致性协议 (MESI)

多核 CPU 中,各核 L1 Cache 可能缓存同一地址,需保证一致性。MESI 协议定义 4 状态:
- M (Modified):已修改,独占;
- E (Exclusive):未修改,独占;
- S (Shared):未修改,共享;
- I (Invalid):无效。

### 3.11.3 预取 (Prefetch)

预测未来访问,提前加载到 Cache。硬件预取基于历史模式,软件预取由指令显式触发。

### 3.11.4 大页 (Huge Pages)

默认 4 KB 页,大页 2 MB / 1 GB,减少页表项数,降低 TLB 缺失。Linux `madvise` / `mmap` 支持。

## 3.13 本章习题

1. 主存 256 MB,按字节编址,需地址线多少位?
   - **答**:$\log_2(256 \text{M}) = \log_2(2^{28}) = 28$ 位。

2. Cache 64 KB,每行 64 B,4 路组相联,主存地址 32 位,求地址划分。
   - **答**:行数 = 64K/64 = 1024;组数 = 1024/4 = 256 = $2^8$;组号 8 位;行内 6 位;Tag = 32-8-6 = 18 位。划分:Tag(18) + 组号(8) + 偏移(6)。

3. Cache $t_c = 5$ ns,主存 $t_m = 100$ ns,命中率 95%,求顺序访问平均时间。
   - **答**:$0.95 \times 5 + 0.05 \times 105 = 4.75 + 5.25 = 10$ ns。

4. 32 位地址,4 KB 页,页表项 4 B,单级页表多大?
   - **答**:虚页数 = $2^{20}$ = 1M;页表 = 1M × 4 B = 4 MB。

5. 简述 TLB 缺失但页命中的处理流程。
   - **答**:TLB 缺失 → 访存查页表 → 页表项有效位 = 1 → 取实页号 → 填入 TLB → 实页号 + 偏移 = 物理地址 → 查 Cache。共 2 次访存 (页表 + Cache 可能命中)。
