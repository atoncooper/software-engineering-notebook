## 7.1 I/O 控制方式

### 7.1.1 程序查询

CPU 不断读设备状态寄存器,等设备就绪。

```
LOOP:
  读状态寄存器
  if (设备未就绪) goto LOOP
  读/写数据寄存器
```

- CPU 与设备**串行**,效率极低
- CPU 全程占用,无法做其他工作
- 适合**慢速、不频繁**设备(如温度传感器)
- 优点:硬件简单

### 7.1.2 程序中断

设备就绪发中断请求,CPU 响应中断,执行中断服务程序处理数据。

```
CPU 执行主程序
  ↓
设备就绪 → 发中断请求 INTR
  ↓
CPU 响应 → 转中断服务程序
  ↓
中断服务程序:读/写设备数据
  ↓
返回主程序
```

- CPU 与设备**部分并行**(CPU 在等设备时可做其他事)
- 数据传输仍**经 CPU**(每字节一次中断)
- 适合**中速设备**(键盘、打印机)
- 缺点:中断开销大(每次中断需保存/恢复现场)

### 7.1.3 DMA (Direct Memory Access)

设备与内存**直接**交换数据,DMA 控制器管理,**不过 CPU**。

```
CPU 初始化 DMA(设地址、计数、方向)
  ↓
DMA 控制总线,设备 ↔ 内存 直接传输(批量)
  ↓
传输完成,DMA 发中断通知 CPU
  ↓
CPU 后处理(校验等)
```

- CPU 与设备**高度并行**(CPU 仅开始/结束介入)
- 数据传输**不过 CPU**(直接设备 ↔ 内存)
- 适合**高速设备**(磁盘、网卡)
- 一次传输一块数据(不是字节)

### 7.1.4 通道

专用 **I/O 处理机**,执行通道程序。

```
CPU 启动通道(通道程序入口)
  ↓
通道独立执行通道程序(一组 I/O 指令)
  ↓
通道完成 → 发中断通知 CPU
```

- CPU 仅**启动通道、处理结束中断**
- 通道**独立执行**一组 I/O 指令
- 适合**大型机**(IBM 大型机)
- 比 DMA 更进一步:CPU 介入更少

### 7.1.5 四方式完整对比

| 方式 | CPU 介入 | 数据路径 | 传输单位 | 速度 | CPU 与设备并行度 | 适用 |
|------|----------|----------|----------|------|------------------|------|
| 程序查询 | 全程 | 设备↔CPU↔内存 | 字 | 慢 | 无 | 慢速 |
| 程序中断 | 每字节 | 设备↔CPU↔内存 | 字 | 中 | 部分 | 中速 |
| DMA | 开始/结束 | 设备↔内存 | 块 | 快 | 高 | 高速 |
| 通道 | 开始/结束 | 设备↔内存 | 块/程序 | 最快 | 最高 | 大型 |

**演进逻辑**:CPU 介入越来越少 → 并行度越来越高 → 适用设备越来越快。

## 7.2 中断

### 7.2.1 中断源分类

**外部中断(硬件中断)**:
- I/O 完成中断(键盘、磁盘)
- 时钟中断(分时系统)
- 电源故障
- 硬件故障

**内部中断(异常 / Exception)**:
- **故障 Fault**:除零、缺页、非法指令(可恢复,重执行)
- **陷阱 Trap**:系统调用、断点(故意,返回下条指令)
- **终止 Abort**:硬件故障(不可恢复)

> **计组视角**:外部中断在**指令执行末**响应;内部中断(异常)在**指令中**响应。

### 7.2.2 中断响应时机

- **外部中断**:**指令执行末**(不在指令中间响应,确保指令原子性)
- **内部中断(异常)**:**指令中**(立即响应,如缺页)
- **DMA 请求**:**总线周期末**(更细粒度,因 DMA 需总线)

> **优先级粒度**:总线周期 < 指令周期。所以 DMA 比中断响应更快。

### 7.2.3 中断响应过程(**硬件**完成)

```
1. 关中断(IF = 0)            ← 防止响应过程被打断
2. 保存断点(PC、PSW 入栈)     ← 必须硬件完成,软件无法保存 PC
3. 取中断向量(中断服务程序入口地址)→ PC
4. 转 PC,开始执行中断服务程序
```

**为什么关中断**?
- 保存断点过程不能被打断(否则断点丢失)
- 多重中断由软件(屏蔽字)控制,不由硬件响应过程控制

**为什么保存断点必须硬件**?
- 软件无法直接保存 PC(指令地址)
- 软件此时还不知道用哪个寄存器存

### 7.2.4 中断服务程序(**软件**完成)

```
1. 保护现场(通用寄存器入栈)    ← 软件保存运行环境
2. 处理中断事件(读/写 I/O 等)
3. 恢复现场(通用寄存器出栈)
4. 开中断(IF = 1)             ← 允许后续中断
5. 中断返回(IRET:恢复 PC、PSW)
```

### 7.2.5 中断优先级

**响应优先级(硬件决定,固定)**:
- 由硬件排队电路决定
- 不可屏蔽中断 NMI > 可屏蔽中断 INTR
- 通常:电源故障 > 内部异常 > 外部中断

**处理优先级(软件决定,动态)**:
- 由**中断屏蔽字**动态调整
- 处理 i 级中断时,屏蔽 i 及更低优先级 → 高优先级可打断
- 处理 i 级中断时,不屏蔽更高优先级 → 多重中断

### 7.2.6 多重中断(嵌套)

中断处理过程中允许**更高优先级**中断打断。

**实现**:**中断屏蔽字**

**例**:4 级中断,优先级 1 > 2 > 3 > 4,屏蔽字每位 1 表示屏蔽该级:

| 处理中的中断级 | 屏蔽字(1/2/3/4 位) | 允许打断的中断 |
|----------------|---------------------|------------------|
| 1 级 | 1111 | 无(最高) |
| 2 级 | 0111 | 1 级 |
| 3 级 | 0011 | 1、2 级 |
| 4 级 | 0001 | 1、2、3 级 |

> **真题陷阱**:
> - **响应优先级由硬件决定**(固定)
> - **处理优先级由屏蔽字动态调整**(可改变)
> - 不可屏蔽中断(NMI)**不能被屏蔽**

### 7.2.7 中断向量与向量表

- **中断向量**:中断服务程序入口地址
- **中断向量表**:存放所有中断向量的表(通常在内存低地址)
- **中断类型号**:索引中断向量表

**例**:x86 中断类型号 n,中断向量 = 内存 [n × 4](实模式,每项 4 字节:2 字节 CS + 2 字节 IP)。

## 7.3 DMA

### 7.3.1 DMA 控制器组成

```
┌──────────────── DMA 控制器 ────────────────┐
│                                             │
│  ┌─────────┐  ┌─────────┐  ┌─────────┐    │
│  │ 主存地址│  │ 字计数器│  │ 数据缓冲│    │
│  │ 寄存器  │  │   WC    │  │ 寄存器  │    │
│  │  MAR    │  │         │  │  DBR    │    │
│  └─────────┘  └─────────┘  └─────────┘    │
│                                             │
│  ┌─────────┐  ┌─────────┐                 │
│  │ 控制/   │  │ 设备地址│                 │
│  │ 状态寄存│  │ 寄存器  │                 │
│  │  器     │  │         │                 │
│  └─────────┘  └─────────┘                 │
│                                             │
└─────────────────────────────────────────────┘
        ↓                              ↓
     内存总线                      设备接口
```

| 寄存器 | 作用 |
|--------|------|
| MAR(主存地址寄存器) | 待访问内存地址,传输中自动 +1 |
| WC(字计数器) | 待传输字数,传输中自动 -1,=0 发中断 |
| DBR(数据缓冲寄存器) | 暂存传输数据 |
| 控制/状态寄存器 | 传输方向、DMA 请求/响应 |
| 设备地址寄存器 | 待访问设备地址 |

### 7.3.2 DMA 三种传输方式

DMA 与 CPU 共享内存总线,需协调访存时机。

#### (1) 周期挪用(周期窃取)

```
CPU 周期:  |_|_|_|_|_|_|_|_|
DMA 挪用:      |^|   |^|     ← CPU 不访存时,DMA 挪用周期
```

- DMA 在 **CPU 不访存**的周期使用总线
- 每次挪用一个周期传一字
- **优点**:CPU 不停止,效率高
- **缺点**:DMA 请求与 CPU 访存冲突时,DMA 优先(CPU 让出一个周期)
- 适用:慢速设备与 CPU 交替访存

#### (2) 停止 CPU 访存

```
CPU 周期:  |_|_|__停止__|_|_|
DMA:             |======|    ← DMA 期间 CPU 完全停止
```

- DMA 传输期间,**CPU 完全停止**访存
- **优点**:简单,DMA 独占总线
- **缺点**:CPU 利用率低(浪费周期)
- 适用:大批量数据传输

#### (3) 交替访存

```
CPU 周期:  |_|_|_|_|_|_|_|
DMA 周期:  |_|_|_|_|_|_|_|  ← 完全并行,周期分时
```

- CPU 与 DMA **分时使用**周期(如奇数周期 CPU,偶数周期 DMA)
- **优点**:效率最高,CPU 不停止
- **缺点**:硬件复杂,主存速度需翻倍
- 适用:高性能系统

### 7.3.3 DMA 三个阶段

```
阶段 1:预处理(CPU 干)
  ↓
阶段 2:数据传输(DMA 干,CPU 闲)
  ↓
阶段 3:后处理(CPU 干)
```

#### (1) 预处理

CPU 执行若干指令,初始化 DMA:
- 设主存起始地址 → MAR
- 设传输字数 → WC
- 设设备地址 → 设备地址寄存器
- 设传输方向(读/写)→ 控制/状态寄存器
- 启动 DMA

CPU 完成后**继续执行其他任务**(不等待传输)。

#### (2) 数据传输

DMA 控制总线:
- 设备 → DBR(数据缓冲)
- DBR → 内存[MAR](写),或 内存[MAR] → DBR(读)
- MAR + 1,WC - 1
- 重复直至 WC = 0
- WC = 0 时,DMA 发**中断**通知 CPU

**整个传输过程 CPU 不介入**(除总线冲突时让出周期)。

#### (3) 后处理

CPU 响应 DMA 中断:
- 校验数据是否正确
- 决定是否继续传输(下一块)
- 释放 DMA

### 7.3.4 DMA vs 中断完整对比

| 对比项 | 中断 | DMA |
|--------|------|-----|
| CPU 介入 | 每字节 | 仅开始/结束(预处理/后处理) |
| 数据路径 | 设备 → CPU → 内存 | 设备 ↔ 内存(不过 CPU) |
| 传输单位 | 字 | 块 |
| 速度 | 慢(中断开销) | 快(批量) |
| 优先级 | 较低 | 较高(DMA 不能被打断) |
| 响应时机 | 指令执行末 | 总线周期末(更细粒度) |
| 异常处理 | CPU | DMA 控制器 |
| 适用 | 中速设备 | 高速设备 |

> **关键**:
> - **DMA 优先级高于中断**(DMA 不能被中断打断传输)
> - **DMA 在总线周期末响应**,中断在指令末响应(总线周期 < 指令周期,DMA 响应更快)
> - **DMA 仍需中断**通知 CPU 传输完成(后处理)

## 7.4 通道

### 7.4.1 通道的本质

通道(Channel)是**专用 I/O 处理机**,有自己的指令系统(通道指令)和程序(通道程序)。CPU 仅启动通道,通道独立执行 I/O,完成后中断通知 CPU。

**与 DMA 的本质区别**:
- DMA 控制器是**固定逻辑**,只能按预设参数传输;
- 通道是**可编程处理机**,能执行通道程序,处理复杂 I/O 序列。

### 7.4.2 通道类型

#### 7.4.2.1 字节多路通道(Byte Multiplexer Channel)

- 多设备**分时**共享通道
- 每设备每次传 **1 字节**,轮流
- 适合**慢速设备**(打印机、终端、卡片机)
- 子通道方式:逻辑上每个设备一个子通道

**时序示意**(3 个设备 A/B/C 依次各传 1 字节):
```
时间:  t1   t2   t3   t4   t5   t6
通道:  A1   B1   C1   A2   B2   C2  ...
       └─ 轮询,每设备 1 字节
```

#### 7.4.2.2 数组选择通道(Block Selector Channel)

- 一次**独占**通道,传完一整块
- 适合**高速设备**(磁盘、磁带)
- 缺点:一次只服务一个设备,其他设备等待
- 通道利用率低(设备寻址时间长,传输时独占)

**时序示意**:
```
时间:  ── 寻址 A ──│── A 传输整块 ──│── 寻址 B ──│── B 传输整块 ──
通道:   独占 A                         独占 B
其他:                     等待                            等待
```

#### 7.4.2.3 数组多路通道(Block Multiplexer Channel)

- 分时(类似字节多路),但每次传**一块**(类似数组选择)
- 综合:高速 + 多设备并发
- 适合**多台高速设备**(多磁盘)
- IBM 大型机主流通道类型

**时序示意**(3 个磁盘 A/B/C 交替传块):
```
时间:  寻址A│A块1│寻址B│B块1│寻址C│C块1│A块2│B块2│...
通道:  交替服务,每设备传一块后切换
其他:  无设备长期等待(交叉寻址掩盖寻址时间)
```

### 7.4.3 通道指令与通道程序

#### 7.4.3.1 通道指令格式

```
┌────────┬──────────┬──────────┬────────┬────────┐
│ 操作码 │ 内存地址  │ 设备地址  │ 计数   │ 标志位 │
│ 8 位   │ 24 位    │ 8 位     │ 16 位  │ 8 位   │
└────────┴──────────┴──────────┴────────┴────────┘
```

| 字段 | 含义 |
|------|------|
| 操作码 | 读/写/反读/控制/转移/结束 |
| 内存地址 | 数据在主存的起始地址 |
| 设备地址 | 目标设备号 |
| 计数 | 传输字节数 |
| 标志位 | 链标志(数据链/命令链)、停机、错误标志 |

#### 7.4.3.2 通道程序示例

**任务**:从磁盘读取 512B 到主存 0x1000,再读 256B 到 0x2000。

```
通道程序(在主存中):
┌─────┬─────────┬─────────┬──────┬────────┐
│ 操作│ 内存地址 │ 设备地址 │ 计数 │ 标志   │
├─────┼─────────┼─────────┼──────┼────────┤
│ READ│ 0x1000  │ 0x10    │ 512  │ 命令链 │  ← 读 512B,后接命令
│ READ│ 0x2000  │ 0x10    │ 256  │ 结束   │  ← 读 256B,程序结束
└─────┴─────────┴─────────┴──────┴────────┘
```

**标志位**:
- **命令链**:下条指令是新操作(同设备)
- **数据链**:下条指令是同一操作的延续(数据分多段)
- **结束**:最后一条指令

#### 7.4.3.3 通道程序执行流程

```
1. CPU 在主存写好通道程序
2. CPU 执行 SIO(Start I/O)指令:
   - 通道地址寄存器 CAW ← 通道程序首地址
   - 启动通道
3. 通道独立执行通道程序:
   - 取通道指令
   - 执行(寻址设备、传输数据)
   - 标志位判断是否继续
4. 通道程序结束 → 通道发中断
5. CPU 响应中断,做后处理
```

### 7.4.4 通道 vs DMA 深度对比

| 对比项 | DMA | 通道 |
|--------|-----|------|
| 本质 | 固定逻辑控制器 | 可编程 I/O 处理机 |
| 指令 | 无(固定逻辑) | 通道指令(可编程) |
| 灵活性 | 低(参数固定) | 高(可执行程序) |
| CPU 介入 | 预处理 + 后处理 | 仅启动 + 结束中断 |
| 数据路径 | 设备 ↔ 内存 | 设备 ↔ 内存(通道控制) |
| 复杂操作 | 不支持(单块传输) | 支持(多段、控制、转移) |
| 适用场景 | 单台高速设备 | 大型机多设备 |
| 代表 | PC 的 8237、现代 SATA | IBM 大型机 ESCON/FICON |

### 7.4.5 IBM 大型机通道架构

IBM z 系列大型机通道是通道概念的现代化演进:

| 代 | 名称 | 速率 | 特点 |
|----|------|------|------|
| 早期 | Bus & Tag | 4.5 MB/s | 并行铜缆 |
| ESCON | Enterprise Systems CONnection | 17 MB/s | 光纤,串行 |
| FICON | Fiber CONnection | 1~8 Gb/s | 光纤,FC 协议承载 |
| FICON Express | — | 16~32 Gb/s | 现代 z15/z16 |

**现代演进**:通道概念在大型机之外演化为:
- **I/O 处理器(IOP)**:服务器中的专用 I/O CPU
- **SmartNIC / DPU**:网络数据路径卸载(NVIDIA BlueField、AMD Pensando)
- **IPU(Infrastructure Processing Unit)**:基础设施卸载(Intel IPU)
- **NVMe 控制器**:SSD 通道化(Multi-queue、SR-IOV)

> **真题陷阱**:
> - **通道是 I/O 处理机**,不是 DMA 的别名
> - **通道程序在主存**,通道取执行
> - **字节多路适合慢速设备**,数组选择适合高速单一设备,数组多路适合多台高速设备
> - **CPU 仅启动和结束处理**,传输过程 CPU 不介入

## 7.5 I/O 接口

### 7.5.1 I/O 接口组成

```
┌──────────────── I/O 接口 ────────────────┐
│  ┌──────────┐  ┌──────────┐              │
│  │ 数据寄存器│  │ 状态寄存器│              │
│  │  (数据端口)│ │ (状态端口)│              │
│  └──────────┘  └──────────┘              │
│  ┌──────────┐  ┌──────────┐              │
│  │ 控制寄存器│  │ 地址译码  │              │
│  │ (控制端口)│  │          │              │
│  └──────────┘  └──────────┘              │
│        ┌──────────────┐                  │
│        │  总线接口    │                  │
│        └──────────────┘                  │
└──────────────────────────────────────────┘
        ↓                    ↓
       系统总线              设备
```

| 寄存器 | 作用 |
|--------|------|
| 数据寄存器 | 暂存传输数据 |
| 状态寄存器 | 设备状态(就绪/忙/错误) |
| 控制寄存器 | CPU 写控制命令(启动/停止/方向) |

### 7.5.2 端口编址

**独立编址(Isolated I/O)**:
- I/O 端口与内存**分离**的地址空间
- 需**专用 I/O 指令**(如 x86 的 IN、OUT)
- 优点:内存空间不浪费
- 缺点:需专用指令
- 代表:x86

**统一编址(Memory-Mapped I/O)**:
- I/O 端口映射到**内存地址空间**
- 用**普通访存指令**(LOAD/STORE)访问
- 优点:不需专用指令
- 缺点:占用内存地址空间
- 代表:ARM、MIPS、RISC-V

| 对比项 | 独立编址 | 统一编址 |
|--------|----------|----------|
| 地址空间 | 独立 | 共享内存空间 |
| 指令 | 专用 IN/OUT | 普通访存 |
| 内存空间 | 不浪费 | 占用 |
| 控制 | 需 I/O 读写信号 | 仅内存读写 |
| 代表 | x86 | ARM、MIPS |

### 7.5.3 可编程接口芯片(了解)

| 芯片 | 功能 |
|------|------|
| 8255 | 可编程并行接口(三端口) |
| 8259 | 可编程中断控制器(级联) |
| 8253 | 可编程定时器/计数器 |
| 8237 | DMA 控制器 |

## 7.6 真题精解

### 【2017 选择】DMA vs 中断

**题目**:下列关于 DMA 的描述,正确的是?

A. DMA 传输需 CPU 每字节介入
B. DMA 传输数据经 CPU
C. DMA 直接控制设备与内存交换数据
D. DMA 不需中断

**答案**:**C**

**解析**:
- DMA 仅开始/结束需 CPU(A 错)
- DMA 数据**不**经 CPU,直接设备 ↔ 内存(B 错,C 对)
- DMA 完成后**仍需中断**通知 CPU 后处理(D 错)

### 【2018 选择】中断响应时机

**题目**:外部中断的响应时机是?

A. 时钟周期末  B. 总线周期末
C. 指令执行末  D. 指令译码后

**答案**:**C**

**解析**:
- 外部中断在**指令执行末**响应(保证指令原子性)
- DMA 请求在**总线周期末**响应(更细粒度)
- 内部中断(异常)在**指令中**响应

### 【2019 综合】DMA 三个阶段

**题目**:简述 DMA 传输的三个阶段及 CPU 在各阶段的工作。

**答**:
1. **预处理**(CPU 干):CPU 设 DMA 主存地址、字计数、设备地址、传输方向,启动 DMA。CPU 之后继续其他任务。
2. **数据传输**(DMA 干):DMA 控制总线,设备 ↔ 内存 直接传输批量数据,传输中 MAR+1、WC-1,WC=0 时 DMA 发中断通知 CPU。
3. **后处理**(CPU 干):CPU 响应中断,校验数据,决定是否继续传输。

### 【2020 选择】多重中断

**题目**:多重中断的实现依赖?

A. 硬件排队  B. 中断屏蔽字
C. 中断向量  D. 中断优先级寄存器

**答案**:**B**

**解析**:多重中断由**中断屏蔽字**动态调整处理优先级。响应优先级由硬件决定(固定),处理优先级由屏蔽字动态调整。

### 【2021 选择】独立编址 vs 统一编址

**题目**:下列关于 I/O 端口编址的描述,正确的是?

A. 独立编址用普通访存指令
B. 统一编址需专用 I/O 指令
C. 独立编址需专用 I/O 指令
D. 统一编址浪费内存空间

**答案**:**C**

**解析**:
- **独立编址**:I/O 与内存分离,需专用 I/O 指令(C 对)
- **统一编址**:I/O 映射到内存,用普通访存指令(A、B 错)
- 统一编址**占用**内存地址空间,但不"浪费"(D 错,只是占用)

### 【2024 综合】DMA 传输分析

**题目**(简化):磁盘转速 7200 RPM,每磁道 1 MB,DMA 周期挪用,内存周期 100 ns,求 DMA 挪用周期占比。

**解**:
- 磁盘转一圈时间 = 60/7200 = 8.33 ms
- 每磁道 1 MB,每秒传输 = 1 MB / 8.33 ms = 120 MB/s
- 每字(4 字节)传输时间 = 4 / 120M = 33.3 ns(磁盘侧)
- DMA 挪用一个内存周期 = 100 ns(每 4 字节一次)
- DMA 占总线比例 = 100 / (100 + 33.3) ≈ ... (具体看磁盘持续传输还是分块)
- 实际:磁盘每 33.3 ns 产生一字,DMA 每 100 ns 挪用一次传一字
- DMA 占用率 = 33.3 / 100 ≈ 33%(每 100 ns 周期中,33.3 ns 给 DMA)

(题目灵活,核心是计算 DMA 占用总线的比例)

## 7.7 真题陷阱(15 条)

1. **外部中断响应**:指令执行末(保证原子性)
2. **DMA 请求响应**:总线周期末(更细粒度)
3. **内部中断(异常)响应**:指令中(立即响应)
4. **DMA 优先级 > 中断**:DMA 不能被打断传输
5. **多重中断**:靠屏蔽字动态调整处理优先级
6. **响应优先级**(硬件固定)vs **处理优先级**(屏蔽字动态)
7. **DMA 不需 CPU 传数据**,但开始/结束需 CPU
8. **DMA 仍需中断**通知传输完成
9. **通道是专用 I/O 处理机**,执行通道程序
10. **独立编址需专用 I/O 指令**(x86 IN/OUT)
11. **统一编址用普通访存指令**(ARM、MIPS)
12. **CPU 响应中断过程**:关中断 → 保存断点 → 取中断向量(硬件完成)
13. **中断服务程序**:保护现场 → 处理 → 恢复现场 → 开中断 → 返回(软件)
14. **关中断原因**:响应过程不能被打断(否则断点丢失)
15. **DMA 三种传输方式**:周期挪用(常用)、停止 CPU、交替访存

## 7.8 易混淆点深辨析

### 7.8.1 中断响应 vs DMA 响应时机

| 时机 | 粒度 | 适合 |
|------|------|------|
| 中断响应 | 指令执行末 | 外部中断(指令原子性) |
| DMA 响应 | 总线周期末 | DMA(细粒度,抢占总线) |
| 异常响应 | 指令中 | 内部中断(立即处理) |

### 7.8.2 响应优先级 vs 处理优先级

| 维度 | 响应优先级 | 处理优先级 |
|------|------------|------------|
| 决定者 | 硬件排队电路 | 中断屏蔽字(软件) |
| 是否可变 | 固定 | 动态可变 |
| 作用 | 决定多个同时请求时谁先响应 | 决定处理中能否被更高优先级打断 |

### 7.8.3 四种 I/O 控制方式演进

```
程序查询 → 程序中断 → DMA → 通道
   ↓          ↓         ↓       ↓
CPU 全程  CPU 每字节  CPU 仅始末  CPU 仅启动
串行      并行(部分)  并行(高)    并行(最高)
```

### 7.8.4 DMA 三种传输方式对比

| 方式 | CPU 是否停止 | 效率 | 适用 |
|------|--------------|------|------|
| 周期挪用 | 不停止(让出周期) | 高 | 慢速设备 |
| 停止 CPU | 完全停止 | 低 | 大批量 |
| 交替访存 | 不停止 | 最高 | 高性能 |

## 7.11 延伸知识

### 7.11.1 PCIe DMA

- 现代 PCIe 设备支持 DMA(Bus Master)
- 设备发起 PCIe 事务,直接读写内存
- 需 IOMMU 隔离(防止设备越权访问)

### 7.11.2 中断控制器 8259A

- 8 级中断输入
- 可级联(主从,共 64 级)
- 优先级:固定优先级(IR0 最高)或循环优先级
- 现代 x86 用 APIC(高级可编程中断控制器)替代

### 7.11.3 MSI/MSI-X(消息信号中断)

- 传统中断:中断引脚(INTA 等)
- MSI:内存写模拟中断(写特定地址触发中断)
- MSI-X:支持更多中断向量(2048)
- PCIe 标准要求支持 MSI/MSI-X

### 7.11.4 IOMMU

- 类似 MMU,但用于设备
- 隔离设备 DMA 访问(防止越权)
- 虚拟化中:SR-IOV 设备直通(pass-through)

## 7.12 本章习题

1. 简述四种 I/O 控制方式的区别(CPU 介入程度、数据路径、传输单位)。
2. 中断响应过程中,哪些是硬件完成?哪些是软件完成?
3. DMA 为什么优先级高于中断?DMA 在何时响应中断请求?
4. 4 级中断优先级 1 > 2 > 3 > 4,给出多重中断的屏蔽字表。
5. 简述 DMA 三种传输方式及适用场景。
6. 独立编址和统一编址的区别?各举一个代表体系结构。
7. 通道的三种类型及适用设备?

### 习题答案

1. 见 7.1.5 表。

2. **硬件**:关中断、保存断点(PC/PSW 入栈)、取中断向量。**软件**:保护现场(通用寄存器)、处理中断事件、恢复现场、开中断、中断返回(IRET)。

3. DMA 优先级高于中断的原因:DMA 传输高速数据,若被打断会丢失数据。DMA 在**总线周期末**响应中断请求(粒度比指令周期小,响应更快)。

4. 见 7.2.6 表。处理 1 级屏蔽 1111,处理 2 级屏蔽 0111,处理 3 级屏蔽 0011,处理 4 级屏蔽 0001。

5. 见 7.3.2 节。**周期挪用**:CPU 不停止,让出周期,适合慢速设备。**停止 CPU**:DMA 期间 CPU 完全停止,简单但浪费,适合大批量。**交替访存**:CPU 与 DMA 分时周期,效率最高,适合高性能。

6. **独立编址**:I/O 端口与内存分离,需专用 I/O 指令(x86 IN/OUT)。**统一编址**:I/O 映射到内存地址空间,用普通访存指令(ARM、MIPS)。

7. **字节多路通道**:多设备分时,每字节轮流,适合慢速设备(打印机、终端)。**数组选择通道**:独占通道传一块,适合高速设备(磁盘)。**数组多路通道**:分时但每次传一块,适合多台高速设备。
