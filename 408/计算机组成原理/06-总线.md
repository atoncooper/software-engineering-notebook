## 6.1 总线概述

### 6.1.1 定义

**总线**(Bus):连接多个部件、能为多个部件**分时共享**的一组信息传输线。

**核心特性**:
- **分时**:同一时刻只有一对设备通信(避免冲突)
- **共享**:多个设备挂在同一条总线上

### 6.1.2 总线特性

| 特性 | 含义 |
|------|------|
| 机械特性 | 物理连接(接插件、尺寸) |
| 电气特性 | 信号方向、电平、驱动能力 |
| 功能特性 | 每根线功能(地址/数据/控制) |
| 时间特性 | 信号时序(同步/异步) |

### 6.1.3 总线带宽

$$
\text{带宽 (B/s)} = \text{工作频率 (Hz)} \times \frac{\text{位宽 (bit)}}{8}
$$

**例 1**:32 位总线,工作频率 66 MHz,带宽 = $66 \times 10^6 \times 4 = 264$ MB/s。

**例 2**:64 位总线,133 MHz,带宽 = $133 \times 10^6 \times 8 = 1064$ MB/s ≈ 1 GB/s。

**DDR(双沿传输)**:每个时钟周期上下沿各传一次,带宽 × 2。
- DDR-400,64 位,带宽 = $400 \times 10^6 \times 8 \times 2 = 6400$ MB/s = 6.4 GB/s

> **真题陷阱**:
> - 实际带宽受总线协议、等待周期影响,理论 ≠ 实际
> - DDR 带宽 × 2(双沿触发)
> - 总线复用(地址/数据分时复用)需多个周期传同一信息

## 6.2 总线分类

### 6.2.1 按位置

| 类型 | 位置 | 例 |
|------|------|------|
| 片内总线 | CPU 芯片内部 | ALU 与寄存器间 |
| 系统总线 | CPU 与各部件之间 | ISA、PCI、PCIe |
| 通信总线 | 计算机之间 | USB、Ethernet、RS-232 |

### 6.2.2 按信号(系统总线三组)

| 类型 | 方向 | 宽度 | 作用 |
|------|------|------|------|
| 数据总线 DB | 双向 | = 字长 | 传输数据 |
| 地址总线 AB | 单向 | = 地址空间 | 指定内存/IO 地址 |
| 控制总线 CB | 双向 | 多种 | 时序、读/写、中断、总线请求等 |

**例**:32 位机,地址空间 4GB → 地址总线 32 位,数据总线 32 位。

### 6.2.3 按传输方向

- **单工**:单向(如广播)
- **半双工**:双向分时(如对讲机)
- **全双工**:双向同时(如电话)

### 6.2.4 按数据传输方式

- **串行总线**:1 位/位时,线少但慢(USB、SATA)
- **并行总线**:多位同时,线多但快(PCI、前端总线)
- 趋势:**高速串行替代并行**(PCIe 替代 PCI,SATA 替代 PATA)

> **真题陷阱**:并行总线高频时**线间串扰**严重,反而不如串行。PCIe 用串行差分对实现高速。

## 6.3 总线性能指标

### 6.3.1 核心指标表

| 指标 | 含义 | 公式/例 | 单位 |
|------|------|---------|------|
| 总线宽度 | 数据线位数 | 32/64 位 | bit |
| 总线频率 | 每秒传输次数 | 66/133/200 MHz | Hz |
| 总线带宽 | 单位时间传输数据量 | 频率 × 宽度 / 8 | B/s |
| 总线复用 | 地址/数据分时复用 | 8086 AD0~AD15 | — |
| 信号线数 | 总线总根数 | 数据 + 地址 + 控制 | 根 |
| 负载能力 | 可挂设备数 | TTL 几个,缓冲后更多 | 个 |
| 总线传输周期 | 完成一次总线操作的时间 | 1~n 个时钟周期 | 周期 |
| 突发传输率 | 突发模式下的实际带宽 | 块大小 × 频率 / 8 | B/s |

### 6.3.2 总线带宽公式与变形

**基础公式**:

$$
\text{带宽 (B/s)} = \text{工作频率 (Hz)} \times \frac{\text{位宽 (bit)}}{8}
$$

**含 DDR 与复用的修正**:

$$
\text{带宽} = \text{频率} \times \frac{\text{位宽}}{8} \times \text{DDR 系数} \times \text{复用系数}
$$

- **DDR 系数**:双沿传输 = 2,单沿 = 1
- **复用系数**:地址/数据复用时 = 0.5(每事务 2 周期),不复用 = 1

### 6.3.3 总线带宽计算示例

**例 1:基础计算**

32 位总线,66 MHz,单沿,不复用:

$$
B = 66 \times 10^6 \times 32/8 = 66 \times 4 = 264 \text{ MB/s}
$$

**例 2:DDR 内存**

64 位 DDR-400 总线,双沿传输:

$$
B = 400 \times 10^6 \times 64/8 \times 2 = 400 \times 8 \times 2 = 6400 \text{ MB/s} = 6.4 \text{ GB/s}
$$

**例 3:地址/数据复用**

32 位总线,100 MHz,地址/数据复用(每事务 2 周期):

$$
B = 100 \times 10^6 \times 32/8 \times 0.5 = 100 \times 4 \times 0.5 = 200 \text{ MB/s}
$$

**例 4:突发传输**

PCIe 4.0 x16(16 通道,每通道 16 GT/s,每拍 1 字节):

$$
B = 16 \times 16 \times 10^9 / 8 = 32 \text{ GB/s}
$$

### 6.3.4 总线复用

**8086 的 AD0~AD15** 是地址/数据复用线:

```
时序:
     ┌── T1 ──┬── T2 ──┬── T3 ──┬── T4 ──┐
AD:  │ 地址   │  数据  │  数据  │  数据  │
ALE: │─┐     │        │        │        │
     │ │ 锁存 │        │        │        │
     └─┘     │        │        │        │
```

- **T1 周期**:输出地址(由 ALE 下降沿锁存到外部锁存器)
- **T2~T4 周期**:数据传输

**优点**:引脚少(8086 仅 40 引脚)
**缺点**:需多周期(地址 + 数据分开传),带宽减半

### 6.3.5 总线事务传输周期

**单事务 vs 突发(Burst)事务**:

```
单事务(每次都含地址):
  地址1 → 数据1 → 地址2 → 数据2 → 地址3 → 数据3
  ↑ 每次都传地址,开销大

突发事务(地址一次,数据多次):
  地址1 → 数据1 → 数据2 → 数据3 → ... → 数据N
  ↑ 地址仅传一次,后续连续数据,效率高
```

**突发传输带宽优势**:

$$
\text{突发带宽} = \frac{\text{块大小} \times \text{频率} \times \text{位宽}/8}{\text{地址周期} + \text{数据周期}}
$$

例:4 周期地址 + 16 周期数据(块 64B,32 位总线 100 MHz):

- 单事务:每事务 1 地址 + 1 数据 = 2 周期,带宽 = 100M × 4 / 2 = 200 MB/s
- 突发:16 数据 + 1 地址 = 17 周期,带宽 = 100M × 4 × 16 / 17 ≈ 376 MB/s

### 6.3.6 总线协议开销

**实际带宽 < 理论带宽**,原因:

| 开销来源 | 说明 |
|----------|------|
| 仲裁周期 | 多设备竞争,需仲裁 |
| 地址周期 | 非复用总线也需寻址 |
| 控制信号 | 读/写、就绪、等待 |
| 等待周期 | 慢设备插 WAIT |
| 协议开销 | 头部、CRC、握手 |
| 突发中断 | 中途换主设备 |

**实际带宽** = 理论带宽 × **有效传输比例**

例:理论 1 GB/s,有效 80%,实际 800 MB/s。

### 6.3.7 总线带宽 vs 内存带宽

| 维度 | 总线带宽 | 内存带宽 |
|------|----------|----------|
| 定义 | 总线单位时间传输量 | 内存单位时间读写量 |
| 限制 | 总线频率、位宽 | 内存芯片速率、位宽 |
| 关系 | CPU↔内存总线带宽 ≥ 内存带宽 | 否则内存带宽被总线限制 |
| 例 | DDR4 总线 25.6 GB/s | DDR4-3200 双通道 51.2 GB/s |

> **真题陷阱**:
> - **总线复用导致带宽减半**(地址/数据分时)
> - **DDR 双沿传输,带宽 × 2**
> - **突发传输提高实际带宽**(地址仅一次)
> - **实际带宽 < 理论带宽**(协议开销)
> - **总线带宽是上限,内存带宽可能更低**

## 6.4 总线仲裁

**问题**:多个设备同时申请总线时,决定谁先使用。

**主设备**(Master):发起总线事务(如 CPU、DMA)
**从设备**(Slave):响应主设备(如内存、I/O)

### 6.4.1 集中式仲裁

#### (1) 链式查询(Chained Daisy Chain)

```
                  总线控制器
                  ┌──────┐
           BR ────│      │
           BG ────│      │──── BG → 设备1 → 设备2 → 设备3 → ...
           BS ────│      │
                  └──────┘

线数:3(BR 总请求, BG 授权, BS 忙)
```

**工作流程**:
1. 任一设备申请 → BR = 1
2. 控制器发 BG(总线授权)
3. BG 沿链路下传,**第一个申请的设备截获 BG**,置 BS = 1
4. 该设备使用总线,用完释放 BS

**特点**:
- **优先级固定**(离控制器近的优先级高)
- **线数最少**(3 根)
- **简单**,但:
  - 易故障(链路中一个设备故障,后续全失效)
  - 优先级不公平(远端设备可能饿死)
  - 慢(BG 链路传播延迟)

#### (2) 计数器定时查询

```
                  总线控制器
                  ┌──────┐  ←── 计数器
           BR ────│      │
           BS ────│      │──── 设备地址线 ⌈log n⌉ 根 → 各设备
                  └──────┘

线数:2 + ⌈log n⌉(BR, BS, 设备地址线)
```

**工作流程**:
1. 任一设备申请 → BR = 1
2. 控制器内计数器从 0 递增
3. 计数器值 = 设备地址时,该设备获总线权,置 BS = 1
4. 计数器停止

**特点**:
- **优先级灵活**(可固定从 0 开始,也可循环)
- **线数中等**($2 + \lceil \log_2 n \rceil$)
- **速度中等**(计数器递增需时间)
- **公平性可调**(循环计数 → 公平;固定从 0 → 类似链式)

#### (3) 独立请求

```
                  总线控制器
                  ┌──────┐
   设备1 ──BR1, BG1──│      │
   设备2 ──BR2, BG2──│      │
   设备3 ──BR3, BG3──│      │
                  └──────┘

线数:2n + 1(n 个 BR, n 个 BG, 1 个 BS)
```

**工作流程**:
1. 每个设备独立申请线 BR_i,独立授权线 BG_i
2. 控制器内部判优(可编程优先级)
3. 优先级最高者获 BG_i

**特点**:
- **速度最快**(无需链路或计数器传播)
- **优先级可编程**(控制器内部判优)
- **线数最多**($2n + 1$,n 大时复杂)
- **公平**(可编程轮转)

### 6.4.2 三种集中式对比

| 方式 | 线数 | 速度 | 优先级 | 复杂度 |
|------|------|------|--------|--------|
| 链式查询 | 3 | 最慢 | 固定(离控制器近) | 最低 |
| 计数器定时 | 2 + ⌈log n⌉ | 中 | 灵活(可循环) | 中 |
| 独立请求 | 2n + 1 | 最快 | 可编程 | 最高 |

### 6.4.3 分布式仲裁

无中央仲裁器,各设备自带仲裁逻辑,通过协议仲裁。

- **令牌传递**:设备环状连接,持有令牌者可用总线
- **冲突检测**(CSMA/CD 类似):先监听,冲突后退避
- **并行竞争仲裁**:各设备并行发优先级编码,胜者获总线

**优点**:无单点故障(无中央仲裁器)
**缺点**:设备逻辑复杂

## 6.5 总线事务与通信方式

### 6.5.1 总线事务五阶段

```
1. 请求(RQ):主设备申请总线
2. 仲裁:决定主设备(由仲裁器或协议)
3. 寻址:主设备发地址(指定从设备)
4. 传数据:主从设备交换数据(读/写)
5. 释放:主设备释放总线
```

### 6.5.2 同步通信

**统一时钟**,固定时序,所有设备按相同时钟节奏工作。

```
T1: 主设备发地址
T2: 主设备发读命令
T3: 从设备发数据
T4: 主设备撤销
```

**优点**:简单,控制逻辑少
**缺点**:**必须匹配速度**(慢设备拖累快设备,不能差异大)
**适用**:部件速度相近(如 CPU 与内存)

### 6.5.3 异步通信(握手)

**不依赖公共时钟**,用 REQ/ACK 握手协议。

**三种互锁方式**:

#### (1) 不互锁

```
主设备: ──REQ──┐              ┌───
                │              │
从设备:         └──DATA──┐    │
                          │    │
                          └────┘  (从设备发完数据,不等 ACK)
```

- 主设备发 REQ 后等固定时间
- 从设备发 DATA 后不等 REQ 撤销
- **最快但不可靠**

#### (2) 半互锁

```
主设备: ──REQ──────────┐  (等 ACK 后才撤销 REQ)
                       │
从设备:        ──ACK───┘        (从设备 ACK 后不等 REQ 撤销)
```

- 主设备发 REQ,等从设备 ACK 后才撤销 REQ
- 从设备发 ACK 后固定时间撤销(不等 REQ 撤销)
- **中等可靠**

#### (3) 全互锁

```
主设备: ──REQ─────────────┐  (等 ACK)
                          │
从设备:        ──ACK──────┘  (等 REQ 撤销)
                          │
主设备:        ←───(撤销 REQ)
                          │
从设备:                    └──(撤销 ACK)
```

- 主设备发 REQ,等从设备 ACK
- 从设备发 ACK,等主设备 REQ 撤销后才撤销 ACK
- **最可靠但最慢**

**异步通信适用**:速度差异大的设备(如 CPU 与 I/O)

### 6.5.4 半同步通信

同步 + WAIT 信号。

- 基本时序同步(统一时钟)
- 慢设备可发 WAIT 信号,延长周期
- 主设备检测 WAIT,若 = 1 则插入等待周期

**优点**:兼具同步简单 + 异步灵活
**适用**:速度差异不大的部件(如 CPU 与慢速内存)

### 6.5.5 分离事务通信

把总线事务**分两阶段**:

```
阶段 1:请求 + 寻址 → 主设备释放总线
        ↓
   从设备准备数据(期间总线可给其他设备用)
        ↓
阶段 2:从设备重新申请总线,返回数据
```

**优点**:
- 总线利用率高(准备数据期间不占总线)
- 多个事务可重叠

**缺点**:
- 控制复杂
- 单个事务延迟增加(需重新申请总线)

**适用**:慢速设备(如内存读,准备数据时间长)

## 6.6 真题精解

### 【2017 选择】总线带宽计算

**题目**:某总线 32 位,工作频率 66 MHz,求总线带宽。

A. 132 MB/s  B. 264 MB/s  C. 528 MB/s  D. 1056 MB/s

**答案**:**B**

**解析**:$66 \times 10^6 \times 32/8 = 66 \times 4 = 264$ MB/s。

### 【2019 选择】链式查询优先级

**题目**:链式查询方式中,总线优先级由什么决定?

A. 设备申请顺序  B. 设备地址大小
C. 设备在链上的位置  D. 控制器内部判优

**答案**:**C**

**解析**:链式查询优先级**固定**,离控制器越近优先级越高。

### 【2021 选择】同步 vs 异步

**题目**:下列关于同步通信和异步通信的描述,正确的是?

A. 同步通信适合速度差异大的设备
B. 异步通信需统一时钟
C. 异步通信适合速度差异大的设备
D. 半同步通信需 REQ/ACK 握手

**答案**:**C**

**解析**:
- 同步通信需统一时钟,适合速度相近(A 错)
- 异步通信不依赖时钟,用握手(B 错)
- 异步适合速度差异大(C 对)
- 半同步用 WAIT 信号,异步才用握手(D 错)

### 【2018 选择】三种仲裁线数

**题目**:n 个设备,链式查询、计数器定时、独立请求三种集中式仲裁,线数分别为?

A. 3, 2+⌈log n⌉, 2n+1
B. 2, 2+⌈log n⌉, 2n
C. 3, ⌈log n⌉, 2n+1
D. 3, 2+⌈log n⌉, 2n

**答案**:**A**

**解析**:
- 链式查询:BR + BG + BS = 3 根
- 计数器定时:BR + BS + ⌈log n⌉ 设备地址线 = 2 + ⌈log n⌉
- 独立请求:n 个 BR + n 个 BG + 1 个 BS = 2n + 1

### 【2020 选择】分离事务

**题目**:分离事务通信的主要优点是?

A. 单个事务延迟小  B. 控制简单
C. 总线利用率高  D. 适合同步通信

**答案**:**C**

**解析**:分离事务在从设备准备数据期间释放总线,可服务其他设备,**提高总线利用率**。代价是控制复杂、单事务延迟增加。

### 【2022 选择】总线复用

**题目**:某总线地址/数据复用,32 位,工作频率 100 MHz,实际带宽?

A. 200 MB/s  B. 400 MB/s  C. 800 MB/s  D. 1600 MB/s

**答案**:**B**(假设复用导致每事务需 2 周期)

**解析**:
- 理论带宽 = $100 \times 10^6 \times 4 = 400$ MB/s
- 地址/数据复用:每个事务需 1 周期地址 + 1 周期数据,实际带宽减半 = 200 MB/s
- (题目明确"实际带宽",按减半算)

> **陷阱**:总线复用导致带宽减半。具体题目需看清是否含地址周期。

## 6.7 真题陷阱(12 条)

1. **总线带宽** = 频率 × 宽度 / 8,DDR 翻倍
2. **总线复用**:地址/数据分时复用,带宽减半
3. **链式查询优先级固定**:离控制器近的优先
4. **独立请求速度最快**但线数最多(2n+1)
5. **计数器定时线数**:2 + ⌈log n⌉
6. **同步通信需统一时钟**,异步用握手
7. **异步适合速度差异大**的设备
8. **全互锁最可靠最慢**,不互锁最快最不可靠
9. **半同步**:同步 + WAIT 信号
10. **分离事务**:提高总线利用率,但单事务延迟增加
11. **串行替代并行趋势**:PCIe 替代 PCI(高频并行线间串扰)
12. **总线事务五阶段**:请求 → 仲裁 → 寻址 → 传数据 → 释放

## 6.8 易混淆点深辨析

### 6.8.1 同步 / 异步 / 半同步 / 分离事务

| 方式 | 时钟 | 握手 | 速度 | 适用 |
|------|------|------|------|------|
| 同步 | 统一 | 无 | 快 | 速度相近 |
| 异步 | 无 | REQ/ACK | 中 | 速度差异大 |
| 半同步 | 统一 | + WAIT | 中 | 慢速内存 |
| 分离事务 | 任意 | 任意 | 利用率高 | 慢设备 |

### 6.8.2 三种握手互锁对比

| 方式 | 主设备 | 从设备 | 可靠性 | 速度 |
|------|--------|--------|--------|------|
| 不互锁 | 等固定时间 | 不等 ACK 撤销 | 低 | 快 |
| 半互锁 | 等 ACK 才撤销 REQ | 不等 REQ 撤销 | 中 | 中 |
| 全互锁 | 等 ACK | 等 REQ 撤销 | 高 | 慢 |

### 6.8.3 三种集中式仲裁

| 方式 | 线数 | 速度 | 优先级 | 适用 |
|------|------|------|--------|------|
| 链式 | 3 | 慢 | 固定 | 简单系统 |
| 计数器 | 2+⌈log n⌉ | 中 | 灵活 | 中等系统 |
| 独立请求 | 2n+1 | 快 | 可编程 | 高性能系统 |

## 6.11 延伸知识

### 6.11.1 PCIe(PCI Express)

- **串行差分对**替代并行 PCI
- **点对点**连接(每设备独占通道,非共享总线)
- **多通道**:x1、x4、x8、x16
- **带宽**:PCIe 4.0 x16 ≈ 32 GB/s
- **事务层 + 数据链路层 + 物理层**

### 6.11.2 AMBA(ARM 总线标准)

- **AXI**(Advanced eXtensible Interface):高性能,分离事务
- **AHB**(Advanced High-performance Bus):高速
- **APB**(Advanced Peripheral Bus):低速外设

### 6.11.3 USB 串行总线

- 串行差分对(D+/D-)
- 半双工(USB 2.0)、全双工(USB 3.0+)
- 集线器星型拓扑
- 仲裁:主机轮询

### 6.11.4 前端总线 FSB 与内存总线

- **FSB**:CPU 与北桥(内存控制器)间总线,早期 x86
- **内存总线**:北桥与内存间
- 现代 x86:**集成内存控制器**(CPU 直连内存),FSB 淘汰,DMI 替代

## 6.12 本章习题

1. 64 位总线,工作频率 200 MHz,DDR 传输,求带宽。
2. n=8 个设备,分别求链式查询、计数器定时、独立请求的线数。
3. 简述同步通信和异步通信的适用场景,说明原因。
4. 全互锁、半互锁、不互锁的可靠性如何?为什么?
5. 分离事务通信为什么能提高总线利用率?代价是什么?

### 习题答案

1. $200 \times 10^6 \times 8 \times 2 = 3200$ MB/s = 3.2 GB/s。

2. n=8:
   - 链式查询:3 根
   - 计数器定时:$2 + \lceil \log_2 8 \rceil = 2 + 3 = 5$ 根
   - 独立请求:$2 \times 8 + 1 = 17$ 根

3. **同步通信**适合速度相近的设备(如 CPU 与内存),因需统一时钟,慢设备会拖累快设备。**异步通信**适合速度差异大的设备(如 CPU 与 I/O),用握手协议不依赖公共时钟,慢设备可按自己节奏响应。

4. **全互锁**最可靠:REQ 和 ACK 互相等待,确保双方都收到对方的信号。**半互锁**次之:主设备等 ACK,从设备不等 REQ 撤销,可能下次 REQ 与残留 ACK 冲突。**不互锁**最不可靠:双方都等固定时间,若实际延迟超预期会丢失数据。

5. 分离事务在从设备准备数据期间释放总线,允许其他设备使用,**提高总线利用率**。代价是:(1) 控制复杂(需两次申请总线);(2) 单个事务延迟增加(重新申请 + 仲裁)。
