## 5.1 CPU 组成与寄存器

### 5.1.1 三大部件

```
┌───────────────────────────────────────────┐
│                  CPU                       │
│  ┌─────────┐  ┌─────────┐  ┌──────────┐  │
│  │   ALU   │  │   CU    │  │  寄存器组 │  │
│  │ 算术逻辑 │  │ 控制单元 │  │ PC IR MAR │  │
│  │  运算    │  │ 产生信号 │  │ MDR PSW   │  │
│  └─────────┘  └─────────┘  └──────────┘  │
└───────────────────────────────────────────┘
```

- **ALU** (Arithmetic Logic Unit):执行算术和逻辑运算
- **CU** (Control Unit):产生控制信号,控制指令执行流程
- **寄存器组**:存储中间数据和控制信息

### 5.1.2 寄存器(必背)

| 寄存器 | 全称 | 作用 | 可见性 |
|--------|------|------|--------|
| **PC** | Program Counter | 下条指令地址 | 用户可见 |
| **IR** | Instruction Register | 当前指令 | 透明 |
| **MAR** | Memory Address Register | 待访问内存地址 | 透明 |
| **MDR** | Memory Data Register | 待读写内存数据 | 透明 |
| **PSW** | Program Status Word | 程序状态字(标志位) | 部分可见 |
| **通用寄存器** GPR | R0~Rn | 运算暂存 | 用户可见 |
| **ACC** | Accumulator | ALU 输入/输出 | 用户可见 |
| **暂存器** TEMP | (内部) | ALU 中间结果 | 透明 |

**PSW 标志位**:
- **ZF** (Zero Flag):结果为零
- **SF** (Sign Flag):结果为负
- **OF** (Overflow Flag):算术溢出
- **CF** (Carry Flag):进位/借位
- **IF** (Interrupt Flag):中断允许
- **TF** (Trap Flag):单步陷阱

### 5.1.3 用户可见 vs 透明

| 寄存器 | 用户可见性 | 说明 |
|--------|------------|------|
| PC | 可见(转移指令可改) | 程序员可通过转移指令修改 |
| 通用寄存器 | 可见 | 程序员直接编程使用 |
| PSW | 部分可见 | 标志位可读,某些位可写 |
| IR | 透明 | 程序员不可见,CU 内部使用 |
| MAR | 透明 | 程序员不可见 |
| MDR | 透明 | 程序员不可见 |
| 暂存器 | 透明 | 程序员不可见 |

> **真题陷阱**:"可见"指程序员可通过指令访问/修改。"透明"指程序员看不到、不能直接操作。

## 5.2 指令执行过程

### 5.2.1 周期层次

```
指令周期 > 机器周期 > 时钟周期
```

- **指令周期**:CPU 取出并执行一条指令的时间
- **机器周期**:指令周期中的一个阶段(取指/间址/执行/中断)
- **时钟周期**:最基本时间单位,= 1/主频

**关系**:指令周期 = 若干机器周期,机器周期 = 若干时钟周期。

**早期机器**:机器周期 = 主存周期(因主存慢)。**现代机器**:机器周期通常 = 1 个时钟周期(主存快 + Cache)。

### 5.2.2 指令周期的四个阶段

```
┌─────────┐  ┌─────────┐  ┌─────────┐  ┌─────────┐
│ 取指周期 │→│ 间址周期 │→│ 执行周期 │→│ 中断周期 │
└─────────┘  └─────────┘  └─────────┘  └─────────┘
   必有        可选(寻址)    必有        可选(有中断)
```

- **取指周期**(必有):从内存取指令到 IR
- **间址周期**(可选):间接寻址时,取有效地址
- **执行周期**(必有):执行指令操作
- **中断周期**(可选):有中断请求时,保存断点、取中断向量

### 5.2.3 取指过程(6 步)

```
1. PC → MAR            (指令地址送 MAR)
2. MAR → 地址总线       (内存地址就绪)
3. CU 发 Read 命令       (启动内存读)
4. 内存 → 数据总线 → MDR  (指令读到 MDR)
5. MDR → IR             (指令送 IR)
6. PC + 1 → PC          (PC 指向下条指令)
```

> **关键**:PC + 1 的 "1" 是指令长度,不是 1 字节。若指令 4 字节,PC ← PC + 4。

### 5.2.4 执行过程(随指令而异)

**LOAD R, [addr]**(直接寻址):
```
1. addr(IR 地址码) → MAR
2. CU 发 Read
3. 内存 → MDR
4. MDR → R
```

**STORE R, [addr]**:
```
1. addr → MAR
2. R → MDR
3. CU 发 Write
4. MDR → 内存
```

**ADD R1, R2, R3**(R1 ← R2 + R3):
```
1. R2 → ALU 输入 A
2. R3 → ALU 输入 B
3. ALU 加法 → 暂存器
4. 暂存器 → R1
```

**JMP addr**(无条件转移):
```
1. addr → PC    (直接转移)
   或 EA → PC   (间接转移)
   或 PC + offset → PC  (相对转移)
```

### 5.2.5 中断周期

**指令执行末**检查中断请求:

```
1. 关中断(IF = 0)         (防止中断嵌套时丢失断点)
2. 保存断点(PC、PSW 入栈)
3. 中断向量地址 → PC       (转中断服务程序)
4. 开中断(IF = 1)         (允许更高级中断)
5. 执行中断服务程序
6. 中断返回 IRET:恢复 PC、PSW
```

**中断向量**:中断服务程序入口地址。中断向量表存放所有中断向量。

## 5.3 数据通路

### 5.3.1 数据通路定义

**数据通路**(Datapath):指令执行过程中数据流经的路径,包括 ALU、寄存器、多路选择器、内部总线。

**核心组件**:

| 组件 | 作用 | 触发信号 |
|------|------|----------|
| PC | 程序计数器,存当前指令地址 | PCWrite |
| MAR | 内存地址寄存器,存访存地址 | MARLoad |
| MDR | 内存数据寄存器,存访存数据 | MDRLoad |
| IR | 指令寄存器,存当前指令 | IRLoad |
| ALU | 算术逻辑单元 | ALUOp |
| 通用寄存器堆 | R0~Rn | RegRead/RegWrite |
| 暂存器 Y/Z | 单总线结构中暂存操作数/结果 | YLoad/ZLoad |
| 多路选择器 | 选路 | 多个 MUX 控制信号 |

### 5.3.2 总线结构对比

| 结构 | ALU 输入 | 优点 | 缺点 | 执行 ADD 拍数 |
|------|----------|------|------|---------------|
| 单总线 | 1 个操作数先入暂存器,再入第 2 个 | 简单,引脚少 | 慢(需 2 拍送操作数) | 4 拍 |
| 双总线 | 两操作数同时上总线 | 快 | ALU 输出需暂存 | 3 拍 |
| 三总线 | A、B 总线送操作数,C 总线取结果 | 最快 | 复杂、成本高 | 1 拍 |

### 5.3.3 单总线数据通路

```
         ┌─────┐  ┌─────┐  ┌─────┐  ┌─────┐
         │ PC  │  │ IR  │  │  Y  │  │  Z  │
         └──┬──┘  └──┬──┘  └──┬──┘  └──┬──┘
            │        │        │        │
   ═════════╪════════╪════════╪════════╪════════ 单总线
            │        │        │        │
         ┌──┴──┐  ┌──┴──┐     │     ┌──┴──┐
         │MAR  │  │MDR  │     │     │ALU  │
         └─────┘  └──┬──┘     │     └─────┘
                     │        │
                  ┌──┴────────┴──┐
                  │  通用寄存器堆  │
                  └──────────────┘
```

### 5.3.4 单总线指令执行流程

#### 5.3.4.1 公共取指(所有指令)

```
1. PC → MAR           (送地址到 MAR)
2. MAR → 内存, MDR ← 内存  (读指令)
3. MDR → IR           (指令送 IR)
4. PC + 4 → PC        (PC 自增)
5. IR 译码            (操作码译码)
```

#### 5.3.4.2 ADD R1, R2, R3(R 型,单总线)

```
1. R2 → 总线 → Y           (第一操作数入 Y)
2. R3 → 总线, ALU: Y + R3  (第二操作数上总线,ALU 加)
3. ALU → Z                 (结果存 Z)
4. Z → 总线 → R1           (结果写回 R1)
```

**共 4 拍**(取指另算)。

#### 5.3.4.3 LOAD R1, 8(R2)(I 型访存)

```
1. R2 → 总线 → Y           (基址入 Y)
2. IR[imm] → 总线, ALU: Y + imm  (算有效地址)
3. ALU → Z → MAR           (地址送 MAR)
4. MAR → 内存, MDR ← 内存  (读内存)
5. MDR → 总线 → R1         (数据写回 R1)
```

#### 5.3.4.4 STORE R1, 8(R2)(I 型访存)

```
1. R2 → 总线 → Y           (基址入 Y)
2. IR[imm] → 总线, ALU: Y + imm  (算有效地址)
3. ALU → Z → MAR           (地址送 MAR)
4. R1 → 总线 → MDR         (数据送 MDR)
5. MDR → 内存              (写内存)
```

#### 5.3.4.5 BEQ R1, R2, offset(条件转移)

```
1. R1 → 总线 → Y
2. R2 → 总线, ALU: Y - R2  (比较)
3. ALU → Z, 检测 Z = 0
4. 若相等: PC + (offset << 2) → PC
   否则: 顺序执行
```

### 5.3.5 数据通路图阅读要点

1. **找公共取指部分**:PC → MAR → 内存 → MDR → IR → 译码
2. **找指令特定数据流**:执行阶段随指令不同
3. **找控制信号**:RegWrite / MemRead / MemWrite / ALUOp / RegDst / MemtoReg / ALUSrc
4. **找多路选择器**:根据控制信号选路

### 5.3.6 典型控制信号

| 信号 | 作用 | 1/0 含义 |
|------|------|----------|
| RegWrite | 寄存器写使能 | 1: 写寄存器 |
| RegRead | 寄存器读使能 | 1: 读寄存器 |
| MemRead | 内存读 | 1: 读内存 |
| MemWrite | 内存写 | 1: 写内存 |
| ALUOp | ALU 操作类型 | 4 位编码(ADD/SUB/AND/OR/SLT) |
| ALUSrc | ALU 第二操作数来源 | 0: 寄存器,1: 立即数 |
| RegDst | 写寄存器号来源 | 0: rt,1: rd |
| MemtoReg | 写回数据来源 | 0: ALU,1: 内存 |
| Branch | 是否转移指令 | 1: 转移(条件成立时) |
| Jump | 是否跳转 | 1: 无条件跳转 |
| MemtoReg | 写回数据来源 | 0: ALU,1: 内存 |
| PCSource | PC 来源 | 0: PC+4,1: 跳转目标 |
| RegWrite | 寄存器写使能 | 1: 写 |

### 5.3.7 控制信号与指令类型对应

| 指令 | RegWrite | MemRead | MemWrite | ALUSrc | RegDst | MemtoReg | Branch |
|------|----------|---------|----------|--------|--------|----------|--------|
| ADD R,R,R | 1 | 0 | 0 | 0 | 1 | 0 | 0 |
| ADDI R,R,imm | 1 | 0 | 0 | 1 | 0 | 0 | 0 |
| LW R,off(R) | 1 | 1 | 0 | 1 | 0 | 1 | 0 |
| SW R,off(R) | 0 | 0 | 1 | 1 | — | — | 0 |
| BEQ R,R,off | 0 | 0 | 0 | 0 | — | — | 1 |
| J target | 0 | 0 | 0 | — | — | — | 0 (Jump=1) |

### 5.3.8 数据通路设计权衡

| 设计点 | 选项 A | 选项 B | 权衡 |
|--------|--------|--------|------|
| 总线数 | 单(慢、简单) | 三(快、复杂) | 速度 vs 成本 |
| ALU 输入 | 寄存器直连 | 经总线 | 速度 vs 引脚 |
| 取指与执行 | 串行 | 流水 | 性能 vs 复杂度 |
| 控制方式 | 硬布线(快) | 微程序(灵活) | 速度 vs 灵活 |
| 寄存器端口 | 2R1W(单口) | 3R2W(多口) | 超标量 vs 成本 |

> **真题陷阱**:
> - **单总线 ADD 需 4 拍**:送操作数 2 拍 + 运算 1 拍 + 写回 1 拍
> - **LOAD 比 ADD 多**:需算地址 + 访存 + 写回
> - **STORE 不写寄存器**:RegWrite = 0
> - **BEQ 用减法判零**:ALU 做 SUB,看 Zero 标志
> - **MAR/MDR 对程序员透明**,硬件自动管理

## 5.4 控制器

### 5.4.1 硬布线控制器(组合逻辑)

**原理**:用组合逻辑电路直接产生控制信号。

```
指令 OP + 时序信号 + 状态条件 → 组合逻辑电路 → 控制信号
```

- **输入**:指令操作码 OP、时序信号(机器周期/节拍)、状态条件(ZF/OF/中断请求)
- **输出**:各控制信号(RegWrite/MemRead/...)
- **实现**:门电路 + 触发器,布尔方程描述

**优点**:速度快(纯组合逻辑)
**缺点**:修改难(需重连电路)、结构复杂、扩展性差
**适用**:RISC(指令简单、规整)

### 5.4.2 微程序控制器(存储逻辑)

**原理**:每条机器指令对应一段微程序,微程序由微指令组成,微指令产生微命令。

```
机器指令 → 操作码映射 → 微程序入口地址 → 执行微程序 → 微指令 → 微命令
```

| 术语 | 含义 | 类比 |
|------|------|------|
| 微命令 | 控制信号(如 RegWrite) | 函数中的语句 |
| 微指令 | 一组同时发出的微命令 | 函数 |
| 微程序 | 一段微指令序列,对应一条机器指令 | 函数集 |
| 微地址 | 微指令在控存中的地址 | 函数入口 |
| 控制存储器 CM | 存储所有微程序,**ROM** | 程序存储器 |

**执行流程**:
1. 取机器指令(同硬布线)
2. 操作码 → 微地址形成电路 → 微程序入口
3. 从 CM 取微指令到 μIR(微指令寄存器)
4. μIR 译码 → 微命令 → 控制信号
5. 微地址下一条微指令(顺序/转移)
6. 微程序结束 → 取下一条机器指令

### 5.4.3 微指令格式

**水平型微指令**:
- 每位直接对应一个微命令(直接编码)
- 一条微指令可同时发出多个微命令(并行度高)
- 微指令长,但微程序短

**垂直型微指令**:
- 类似机器指令:微操作码 + 微操作数
- 一条微指令只发一个微命令(并行度低)
- 微指令短,但微程序长

**对比**:

| 维度 | 水平型 | 垂直型 |
|------|--------|--------|
| 微指令长度 | 长 | 短 |
| 并行度 | 高 | 低 |
| 微程序长度 | 短 | 长 |
| 编程 | 难(需懂硬件) | 易(类似汇编) |
| 应用 | 高性能机 | 简单机 |

### 5.4.4 微命令编码方式

**直接编码**:1 位 = 1 微命令
- 优点:并行度高、不需译码
- 缺点:微指令长(若 100 个微命令需 100 位)

**字段直接编码**(最常用):
- 互斥微命令分到同一段,每段译码
- 每段需留 1 个"不发"状态(全 0)
- 例:3 位字段可编码 7 个互斥微命令 + 1 个不发

**字段间接编码**:
- 某字段含义依赖另一字段
- 复杂但编码效率更高

### 5.4.5 微地址形成方式

- **增量计数器法**:μPC + 1(类似 PC)
- **断定方式**(下址字段法):微指令中含下条微指令地址
- **测试网络**:根据状态条件转移(类似条件转移)

### 5.4.6 硬布线 vs 微程序对比

| 对比项 | 硬布线 | 微程序 |
|--------|--------|--------|
| 实现方式 | 组合逻辑电路 | 存储逻辑(ROM) |
| 速度 | 快 | 慢(需读 CM) |
| 修改 | 难(改电路) | 易(改 CM) |
| 复杂度 | 高 | 低 |
| 扩展性 | 差 | 好 |
| 适用 | RISC | CISC |
| 新增指令 | 需重新设计电路 | 仅添加微程序 |

## 5.5 指令流水线

### 5.5.1 五段流水线(MIPS 经典)

```
┌────┬────┬────┬─────┬────┐
│ IF │ ID │ EX │ MEM │ WB │
└────┴────┴────┴─────┴────┘
```

| 段 | 全称 | 功能 |
|----|------|------|
| IF | Instruction Fetch | 取指:PC → MAR → 内存 → MDR → IR;PC + 4 → PC |
| ID | Instruction Decode | 译码:IR 译码;读寄存器(取操作数) |
| EX | Execute | 执行:ALU 运算(算术/逻辑/地址计算) |
| MEM | Memory | 访存:LOAD 读内存,STORE 写内存;其他指令 bypass |
| WB | Write Back | 写回:结果写回寄存器 |

**每段 1 个时钟周期**(理想)。

### 5.5.2 流水线时空图

**理想情况(无冲突)**:

```
指令   1  2  3  4  5  6  7
I1    IF ID EX MEM WB
I2       IF ID  EX  MEM WB
I3          IF  ID  EX  MEM WB
I4              IF  ID  EX  MEM WB
```

每周期一条指令完成,5 段流水线 7 条指令共 11 周期(= 5 + 7 - 1)。

### 5.5.3 三大公式

**k 段流水线,n 条指令**:

- **总执行时间**:$T = (k + n - 1) \cdot \Delta t$
- **非流水线时间**:$T_{seq} = n \cdot k \cdot \Delta t$

**加速比**:

$$S = \frac{T_{seq}}{T} = \frac{nk}{k + n - 1} \xrightarrow{n \to \infty} k$$

**吞吐率**:

$$TP = \frac{n}{T} = \frac{n}{(k + n - 1) \Delta t} \xrightarrow{n \to \infty} \frac{1}{\Delta t}$$

**效率**(流水线设备利用率):

$$E = \frac{S}{k} = \frac{n}{k + n - 1} \xrightarrow{n \to \infty} 1$$

### 5.5.4 流水线优点

- **单条指令延迟不变**(还是 k 个周期)
- **吞吐率提升**(每周期完成一条)
- **整体加速比趋近 k**

### 5.5.5 例题

**【5.5.5】** 5 段流水线,10 条指令,无冲突,每段 1ns。求总时间、加速比、吞吐率、效率。

**解**:
- 总时间 $T = (5 + 10 - 1) \times 1 = 14$ ns
- 非流水线时间 $T_{seq} = 10 \times 5 \times 1 = 50$ ns
- 加速比 $S = 50 / 14 \approx 3.57$
- 吞吐率 $TP = 10 / 14 \approx 0.714$ 条/ns
- 效率 $E = 3.57 / 5 \approx 71.4\%$

## 5.6 流水线冲突

### 5.6.1 结构冲突(资源冲突)

**原因**:多条指令同时争用同一部件。

**典型场景**:IF 段(取指)与 MEM 段(访存)同时访问内存。

**解决**:
1. **资源重复**:分离指令 Cache 和数据 Cache(哈佛结构)
2. **停顿一个周期**:让 MEM 先访存,IF 等一拍
3. **双端口存储器**:同时支持两路访问

```
冲突情况:
指令   1  2  3  4  5
I1    IF ID EX MEM WB
I2       IF ID  EX  MEM WB
I3          IF stall ID  EX MEM WB   ← I1 在 MEM 访存,I3 的 IF 等待
```

### 5.6.2 数据冲突(数据相关)

**原因**:后续指令需要前面指令的运算结果,但前面未写回。

**三种数据相关**:

| 类型 | 含义 | 基本流水线出现? |
|------|------|-------------------|
| **RAW** (Read After Write) | I2 读 I1 写的结果,真相关 | ✅ 是 |
| **WAR** (Write After Read) | I2 写 I1 读的寄存器,反相关 | ❌ 否(顺序执行) |
| **WAW** (Write After Write) | I2 写 I1 写的寄存器,输出相关 | ❌ 否(顺序写) |

> **关键**:基本流水线(顺序发射、顺序执行、顺序写回)只有 RAW;乱序执行才有 WAR/WAW。

**RAW 冲突示例**:

```
I1: ADD R1, R2, R3   (R1 在 WB 段才写回)
I2: SUB R4, R1, R5   (R4 ← R1 - R5,需要 R1)

指令   1  2  3  4  5  6
I1    IF ID EX MEM WB
I2       IF ID  EX ...     ← I2 EX 需要 R1,但 I1 还在 MEM,未写回!
```

**解决 1:转发(Forwarding / Bypassing)**

```
I1 EX 段算出 R1 → 直接转发到 I2 EX 段(不等 WB)

指令   1  2  3  4  5  6
I1    IF ID EX MEM WB
I2       IF ID  EX MEM WB    ← I1 EX 结果转发到 I2 EX
                          ↑
                       转发路径
```

**转发路径**:
- EX/MEM → EX(前指令 EX 已算出,后指令 EX 需要)
- MEM/WB → EX(前指令 MEM 段,后指令 EX 需要)

**Load-Use 冲突**(转发无法解决):

```
I1: LW  R1, [R2]    (R1 在 MEM 段才读到)
I2: ADD R3, R1, R4   (R3 ← R1 + R4,EX 需要 R1)

指令   1  2  3  4  5  6
I1    IF ID EX MEM WB       ← R1 在 MEM 末才有
I2       IF ID  EX ...      ← I2 EX 在 I1 MEM 之前,转发来不及!
```

**解决**:必须停顿 1 个周期 + 转发

```
指令   1  2  3  4  5  6  7
I1    IF ID EX MEM WB
I2       IF ID stall EX MEM WB    ← 插入气泡
                 ↑
               转发:MEM/WB → EX
```

**解决 2:停顿(Stall / Bubble)**

无法转发时,插入空周期(气泡)。

**解决 3:编译器调度**

调整指令顺序,避免 Load-Use:

```
原始:                    优化后:
LW  R1, [R2]             LW  R1, [R2]
ADD R3, R1, R4           ADD R5, R6, R7   ← 无关指令填入
ADD R5, R6, R7           ADD R3, R1, R4   ← 此时 R1 已就绪
```

### 5.6.3 控制冲突(分支冲突)

**原因**:转移指令改变 PC,后续已取指令作废。

```
I1: BEQ R1, R2, L1    (条件转移)

指令   1  2  3  4  5
I1    IF ID EX MEM WB
I2       IF ID  ...     ← I2 是错误指令(若 I1 转移成功,I2 应作废)
I3          IF  ...     ← I3 也作废
```

**转移损失**(Branch Penalty):转移成功时,流水线需冲刷错误指令,损失周期数。

**解决 1:提前判断**

在 **ID 段**判断分支(而非 EX 或 MEM),减少气泡。
- 原本在 EX 段判断 → 损失 2 周期
- 在 ID 段判断 → 损失 1 周期
- 需在 ID 段加比较器(直接比较寄存器)

**解决 2:分支预测**

- **静态预测**:
  - 总是预测不转移(Not Taken):简单,准确率 50%
  - 总是预测转移(Taken):循环回边时准确率高
  - 根据指令方向:向后转移预测 Taken,向前预测 Not Taken

- **动态预测**:
  - **1 位预测位**:上一次实际方向 → 预测本次同方向
    - 缺点:循环退出时连续错 2 次
  - **2 位饱和计数器**(最常用):4 状态
    - 状态:强不转移 (00) → 弱不转移 (01) → 弱转移 (10) → 强转移 (11)
    - 转移成功 → 计数器 +1(饱和到 11)
    - 转移失败 → 计数器 -1(饱和到 00)
    - 预测:高两位为 1(10/11)预测 Taken
    - 优点:循环退出只错 1 次
  - **历史模式**:2 位全局历史寄存器,记录最近 2 次转移方向,索引模式表

**解决 3:延迟分支(Delayed Branch)**

- 转移指令后的"延迟槽"指令**总是执行**(无论转移是否成功)
- 编译器把无关指令填入延迟槽

```
原始:                    优化后(填延迟槽):
ADD R1, R2, R3           BEQ R1, R2, L1
BEQ R1, R2, L1           ADD R1, R2, R3   ← 延迟槽,无论转移都执行
SUB R4, R5, R6           SUB R4, R5, R6
```

**解决 4:停顿**

最简单但慢,转移时冲刷流水线。

### 5.6.4 三种冲突总结表

| 冲突类型 | 原因 | 解决方法 |
|----------|------|----------|
| 结构冲突 | 争用同一部件 | 资源重复(分离 Cache)、停顿 |
| 数据冲突 | 数据相关(RAW) | 转发、停顿、编译器调度 |
| 控制冲突 | 转移改变 PC | 提前判断、分支预测、延迟分支 |

## 5.7 高级流水线

### 5.7.1 超标量(Superscalar)

每周期发射多条指令(多套执行部件)。

```
I1 IF ID EX MEM WB
I2 IF ID EX MEM WB    ← 并行发射,2 条/周期
I3    IF ID EX MEM WB
I4    IF ID EX MEM WB
```

- CPI < 1(每周期多条指令完成)
- 硬件复杂(多套 ALU、多端口寄存器)
- 例:Pentium(2 发射)、Core i7(4~6 发射)

**in-order vs out-of-order 发射**:

| 发射方式 | 说明 | 优点 | 缺点 |
|----------|------|------|------|
| 顺序发射(in-order) | 按程序顺序发射 | 简单 | 一条阻塞全停 |
| 乱序发射(out-of-order) | 后续就绪指令可先发射 | 高 ILP | 硬件复杂 |

### 5.7.2 超流水(Superpipeline)

更深流水线,每段更短,主频更高。

```
普通 5 段:IF ID EX MEM WB
超流水 10 段:IF1 IF2 ID1 ID2 EX1 EX2 MEM1 MEM2 WB1 WB2
```

- 主频提升(每段更短)
- 但冲突损失更大(冲刷更多段)
- 加速比理论上更高
- 例:Pentium 4(20~31 段,主频达 3.8 GHz)

**主频 vs IPC 的权衡**:
- 段数 ↑ → 主频 ↑,但 IPC ↓(分支损失、数据冲突放大)
- 存在**最优段数**,过深反而性能下降(Pentium 4 教训)

### 5.7.3 VLIW(超长指令字)

编译器把多条独立指令打包为一条长指令。

```
长指令字:| 指令1 | 指令2 | 指令3 | 指令4 |  (一条指令,多个操作)
```

- 硬件简单(不需动态调度)
- 编译器复杂(需找并行指令)
- 代码体积大
- 例:Itanium IA-64(128 位指令字,3 条 41 位操作 + 5 位模板)

**VLIW vs Superscalar**:

| 维度 | VLIW | Superscalar |
|------|------|-------------|
| 调度方 | 编译器(静态) | 硬件(动态) |
| 硬件复杂度 | 低 | 高 |
| 编译器复杂度 | 高 | 低 |
| 代码体积 | 大 | 小 |
| 兼容性 | 差(依赖编译器) | 好 |
| 代表 | Itanium、DSP | x86、ARM |

### 5.7.4 动态调度(Tomasulo 算法)

#### 5.7.4.1 硬件结构

```
┌──────────────────────────────────────────┐
│              保留站(Reservation Station)  │
│  ┌─────┬─────┬─────┬─────┬─────┐         │
│  │ RS1 │ RS2 │ RS3 │ ... │ RSn │         │
│  └──┬──┴──┬──┴──┬──┴─────┴──┬──┘         │
│     │     │     │            │            │
│     └─────┴─────┴────────────┘            │
│              ↓ 公共数据总线 CDB             │
│  ┌──────────────────────────┐             │
│  │  寄存器堆 + 寄存器状态表  │             │
│  └──────────────────────────┘             │
└──────────────────────────────────────────┘
```

#### 5.7.4.2 保留站字段

| 字段 | 含义 |
|------|------|
| Op | 操作类型 |
| Qj, Qk | 源操作数来源 RS 号(0 表示已就绪) |
| Vj, Vk | 源操作数值 |
| Busy | 占用标志 |
| A | 地址(访存类) |

#### 5.7.4.3 算法流程

```
1. 发射(Issue):
   - 若有空 RS:取指令到 RS
   - 读寄存器:若值就绪写入 Vj/Vk;否则记 Qj/Qk 为产生该值的 RS
   - 重命名:目标寄存器指向本 RS

2. 执行(Execute):
   - 监听 CDB:Qj/Qk 匹配时,捕获值写入 Vj/Vk,Q 置 0
   - 操作数齐备(Qj=Qk=0):执行运算
   - 乱序执行(就绪即可执行)

3. 写回(Write Back):
   - 运算完成:CDB 广播 (RS号, 结果)
   - 等待该结果的 RS 捕获
   - 目标寄存器更新
```

#### 5.7.4.4 寄存器重命名消除假相关

- **WAR** (Write-After-Read):R1 被多次写,重命名为不同 RS → 消除
- **WAW** (Write-After-Write):同样重命名 → 消除
- **RAW** (Read-After-Write):真相关,**不能消除**,需等待

**例**:
```
I1: ADD R1, R2, R3    → RS1 写 R1
I2: SUB R4, R1, R5    → RS2 读 R1(Qj=RS1,真相关)
I3: MUL R1, R6, R7    → RS3 写 R1(重命名,R1→RS3,消除 WAW)
I4: ADD R8, R1, R9    → RS4 读 R1(Qj=RS3)
```

I4 读 RS3 而非 RS1,即使 I3 在 I1 后,WAW 消除,可乱序。

### 5.7.5 重排序缓冲区 ROB(Reorder Buffer)

**问题**:Tomasulo 乱序写回 → **不精确异常**(异常时后续指令已写回,无法回滚)。

**ROB 解决**:把写回拆为**写 ROB** + **提交(Commit)** 两步,提交按程序顺序。

#### 5.7.5.1 ROB 结构

| 字段 | 含义 |
|------|------|
| Entry | 项号(循环队列) |
| Instruction | 指令 |
| State | 发射/执行/写回/提交 |
| Destination | 目标寄存器 |
| Value | 结果值 |

#### 5.7.5.2 流程修正

```
1. 发射:RS + ROB 项(顺序分配)
2. 执行:同 Tomasulo
3. 写回:CDB → ROB(不直接写寄存器)
4. 提交:队首 ROB 项写回寄存器,出队(顺序提交)
```

- 异常时:ROB 中未提交项全部丢弃 → **精确异常**
- 分支预测失败:ROB 中预测路径的项全部丢弃

### 5.7.6 推测执行(Speculative Execution)

**分支预测 + 推测执行**:沿预测路径执行,但不提交,验证后才提交。

```
1. 分支指令预测方向
2. 推测路径指令进入 ROB(标记推测)
3. 分支结果确定:
   - 预测正确:正常提交
   - 预测错误:ROB 中推测项全部丢弃,从正确路径重新取指
```

**关键支撑**:
- ROB 隔离推测结果(不污染寄存器堆)
- 分支预测器(BTB + 2 位饱和计数器)

### 5.7.7 分支预测

#### 5.7.7.1 静态预测

- **总是不跳转**(Not Taken):简单,准确率约 60%
- **总是跳转**(Taken):适合循环,准确率约 65%
- **BTFN**(Backward Taken, Forward Not Taken):后向跳转(循环)预测跳转

#### 5.7.7.2 动态预测

**1 位预测位**:上次结果预测下次(简单,循环退出错 2 次)

**2 位饱和计数器**(Bimodal):
```
   强不跳(00) ──不跳── 强不跳(00)
       │ 跳                  │ 不跳
       ▼                     ▼
   弱不跳(01) ──跳── 弱跳(10)
       │ 不跳                │ 跳
       ▼                     ▼
   强跳(11) ──跳── 强跳(11)
```

- 循环退出只错 1 次(强跳 → 弱跳,仍预测跳)
- 状态图见 §5.6

#### 5.7.7.3 分支目标缓冲器 BTB(Branch Target Buffer)

**作用**:在**取指阶段**就预测分支方向和目标地址,避免流水线气泡。

| 字段 | 含义 |
|------|------|
| Tag | 分支指令地址 |
| Target | 预测目标地址 |
| Prediction | 2 位饱和计数器状态 |

**流程**:
1. 取指 PC → 查 BTB
2. 命中且预测跳转 → PC ← Target
3. 不命中 → 顺序取指
4. 分支结果确定 → 更新 BTB

### 5.7.8 多线程(Multi-Threading)

| 类型 | 切换粒度 | 资源共享 | 例 |
|------|----------|----------|----|
| 细粒度多线程 | 每周期 | 寄存器分时 | — |
| 粗粒度多线程 | stall 时切换 | 寄存器分时 | — |
| 同步多线程 SMT | 同周期混合 | 寄存器堆共享 | Intel 超线程 |

**SMT(Simultaneous Multi-Threading)**:
- 同一周期,多个线程的指令混合发射
- 寄存器堆逻辑分区,执行单元共享
- 例:Intel HT(2 线程)、IBM POWER(8 线程)

### 5.7.9 高级流水线技术对比

| 技术 | 提升 | 硬件成本 | 主要解决 |
|------|------|----------|----------|
| 超标量 | ILP | 高(多套执行部件) | 多发射 |
| 超流水 | 主频 | 中(深流水) | 时钟频率 |
| VLIW | ILP | 低(编译器干) | 静态并行 |
| 动态调度 | ILP | 高(保留站+CDB) | 数据冲突 |
| ROB | 精确异常 | 中(ROB 表) | 乱序提交 |
| 推测执行 | ILP | 高(预测+ROB) | 控制冲突 |
| SMT | TLP | 中(寄存器分区) | 线程并行 |

> **真题陷阱**:
> - **Tomasulo 用保留站实现寄存器重命名**,消除 WAR/WAW
> - **ROB 实现精确异常和推测执行**
> - **2 位饱和计数器**比 1 位预测位更适合循环
> - **BTB 在取指阶段预测**,避免气泡
> - **VLIW 依赖编译器**,Superscalar 依赖硬件
> - **超流水过深反而性能下降**(Pentium 4 教训)

## 5.8 真题精解

### 【2016 选择】寄存器可见性

**题目**:下列寄存器中,对用户透明的是?

A. PC  B. 通用寄存器  C. PSW  D. MAR

**答案**:**D**

**解析**:MAR、MDR、IR 是 CPU 内部寄存器,程序员不可见(透明)。PC、通用寄存器、PSW 可见。

### 【2017 综合】流水线数据冲突转发

**题目**:5 段流水线(IF/ID/EX/MEM/WB),分析以下指令序列的冲突,给出转发方案:

```
I1: ADD R1, R2, R3
I2: SUB R4, R1, R5
I3: OR  R6, R1, R7
I4: AND R8, R1, R9
```

**分析**:
- I2/I3/I4 都读 R1(I1 写)
- I1 在 EX 末算出 R1,可转发到 I2 EX
- I1 在 MEM 段,可转发到 I3 EX(MEM/WB → EX)
- I1 在 WB 段,可转发到 I4 EX(WB → EX,前半周期写后半周期读)

**时空图(转发后无停顿)**:

```
指令   1  2  3  4  5  6  7
I1    IF ID EX MEM WB
I2       IF ID  EX  MEM WB    ← EX/MEM → EX 转发
I3          IF  ID  EX  MEM WB ← MEM/WB → EX 转发
I4              IF  ID  EX  MEM WB ← WB → EX 转发(前写后读)
```

### 【2018 选择】微程序控制器

**题目**:微程序控制器中,存放微程序的是?

A. RAM  B. ROM  C. Cache  D. 寄存器

**答案**:**B**(ROM,控制存储器 CM)

**解析**:控存 CM 用 ROM(只读),出厂时写入,运行时不可改。

### 【2019 综合】流水线加速比

**题目**:5 段流水线,10 条指令,无冲突,每段 1ns。求加速比、吞吐率、效率。

**解**:
- $T = (5 + 10 - 1) \times 1 = 14$ ns
- $T_{seq} = 10 \times 5 = 50$ ns
- $S = 50/14 \approx 3.57$
- $TP = 10/14 \approx 0.714$ 条/ns
- $E = 3.57/5 \approx 71.4\%$

### 【2020 选择】控制冲突分支预测

**题目**:关于分支预测,下列正确的是?

A. 静态预测准确率高于动态预测
B. 2 位饱和计数器比 1 位预测位更适合循环
C. 总是预测 Taken 比总是预测 Not Taken 准确率高
D. 延迟槽需要硬件预测

**答案**:**B**

**解析**:
- 动态预测准确率高于静态(A 错)
- 2 位饱和计数器在循环退出时只错 1 次,1 位会错 2 次(B 对)
- 总是预测 Taken/Not Taken 准确率视程序而定(C 错)
- 延迟槽由编译器填充,不需硬件预测(D 错)

### 【2022 综合】流水线时空图与气泡

**题目**:5 段流水线,指令序列:

```
I1: LW  R1, 0(R2)
I2: ADD R3, R1, R4
I3: SUB R5, R6, R7
```

I1 与 I2 有 Load-Use 冲突。画出时空图。

**时空图**:

```
指令   1  2  3  4  5  6  7  8
I1    IF ID EX MEM WB
I2       IF ID --  EX  MEM WB    ← 停顿 1 拍(气泡 --),MEM/WB → EX 转发
I3          IF  ID  EX  MEM WB    ← I3 不受影响
```

**解释**:I2 在 ID 段(周期 3)检测到 Load-Use,周期 4 插入气泡,I1 在 MEM 末读到 R1,转发到 I2 EX(周期 5)。

### 【2024 综合】数据通路图阅读

**题目**(简化):给出单总线数据通路图,问 ADD R1, R2, R3 的执行步骤与控制信号。

**答**:
1. R2 → 总线 → Y(暂存器),控制信号:R2out, Yin
2. R3 → 总线,ALU: Y + R3,控制信号:R3out, ALUop = ADD
3. ALU 输出 → Z(暂存器),控制信号:Zin
4. Z → 总线 → R1,控制信号:Zout, R1in, RegWrite

## 5.9 真题陷阱(18 条)

1. **PC 自增在取指后**:PC + 指令长度(不是 +1 字节)
2. **MAR/MDR/IR 透明**,PC/GPR/PSW 可见
3. **微程序控制器用 ROM**(控存),不是 RAM
4. **水平型微指令并行度高**,垂直型像机器指令
5. **字段直接编码每段留 1 个"不发"状态**(全 0)
6. **流水线加速比** $S = nk/(k+n-1)$,n→∞ 趋近 k
7. **流水线效率** $E = S/k = n/(k+n-1)$,n→∞ 趋近 1
8. **数据冲突 RAW 最常见**,转发解决
9. **Load-Use 冲突**:转发无法解决,需停顿 1 拍 + 转发
10. **WAR/WAW 在基本流水线不出现**,乱序执行才有
11. **分支预测 2 位饱和计数器**:循环退出只错 1 次
12. **延迟槽**:无论转移是否成功,延迟槽指令都执行
13. **结构冲突**:分离指令/数据 Cache 可解决
14. **硬布线快,微程序灵活**
15. **机器周期**:早期 = 主存周期,现代 = 1 时钟周期
16. **微地址形成**:增量计数器法、断定方式、测试网络
17. **超标量 CPI < 1**,超流水主频更高
18. **Tomasulo 用寄存器重命名消除 WAR/WAW**,RAW 不能消除

## 5.10 易混淆点深辨析

### 5.10.1 硬布线 vs 微程序

| 维度 | 硬布线 | 微程序 |
|------|--------|--------|
| 实现 | 组合逻辑电路 | 存储逻辑(ROM) |
| 速度 | 快 | 慢 |
| 修改 | 难 | 易 |
| 适用 | RISC | CISC |
| 新增指令 | 重新设计电路 | 添加微程序 |
| 控制信号来源 | 布尔方程 | 微指令译码 |

### 5.10.2 水平型 vs 垂直型微指令

| 维度 | 水平型 | 垂直型 |
|------|--------|--------|
| 微指令长度 | 长 | 短 |
| 并行度 | 高(同时发多微命令) | 低(一个微命令) |
| 微程序长度 | 短 | 长 |
| 编程难度 | 难 | 易 |
| 编码方式 | 直接/字段 | 操作码+操作数 |

### 5.10.3 三种冲突对比

| 冲突 | 原因 | 解决 |
|------|------|------|
| 结构 | 争用部件 | 资源重复、停顿 |
| 数据 | RAW | 转发、停顿、调度 |
| 控制 | 转移 | 预测、延迟槽 |

### 5.10.4 转发路径

| 转发路径 | 适用场景 |
|----------|----------|
| EX/MEM → EX | 前指令 EX 算出,后指令 EX 需要 |
| MEM/WB → EX | 前指令 MEM 段,后指令 EX 需要 |
| WB → EX(前写后读) | 前指令 WB 段,后指令 EX 需要 |

### 5.10.5 RAW / WAR / WAW

| 类型 | 含义 | 真相关? | 基本流水线出现? |
|------|------|---------|-------------------|
| RAW | I2 读 I1 写 | 真 | ✅ |
| WAR | I2 写 I1 读 | 假 | ❌ |
| WAW | I2 写 I1 写 | 假 | ❌ |

## 5.13 延伸知识

### 5.13.1 MIPS 五级流水线细节

- 寄存器堆:前半周期写、后半周期读(WB → ID 同周期)
- 分支在 ID 段判断(需加比较器)
- Load-Use 必须停顿 1 拍

### 5.13.2 x86 流水线

- CISC 变长指令,内部译码为微操作(μop)
- 微操作走 RISC 风格流水线
- P6 微架构(1995)引入乱序执行

### 5.13.3 分支预测器

- **局部分支预测器**:每个分支独立计数器
- **全局分支预测器**:全局历史寄存器(GHR)索引模式表
- **Tournament 预测器**:选择器在局部/全局间动态选择
- **TAGE 预测器**:历史长度分级,现代高准确率(>97%)

### 5.13.4 Tomasulo 算法核心

1. 指令发射:操作数未就绪则记保留站,就绪则存值
2. 等待 CDB:操作数未就绪时监听 CDB
3. 执行:操作数就绪后送 ALU
4. 写回:CDB 广播结果

### 5.13.5 ARM Cortex 流水线

- Cortex-A78:11~15 级乱序超标量
- 多发射(每周期 4~6 条)
- 分支预测准确率 >95%

## 5.14 本章习题

1. 5 段流水线,20 条指令,无冲突,每段 1ns。求总时间、加速比、吞吐率、效率。
2. 分析以下指令序列的数据冲突,给出转发方案(不需停顿):
   ```
   I1: ADD R1, R2, R3
   I2: SUB R4, R1, R5
   I3: OR  R6, R1, R7
   ```
3. 分析 Load-Use 冲突,画时空图:
   ```
   I1: LW  R1, 0(R2)
   I2: ADD R3, R1, R4
   ```
4. 解释为什么基本流水线只有 RAW,WAR/WAW 不出现。
5. 比较 1 位预测位和 2 位饱和计数器在循环中的表现。
6. 解释硬布线控制器和微程序控制器的本质区别。
7. 单总线数据通路下,ADD R1, R2, R3 需要几个时钟周期?

### 习题答案

1. $T = (5 + 20 - 1) \times 1 = 24$ ns;$T_{seq} = 20 \times 5 = 100$ ns;$S = 100/24 \approx 4.17$;$TP = 20/24 \approx 0.83$ 条/ns;$E = 4.17/5 \approx 83.3\%$。

2. I1 在 EX 末算出 R1,转发到 I2 EX(EX/MEM → EX);I1 在 MEM 段,转发到 I3 EX(MEM/WB → EX)。无停顿。

3. I1 在 MEM 末才有 R1,I2 EX 在 I1 MEM 之前,转发来不及。停顿 1 拍 + 转发:
   ```
   指令   1  2  3  4  5  6  7
   I1    IF ID EX MEM WB
   I2       IF ID --  EX  MEM WB
   ```
   周期 5: I1 MEM 末 → I2 EX(转发)

4. 基本流水线**顺序发射、顺序执行、顺序写回**:
   - 顺序写回 → I1 写早于 I2 写 → 不出现 WAW
   - 顺序执行 → I1 读早于 I2 写 → 不出现 WAR
   - 但 I2 读可能早于 I1 写(同时刻发射) → 出现 RAW

5. **1 位预测位**:循环回边每次预测正确;循环退出时连续错 2 次(最后一次回边预测 Taken 实际 Not Taken,退出后第一次预测 Not Taken 实际 Taken)。
   **2 位饱和计数器**:循环退出只错 1 次(强转移状态错一次退到弱转移,下次仍预测 Taken,但循环已退出 → 实际上退出后下次循环进入也是 Taken,所以...)。实际:循环退出时,2 位计数器从强转移 (11) → 弱转移 (10),预测 Taken 实际 Not Taken,错 1 次;下次再进入循环(若有),预测 Taken 仍正确。所以 2 位只错 1 次。

6. **硬布线**:组合逻辑电路直接产生控制信号,快但修改难。**微程序**:每条机器指令对应一段微程序,存于 ROM,慢但易修改。本质:**硬件 vs 存储**实现控制逻辑。

7. 单总线 ADD R1, R2, R3:
   - R2 → Y(1 拍)
   - R3 → 总线,Y + R3 → Z(1 拍)
   - Z → R1(1 拍)
   共 3 拍(执行阶段)。
