## 5.1 UDP

### 5.1.1 特点

- **无连接**:发送前不需建立连接
- **不可靠**:不保证交付,无确认重传
- **面向报文**:整段发送,不拆不分
- **首部 8 字节** (源端口、目的端口、长度、校验和)
- **支持多播、广播**
- **无拥塞控制**:发送速率不受网络拥塞影响

### 5.1.2 首部 (8 字节)

```
┌──────────┬──────────┐
│ 源端口 16 │ 目的端口 16 │
│ 长度 16   │ 校验和 16  │
└──────────┴──────────┘
```

**校验和**含伪首部:
```
┌──────────────────────┐
│ 源 IP (4B)            │ 伪首部 (12B,只算校验和)
│ 目的 IP (4B)          │
│ 0 (1B) │ 协议=17 (1B) │
│ UDP 长度 (2B)         │
└──────────────────────┘
```

**伪首部作用**:检测 IP 报文是否错投到错误端口/主机。

### 5.1.3 应用

| 协议 | 端口 | 用途 |
|------|------|------|
| DNS | 53 | 域名解析 |
| DHCP | 67/68 | IP 分配 |
| TFTP | 69 | 简单文件传输 |
| SNMP | 161/162 | 网络管理 |
| RIP | 520 | 路由协议 |
| NTP | 123 | 时间同步 |

## 5.2 TCP 首部 (完整字段)

### 5.2.1 首部结构 (20 字节固定 + 选项)

```
┌─0─4─8─16──────────31─┐
│ 源端口 16 │ 目的端口 16 │
│ 序号 seq 32            │
│ 确认号 ack 32          │
│ 数据偏移 4 │ 保留 6 │ 标志 6 │ 窗口 16 │
│ 校验和 16 │ 紧急指针 16  │
│ 选项 (可变,0~40B)     │
└────────────────────────┘
```

### 5.2.2 完整字段表

| 字段 | 位数 | 含义 |
|------|------|------|
| 源端口 | 16 | 发送方端口 |
| 目的端口 | 16 | 接收方端口 |
| 序号 seq | 32 | 数据第一个字节的编号 |
| 确认号 ack | 32 | 期望收到下一字节编号 |
| 数据偏移 | 4 | 首部长度,以 4 字节为单位 |
| 保留 | 6 | 未来使用 |
| 标志位 | 6 | URG/ACK/PSH/RST/SYN/FIN |
| 窗口 rwnd | 16 | 接收窗口,流量控制 |
| 校验和 | 16 | 含伪首部 |
| 紧急指针 | 16 | URG=1 时有效 |
| 选项 | 0-40 | MSS, SACK, Window Scale, Timestamp |

### 5.2.3 标志位详解

| 标志 | 含义 | 触发场景 |
|------|------|----------|
| URG | 紧急数据 | 配合紧急指针,优先发送 |
| ACK | 确认号有效 | 除初始 SYN 外都置 1 |
| PSH | 推送 | 接收方立即交应用 |
| RST | 重置连接 | 异常情况,强制关闭 |
| SYN | 同步序号 | 建立连接 |
| FIN | 发送完毕 | 释放连接 |

### 5.2.4 常用选项

| 选项 | 含义 |
|------|------|
| MSS (Max Segment Size) | 最大报文段长度 (默认 536,以太网常 1460) |
| SACK (Selective ACK) | 选择确认,提升重传效率 |
| Window Scale | 窗口扩大 (突破 16 位 64KB 限制) |
| Timestamp | 时间戳,RTT 估算与 PAWS 防序号回绕 |

## 5.3 TCP 连接管理

### 5.3.1 三次握手 (完整时序)

```
客户端                              服务器 (LISTEN)
  │                                    │
  │ ── SYN, seq=x ──────────────────► │ (1) 客户端 SYN_SENT
  │                                    │ 服务器 SYN_RCVD
  │ ◄── SYN+ACK, seq=y, ack=x+1 ───  │ (2)
  │                                    │
  │ ── ACK, ack=y+1 ─────────────────► │ (3) 双方 ESTABLISHED
  │                                    │
```

**三次握手详细步骤**:
1. **客户端发 SYN**:seq=x,进入 SYN_SENT
2. **服务器收 SYN**:回 SYN+ACK, seq=y, ack=x+1,进入 SYN_RCVD
3. **客户端收 SYN+ACK**:回 ACK, ack=y+1,进入 ESTABLISHED
4. **服务器收 ACK**:进入 ESTABLISHED

**为什么三次,不是两次?**
- 防止旧 SYN 报文滞留导致服务器误开连接 (资源浪费)
- 双方确认彼此收发能力:
  - 第一次:服务器确认客户端能发
  - 第二次:客户端确认服务器能发能收
  - 第三次:服务器确认客户端能收

**两次握手的问题**:服务器收到旧 SYN,回 SYN+ACK 后以为连接建立,但客户端不会响应,服务器一直等,资源被旧报文占用。

### 5.3.2 四次挥手 (完整时序)

```
客户端                              服务器 (ESTABLISHED)
  │                                    │
  │ ── FIN, seq=u ─────────────────► │ (1) 客户端 FIN_WAIT_1
  │                                    │ 服务器 CLOSE_WAIT
  │ ◄── ACK, ack=u+1 ─────────────── │ (2) 客户端 FIN_WAIT_2
  │                                    │ (服务器可能继续发数据)
  │ ◄── FIN, seq=v ───────────────── │ (3) 客户端 TIME_WAIT
  │                                    │ 服务器 LAST_ACK
  │ ── ACK, ack=v+1 ───────────────► │ (4) 服务器 CLOSED
  │                                    │ 客户端等 2MSL → CLOSED
```

**四次挥手详细步骤**:
1. **客户端发 FIN**:seq=u,进入 FIN_WAIT_1 (主动关闭)
2. **服务器收 FIN**:回 ACK, ack=u+1,进入 CLOSE_WAIT (半关闭,仍可发数据)
3. **客户端收 ACK**:进入 FIN_WAIT_2
4. **服务器发完数据,发 FIN**:seq=v,进入 LAST_ACK
5. **客户端收 FIN**:回 ACK, ack=v+1,进入 TIME_WAIT,等 2MSL 后 CLOSED
6. **服务器收 ACK**:进入 CLOSED

**为什么四次?**
- TCP 全双工,每方独立关闭
- FIN 只表示"我没数据了",但仍可接收
- 服务器收到 FIN 后,可能还有数据要发,先 ACK,数据发完再 FIN

### 5.3.3 2MSL 等待

**TIME_WAIT 状态等待 2MSL** (Maximum Segment Lifetime,默认 2 分钟):

**作用**:
1. **防最后 ACK 丢失**:若 ACK 丢失,服务器重发 FIN,客户端仍能响应
2. **让旧连接报文消亡**:本次连接的所有报文在网络中消失,避免影响新连接

**MSL (Maximum Segment Lifetime)**:报文最大生存时间,通常 2 分钟,Linux 默认 60s。

### 5.3.4 完整状态机 (11 状态)

```
                 ┌──────────┐
                 │  CLOSED  │
                 └────┬─────┘
        主动开 │         │ 被动开 (服务器)
        applist│         │
              ▼         ▼
       ┌──────────┐  ┌──────────┐
       │ SYN_SENT │  │  LISTEN  │
       └────┬─────┘  └────┬─────┘
   收 SYN+ACK│         收 SYN │
   发 ACK    │        发 SYN+ACK│
            ▼              ▼
       ┌──────────────────────┐
       │     ESTABLISHED      │
       └──────────┬───────────┘
        主动关 │         │ 被动关
        发 FIN │         │ 收 FIN,发 ACK
              ▼         ▼
       ┌──────────┐  ┌──────────┐
       │FIN_WAIT_1│  │CLOSE_WAIT│
       └────┬─────┘  └────┬─────┘
        收 ACK│         应用 close│
              ▼         发 FIN │
       ┌──────────┐         ▼
       │FIN_WAIT_2│  ┌──────────┐
       └────┬─────┘  │ LAST_ACK │
        收 FIN│         └────┬─────┘
        发 ACK│         收 ACK │
              ▼              ▼
       ┌──────────┐     ┌──────────┐
       │TIME_WAIT │     │  CLOSED  │
       └────┬─────┘     └──────────┘
        2MSL │
            ▼
       ┌──────────┐
       │  CLOSED  │
       └──────────┘
```

**关键状态**:
- **LISTEN**:服务器等待连接
- **SYN_SENT**:客户端发 SYN,等 SYN+ACK
- **SYN_RCVD**:服务器收 SYN,已发 SYN+ACK,等 ACK
- **ESTABLISHED**:连接建立
- **FIN_WAIT_1**:主动方发 FIN,等 ACK
- **FIN_WAIT_2**:主动方收 ACK,等对方 FIN
- **CLOSE_WAIT**:被动方收 FIN,等本方应用 close
- **LAST_ACK**:被动方发 FIN,等最后 ACK
- **TIME_WAIT**:主动方发完最后 ACK,等 2MSL
- **CLOSED**:无连接

**SYN_RCVD 触发**:服务器收到 SYN,或客户端收到 SYN+ACK (但客户端进入 SYN_SENT→ESTABLISHED)。

## 5.4 TCP 可靠传输

### 5.4.1 序号与确认

- **序号 seq**:数据第一个字节的编号 (按字节计)
- **确认号 ack**:期望收到的下一个字节编号 (**累计确认**)

**例**:收 seq=1000, len=500,则回 ack=1500 (期望下一字节 1500)。

### 5.4.2 重传机制

**超时重传**:
- RTO (Retransmission Timeout) 自适应
- RTT 估算:$\text{RTT}_S = \alpha \cdot \text{RTT}_S + (1-\alpha) \cdot \text{RTT}_M$ ($\alpha=0.125$)
- RTO = RTT_S + 4·RTT_D (偏差)

**快重传**:
- 收到 3 个重复 ACK,判定丢包
- 立即重传,不等超时
- 提高效率,减少等待

### 5.4.3 流量控制 (滑动窗口)

接收方在 ACK 中告知窗口 (rwnd),发送方据此调整发送窗口。

**窗口变化例**:
```
A → B: seq=1, len=100, rwnd=4000
B → A: ack=101, rwnd=4000
A → B: seq=101, len=100, rwnd=4000
...
B 缓冲满:B → A: ack=201, rwnd=0   (零窗口)
A 停止发送,定期发零窗口探测报文 (防止死锁)
B 缓冲有空:B → A: ack=201, rwnd=2000
A 继续发送
```

**零窗口死锁问题**:
- 若 B 发 rwnd=2000 的报文丢失,A 永远等
- 解决:**A 持续定时器**,到时发零窗口探测报文 (1 字节)

## 5.5 TCP 拥塞控制 (完整推演)

### 5.5.1 拥塞窗口 cwnd

$$
\text{发送窗口} = \min(\text{cwnd}, \text{rwnd})
$$

- cwnd 由发送方根据网络拥塞动态调整
- rwnd 由接收方根据缓冲区动态告知

### 5.5.2 慢开始 (Slow Start)

- cwnd 从 1 开始 (单位:MSS)
- **每收到一个 ACK,cwnd +1** → 每 RTT 翻倍 (**指数增长**)
- 增长到 ssthresh 后,改用拥塞避免

### 5.5.3 拥塞避免 (Congestion Avoidance)

- cwnd **线性增长**,每 RTT +1
- 直到丢包

### 5.5.4 快重传 (Fast Retransmit)

- 收到 **3 个重复 ACK**,判定丢包
- 立即重传丢失报文,不等 RTO

### 5.5.5 快恢复 (Fast Recovery)

收到 3 个重复 ACK 后:
- ssthresh = cwnd / 2
- cwnd = ssthresh (**不是 1**)
- 进入拥塞避免 (线性增长)

### 5.5.6 超时处理

RTO 超时:
- ssthresh = cwnd / 2
- cwnd = 1
- 慢开始 (指数增长)

### 5.5.7 AIMD (Additive Increase, Multiplicative Decrease)

- **加性增**:线性 +1 (拥塞避免)
- **乘性减**:减半 (快恢复/超时的 ssthresh)

这是 TCP **公平性**的基础:多连接竞争带宽,AIMD 使各连接公平分享。

### 5.5.8 完整推演例题

**初始**:cwnd = 1, ssthresh = 16

| RTT | cwnd | 阶段 | 备注 |
|-----|------|------|------|
| 1 | 2 | 慢开始 | 指数 |
| 2 | 4 | 慢开始 | 指数 |
| 3 | 8 | 慢开始 | 指数 |
| 4 | 16 | 慢开始→避免 | 到 ssthresh |
| 5 | 17 | 拥塞避免 | 线性 |
| 6 | 18 | 拥塞避免 | 线性 |
| 7 | 19 | 拥塞避免 | 收到 3 重复 ACK |
| 7后 | 9 | 快恢复 | ssthresh=9, cwnd=9 |
| 8 | 10 | 拥塞避免 | 线性 |
| 9 | 11 | 拥塞避免 | 超时 |
| 9后 | 1 | 慢开始 | ssthresh=5, cwnd=1 |
| 10 | 2 | 慢开始 | 指数 |
| 11 | 4 | 慢开始 | 指数 (< ssthresh=5) |
| 12 | 5 | 慢开始→避免 | 到 ssthresh |
| 13 | 6 | 拥塞避免 | 线性 |

**关键点**:
- 慢开始:每 RTT 翻倍 (1→2→4→8→16)
- 拥塞避免:每 RTT +1
- 快恢复:cwnd = ssthresh (不回 1)
- 超时:cwnd = 1 (回起点)

## 5.7 真题陷阱与高频考点 (30 条)

1. **三次握手防旧 SYN**:不是两次
2. **四次挥手全双工**:每方独立关
3. **TIME_WAIT 2MSL**:防最后 ACK 丢失 + 旧报文消亡
4. **CLOSE_WAIT 等应用 close**:被动方收到 FIN 后的状态
5. **快重传 3 个重复 ACK**:不等超时
6. **快恢复 cwnd = ssthresh**,不到 1
7. **超时才 cwnd = 1**,慢开始
8. **发送窗口 = min(cwnd, rwnd)**
9. **累计确认**:ack = 期望下一字节
10. **UDP 首部 8B,TCP 首部 20B+**
11. **TCP 面向字节流,UDP 面向报文**
12. **零窗口探测**:防止死锁,持续定时器
13. **SYN_RCVD**:服务器收到 SYN,已发 SYN+ACK
14. **MSL 默认 2 分钟**,2MSL = 4 分钟 (Linux 实际 60s)
15. **数据偏移以 4 字节为单位**
16. **窗口 rwnd 单位是字节**
17. **MSS 默认 536**,以太网常 1460
18. **TCP 选项最大 40 字节**
19. **SYN 不含数据但消耗一个序号**
20. **FIN 不含数据但消耗一个序号**
21. **ACK 不消耗序号**
22. **伪首部参与 UDP/TCP 校验和**,但本身不传输
23. **UDP 校验和可选** (IPv4),TCP 校验和必填
24. **慢开始指数增长,每 RTT 翻倍**
25. **拥塞避免线性增长,每 RTT +1**
26. **ssthresh 初值常 16**,可配
27. **快恢复后线性增长,不指数**
28. **超时后必回 1,慢开始**
29. **TCP 端口 16 位,最多 65535**
30. **TCP 全双工**:双方可同时收发

## 5.9 综合计算示例

### 5.9.1 拥塞窗口推演

**题**:cwnd=1, ssthresh=8。RTT 5 时收 3 重复 ACK,RTT 8 时超时。给出 cwnd 变化。

**解**:
| RTT | cwnd | 阶段 |
|-----|------|------|
| 1 | 2 | 慢开始 |
| 2 | 4 | 慢开始 |
| 3 | 8 | 到 ssthresh,改避免 |
| 4 | 9 | 拥塞避免 |
| 5 | 10 | 收 3 ACK,ssthresh=5, cwnd=5 |
| 6 | 6 | 拥塞避免 |
| 7 | 7 | 拥塞避免 |
| 8 | 8 | 超时,ssthresh=4, cwnd=1 |
| 9 | 2 | 慢开始 |
| 10 | 4 | 到 ssthresh,改避免 |

### 5.9.2 序号与确认

**题**:A 发 seq=1000, len=500 给 B,B 收到后回什么?

**解**:
- B 回 ack = 1000 + 500 = 1500 (期望下一字节)
- 若 B 有数据 seq=2000, len=200,则回 seq=2000, ack=1500

### 5.9.3 三次握手序号

**题**:A → B 三次握手,A 初始 seq=1000,B 初始 seq=5000。给出三次报文。

**解**:
1. A→B: SYN, seq=1000
2. B→A: SYN+ACK, seq=5000, ack=1001 (SYN 消耗 1 序号)
3. A→B: ACK, seq=1001, ack=5001
