## 6.1 网络应用模型

### 6.1.1 C/S 模型 (Client/Server)

- 客户端请求,服务器响应
- 服务器固定地址,被动等待
- 客户端主动发起,临时地址
- 通信双向但角色固定

**特点**:简单可靠,但服务器是瓶颈。

### 6.1.2 P2P 模型 (Peer-to-Peer)

- 每个节点既是客户端又是服务器
- 可扩展性强 (用户越多资源越多)
- 管理复杂,版权问题
- 流量在节点间分散,减轻服务器压力

**应用**:BitTorrent, eMule, 区块链。

### 6.1.3 对比

| 维度 | C/S | P2P |
|------|-----|-----|
| 服务器 | 必需 | 不必需 |
| 可扩展性 | 受服务器限制 | 强 |
| 资源共享 | 集中 | 分布 |
| 管理 | 易 | 难 |
| 安全 | 易控制 | 难 |

## 6.2 DNS (Domain Name System)

### 6.2.1 作用

**域名 → IP 地址解析**。

### 6.2.2 层次命名空间

```
www.example.com.
│    │       │
│    │       └── 顶级域名 TLD (com)
│    └────────── 二级域名 (example)
└─────────────── 三级域名 (www)
                                     └── 根域名 (.)
```

**根域名服务器**:13 套 (A~M),全球分布 (用 anycast 实际更多)。

**域名服务器层次**:
| 服务器 | 作用 |
|--------|------|
| 根服务器 | 知道所有 TLD 服务器地址 |
| TLD 服务器 | 知道该顶级域下权威服务器 (如 .com 的所有权威) |
| 权威服务器 | 知道本域内主机 IP (如 example.com 的权威) |
| 本地 DNS | 用户配置的递归解析器 (如 8.8.8.8) |

### 6.2.3 查询方式 (完整流程图)

**递归查询**:主机 → 本地 DNS,本地 DNS 全权代为查询,返回最终结果。
**迭代查询**:本地 DNS → 根 → 顶级 → 权威,逐级返回下一服务器地址,本地 DNS 自己再去查。

**完整查询流程** (访问 www.example.com):

```
主机                  本地DNS              根服务器       TLD(.com)     权威(example.com)
 │                       │                    │              │              │
 │ ── 查 www.example.com→│                    │              │              │
 │                       │ ── 查 www.example.com → │          │              │
 │                       │ ◄── 返回 TLD(.com) 地址 ─ │        │              │
 │                       │ ── 查 www.example.com ──────────→ │              │
 │                       │ ◄── 返回权威地址 ──────────────── │              │
 │                       │ ── 查 www.example.com ──────────────────────→ │
 │                       │ ◄── 返回 IP 1.2.3.4 ────────────────────────── │
 │ ◄── 返回 IP 1.2.3.4 ──│                    │              │              │
```

> **真题陷阱** (必背):
> - 主机 → 本地 DNS:**递归**
> - 本地 DNS → 根/TLD/权威:**迭代**
> - DNS 用 **UDP 53** 端口 (响应超 512 字节或区域传送用 TCP 53)

### 6.2.4 资源记录 (Resource Record)

| 类型 | 含义 | 例 |
|------|------|------|
| A | 域名 → IPv4 | www.example.com A 1.2.3.4 |
| AAAA | 域名 → IPv6 | www.example.com AAAA 2001:db8::1 |
| CNAME | 别名 → 规范名 | www CNAME server.example.com |
| NS | 域的权威服务器 | example.com NS ns1.example.com |
| MX | 邮件交换 | example.com MX mail.example.com |
| PTR | IP → 域名 (反向) | 4.3.2.1.in-addr.arpa PTR www.example.com |
| SOA | 起始授权 | 区域管理信息 |
| TXT | 文本记录 | SPF, DKIM |

**记录格式**:`<域名> <TTL> <类> <类型> <值>`

### 6.2.5 DNS 缓存

- 本地 DNS 缓存查询结果 (TTL 控制)
- 主机本身也缓存
- 缓存减少根服务器压力,加速解析

## 6.4 HTTP/HTTPS

### 6.4.1 特点

- **无状态** (Cookie 解决)
- 基于 **TCP 80** 端口
- 请求-响应模型
- 报文为 ASCII 文本

### 6.4.2 持久连接 vs 非持久

| 类型 | HTTP 版本 | 特点 |
|------|----------|------|
| 非持久 | 1.0 | 每对象单独 TCP 连接,每次 2 RTT (建连+请求) |
| 持久非流水线 | 1.1 | 多对象共享 TCP,但每请求等响应 |
| 持久流水线 | 1.1 | 连续发请求不等响应 |
| 多路复用 | 2.0 | 一个 TCP 多请求并行 |

**非持久连接开销分析**:
- 一个网页含 1 HTML + N 图片
- 非持久:1+N 次 TCP 握手 → (1+N)×2 RTT + 传输
- 持久:1 次握手 + (1+N) RTT + 传输

### 6.4.3 HTTP 请求报文格式 (完整)

```
GET /index.html HTTP/1.1          ← 请求行 (方法 URL 版本)
Host: www.example.com             ← 头部行
User-Agent: Mozilla/5.0
Accept: text/html
Accept-Language: zh-CN
Accept-Encoding: gzip
Connection: keep-alive
Cookie: sessionid=abc123
                                  ← 空行 (CRLF)
(请求体,GET 无,POST 有)
```

**请求方法**:
| 方法 | 含义 |
|------|------|
| GET | 获取资源 |
| POST | 提交数据 |
| PUT | 上传资源 |
| DELETE | 删除资源 |
| HEAD | 获取头 (无体) |
| OPTIONS | 查询服务器支持方法 |

### 6.4.4 HTTP 响应报文格式 (完整)

```
HTTP/1.1 200 OK                   ← 状态行 (版本 状态码 短语)
Content-Type: text/html           ← 头部行
Content-Length: 1024
Server: Apache/2.4
Set-Cookie: sessionid=abc123
Connection: keep-alive
                                  ← 空行 (CRLF)
<html>...                         ← 响应体
```

**状态码**:
| 类别 | 含义 | 典型 |
|------|------|------|
| 1xx | 信息 | 100 Continue |
| 2xx | 成功 | 200 OK |
| 3xx | 重定向 | 301 永久, 302 临时, 304 未修改 |
| 4xx | 客户端错 | 404 Not Found, 403 Forbidden |
| 5xx | 服务器错 | 500 Internal Error, 503 Service Unavailable |

### 6.4.5 HTTPS

HTTP + TLS/SSL。
- 端口 **443**
- TLS 握手建立加密通道
- 提供机密性、完整性、身份认证 (证书)

**TLS 握手简化流程**:
1. ClientHello (支持的密码套件、随机数)
2. ServerHello (选定套件、随机数、证书)
3. 客户端验证证书,生成预主密钥,用服务器公钥加密发送
4. 双方计算会话密钥
5. 加密通信开始

### 6.4.6 HTTP 版本对比

| 版本 | 特点 | 端口 |
|------|------|------|
| 1.0 | 非持久 | 80 |
| 1.1 | 持久,流水线,Host 头,分块传输 | 80 |
| 2.0 | 多路复用,二进制分帧,头部压缩 (HPACK) | 80 |
| 3.0 | 基于 QUIC (UDP),解决队头阻塞 | 443 |

### 6.4.7 Cookie

**作用**:HTTP 无状态,Cookie 用于维持会话。

**机制**:
1. 服务器响应中 `Set-Cookie: sessionid=abc123`
2. 浏览器存储 Cookie
3. 后续请求自动带 `Cookie: sessionid=abc123`
4. 服务器识别用户

## 6.5 邮件系统

### 6.5.1 组成

- **UA** (User Agent):用户代理 (Outlook、Thunderbird、Foxmail)
- **MTA** (Mail Transfer Agent):邮件传输服务器 (Sendmail、Postfix)
- **MDA** (Mail Delivery Agent):邮件投递代理

### 6.5.2 完整邮件发送流程

```
发送方UA ──SMTP──► 发送方MTA ──SMTP──► 接收方MTA ──► 接收方MDA ──POP3/IMAP──► 接收方UA
   │                  │                  │                              │
   │     (推)         │      (推)        │                              │ (拉)
```

1. **发送方 UA → 发送方 MTA**:用 **SMTP** (推)
2. **发送方 MTA → 接收方 MTA**:用 **SMTP** (推)
3. **接收方 MTA → 接收方 MDA**:本地存储
4. **接收方 UA ← 接收方 MDA**:用 **POP3 或 IMAP** (拉)

### 6.5.3 协议

| 协议 | 方向 | 端口 | 载体 |
|------|------|------|------|
| SMTP | 客户端 → 服务器,服务器 → 服务器 (推) | 25 | TCP |
| POP3 | 服务器 → 客户端 (拉) | 110 | TCP |
| IMAP | 服务器 → 客户端 (同步) | 143 | TCP |
| SMTPS | SMTP + SSL | 465 | TCP |
| IMAPS | IMAP + SSL | 993 | TCP |

**SMTP 推**:发送方把邮件推给接收方服务器。
**POP3/IMAP 拉**:接收方从服务器拉邮件到本地。

**POP3 vs IMAP**:
| 协议 | 特点 |
|------|------|
| POP3 | 下载到本地,服务器删除 (默认),简单 |
| IMAP | 同步,服务器保留,多设备一致 |

> **真题陷阱**:
> - SMTP 是**推**,POP3/IMAP 是**拉**
> - SMTP 用 TCP 25,POP3 用 TCP 110
> - 邮件发送全程用 SMTP,接收用 POP3/IMAP

### 6.5.4 MIME

Multipurpose Internet Mail Extensions,扩展 SMTP 支持非 ASCII 内容 (图片、音频、视频等)。

**关键头**:
- `Content-Type: text/html; charset=utf-8`
- `Content-Transfer-Encoding: base64`

## 6.6 FTP (File Transfer Protocol)

### 6.6.1 特点

- **双连接**:控制连接 (TCP 21) + 数据连接 (TCP 20)
- 控制连接保持,数据连接按需建立
- 控制连接传命令 (ASCII),数据连接传文件 (二进制)

### 6.6.2 主动模式 (PORT) vs 被动模式 (PASV)

**主动模式 (PORT)**:
1. 客户端连服务器 21 (控制)
2. 客户端发 PORT 命令告知自己 IP:Port
3. 服务器从 20 端口**主动连**客户端指定端口 (数据)

**被动模式 (PASV)**:
1. 客户端连服务器 21 (控制)
2. 客户端发 PASV 命令
3. 服务器返回自己 IP:动态端口
4. 客户端**主动连**服务器指定端口 (数据)

> **真题陷阱**:
> - 控制连接 21,数据连接 20 (主动模式)
> - 被动模式数据端口动态,适合客户端在 NAT 后

## 6.7 其他协议

### 6.7.1 Telnet

- 远程登录
- TCP 23
- 明文传输,不安全

### 6.7.2 SSH

- 安全远程登录
- TCP 22
- 加密,替代 Telnet

### 6.7.3 SNMP

- 网络管理
- UDP 161 (agent) / 162 (trap)
- 简单网络管理协议

### 6.7.4 NTP

- 网络时间协议
- UDP 123
- 时间同步

## 6.8 真题陷阱与高频考点 (30 条)

1. **DNS 递归 vs 迭代**:主机 ↔ 本地 DNS 递归,本地 DNS ↔ 根/权威迭代
2. **DNS 用 UDP 53** (区域传送或响应超 512B 用 TCP)
3. **HTTP 1.1 默认持久**
4. **SMTP 推,POP3/IMAP 拉**
5. **SMTP TCP 25,POP3 TCP 110,IMAP TCP 143**
6. **FTP 控制连接 21,数据连接 20** (主动模式)
7. **HTTPS 端口 443**
8. **HTTP 无状态**,Cookie 解决
9. **DHCP UDP 67/68**
10. **DNS 资源记录类型**:A、AAAA、CNAME、NS、MX、PTR
11. **根服务器 13 套** (A~M)
12. **HTTP 1.0 非持久,1.1 持久**
13. **HTTP 2.0 多路复用,二进制分帧**
14. **HTTP 3.0 基于 QUIC (UDP)**
15. **TLS 握手在 TCP 之上**
16. **HTTP 状态码 5 类**:1xx 信息、2xx 成功、3xx 重定向、4xx 客户端错、5xx 服务器错
17. **301 永久重定向,302 临时重定向,304 未修改**
18. **404 Not Found, 403 Forbidden, 500 Internal Error**
19. **FTP 主动模式服务器连客户端,被动模式客户端连服务器**
20. **MIME 扩展 SMTP 支持非 ASCII**
21. **POP3 下载删服务器,IMAP 同步保留**
22. **P2P 可扩展性强,管理复杂**
23. **C/S 服务器固定地址,被动等待**
24. **DNS 缓存减少根服务器压力**
25. **MX 记录邮件交换,NS 记录权威服务器**
26. **Cookie 在响应中 Set-Cookie,在请求中 Cookie**
27. **HTTP 请求方法:GET/POST/PUT/DELETE/HEAD/OPTIONS**
28. **SMTP 服务器间也是推**
29. **FTP 控制连接保持,数据连接按需**
30. **Telnet TCP 23 明文,SSH TCP 22 加密**

## 6.11 速查表

| 考点 | 结论 |
|------|------|
| DNS 递归 | 主机 ↔ 本地 |
