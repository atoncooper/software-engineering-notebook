## 8.0 形式化定义

### 8.0.1 信号量 (Semaphore) 形式定义

信号量 S 是一个二元组 (V, L),其中:
- V (value):整型变量,表示可用资源数 / 信号状态
- L (list):等待该信号量的 PCB 队列

**PV 原语 (原子操作,不可中断)**:

```
P(S):                       V(S):
  S.V = S.V - 1;              S.V = S.V + 1;
  if (S.V < 0) {             if (S.V <= 0) {
    block(S.L);                 wakeup(S.L);
  }                            }
```

**关键性质**:
1. **P/V 必须原语**:用关中断或 TSL 实现,保证 V.value 修改与队列操作不被打断
2. **S.V < 0 时其绝对值 = L 中阻塞进程数**
3. **S.V > 0 时表示可用资源数**

### 8.0.2 信号量三种用途

| 用途 | 初值 | P 操作含义 | V 操作含义 | 典型 |
|------|------|-----------|-----------|------|
| 互斥 | 1 | 进入临界区 | 离开临界区 | mutex |
| 同步 | 0 | 等待前驱完成 | 通知后继可执行 | 前驱图 |
| 资源 | N | 申请资源 | 释放资源 | empty/full |

### 8.0.3 三大法则 (满分必背)

**法则一:先同步后互斥**
```
正确: P(sync); P(mutex);  临界区;  V(mutex); V(sync)
错误: P(mutex); P(sync);  临界区;  ...        // 易死锁
```
原因:若先 P(mutex) 占用临界区,再 P(sync) 阻塞,其他进程无法进入临界区执行 V(sync),导致死锁。

**法则二:V 操作顺序无关**
- 多个 V 可任意顺序执行,不引发死锁 (只可能影响效率)
- 但**建议先 V(mutex) 再 V(sync)**:让其他等待临界区的进程早进,提高并发度

**法则三:互斥信号量初值=1,资源信号量初值=容量,同步信号量初值=0**

## 8.2 模板速查

### 8.2.1 生产者-消费者 (单缓冲区)

```c
semaphore mutex = 1;   // 互斥访问缓冲区
semaphore empty  = N;  // 空槽数 (同步)
semaphore full   = 0;  // 满槽数 (同步)

void producer() {
    while (1) {
        生产物品;
        P(empty);      // 申请空槽 (同步)
        P(mutex);      // 进入临界区
        放入物品;
        V(mutex);      // 离开临界区
        V(full);       // 增加满槽
    }
}

void consumer() {
    while (1) {
        P(full);       // 申请满槽
        P(mutex);
        取出物品;
        V(mutex);
        V(empty);
        消费物品;
    }
}
```

**关键**:
- P(empty/full) 在 P(mutex) 之前 (先同步后互斥)
- V 操作顺序无关,但建议先 V(mutex) 后 V(full/empty)

### 8.2.2 读者-写者 (读者优先)

```c
semaphore rw = 1;      // 读写互斥 (写者独占)
semaphore mutex = 1;   // readcount 互斥
int readcount = 0;

void reader() {
    P(mutex);
    readcount++;
    if (readcount == 1) P(rw);   // 第一个读者锁写
    V(mutex);
    读操作;
    P(mutex);
    readcount--;
    if (readcount == 0) V(rw);   // 最后一个读者解锁
    V(mutex);
}

void writer() {
    P(rw);
    写操作;
    V(rw);
}
```

**陷阱**:读者优先会饿死写者 (只要有读者源源不断,rw 永不释放)。

### 8.2.3 哲学家进餐 (限制人数法)

```c
semaphore room = 4;                      // 限制同时就餐人数
semaphore chop[5] = {1,1,1,1,1};

void philosopher(int i) {
    while (1) {
        思考;
        P(room);
        P(chop[i]);
        P(chop[(i+1)%5]);
        吃饭;
        V(chop[i]);
        V(chop[(i+1)%5]);
        V(room);
    }
}
```

**三种解法对比**:
| 解法 | 思路 | 优劣 |
|------|------|------|
| 限制人数 | 同时最多 4 人抢筷 | 简单,通用 |
| 奇偶法 | 奇数先左后右,偶数先右后左 | 不需额外信号量 |
| 同时拿 | 拿两根原子化 | 最严格 |

### 8.2.4 理发师睡觉

```c
semaphore customers = 0;   // 等待的顾客数
semaphore barbers   = 0;   // 等待的理发师数
semaphore mutex     = 1;   // waiting 互斥
int waiting = 0;           // 实际等待人数
int CHAIRS = N;            // 椅子数

void barber() {
    while (1) {
        P(customers);      // 等顾客
        P(mutex);
        waiting--;
        V(barbers);        // 通知顾客
        V(mutex);
        理发;
    }
}

void customer() {
    P(mutex);
    if (waiting < CHAIRS) {
        waiting++;
        V(customers);      // 通知理发师
        V(mutex);
        P(barbers);        // 等理发师叫号
        坐下理发;
    } else {
        V(mutex);          // 满座,离开
    }
}
```

### 8.2.5 前驱图

```c
// 每条有向边对应一个信号量 s = 0
// 前驱完成后 V(s); 后继开始前 P(s)

semaphore a=0, b=0, c=0, d=0;
// S1 → S2 (a), S1 → S3 (b), S2 → S4 (c), S3 → S4 (d)

void S1() { ...; V(a); V(b); }
void S2() { P(a); ...; V(c); }
void S3() { P(b); ...; V(d); }
void S4() { P(c); P(d); ...; }
```

**口诀**:**前驱 V,后继 P,多入度多 P**。

## 8.3 真题变形

### 8.3.1 多生产者多消费者

**题**:面包师有 N 个面包位。厨师做面包放位上,顾客取面包。多厨师多顾客。

**分析**:N 个空位作为资源信号量 (empty=N),已放面包数为 full=0。生产消费均需互斥访问货架。

```c
semaphore mutex = 1, empty = N, full = 0;

void chef() {
    while (1) {
        做面包;
        P(empty); P(mutex);
        放上面包;
        V(mutex); V(full);
    }
}

void customer() {
    while (1) {
        P(full); P(mutex);
        取面包;
        V(mutex); V(empty);
        吃面包;
    }
}
```

### 8.3.2 读写者变形 (读写公平)

**题**:读者优先会饿死写者,改成"读写公平"——读者也不能无限占。

**核心**:加信号量 w,读者进入前也 P(w),与写者公平竞争 w。

```c
semaphore rw = 1, mutex = 1, w = 1;
int readcount = 0;

void reader() {
    P(w);                  // 排队公平 (新增)
    P(mutex);
    readcount++;
    if (readcount == 1) P(rw);
    V(mutex);
    V(w);                  // 释放 w (新增)
    读;
    P(mutex);
    readcount--;
    if (readcount == 0) V(rw);
    V(mutex);
}

void writer() {
    P(w);
    P(rw);
    写;
    V(rw);
    V(w);
}
```

**关键**:加 w 信号量,读者也 P(w),与写者竞争,避免读者无限涌入。一旦写者 P(w) 成功,后续读者必须等写者 V(w)。

### 8.3.3 前驱图变形 (多入度)

**题**:S1 → S2, S1 → S3, S2 → S4, S3 → S4 (S4 需等 S2 和 S3 都完成)。

```c
semaphore a = 0, b = 0, c = 0, d = 0;
// S1→S2:a; S1→S3:b; S2→S4:c; S3→S4:d

void S1() { ...; V(a); V(b); }
void S2() { P(a); ...; V(c); }
void S3() { P(b); ...; V(d); }
void S4() { P(c); P(d); ...; }
```

**注意**:S4 必须同时 P(c) 和 P(d),缺一不可。

### 8.3.4 司法考试变题 (多类资源配对)

**题**:仓库存储 A、B 两类零件,装配需 1A + 1B。两个供应商分别供 A、B,一个装配工。

```c
semaphore mutex = 1, sa = 0, sb = 0;
int countA = 0, countB = 0;

void supplierA() {
    while (1) {
        生产A;
        P(mutex);
        放A; countA++;
        V(sa);            // 通知有 A
        V(mutex);
    }
}

void supplierB() {
    while (1) {
        生产B;
        P(mutex);
        放B; countB++;
        V(sb);
        V(mutex);
    }
}

void assembler() {
    while (1) {
        P(sa); P(sb);     // 等两种都到
        P(mutex);
        取A; 取B;
        V(mutex);
        装配;
    }
}
```

### 8.3.6 苹果橘子问题 (经典)

**题**:爸爸放苹果,妈妈放橘子,儿子吃橘子,女儿吃苹果。盘子容量 N。

```c
semaphore plate = N;     // 盘子容量
semaphore apple = 0;     // 苹果数
semaphore orange = 0;    // 橘子数
semaphore mutex = 1;

void father() { 削苹果; P(plate); P(mutex); 放; V(mutex); V(apple); }
void mother() { 削橘子; P(plate); P(mutex); 放; V(mutex); V(orange); }
void son()    { P(orange); P(mutex); 取橘子; V(mutex); V(plate); 吃; }
void daughter(){ P(apple); P(mutex); 取苹果; V(mutex); V(plate); 吃; }
```

### 8.3.7 吸烟者问题 (经典)

**题**:三个吸烟者各拥有烟草、纸、火柴中的一种。桌上有两种材料时,缺第三种的吸烟者吸烟。代理每次随机放两种。

```c
semaphore offer1 = 0;  // 烟草+纸 (给火柴者)
semaphore offer2 = 0;  // 烟草+火柴 (给纸者)
semaphore offer3 = 0;  // 纸+火柴 (给烟草者)
semaphore finish = 0;
semaphore mutex  = 1;
int turn = 0;

void agent() {
    while (1) {
        P(mutex);
        if (turn == 0)      V(offer1);
        else if (turn == 1) V(offer2);
        else                V(offer3);
        turn = (turn+1) % 3;
        V(mutex);
        P(finish);          // 等吸烟者吸完
    }
}

void smoker1() { while (1) { P(offer1); 卷烟; 吸; V(finish); } }  // 火柴
void smoker2() { while (1) { P(offer2); 卷烟; 吸; V(finish); } }  // 纸
void smoker3() { while (1) { P(offer3); 卷烟; 吸; V(finish); } }  // 烟草
```

## 8.4 历年真题完整推演

### 8.4.1 2016 真题 (桥通行问题)

**题**:南北向桥,每次仅允许一辆车通过。桥上最多 K 辆车 (同方向)。南北车不能同时在桥上。

**分析**:
- 桥总容量 K (资源信号量)
- 同方向互斥计数
- 反方向需等桥空

```c
semaphore bridge = K;     // 桥总容量
semaphore mutexN = 1;     // 南向北计数互斥
semaphore mutexS = 1;     // 北向南计数互斥
semaphore mutex  = 1;     // 方向切换互斥
int countN = 0, countS = 0;

void north2south() {
    P(mutexN);
    if (countN == 0) P(mutex);   // 第一辆北向车抢桥
    countN++;
    V(mutexN);
    P(bridge);                   // 桥位
    过桥;
    V(bridge);
    P(mutexN);
    countN--;
    if (countN == 0) V(mutex);   // 最后一辆北向车释放桥
    V(mutexN);
}

void south2north() {
    P(mutexS);
    if (countS == 0) P(mutex);
    countS++;
    V(mutexS);
    P(bridge);
    过桥;
    V(bridge);
    P(mutexS);
    countS--;
    if (countS == 0) V(mutex);
    V(mutexS);
}
```

**考点**:
1. 与读者写者类似:同方向共享 bridge,反方向互斥
2. count==0 时抢/释放方向锁 (mutex)
3. bridge 信号量实现 K 辆并发

### 8.4.3 2020 真题 (前驱图 + 缓冲区)

**题**:三个进程 P1, P2, P3 共享一个缓冲区。P1 写入,P2 读取处理后写回,P3 统计。缓冲区容量 1。

**分析**:三个进程形成流水线,需顺序同步。

```c
semaphore s12 = 1;  // P1→P2: 初值 1 (缓冲区空,P1 可写)
semaphore s23 = 0;  // P2→P3
semaphore s31 = 0;  // P3→P1 (P3 处理完后通知 P1 可再写)

void P1() { while (1) { 数据准备; P(s12); 写入; V(s23); } }
void P2() { while (1) { P(s23); 读取处理; 写回; V(s31); } }
void P3() { while (1) { P(s31); 统计; V(s12); } }
```

### 8.4.4 2022 真题 (理发店变形)

**题**:理发店 2 理发师,N 椅子。顾客来,有空椅则等,否则离开。两理发师可同时工作。

```c
semaphore customers = 0;
semaphore barbers   = 0;
semaphore mutex     = 1;
int waiting = 0;
int CHAIRS = N;
int BARBERS = 2;

void barber() {
    while (1) {
        P(customers);
        P(mutex);
        waiting--;
        V(barbers);
        V(mutex);
        理发;
    }
}

void customer() {
    P(mutex);
    if (waiting < CHAIRS) {
        waiting++;
        V(customers);
        V(mutex);
        P(barbers);
        坐下理发;
    } else {
        V(mutex);
    }
}
```

**陷阱**:barbers 信号量初值为 0 (而非 2),因为初始时没有顾客在等理发师叫号。理发师通过 V(barbers) 主动通知。

### 8.5.2 答题模板 (五步法)

```c
// 1. 信号量定义 (含初值与含义注释)
semaphore mutex = 1;   // 互斥访问缓冲区
semaphore empty = N;   // 同步:空槽数
semaphore full  = 0;   // 同步:满槽数

// 2. 共享变量
int count = 0;

// 3. 进程代码
void producer() {
    while (1) {
        // 准备
        P(empty);
        P(mutex);
        // 临界区
        V(mutex);
        V(full);
    }
}

void consumer() {
    while (1) {
        P(full);
        P(mutex);
        // 临界区
        V(mutex);
        V(empty);
    }
}

// 4. 死锁分析:无死锁 (P 顺序正确)
// 5. 饥饿分析:无饥饿 (公平调度)
```

### 8.5.3 常见错误

| 错误 | 后果 | 修正 |
|------|------|------|
| 先 P(mutex) 后 P(empty) | 死锁 | 调换顺序 |
| V(mutex) 缺失 | 永久阻塞 | 补全 V |
| 信号量初值错 | 行为异常 | mutex=1,资源=N,同步=0 |
| 未用 while (条件变量场景) | 虚假唤醒 | 加 while |
| 多临界区共用一个 mutex | 并发度损失 | 每区独立 mutex |
| 读者优先无 w 限制 | 写者饥饿 | 加 w 改公平 |

## 8.6 高频陷阱 (满分必看)

### 8.6.1 P/V 顺序陷阱 (20 大坑)

1. **先同步后互斥**:P(empty/full) 必在 P(mutex) 前
2. **V 操作顺序无关**但建议先 V(mutex) 后 V(同步) 提高并发
3. **多个 P 在前**:如 P(sa);P(sb);P(mutex) 是合法的,只要不是先 mutex 后同步
4. **嵌套 P 的死锁**:循环等待 → 死锁
5. **V 不能漏**:漏一个 V 必死锁/阻塞
6. **P 多了**:多 P 一个 → 永久阻塞
7. **if vs while**:PV 模型用 if,条件变量用 while (虚假唤醒)

### 8.6.2 信号量初值陷阱

8. **互斥信号量初值必须为 1** (否则无互斥)
9. **资源信号量初值=资源数** (empty=N)
10. **同步信号量初值=0** (前驱必须等)
11. **多入度前驱图每个信号量独立=0**
12. **理发师问题 barbers=0** (初始无理发师在等)

### 8.6.3 模型识别陷阱

13. **桥/山路 = 读者写者变形** (同向共享,反向互斥)
14. **苹果橘子 = 多生产者单消费者** (每类消费者各等自己的资源)
15. **吸烟者 = 多生产者多消费者 + 轮转调度**
16. **前驱图 = 顺序同步** (无互斥,只有同步)
17. **理发师 = 资源+计数** (CHAIRS 是上限)

### 8.6.4 死锁/饥饿分析陷阱

18. **死锁四条件**:互斥、占有等待、不剥夺、循环等待
19. **饥饿不等于死锁**:读者优先会饿死写者但不是死锁
20. **限制人数防死锁**:哲学家 5 人同时抢 5 筷必死锁,限 4 人则不死锁

### 8.6.5 真题变形陷阱

21. **多生产者多消费者**:别忘记 mutex 保护共享变量 (count)
22. **读写公平**:w 信号量必须 P/V 配对 (reader 和 writer 都 P(w) 再 V(w))
23. **K 辆并发桥**:bridge=K 不能省,否则退化为 1 辆
24. **多理发师**:BARBERS 数量只影响并发度,不影响信号量初值 (barbers 仍=0)
25. **前驱图多入度**:S4 需 P(c) AND P(d),不能只 P 一个
