## 1.1 定义与功能

### 1.1.1 定义

**操作系统**(Operating System, OS):控制和管理计算机硬件和软件资源、合理组织计算机工作流程、方便用户使用的**程序集合**。它是**最基本的核心系统软件**。

**三层含义**:
1. **资源管理者**:管理 CPU、内存、I/O、文件等资源
2. **工作流程组织者**:合理调度进程,提高效率
3. **用户接口提供者**:为用户提供方便的使用环境

### 1.1.2 功能(四大管理)

| 功能 | 内容 | 对应章节 |
|------|------|----------|
| **处理机管理** | 进程控制、同步、通信、调度 | 2-4 章 |
| **存储器管理** | 内存分配、回收、保护、扩充(虚拟内存) | 5 章 |
| **文件管理** | 目录管理、文件读写、存储空间管理 | 6 章 |
| **设备管理** | 缓冲管理、设备分配、设备驱动 | 7 章 |

### 1.1.3 目标

- **有效性**(提高资源利用率)——早期 OS 主要目标
- **方便性**(方便用户使用)——现代 OS 主要目标
- **可扩充性**(适应硬件发展)
- **开放性**(标准化,可互操作)

## 1.2 特征(四大特征)

### 1.2.1 四大特征表

| 特征 | 含义 | 是否基本 |
|------|------|----------|
| **并发** | 多道程序同时处于运行状态(宏观同运,微观交替) | **最基本** |
| **共享** | 资源可被多个并发进程共同使用 | **最基本** |
| **虚拟** | 物理 → 逻辑映射(一台 CPU 虚拟为多台) | 派生 |
| **异步** | 进程以不可预知速度推进 | 派生 |

### 1.2.2 并发 vs 并行(深度辨析)

| 维度 | 并发 (concurrent) | 并行 (parallel) |
|------|-------------------|------------------|
| 时刻 | 同一**时间段内** | 同一**时刻** |
| 硬件 | 单 CPU 即可 | 需多 CPU / 多核 |
| 实现 | 多道程序交替占用 CPU | 多 CPU 同时执行多进程 |
| 例 | 单核跑 10 个进程 | 4 核跑 4 个进程 |

> **关键**:**并发是并行的必要条件,但不是充分条件**。单 CPU 只能并发,多 CPU 才能并行。

### 1.2.3 共享的两种方式

- **互斥共享**(临界资源):一段时间内只允许一个进程访问
  - 例:打印机、磁带机
  - 需同步机制
- **同时访问**:允许多进程交替访问
  - 例:磁盘、内存
  - 时间上交替(微观仍互斥,宏观同时)

### 1.2.4 虚拟

- **处理机虚拟**:一台 CPU → 多台"虚拟 CPU"(每个进程以为自己独占 CPU)
- **内存虚拟**:一块物理内存 → 多块"虚拟内存"(每个进程有独立地址空间)
- **设备虚拟**:一台打印机 → 多台"虚拟打印机"(SPOOLing)

### 1.2.5 异步

进程以不可预知速度推进:
- 进程执行速度受其他进程影响
- 进程会停顿(等 I/O、等信号量)
- 同一程序多次运行结果可能不同(若同步不当)

### 1.2.6 四大特征关系

```
并发 ←→ 共享     (互为前提:并发需要共享资源,共享需要并发进程)
  ↓
虚拟 ←→ 异步     (虚拟依赖并发,异步是并发的结果)
```

**最基本**:并发 + 共享(其他特征由此派生)。

## 1.3 发展历程

### 1.3.1 阶段表

| 阶段 | 时间 | 主要特征 | 关键技术 | 缺点 |
|------|------|----------|----------|------|
| 手工操作 | 40s-50s | 独占、串行 | — | CPU 等人 |
| 单道批处理 | 50s-60s | 内存一道程序 | 自动性 | CPU 等 I/O |
| **多道程序** | 60s | 多道、无序、共享 | **并发基础** | 无交互 |
| 分时系统 | 60s-70s | 时间片轮转、交互 | 多路性 | 不够实时 |
| 实时系统 | 70s | 及时响应、高可靠 | 截止时间 | 专用 |
| 网络/分布式 | 80s+ | 资源共享、透明 | 网络 | 复杂 |
| 嵌入式 | 90s+ | 资源受限、专用 | 裁剪 | — |
| 现代(移动/云) | 2000s+ | 移动、虚拟化、容器 | 虚拟化 | — |

### 1.3.2 多道程序设计

**多道**:内存同时存在多道程序,**交替**占用 CPU 运行。

```
程序 A:|--CPU--|--I/O--|--CPU--|
程序 B:|--I/O--|--CPU--|--I/O--|
CPU:    |A      |B      |A      |    (CPU 和 I/O 并行工作)
```

**优点**:
- 提高 CPU、I/O 利用率
- 增加系统吞吐量

**缺点**:
- 延长响应时间
- **无交互能力**(用户提交后不能干预)

### 1.3.3 分时系统

**时间片轮转**,每个用户在各自时间片内独占 CPU。

**四大特征**:
- **多路性**:多用户同时使用
- **独立性**:互不干扰
- **交互性**:用户可直接交互
- **及时性**:响应快

**典型系统**:Unix、Linux、Windows

### 1.3.4 实时系统

在**严格时间限制**内响应。

**分类**:
- **硬实时**:绝对截止时间(导弹控制、核反应堆、心脏起搏器)
- **软实时**:偶尔超时可容忍(视频流、在线交易)

**特征**:
- **及时性**:响应时间严格
- **可靠性**:高可靠

**典型系统**:VxWorks、RT-Linux、QNX

### 1.3.5 分时 vs 实时对比

| 维度 | 分时系统 | 实时系统 |
|------|----------|----------|
| 目标 | 通用、交互 | 专用、及时 |
| 响应时间 | 秒级 | 毫秒/微秒级 |
| 可靠性 | 一般 | 极高 |
| 交互性 | 强 | 弱(专用) |
| 调度 | 公平(时间片) | 优先级(截止时间) |

## 1.4 操作系统基本结构

### 1.4.1 层次

```
┌─────────────────────────┐
│         用户             │
├─────────────────────────┤
│       应用软件           │
├─────────────────────────┤
│  操作系统 (内核+系统调用)│
├─────────────────────────┤
│         硬件             │
└─────────────────────────┘
```

### 1.4.2 内核功能

| 功能 | 说明 |
|------|------|
| 时钟管理 | 系统时钟、时间片 |
| 中断机制 | 中断响应、中断处理 |
| 原语 (primitive) | 不可中断的原子操作(进程创建、阻塞等) |
| 系统控制数据结构 | PCB、页表、文件表等 |

### 1.4.3 特权指令 vs 非特权指令

| 类型 | 执行态 | 例 |
|------|--------|------|
| **特权指令** | 仅内核态 | I/O 指令、置中断屏蔽、清内存、停机、置时钟 |
| **非特权指令** | 用户态可执行 | 算术运算、访存、访管指令(trap/syscall) |

> **关键**:**访管指令(trap/syscall)是非特权指令**,用户态可执行。执行后产生自陷,进入内核态。

### 1.4.4 用户态 vs 内核态

**用户态**(User Mode):运行用户程序,特权指令不可用
**内核态**(Kernel Mode):运行内核代码,所有指令可用

**用户态 → 内核态的触发**:
- **中断**(外部中断,如时钟、I/O)
- **异常**(内部异常,如缺页、除零)
- **系统调用**(访管指令 trap)

**内核态 → 用户态的触发**:
- 中断/异常/系统调用返回(IRET 等)

> **真题陷阱**:用户态 → 内核态由**硬件自动完成**(状态字 PSW 修改),不需要软件介入。

## 1.5 中断与异常

### 1.5.1 中断 vs 异常

| 类型 | 别名 | 来源 | 性质 | 例 |
|------|------|------|------|------|
| **中断** | 外中断 | CPU 外部 | 异步 | I/O 完成、时钟中断、键盘 |
| **异常** | 内中断 | CPU 内部 | 同步 | 除零、缺页、地址越界、系统调用 |

### 1.5.2 异常分类

| 类型 | 处理 | 返回点 | 例 |
|------|------|--------|------|
| **故障 Fault** | 可恢复,重新执行 | 触发指令 | 缺页、除零(可恢复) |
| **自陷 Trap** | 有意触发 | 下条指令 | 系统调用、断点 |
| **终止 Abort** | 不可恢复 | 进程结束 | 硬件错误、非法指令 |

> **关键**:故障返回触发指令(重新执行),自陷返回下条指令。

### 1.5.3 中断处理过程

```
1. 关中断                ← 硬件
2. 保存断点(PC、PSW)     ← 硬件
3. 中断服务程序寻址(中断向量)← 硬件
4. 保存现场(通用寄存器)   ← 软件
5. 中断事件处理           ← 软件
6. 恢复现场              ← 软件
7. 开中断                ← 软件
8. 中断返回(IRET)        ← 硬件
```

**硬件完成**:1、2、3、8(关中断、保存断点、找入口、返回)
**软件完成**:4、5、6、7(保存现场、处理、恢复、开中断)

### 1.5.4 中断向量

- **中断向量**:中断服务程序入口地址
- **中断向量表**:存放所有中断向量(通常在内存低地址)
- **中断类型号**:索引中断向量表

> **真题陷阱**:
> - 中断响应由**硬件**完成(保存断点、找中断服务程序入口)
> - 中断处理由**软件**完成(中断服务程序)
> - 用户态 → 内核态的转换由中断/异常/系统调用触发

## 1.6 系统调用

### 1.6.1 定义

**系统调用**(System Call):操作系统提供给应用程序的接口,让用户程序获得内核服务(如 read、write、fork)。

### 1.6.2 系统调用 vs 库函数

| 维度 | 库函数 | 系统调用 |
|------|--------|----------|
| 实现 | 用户态 | 内核态 |
| 是否陷入内核 | 不一定 | 必陷入 |
| 例 | strcpy(不陷入)、printf(封装 write) | read、write、fork |
| 接口 | C 标准库 | OS 内核 |

**关系**:
- 部分库函数**不调用**系统调用(如 strcpy)
- 部分库函数**封装**系统调用(如 printf 封装 write)
- 系统调用**必须**陷入内核态执行

### 1.6.3 分类

| 类别 | 系统调用例 |
|------|-----------|
| 设备管理 | 申请设备、释放设备 |
| 文件管理 | 创建、删除、读、写 |
| 进程管理 | 创建、终止、阻塞、唤醒 |
| 进程通信 | 消息发送、接收、共享内存 |
| 存储管理 | 申请内存、释放内存 |

### 1.6.4 执行过程

```
1. 用户程序执行访管指令(trap/syscall)
2. 产生自陷,从用户态进入内核态  ← 硬件完成
3. 内核查系统调用号,找到对应处理函数
4. 执行系统调用(在内核态)
5. 返回用户态(IRET)
```

> **访管指令**:用户态可执行,执行后必陷入内核态,是**非特权指令**。

### 1.6.5 系统调用与中断/异常关系

- **系统调用是一种异常(自陷)**
- 由用户**主动**触发(通过访管指令)
- 必经"用户态 → 内核态"切换

## 1.7 大内核 vs 微内核

### 1.7.1 大内核(单内核 / Monolithic Kernel)

**所有**内核功能(进程、内存、文件、设备、网络、驱动)集成在内核态。

```
┌───────────────┐
│   大内核       │
│ ┌───────────┐ │
│ │ 进程 内存 │ │
│ │ 文件 设备 │ │  ← 全部在内核态
│ │ 网络 驱动 │ │
│ └───────────┘ │
└───────────────┘
```

- **优点**:性能高(内核内调用,无切换开销)
- **缺点**:稳定性低(一处错全崩)、扩展性差
- **代表**:Linux、Unix、早期 Windows

### 1.7.2 微内核(Micro Kernel)

内核只留**最基本**功能(进程调度、IPC、中断),其他作为服务进程运行在用户态。

```
┌───────────────┐
│   微内核       │
│ ┌───────────┐ │
│ │ 调度 IPC  │ │  ← 仅基本功能在内核态
│ └───────────┘ │
└───────────────┘
       ↕ IPC
┌───────────────┐
│ 文件服务(用户态)│
│ 设备服务(用户态)│
│ 网络服务(用户态)│
└───────────────┘
```

- **优点**:稳定性高(服务进程隔离)、扩展性好
- **缺点**:性能低(频繁用户/内核态切换 + IPC 开销)
- **代表**:Mach、QNX、Windows NT(部分)

### 1.7.3 对比表

| 对比项 | 大内核 | 微内核 |
|--------|--------|--------|
| 结构 | 内核集成所有功能 | 内核只留基本功能 |
| 性能 | 高 | 低(IPC 开销) |
| 稳定性 | 较低 | 高 |
| 扩展性 | 差 | 好 |
| 代码量 | 大 | 小 |
| 代表 | Linux、Unix | Mach、QNX |

### 1.7.4 性能差异原因

**大内核**:进程管理、文件、设备等都在内核态,调用直接(函数调用)
**微内核**:文件服务在用户态,内核调用文件服务需 IPC(消息传递),开销大

## 1.8 真题精解

### 【2016 选择】用户态内核态切换

**题目**:用户程序调用系统调用时,CPU 状态?

A. 一直用户态  B. 一直内核态
C. 用户态 → 内核态  D. 内核态 → 用户态

**答案**:**C**

**解析**:系统调用通过访管指令(trap)触发自陷,CPU 从用户态切换到内核态执行内核代码,完成后返回用户态。

### 【2018 选择】中断 vs 异常分类

**题目**:下列事件中,属于异常(内中断)的是?

A. 键盘输入  B. 时钟中断
C. 缺页  D. I/O 完成

**答案**:**C**

**解析**:
- A、B、D 都是外部中断(异步)
- C 缺页是 CPU 内部异常(同步,执行指令时产生)

### 【2019 选择】并发与并行

**题目**:单 CPU 多道程序系统中,以下正确的是?

A. 多道程序并行执行
B. 多道程序并发执行
C. 程序执行顺序确定
D. 程序执行速度可预知

**答案**:**B**

**解析**:
- 单 CPU 只能并发(同时间段内),不能并行(同时刻)(A 错 B 对)
- 多道程序执行顺序不确定(异步)(C 错)
- 执行速度不可预知(D 错)

### 【2021 选择】大内核 vs 微内核

**题目**:关于大内核和微内核,下列正确的是?

A. 大内核比微内核稳定
B. 微内核比大内核性能高
C. 微内核比大内核稳定
D. 大内核代码量比微内核少

**答案**:**C**

**解析**:
- 大内核一处错全崩,稳定性低(A 错)
- 微内核频繁 IPC,性能低(B 错)
- 微内核服务进程隔离,稳定性高(C 对)
- 大内核代码量大(D 错)

### 【2020 选择】访管指令

**题目**:关于访管指令,下列正确的是?

A. 是特权指令,只能在内核态执行
B. 是非特权指令,可在用户态执行
C. 执行后不改变 CPU 状态
D. 仅用于 I/O 操作

**答案**:**B**

**解析**:
- 访管指令(trap/syscall)是**非特权指令**,用户态可执行
- 执行后产生自陷,CPU 从用户态 → 内核态(C 错)
- 用于系统调用,不仅 I/O(D 错)

## 1.9 真题陷阱(15 条)

1. **并发是最基本特征**:与共享并列,但并发是前提
2. **并发 vs 并行**:单 CPU 只能并发,多 CPU 才能并行
3. **共享分两种**:互斥共享(打印机) vs 同时访问(磁盘)
4. **中断 vs 异常**:外/异步 vs 内/同步
5. **异常分三类**:故障(可恢复)/自陷(有意)/终止(不可恢复)
6. **故障返回触发指令**(重新执行),**自陷返回下条指令**
7. **用户态 → 内核态**:由中断/异常/系统调用触发,硬件自动完成
8. **访管指令是非特权指令**:用户态可执行,但执行后陷入内核态
9. **系统调用是一种异常(自陷)**:由用户主动触发
10. **系统调用 vs 库函数**:库函数可能不调系统调用
11. **多道程序设计**:并发的基础,但无交互能力
12. **分时系统**:多路性、独立性、交互性、及时性
13. **实时系统**:及时性、可靠性,分硬实时/软实时
14. **大内核性能高,微内核稳定性高**
15. **中断响应硬件完成,中断处理软件完成**

## 1.10 易混淆点深辨析

### 1.10.1 并发 vs 并行 vs 共享 vs 异步

| 概念 | 含义 | 关系 |
|------|------|------|
| 并发 | 同时间段内多事件 | 最基本,与共享互为前提 |
| 并行 | 同时刻多事件 | 需多 CPU,是并发的扩展 |
| 共享 | 资源多进程共用 | 最基本,与并发互为前提 |
| 异步 | 速度不可预知 | 并发的结果 |

### 1.10.2 中断 vs 异常 vs 系统调用

| 维度 | 中断 | 异常 | 系统调用 |
|------|------|------|----------|
| 来源 | 外部 | 内部 | 内部(主动) |
| 性质 | 异步 | 同步 | 同步 |
| 触发 | I/O、时钟 | 缺页、除零 | 访管指令 |
| 是否异常 | 否 | 是 | 是(自陷) |

### 1.10.3 故障 vs 自陷 vs 终止

| 类型 | 返回点 | 可恢复 | 例 |
|------|--------|--------|------|
| 故障 | 触发指令(重执行) | 可 | 缺页、除零(可恢复) |
| 自陷 | 下条指令 | — | 系统调用、断点 |
| 终止 | 进程结束 | 不可 | 硬件错误 |

### 1.10.4 大内核 vs 微内核

| 维度 | 大内核 | 微内核 |
|------|--------|--------|
| 内核功能 | 全部 | 仅基本(调度+IPC) |
| 性能 | 高 | 低(IPC 开销) |
| 稳定性 | 低 | 高(服务隔离) |
| 扩展性 | 差 | 好 |

## 1.14 本章习题

1. 解释并发与并行的区别,各举一例。
2. 操作系统的四大特征是什么?哪个最基本?为什么?
3. 中断和异常的区别?异常分为哪三类?各举一例。
4. 用户态如何切换到内核态?是硬件还是软件完成?
5. 访管指令是特权指令吗?为什么?
6. 系统调用和库函数的区别?
7. 大内核和微内核的优缺点?各举一个代表系统。
8. 多道程序设计的优缺点?

### 习题答案

1. **并发**:同一时间段内多事件发生(单 CPU 多道程序)。**并行**:同一时刻多事件发生(多核 CPU 同时执行多进程)。

2. 四大特征:并发、共享、虚拟、异步。**并发和共享是最基本**(互为前提:并发需要共享资源,共享需要并发进程)。

3. **中断**来自 CPU 外部(异步),如 I/O 完成、时钟。**异常**来自 CPU 内部(同步),分为:**故障**(缺页,可恢复重执行)、**自陷**(系统调用,有意)、**终止**(硬件错误,不可恢复)。

4. 通过中断/异常/系统调用触发,**硬件自动完成**(修改 PSW 状态字)。

5. **非特权指令**。访管指令(trap/syscall)用户态可执行,执行后产生自陷进入内核态。若为特权指令,用户态无法执行,就无法主动请求内核服务了。

6. **库函数**在用户态实现,可能不调用系统调用(strcpy),也可能封装系统调用(printf 封装 write)。**系统调用**必须陷入内核态执行,是 OS 提供的接口。

7. **大内核**:性能高(内核内调用),稳定性低(一处错全崩),代表 Linux。**微内核**:稳定性高(服务隔离),性能低(IPC 开销),代表 QNX。

8. **优点**:提高 CPU 和 I/O 利用率,增加系统吞吐量。**缺点**:延长响应时间,无交互能力。
