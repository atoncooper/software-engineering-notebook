## 5.1 程序装入与链接

### 5.1.1 装入

| 方式 | 时机 | 特点 | 是否需硬件 |
|------|------|------|------------|
| 绝对装入 | 编译时 | 地址固定,只能放指定位置 | 否 |
| 静态重定位(可重定位装入) | 装入时 | 装入时改地址,运行中不动 | 否 |
| 动态重定位(动态运行时装入) | 运行时 | 需**重定位寄存器**,可移动 | **是** |

**动态重定位**:运行时把逻辑地址 + 重定位寄存器值 = 物理地址。优点:进程可在内存中移动(利于紧凑)。

### 5.1.2 链接

| 方式 | 时机 | 特点 |
|------|------|------|
| 静态链接 | 编译后 | 一次性链接成完整可执行 |
| 装入时动态链接 | 装入时 | 边装入边链接 |
| 运行时动态链接 | 运行时 | 用到才链接,共享库(DLL) |

**运行时动态链接**优点:共享库(多个进程共享一份)、按需链接(节省空间)。

## 5.2 连续分配

### 5.2.1 单一连续分配

内存分**系统区 + 用户区**,用户区一道程序。

- **无内部碎片**
- **有外部碎片**(剩余空间不够下一道)

### 5.2.2 固定分区分配

内存分**固定大小**分区。分区大小可等可不等。

- **内部碎片**:分区未用满
- **外部碎片**:有空分区但无程序可分配(通常不算,因分区已分)

### 5.2.3 动态分区分配

按需分配,分区大小动态。

- **外部碎片**:空闲块太小无法用
- **无内部碎片**

**分配算法**:

| 算法 | 策略 | 特点 |
|------|------|------|
| **首次适应**(First Fit) | 按地址顺序找第一个够大 | 简单,常用 |
| **最佳适应**(Best Fit) | 找最小的够大 | 外部碎片多 |
| **最坏适应**(Worst Fit) | 找最大的 | 大作业难分配 |
| **循环首次适应**(Next Fit) | 从上次位置继续 | 平衡分配 |

**碎片处理**:
- **紧凑(compaction)**:移动进程合并外部碎片,需动态重定位
- 紧凑开销大,通常避免

## 5.3 分页

### 5.3.1 基本概念

- **页(page)**:进程逻辑空间分固定大小块
- **页框(frame)**:物理内存分同大小块
- **页表**:页号 → 页框号映射

页大小通常 **4 KB**(与 Cache 行、磁盘块对齐)。

### 5.3.2 地址结构

```
逻辑地址 = 页号 P + 页内偏移 W
物理地址 = 页框号 F + 页内偏移 W
```

若页大小 4 KB,则 W 占 12 位。32 位地址:页号 20 位 + 偏移 12 位。

```
逻辑地址:| 页号 P (20 位) | 页内偏移 W (12 位) |
                              ↓
页表:页号 → 页框号
                              ↓
物理地址:| 页框号 F (20 位) | 页内偏移 W (12 位) |
```

### 5.3.3 地址变换

```
1. 逻辑地址 → 页号 P + 偏移 W
2. 查页表:P 对应的页框号 F
   - 先查快表 TLB(命中则跳过页表)
   - TLB 缺失则查内存中的页表
3. 物理地址 = F × 页大小 + W
4. 访问物理地址
```

**访存次数**:
- 无 TLB:**2 次**(查页表 + 取数据)
- TLB 命中:**1 次**(直接取数据)
- TLB 缺失:**2 次** + TLB 更新

### 5.3.4 多级页表

避免单级页表过大。32 位地址,4 KB 页,页表项 4 B:
- 一级页表项数 = 2²⁰,需 **4 MB 连续内存**(太大)
- 二级页表:页号拆为"一级 10 位 + 二级 10 位"
- 每级页表 4 KB(1024 项 × 4 B),无需连续大块内存

**二级页表访存次数**(无 TLB):**3 次**(一级页表 + 二级页表 + 数据)

```
逻辑地址:| 一级页号 (10) | 二级页号 (10) | 偏移 (12) |
                ↓                ↓
            一级页表         二级页表(指向页框)
                ↓                ↓
              页框号 F           ↓
                              ↓
                         物理地址 = F × 4KB + W
```

### 5.3.5 页表项各位

页表项各位(标志位):

| 位 | 含义 |
|----|------|
| **有效位(Valid)** | 是否在内存(0 → 缺页) |
| **修改位(Dirty)** | 是否被写过(置换时需写回磁盘) |
| **访问位(Reference)** | 最近是否访问(用于置换) |
| **保护位** | 读/写/执行权限 |
| **有效位** | 页表项是否有效 |

### 5.3.6 TLB(Translation Lookaside Buffer)

**TLB**(快表):页表的**高速缓存**(Cache),存放最近访问的页表项。

- **TLB 命中**:无需访存查页表,直接得页框号
- **TLB 缺失**:查内存页表,更新 TLB
- TLB 通常用全相联或组相联

**TLB + Cache 访问流程**:
```
逻辑地址 → TLB
            ↓ 命中:页框号
            ↓ 缺失:查页表 → 页框号(更新 TLB)
物理地址 → Cache
            ↓ 命中:数据
            ↓ 缺失:查内存
```

## 5.4 分段与段页式

### 5.4.1 分段

按程序**逻辑结构**分段(代码段、数据段、栈段),段长**可变**。

- 逻辑地址 = 段号 + 段内偏移
- 段表:段号 → 段基址 + 段长
- 地址变换:查段表得基址,加偏移(需**检查越界**)

### 5.4.2 分页 vs 分段

| 对比项 | 分页 | 分段 |
|--------|------|------|
| 划分依据 | 物理(固定大小) | 逻辑(按程序结构) |
| 大小 | 固定 | 可变 |
| 碎片 | **内部碎片** | **外部碎片** |
| 共享 | 难 | 易(按段共享) |
| 可见性 | 透明 | 程序员可见 |
| 越界检查 | 无(页内偏移固定) | 有(段长可变) |

### 5.4.3 段页式

先分段再分页。

- 逻辑地址 = 段号 + 页号 + 页内偏移
- 段表 → 页表基地址;页表 → 页框号
- **3 次访存**(段表 + 页表 + 数据)

## 5.5 虚拟内存

### 5.5.1 局部性原理

- **时间局部性**:刚访问的指令/数据,不久后很可能再访问(循环)
- **空间局部性**:访问某地址,附近地址也 likely 被访问(数组)

**例**:
```c
for (i = 0; i < 1000; i++)
    sum += a[i];  // 时间局部性:sum 反复访问;空间局部性:a[i] 连续访问
```

### 5.5.2 请求分页

在分页基础上,**只装入当前需要的页**,其他页存磁盘。

**缺页中断处理流程**:
1. CPU 访问逻辑地址
2. 查页表,有效位 = 0 → **缺页中断**
3. 操作系统从磁盘调入该页(若无空闲页框,先置换)
4. 更新页表
5. **重新执行指令**

**关键**:
- 缺页中断属于**异常(内中断)**
- 缺页中断在**指令执行中**产生(非指令末)
- 处理后**重新执行**该指令

### 5.5.3 内存映射文件(mmap)

把磁盘文件映射到内存地址空间,访问内存 = 读写文件。

- 优点:不需 read/write 系统调用,效率高
- 应用:动态链接库、文件 I/O、进程间共享

## 5.6 页面置换算法

### 5.6.1 OPT(最佳置换)

选**最长时间不再访问**的页淘汰。

- **不可实现**(需预知未来),仅作理论下界
- **缺页率最低**

### 5.6.2 FIFO(先进先出)

按调入顺序淘汰**最老**的。

- 实现简单
- **Belady 异常**:增加页框数反而缺页率上升(FIFO 独有)

### 5.6.3 LRU(最近最少使用)

淘汰**最近最久未访问**的页。

- 需记录每次访问时间或用栈维护
- 性能接近 OPT
- **无 Belady 异常**(LRU 属**栈式算法**)

**实现**:
- **计数器法**:每页维护计数器,访问时 +1
- **栈法**:维护访问栈,访问时移到栈顶,淘汰栈底

### 5.6.4 CLOCK(简单时钟 / NRU)

页框组织成**环形链表**,指针扫描:
- 访问位 = 0:淘汰
- 访问位 = 1:改为 0,跳过

```
       ↓ 指针
   ┌─→ ┌──┐ → ┌──┐ → ┌──┐ → ┌──┐ ─┐
   │   │P1│   │P2│   │P3│   │P4│  │
   │   └──┘   └──┘   └──┘   └──┘  │
   └──────────────────────────────┘
```

**改进型 CLOCK**:考虑**访问位 + 修改位**,优先淘汰 (0,0),其次 (0,1),再 (1,0),最后 (1,1)。**两次扫描**:
- 第 1 轮:找 (0,0) 淘汰
- 第 2 轮:找 (0,1) 淘汰(期间把访问位清 0)
- 第 3 轮:再找 (0,0)
- 第 4 轮:再找 (0,1)

### 5.6.5 LFU(最不经常使用)

淘汰**访问次数最少**的。

- 需计数器
- 新页计数小易被淘汰(可衰减解决)

### 5.6.6 完整例题

**访问序列**:7, 0, 1, 2, 0, 3, 0, 4, 2, 3, 0, 3, 2, 1, 2, 0, 1, 7, 0, 1
**页框数**:3

**FIFO**:
```
访问  页框1 页框2 页框3  缺页?
7     7     -     -     ✓
0     7     0     -     ✓
1     7     0     1     ✓
2     2     0     1     ✓(淘汰 7)
0     2     0     1     命中
3     2     3     1     ✓(淘汰 0)
0     2     3     0     ✓(淘汰 1)
4     4     3     0     ✓(淘汰 2)
2     4     2     0     ✓(淘汰 3)
3     4     2     3     ✓(淘汰 0)
0     0     2     3     ✓(淘汰 4)
3     0     2     3     命中
2     0     2     3     命中
1     0     1     3     ✓(淘汰 2)
2     0     1     2     ✓(淘汰 3)
0     0     1     2     命中
1     0     1     2     命中
7     7     1     2     ✓(淘汰 0)
0     7     0     2     ✓(淘汰 1)
1     7     0     1     ✓(淘汰 2)
```
缺页 15 次,缺页率 15/20 = 75%。

**LRU**(略,缺页率更低)。

### 5.6.7 Belady 异常

**只有 FIFO 会出现**:增加页框数反而缺页率上升。

**例**:访问序列 1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5
- 3 页框:缺页 9 次
- 4 页框:缺页 10 次(反而多!)

**LRU/OPT 是栈式算法**:任何时刻内存中页面集合是页框数多时的子集,**不会 Belady**。

### 5.6.8 缺页率计算

$$\text{缺页率} = \frac{\text{缺页次数}}{\text{总访问次数}}$$

> **真题陷阱**:
> - 首次访问必缺页(页未调入)
> - 置换时若有修改还需写回磁盘,I/O 增加
> - 缺页中断在指令执行中产生,处理后重新执行指令

## 5.7 抖动与工作集

### 5.7.1 抖动(Thrashing)

**频繁缺页**,系统大部分时间用于页面调入调出,实际工作很少。

**原因**:并发进程过多,每个进程分到的页框**少于其工作集**。

**解决**:
- 减少并发进程数
- 增加物理内存
- 调整页面置换算法
- 工作集模型

### 5.7.2 工作集

某段时间间隔 ∆ 内进程访问的**页面集合**。

- 工作集大小决定进程所需**最少页框**
- 分配页框 < 工作集 → 抖动

### 5.7.3 驻留集

操作系统分配给进程的**页框数**。

- **固定分配**:页框数不变
- **可变分配**:根据缺页率动态调整

### 5.7.4 缺页率控制

- 缺页率过高 → 增加页框(防止抖动)
- 缺页率过低 → 减少页框(提高利用率)

## 5.8 真题精解

### 【2016 选择】TLB + 页表访存

**题目**:分页系统中,TLB 命中时,访问一个数据需几次访存?

A. 0 次  B. 1 次  C. 2 次  D. 3 次

**答案**:**B**

**解析**:TLB 命中 → 直接得页框号 → 拼物理地址 → 1 次访存取数据。

### 【2017 综合】页面访问序列 LRU 推演

**题目**:见 5.6.6 节,用 LRU 推演访问序列 7,0,1,2,0,3,...,计算缺页率。

**答**:见 5.6.6 节 FIFO 推演;LRU 类似但每次淘汰最久未访问,缺页率更低。

### 【2019 选择】Belady 异常

**题目**:下列页面置换算法中,可能出现 Belady 异常的是?

A. OPT  B. LRU  C. FIFO  D. CLOCK

**答案**:**C**

**解析**:只有 **FIFO** 会出现 Belady 异常。LRU/OPT 是栈式算法,不会 Belady。

### 【2020 综合】二级页表地址变换

**题目**:32 位地址,4 KB 页,二级页表,求地址结构和访存次数。

**答**:
- 地址结构:一级页号(10) + 二级页号(10) + 偏移(12)
- 无 TLB:3 次访存(一级页表 + 二级页表 + 数据)
- TLB 命中:1 次访存

### 【2021 综合】改进 CLOCK

**题目**:改进 CLOCK 算法的优先淘汰策略?

**答**:优先 (0,0),其次 (0,1),再 (1,0),最后 (1,1)。两次扫描:
- 第 1 轮:找 (0,0)
- 第 2 轮:找 (0,1),期间清访问位
- 第 3 轮:再找 (0,0)
- 第 4 轮:再找 (0,1)

### 【2024 综合】虚拟地址 → 物理地址

**题目**:给出虚拟地址、页表、TLB 状态,求物理地址并计算访存次数。

**答**:
1. 拆分虚拟地址为页号 + 偏移
2. 查 TLB:
   - 命中:得页框号
   - 缺失:查页表(访存 +1)
3. 物理地址 = 页框号 × 页大小 + 偏移
4. 查 Cache:
   - 命中:得数据(总访存 = TLB 命中 ? 1 : 2)
   - 缺失:查内存(总访存 +1)

## 5.9 真题陷阱(15 条)

1. **动态重定位需重定位寄存器**:运行时可移动
2. **首次适应最常用**:地址顺序,简单高效
3. **页大小 4 KB 与偏移 12 位**:对应关系
4. **TLB 命中访存 1 次,缺失访存 2 次**(无多级)
5. **二级页表访存 3 次**:一级 + 二级 + 数据
6. **有效位 = 0 触发缺页中断**:从磁盘调入
7. **OPT 不可实现,仅下界**
8. **FIFO 有 Belady,LRU/OPT 不会**
9. **LRU 是栈式算法**:页框多时页面集是子集
10. **改进 CLOCK 优先 (0,0)**:访问位+修改位
11. **抖动 = 频繁缺页**:页框少于工作集
12. **分页内部碎片,分段外部碎片**
13. **缺页中断在指令中产生,处理后重执行**
14. **缺页中断是异常(内中断)**
15. **修改页置换需写回磁盘**(I/O 增加)

## 5.10 易混淆点深辨析

### 5.10.1 分页 vs 分段 vs 段页式

| 维度 | 分页 | 分段 | 段页式 |
|------|------|------|--------|
| 划分 | 物理(固定) | 逻辑(可变) | 先段后页 |
| 碎片 | 内部 | 外部 | 内部 |
| 共享 | 难 | 易 | 易 |
| 越界检查 | 无 | 有 | 有(段级) |
| 访存(无 TLB) | 2 | 2 | 3 |

### 5.10.2 内部碎片 vs 外部碎片

| 类型 | 含义 | 出现于 |
|------|------|--------|
| **内部碎片** | 分配大于所需,内部浪费 | 固定分区、分页 |
| **外部碎片** | 空闲块太小无法用 | 动态分区、分段 |

### 5.10.3 五种页面置换算法

| 算法 | 淘汰 | Belady | 实现 |
|------|------|--------|------|
| OPT | 最久不再访问 | 否 | 不可实现 |
| FIFO | 最老 | **是** | 简单 |
| LRU | 最久未访问 | 否 | 计数器/栈 |
| CLOCK | 访问位 0 | 否 | 环形链表 |
| LFU | 访问次数最少 | 否 | 计数器 |

### 5.10.4 TLB vs Cache

| 维度 | TLB | Cache |
|------|-----|-------|
| 缓存 | 页表项 | 数据/指令 |
| 命中后 | 得页框号 | 得数据 |
| 访存次数 | 减少(跳过页表) | 减少(跳过内存) |

## 5.13 延伸知识

### 5.13.1 Linux 内存管理

- **Buddy 系统**:物理页框分配(2^k 页为单位)
- **Slab 分配器**:小对象分配(内核数据结构)
- **匿名页 + 文件页**:匿名页(堆栈) vs 文件页(mmap)
- **swap**:换出匿名页到 swap 分区

### 5.13.2 Huge Pages

- 标准页 4 KB,大页 2 MB / 1 GB
- 减少 TLB 缺失(单个 TLB 项覆盖更大空间)
- 适用:数据库、大内存应用

### 5.13.3 NUMA

- 非一致内存访问:多 CPU 各有本地内存
- 本地访问快,远程访问慢
- NUMA 调度:进程尽量用本地内存

### 5.13.4 内存压缩

- Android/iOS:内存紧张时压缩冷页
- zram:压缩 swap 设备
- 比 swap 快(无磁盘 I/O)

### 5.13.5 KSM(Kernel Samepage Merging)

- 合并相同内容的页(如虚拟机运行相同 OS)
- 减少内存占用
- 适用于虚拟化环境

## 5.14 本章习题

1. 动态重定位需要什么硬件支持?为什么?
2. 分页和分段的区别?各有什么碎片?
3. 简述分页地址变换过程,TLB 命中和缺失分别几次访存?
4. 二级页表的地址结构和访存次数?
5. 五种页面置换算法的特点?哪个会出现 Belady 异常?
6. 什么是栈式算法?为什么 LRU 不会 Belady?
7. 改进 CLOCK 算法的淘汰优先级?
8. 什么是抖动?如何解决?

### 习题答案

1. **重定位寄存器**。运行时把逻辑地址 + 寄存器值 = 物理地址,使进程可在内存中移动(利于紧凑)。

2. 见 5.10.1 表。分页:物理划分固定大小,内部碎片;分段:逻辑划分可变大小,外部碎片。

3. 见 5.3.3 节。**TLB 命中:1 次访存**;**TLB 缺失:2 次访存**(查页表 + 取数据)。

4. 32 位地址,4 KB 页:一级页号(10) + 二级页号(10) + 偏移(12)。无 TLB 访存 3 次:一级页表 + 二级页表 + 数据。

5. 见 5.10.3 表。**FIFO 出现 Belady 异常**,其他不会。

6. **栈式算法**:任何时刻内存中页面集合是页框数多时的子集。LRU 是栈式:页框多时,内存中页面集包含页框少时的集合,所以增加页框不会增加缺页。FIFO 不是栈式,可能 Belady。

7. **(0,0)** 优先 → (0,1) → (1,0) → (1,1)。两次扫描。

8. **抖动**:频繁缺页,系统大部分时间用于页面调入调出。**解决**:减少并发进程数、增加物理内存、调整置换算法、工作集模型。
