## 6.1 文件逻辑结构

### 6.1.1 类型

- **有结构文件**:记录式,数据库记录
  - 定长记录 / 变长记录
- **无结构文件**:流式,文本、二进制

### 6.1.2 文件操作

| 操作 | 说明 |
|------|------|
| create | 创建文件 |
| delete | 删除文件 |
| open | 打开文件(返回 fd) |
| close | 关闭文件 |
| read | 读 |
| write | 写 |
| seek | 定位读写指针 |

**open 操作**:把 FCB 读入内存的**打开文件表**,返回文件描述符 fd。后续 read/write 通过 fd 直接访问,无需重新查目录。

## 6.2 文件物理结构

### 6.2.1 连续分配

文件占用**连续**磁盘块。

- 优点:
  - 顺序访问快
  - 随机访问也快(直接算偏移)
- 缺点:
  - **外部碎片**
  - 文件难增长(需紧凑)
- 适合 CD-ROM(只读,大小固定)

### 6.2.2 链接分配

每个文件块含**下一块指针**。

**隐式链接**:
- 目录存首块指针
- 块内含下一块指针
- 随机访问慢(需遍历链)

**显式链接(FAT)**:
- **文件分配表(FAT)**:所有链接指针**集中在内存**
- 每个表项对应一个磁盘块,存下一块号
- 随机访问快(查 FAT,无需遍历磁盘链)

**FAT 表项位数** = log₂(磁盘总块数)

**例**:磁盘 2³² 块,FAT 项 **32 位**。

- 优点:无外部碎片,文件可增长
- 缺点:随机访问慢(隐式);FAT 占内存(显式)

### 6.2.3 索引分配(inode)

每个文件有**索引表**,记录所有数据块号。

**多级索引(Unix inode)**:

典型 inode 含 13 个指针:
- **10 个直接块指针**
- **1 个一级间接指针**
- **1 个二级间接指针**
- **1 个三级间接指针**

### 6.2.4 inode 最大文件大小完整计算

**给定**:块大小 4 KB,指针 4 B

**一级间接指针数** = 块大小 / 指针大小 = 4 KB / 4 B = **1024**

**计算**:

| 级别 | 指针数 | 容量 |
|------|--------|------|
| 直接(10) | 10 | 10 × 4 KB = **40 KB** |
| 一级间接(1) | 1024 | 1024 × 4 KB = **4 MB** |
| 二级间接(1) | 1024² | 1024² × 4 KB = **4 GB** |
| 三级间接(1) | 1024³ | 1024³ × 4 KB = **4 TB** |

**总最大** ≈ 40 KB + 4 MB + 4 GB + 4 TB ≈ **4 TB**

**例题**:块大小 1 KB,指针 4 B,inode 含 8 直接 + 1 一级 + 1 二级 + 1 三级:
- 一级指针数 = 1 KB / 4 B = 256
- 直接:8 × 1 KB = 8 KB
- 一级:256 × 1 KB = 256 KB
- 二级:256² × 1 KB = 64 MB
- 三级:256³ × 1 KB = 16 GB
- 总 ≈ 16 GB + 64 MB + 256 KB + 8 KB ≈ 16 GB

> **真题陷阱**:
> - 计算时注意**指针大小、块大小、各级指针数**
> - 一级间接指针数 = 块大小 / 指针大小

### 6.2.5 三种物理结构对比

| 结构 | 顺序访问 | 随机访问 | 碎片 | 增长 |
|------|----------|----------|------|------|
| 连续 | 最快 | 最快 | 外部 | 难 |
| 链接 | 快 | 慢 | 无 | 易 |
| 索引 | 快 | 快 | 无 | 易 |

## 6.3 目录

### 6.3.1 目录结构

| 类型 | 特点 | 缺点 |
|------|------|------|
| **单级** | 所有文件同一目录 | 命名冲突 |
| **两级** | 用户目录 + 主目录 | 不能分类 |
| **树形** | 层次结构,主流 | 共享难 |
| **无环图** | 允许共享子目录/文件 | 实现复杂 |

### 6.3.2 FCB(文件控制块)

**FCB** 内容:
- 文件名
- 文件类型
- 物理位置(首块号 / inode 号)
- 大小
- 创建/修改/访问时间
- 权限
- 属主

**目录本质**:目录是文件,其内容是该目录下所有文件的 **FCB**。

### 6.3.3 inode 与目录

- **目录项**:文件名 + inode 号
- **inode**:文件元数据 + 数据块指针
- 文件名 → inode 号 → inode → 数据块

```
目录项:| 文件名 | inode 号 |
              ↓
inode: | 元数据 | 直接块指针 | 间接指针 | ...
              ↓
           数据块
```

### 6.3.4 路径

- **绝对路径**:从根开始(`/home/user/file.txt`)
- **相对路径**:从当前目录开始(`./file.txt`)

### 6.3.5 目录查询

- **线性查找**:简单,慢
- **哈希查找**:快,但需处理冲突
- **B+ 树**:数据库、现代文件系统(ext4、NTFS)

## 6.4 文件存储空间管理

### 6.4.1 空闲表

类似内存动态分区,记录空闲区起始 + 长度。适合**连续分配**。

### 6.4.2 空闲链

- **空闲块链**:每块指向下一空闲块
- **空闲区链**:每区起始 + 长度

### 6.4.3 位示图

每位对应一个磁盘块,**1 占用,0 空闲**。

- 空间:$N$ 块需 $N/8$ 字节
- 适合大磁盘,易在内存中维护

**计算**:磁盘 1 TB,块 4 KB → 2²⁸ 块,位示图 = 2²⁸ / 8 = **32 MB**。

**位示图与块号换算**:
- 字长 w 位(通常 16 或 32)
- 块号 b 对应:字 i = b / w,位 j = b % w

### 6.4.4 成组链接法

**Unix 使用**。空闲块**分组**,每组的第一个块存本组块数 + 下一组首块指针。

```
空闲块栈(内存):
┌─────────────────┐
│ 当前组块数 n     │
│ 块号 1           │
│ 块号 2           │
│ ...              │
│ 块号 n           │ → 指向下一组首块(下一组的"组头")
└─────────────────┘
```

- 优点:空闲块信息占空间少
- 适合大文件系统
- 分配:从栈弹出块号,n--
- 回收:压入栈,n++;若栈满,把整组写入新释放的块

### 6.4.5 四种方法对比

| 方法 | 空间 | 速度 | 适用 |
|------|------|------|------|
| 空闲表 | 中 | 快 | 连续分配 |
| 空闲链 | 小 | 中 | 小磁盘 |
| 位示图 | 中 | 快 | 大磁盘 |
| 成组链接 | 小 | 中 | 大文件系统(Unix) |

## 6.5 文件共享与保护

### 6.5.1 硬链接

多个目录项指向**同一 inode**,共享同一文件。

- 删除一个链接,文件仍在(inode **引用计数** > 0)
- **不能跨文件系统**(因 inode 是文件系统内)
- `ln file link` 创建硬链接

```
目录项1: file → inode 123
目录项2: link → inode 123   ← 同一 inode

inode 123: 引用计数 = 2
```

### 6.5.2 符号链接(软链接)

**特殊文件**,内容是指向目标文件的**路径**。

- 删除原文件,符号链接**失效(悬空)**
- **可跨文件系统**
- 需额外 I/O 解析路径
- `ln -s file link` 创建符号链接

```
目录项: link → inode 456 (符号链接文件)

inode 456: 内容 = "/path/to/file"
```

### 6.5.3 硬链接 vs 软链接

| 维度 | 硬链接 | 软链接 |
|------|--------|--------|
| 共享对象 | inode | 路径 |
| 跨文件系统 | 否 | 是 |
| 删除原文件 | 不影响 | 悬空 |
| 引用计数 | 有 | 无 |
| I/O 开销 | 小 | 大(需解析路径) |
| 创建 | ln | ln -s |

### 6.5.4 文件保护

| 方法 | 说明 |
|------|------|
| **访问控制表 ACL** | 每个文件一个表,记录各用户权限 |
| **用户分类** | owner、group、others(Unix 9 位权限) |
| **口令** | 文件加密口令,简单但不安全 |
| **密码** | 文件内容加密 |

**Unix 权限**(9 位):
```
| owner | group | others |
| r w x | r w x | r w x  |
| 1 1 1 | 1 0 1 | 0 0 1  | = 751
```

## 6.6 真题精解

### 【2016 选择】inode 多级索引

**题目**:Unix inode,10 直接 + 1 一级 + 1 二级 + 1 三级,块 4 KB,指针 4 B,求最大文件大小。

**答案**:$10 \times 4\text{KB} + 1024 \times 4\text{KB} + 1024^2 \times 4\text{KB} + 1024^3 \times 4\text{KB}$ ≈ 4 TB

**解析**:见 6.2.4 节。

### 【2018 综合】FAT 表项位数

**题目**:磁盘 2³² 块,FAT 表项至少多少位?

**答案**:**32 位**

**解析**:FAT 表项位数 = log₂(磁盘块数) = log₂(2³²) = 32 位。

### 【2020 选择】硬链接 vs 软链接

**题目**:关于硬链接,下列正确的是?

A. 可跨文件系统
B. 删除原文件后链接悬空
C. 多个目录项共享同一 inode
D. 创建硬链接用 ln -s

**答案**:**C**

**解析**:
- 硬链接不能跨文件系统(A 错)
- 硬链接删除原文件不影响(引用计数 > 0)(B 错)
- 硬链接共享 inode(C 对)
- `ln -s` 创建软链接(D 错)

### 【2022 选择】位示图空间

**题目**:磁盘 1 TB,块 4 KB,位示图需多少空间?

A. 8 MB  B. 16 MB  C. 32 MB  D. 64 MB

**答案**:**C**

**解析**:
- 块数 = 1 TB / 4 KB = 2⁴⁰ / 2¹² = 2²⁸
- 位示图 = 2²⁸ / 8 = 2²⁵ = 32 MB

### 【2024 综合】文件系统设计

**题目**:设计文件系统,给定块大小、inode 结构,计算最大文件大小和位示图空间。

**答**:综合 6.2.4 和 6.4.3 计算。

## 6.7 真题陷阱(15 条)

1. **FAT 表项位数** = log₂(磁盘块数)
2. **inode 多级索引**:直接 + 一级 + 二级 + 三级,需逐级算最大
3. **一级间接指针数** = 块大小 / 指针大小
4. **硬链接共享 inode**:引用计数
5. **软链接是路径**:可跨文件系统,但悬空风险
6. **位示图空间** = 块数 / 8 字节
7. **链接分配随机访问慢**:需遍历链(隐式)
8. **连续分配有外部碎片**:文件增长困难
9. **FCB 是目录项**:目录是文件,内容是 FCB 集合
10. **成组链接法**:Unix 空闲块管理
11. **open 操作**:把 FCB 读入打开文件表
12. **inode 不含文件名**:文件名在目录项
13. **硬链接不能跨文件系统**:inode 是文件系统内
14. **软链接需额外 I/O**:解析路径
15. **Unix 9 位权限**:owner/group/others 各 rwx

## 6.11 延伸知识

### 6.11.1 ext4 文件系统

- ** extents**:连续块范围,替代传统间接块
- **日志**(JBD2):元数据日志,崩溃恢复
- **延迟分配**:写数据时不立即分配块
- **在线碎片整理**

### 6.11.2 NTFS

- **MFT**(Master File Table):文件系统元数据
- **ADS**(Alternate Data Streams):隐藏数据流
- **日志**:$LogFile
- **压缩 / 加密**:内建支持

### 6.11.3 ZFS / Btrfs

- **写时复制**(CoW):修改不覆盖原数据
- **快照**: instantaneous snapshot
- **数据完整性**:校验和
- **池化存储**:多磁盘组合

### 6.11.4 网络文件系统

- **NFS**(Unix):Sun RPC,无状态
- **SMB/CIFS**(Windows):有状态
- **分布式文件系统**:HDFS、Ceph、GlusterFS

### 6.11.5 文件锁

- **共享锁**(读锁):多个进程可同时持
- **排他锁**(写锁):独占
- **fcntl / flock**:Unix 文件锁接口

## 6.12 本章习题

1. 文件的三种物理结构及特点?
2. Unix inode(10 直接 + 1 一级 + 1 二级 + 1 三级),块 4 KB,指针 4 B,求最大文件大小。
3. FAT 表项位数如何确定?磁盘 2²⁰ 块需多少位?
4. 硬链接和软链接的区别?
5. 位示图管理磁盘空间,磁盘 1 TB,块 4 KB,求位示图大小。
6. 成组链接法的工作原理?
7. 简述 open 操作的执行过程。

### 习题答案

1. 见 6.8.1 表。连续分配:外部碎片,随机快;链接分配:无碎片,随机慢;索引分配:无碎片,随机快。

2. 见 6.2.4 节。最大 ≈ 40 KB + 4 MB + 4 GB + 4 TB ≈ 4 TB。

3. FAT 表项位数 = log₂(磁盘块数)。2²⁰ 块需 20 位。

4. 见 6.8.2 表。硬链接共享 inode,引用计数,不跨文件系统,删除原文件不影响;软链接是路径文件,可跨文件系统,删除原文件悬空,I/O 开销大。

5. 块数 = 1 TB / 4 KB = 2²⁸。位示图 = 2²⁸ / 8 = 32 MB。

6. 见 6.4.4 节。空闲块分组,每组首块存本组块数 + 下一组首块指针。内存维护空闲块栈,分配从栈弹,回收压栈,栈满则整组写入新释放块。

7. 见 6.1.2 节。open 把 FCB 读入内存打开文件表,返回 fd。后续 read/write 通过 fd 直接访问,无需重新查目录。
