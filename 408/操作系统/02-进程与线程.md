## 2.1 进程概念

### 2.1.1 定义

**进程**(Process):程序在数据集合上的一次执行过程,是系统**资源分配和保护的基本单位**。

**程序 vs 进程**:

| 维度 | 程序 | 进程 |
|------|------|------|
| 性质 | 静态 | 动态 |
| 存在 | 磁盘 | 内存 |
| 资源 | 无 | 有 PCB、地址空间 |
| 生命 | 永久 | 临时(创建-终止) |
| 多个 | 同一程序可对应多个进程 | 唯一 |

### 2.1.2 PCB(Process Control Block)

**PCB**:进程存在的**唯一标志**,操作系统通过 PCB 管理进程。

**内容(四大类)**:

| 类别 | 内容 |
|------|------|
| **进程标识信息** | PID、父进程 PID、用户 ID、组 ID |
| **处理机状态** | 通用寄存器、PC、PSW、栈指针 |
| **进程调度信息** | 状态、优先级、调度策略、等待事件、时间片 |
| **进程控制信息** | 代码/数据/堆栈指针、文件描述符表、信号量、资源列表 |

**PCB 组织方式**:
- **线性方式**:所有 PCB 在一张线性表
- **链接方式**:按状态分队列(就绪队列、阻塞队列等)
- **索引方式**:按状态建索引表

### 2.1.3 进程映像

```
进程 = 程序代码 + 数据 + PCB + 堆栈
```

```
┌────────────────────┐ 高地址
│   栈 stack (向下)   │  ← 局部变量、函数调用
├────────────────────┤
│   ↓                 │
│   空闲              │
│   ↑                 │
├────────────────────┤
│   堆 heap (向上)    │  ← 动态分配
├────────────────────┤
│   数据段 data       │  ← 全局变量
├────────────────────┤
│   代码段 text       │  ← 程序指令
└────────────────────┘ 低地址
```

## 2.2 进程状态与转换

### 2.2.1 三态模型

- **就绪**(Ready):具备运行条件,等 CPU
- **运行**(Running):占用 CPU
- **阻塞**(Blocked/Wait):等某事件(I/O、信号量)

```
        时间片到/被抢占
        ┌──────────┐
        ▼          │
     ┌─────┐  调度  ┌─────┐
     │就绪 │ ─────→ │运行 │
     └─────┘        └─────┘
        ▲             │
        │  I/O完成    │ I/O请求
        │  唤醒       ▼
        │  ┌────────┐
        └──│ 阻塞   │
           └────────┘
```

**关键转换**:

| 转换 | 触发 |
|------|------|
| 就绪 → 运行 | 调度(选中) |
| 运行 → 就绪 | 时间片到 / 被抢占 |
| 运行 → 阻塞 | I/O 请求、等信号量(主动) |
| 阻塞 → 就绪 | 事件完成(I/O 完成、信号量释放) |

**禁止转换**:
- **阻塞 → 运行**:即使 CPU 空闲,阻塞进程也必须**先就绪**(不能直接跳过就绪)
- **就绪 → 阻塞**:就绪进程不执行,无法请求 I/O

### 2.2.2 五态模型

加入创建和终止:

```
创建 → 就绪 ↔ 运行 → 终止
              ↓ ↑
             阻塞
```

- **创建**(New):正在分配 PCB、资源
- **终止**(Terminated):已结束,PCB 待回收(父进程 wait 后回收)

### 2.2.3 七态模型(高级)

加入挂起状态(进程被换出到磁盘):

```
            挂起             激活
就绪 ←────────────→ 就绪挂起
  ↕                    ↕
运行                  阻塞挂起
  ↓                    ↑
阻塞 ←────────────→ 阻塞挂起
            挂起             激活
```

- **就绪挂起**(Ready Suspend):就绪进程被换出到磁盘,激活后才能调度
- **阻塞挂起**(Blocked Suspend):阻塞进程被换出,事件完成后转为就绪挂起

**挂起原因**:内存不足、用户请求、系统检查

## 2.3 进程控制

### 2.3.1 创建(Create)

**原语 create()**:
1. 申请空白 PCB
2. 分配资源(内存、文件、I/O)
3. 初始化 PCB(标识、状态=就绪、PC=程序入口、栈)
4. PCB 加入就绪队列

**引发创建的事件**:
- 用户登录(终端登录)
- 作业调度(批处理)
- 服务请求(用户请求服务)
- 应用请求(进程 fork 新进程)

### 2.3.2 终止(Terminate)

**原语 terminate()**:
1. 检索 PCB
2. 终止所有子进程(避免孤儿)
3. 回收资源(内存、文件、I/O)
4. PCB 从队列移除(等父进程 wait 后彻底回收)

**引发终止**:
- 正常结束(exit)
- 异常(除零、越界、非法指令)
- 外界干预(kill、撤销)

### 2.3.3 阻塞与唤醒

**阻塞 block()**:运行态 → 阻塞态。进程**主动**调用。
- 流程:保存现场 → 改 PCB 状态为阻塞 → 加入阻塞队列 → 调度器选下一个

**唤醒 wakeup()**:阻塞态 → 就绪态。由**其他进程**调用。
- 流程:从阻塞队列移除 → 改 PCB 状态为就绪 → 加入就绪队列

> **配对原则**:阻塞和唤醒必须**成对出现**,否则进程永久挂起。

### 2.3.4 切换(Switch)

**进程切换 = 保存当前进程现场 + 恢复下一进程现场**。

**上下文切换开销**:
- **直接开销**:保存/恢复寄存器、PCB 更新、TLB 刷新
- **间接开销**:Cache 失效(冷启动)、分支预测器失效

**减少切换开销**:
- 寄存器窗口(SPARC)
- 上下文标识(PCID,避免 TLB 刷新)
- 内核态线程切换(同进程线程切换不需切页表)

## 2.4 线程

### 2.4.1 引入

**线程**(Thread):进程内的执行单元,是 **CPU 调度的基本单位**。进程退化为**资源分配单位**。

```
传统进程:资源 + 调度 单位
线程引入后:
  进程 = 资源分配单位
  线程 = CPU 调度单位
```

### 2.4.2 线程 vs 进程

| 对比项 | 进程 | 线程 |
|--------|------|------|
| 资源 | 资源分配单位 | 不拥有资源,共享进程资源 |
| 调度 | 跨进程切换开销大 | 同进程内线程切换开销小 |
| 地址空间 | 独立 | 共享 |
| 通信 | 需 IPC | 直接共享内存 |
| 崩溃影响 | 一个进程崩溃不影响其他 | 一个线程崩溃整个进程崩溃 |
| 系统调用 | 阻塞自己 | 用户级阻塞整个进程,内核级阻塞单个 |

### 2.4.3 用户级 vs 内核级

| 对比项 | 用户级线程 | 内核级线程 |
|--------|------------|------------|
| 管理 | 用户库(pthreads 早期) | 内核 |
| 调度 | 用户态调度器 | 内核调度 |
| 阻塞 | 整个进程阻塞 | 单个线程阻塞 |
| 并行 | 单 CPU 内并发,**不能并行** | 多 CPU 可并行 |
| 系统调用 | 阻塞整个进程 | 阻塞单个线程 |
| 切换开销 | 小(用户态) | 大(陷入内核) |

### 2.4.4 多线程模型

- **一对一**:每个用户线程对应一个内核线程(Windows、Linux NPTL)
- **多对一**:多个用户线程映射到一个内核线程(早期 Solaris)
- **多对多**:用户线程数可多于内核线程数(Solaris 旧版)

### 2.4.5 线程控制

- **创建**:pthread_create / clone
- **终止**:pthread_exit / 退出
- **同步**:pthread_join / mutex / cond
- **线程库**:pthreads(POSIX)、Win32 threads、Java threads

## 2.5 进程通信

### 2.5.1 共享存储(Shared Memory)

- 多个进程映射同一物理内存区域
- **最快 IPC**(直接内存访问)
- 需配合同步机制(信号量)保证互斥

**两种形式**:
- **共享数据结构**(低级):少量数据,需互斥
- **共享内存区**(高级):大块数据,fastest

### 2.5.2 消息传递(Message Passing)

以格式化消息为单位交换数据。

- **直接通信**:Send(P, msg)、Receive(Q, msg),指定对方
- **间接通信**:通过信箱(mailbox),解耦

**消息结构**:
```
┌─────────────────────────┐
│ 消息头                   │
│ (发送者/接收者/类型/长度) │
├─────────────────────────┤
│ 消息体                   │
└─────────────────────────┘
```

**两种实现**:
- **同步(阻塞)**:发送方等接收方收到才返回
- **异步(非阻塞)**:发送方发完立即返回,消息存队列

### 2.5.3 管道(Pipe)

连接两个进程的 FIFO 队列。

- **匿名管道**:父子进程间,半双工
- **命名管道**(FIFO):任意进程间,半双工或全双工

**管道本质**:固定大小缓冲区(如 4 KB),写满则写阻塞,读空则读阻塞。

```
写端 ──→ [缓冲区 4KB] ──→ 读端
       写满阻塞       读空阻塞
```

### 2.5.4 信号(Signal)

异步通知机制。

| 信号 | 含义 |
|------|------|
| SIGINT | 中断(Ctrl+C) |
| SIGKILL | 强制终止(不可捕获) |
| SIGTERM | 终止(可捕获) |
| SIGCHLD | 子进程状态变化 |
| SIGSEGV | 段错误 |

### 2.5.5 套接字(Socket)

跨网络通信。可用于本地(Unix Socket)或跨网络(TCP/UDP)。

### 2.5.6 五种通信方式对比

| 方式 | 数据量 | 同步 | 适用 |
|------|--------|------|------|
| 共享存储 | 大 | 需信号量 | 同机,大数据 |
| 消息传递 | 中 | 自带 | 同机/异机 |
| 管道 | 中 | 自带 | 父子进程 |
| 信号 | 小 | 异步 | 通知 |
| 套接字 | 大 | 自带 | 跨网络 |

## 2.6 调度

### 2.6.1 三级调度

| 层级 | 对象 | 频率 | 作用 |
|------|------|------|------|
| **高级**(作业调度) | 作业 | 分钟级 | 选作业进内存 |
| **中级**(内存调度) | 进程(内外存交换) | 秒级 | 决定驻留 / 换出 |
| **低级**(进程调度) | 进程(CPU 分配) | 毫秒级 | 选进程上 CPU |

### 2.6.2 调度时机

**主动放弃**(非抢占式也可触发调度):
- 进程阻塞(I/O 请求、等信号量)
- 进程结束
- 进程主动 yield

**被动放弃**(仅抢占式可触发):
- 时间片到
- 更高优先级进程到达
- 中断返回(更高优先级就绪)

### 2.6.3 评价指标

| 指标 | 公式 | 适用 |
|------|------|------|
| **CPU 利用率** | CPU 忙时间 / 总时间 | 通用 |
| **吞吐量** | 单位时间完成进程数 | 批处理 |
| **周转时间** | 完成 - 提交 | 批处理 |
| **平均周转时间** | Σ 周转 / n | 批处理 |
| **带权周转时间** | 周转 / 服务时间 ≥ 1 | 批处理 |
| **等待时间** | 在就绪队列中等待的总时间 | 通用 |
| **响应时间** | 首次响应 - 提交 | 交互 |

## 2.7 调度算法

### 2.7.1 FCFS(先来先服务)

按**到达顺序**服务。

- 优点:简单,公平
- 缺点:**短作业被长作业拖累**(护航效应)
- 非抢占式
- 适用:作业调度、批处理

### 2.7.2 SJF(短作业优先)

选**服务时间最短**的。

- 优点:**平均等待时间最短**
- 缺点:长作业**饥饿**;服务时间需预知
- 非抢占式(SJF)或抢占式(**SRTF**,最短剩余时间优先)

**SRTF 抢占式 SJF**:新进程到达时,若其剩余时间 < 当前运行进程剩余时间,则抢占。

### 2.7.3 优先级调度

选**优先级最高**者。

- **静态优先级**:创建时确定,不变 → 可能饥饿
- **动态优先级**:随等待时间增加优先级 → 避免饥饿
- 可抢占或非抢占

### 2.7.4 HRRN(高响应比优先)

$$R = \frac{\text{等待时间} + \text{服务时间}}{\text{服务时间}} = 1 + \frac{\text{等待时间}}{\text{服务时间}}$$

选 R 最高者。

- 等待越久 R 越高(避免饥饿)
- 服务越短 R 越高(短作业偏好)
- **非抢占式**
- 综合 FCFS 与 SJF

### 2.7.5 RR(时间片轮转)

**时间片 q** 到期则切换。

- q 大 → FCFS;q 小 → 切换频繁,开销大
- 适合分时系统
- 抢占式

> **真题陷阱**:q 太小,上下文切换开销主导,性能下降。通常 q = 10~100 ms。

### 2.7.6 多级反馈队列(MLFQ)

多个就绪队列,优先级递减,时间片递增。

```
队列 1: q = 2  (最高优先级)
队列 2: q = 4
队列 3: q = 8
...
队列 N: RR    (最低优先级)
```

**规则**:
1. 新进程进队列 1(最高优先级,q 最小)
2. 用完时间片未完成,降级到队列 2
3. 队列 1 空才调度队列 2,以此类推
4. 最低队列用 RR

**优点**:
- 短作业优先完成(在队列 1 就完成)
- 长作业不会饥饿(会降级但不会饿死)
- 响应快(新进队列 1 立即响应)
- I/O 密集型优先(用不完时间片就阻塞,不降级)

**目前公认较好的通用调度算法**。

### 2.7.7 完整例题

**【例 1】FCFS / SJF / SRTF 比较**

四个进程:

| 进程 | 到达 | 服务 |
|------|------|------|
| P1 | 0 | 8 |
| P2 | 1 | 4 |
| P3 | 2 | 9 |
| P4 | 3 | 5 |

**FCFS 顺序**:P1, P2, P3, P4

| 进程 | 开始 | 完成 | 周转 | 等待 |
|------|------|------|------|------|
| P1 | 0 | 8 | 8 | 0 |
| P2 | 8 | 12 | 11 | 7 |
| P3 | 12 | 21 | 19 | 10 |
| P4 | 21 | 26 | 23 | 18 |

平均周转 = (8+11+19+23)/4 = 15.25
平均等待 = (0+7+10+18)/4 = 8.75

**SJF(非抢占)**:
- t=0:P1 开始(P1 是唯一就绪)
- t=8:就绪 P2, P3, P4,选最短 P2(4)
- t=12:就绪 P3, P4,选最短 P4(5)
- t=17:执行 P3(9)
- t=26:全部完成

| 进程 | 开始 | 完成 | 周转 | 等待 |
|------|------|------|------|------|
| P1 | 0 | 8 | 8 | 0 |
| P2 | 8 | 12 | 11 | 7 |
| P4 | 12 | 17 | 14 | 9 |
| P3 | 17 | 26 | 24 | 15 |

平均周转 = (8+11+14+24)/4 = 14.25
平均等待 = (0+7+9+15)/4 = 7.75

**SRTF(抢占)**:
- t=0:P1 开始(剩余 8)
- t=1:P2 到达,剩余 4 < 8,抢占 P1
- t=5:P2 完成,就绪 P1(7), P3(9), P4(5),选 P1
- ...

(具体推演略,SRTF 平均周转时间最短)

### 2.7.8 算法对比表

| 算法 | 抢占 | 饥饿 | 适用 | 优点 | 缺点 |
|------|------|------|------|------|------|
| FCFS | 否 | 否 | 批处理 | 简单公平 | 护航效应 |
| SJF | 否/是 | 是 | 短作业 | 平均等待最短 | 长作业饥饿 |
| 优先级 | 否/是 | 静态会 | 通用 | 灵活 | 静态饥饿 |
| HRRN | 否 | 否 | 综合 | 平衡 | 计算开销 |
| RR | 是 | 否 | 分时 | 响应快 | 切换开销 |
| 多级反馈 | 是 | 否 | 通用 | 综合最优 | 复杂 |

## 2.8 真题精解

### 【2016 选择】进程状态转换

**题目**:下列进程状态转换中,不可能的是?

A. 就绪 → 运行  B. 运行 → 就绪
C. 运行 → 阻塞  D. 阻塞 → 运行

**答案**:**D**

**解析**:阻塞 → 运行 不允许,必须先 阻塞 → 就绪 → 运行。

### 【2017 综合】HRRN 调度计算

**题目**:四个进程,到达时间和服务时间:

| 进程 | 到达 | 服务 |
|------|------|------|
| P1 | 0 | 10 |
| P2 | 1 | 5 |
| P3 | 2 | 3 |
| P4 | 3 | 8 |

用 HRRN 调度,计算平均周转时间。

**解**:
- t=0:仅 P1 就绪,执行 P1
- t=10:P1 完成,就绪 P2, P3, P4
  - P2:R = (10-1+5)/5 = 14/5 = 2.8
  - P3:R = (10-2+3)/3 = 11/3 ≈ 3.67
  - P4:R = (10-3+8)/8 = 15/8 = 1.875
  - 选 R 最大的 P3
- t=13:P3 完成
  - P2:R = (13-1+5)/5 = 17/5 = 3.4
  - P4:R = (13-3+8)/8 = 18/8 = 2.25
  - 选 P2
- t=18:P2 完成,执行 P4
- t=26:P4 完成

| 进程 | 完成 | 周转 |
|------|------|------|
| P1 | 10 | 10 |
| P3 | 13 | 11 |
| P2 | 18 | 17 |
| P4 | 26 | 23 |

平均周转 = (10+11+17+23)/4 = 15.25

### 【2019 选择】线程与进程区别

**题目**:下列关于线程的描述,正确的是?

A. 线程是资源分配的基本单位
B. 线程是 CPU 调度的基本单位
C. 同进程内线程切换需要切换页表
D. 线程间通信必须用 IPC

**答案**:**B**

**解析**:
- 进程是资源分配单位,线程是 CPU 调度单位(A 错 B 对)
- 同进程内线程共享地址空间,不需切换页表(C 错)
- 线程间通信直接共享内存,不需 IPC(D 错)

### 【2020 选择】用户级线程阻塞

**题目**:用户级线程执行系统调用时,会发生?

A. 仅该线程阻塞
B. 整个进程阻塞
C. CPU 切换到其他进程
D. 系统调用立即返回

**答案**:**B**

**解析**:用户级线程对内核不可见,内核看到的是进程。系统调用阻塞 → 整个进程阻塞,所有用户级线程都不能执行。

### 【2022 综合】多级反馈队列

**题目**:三级反馈队列,q1=2, q2=4, q3=RR。进程 P1, P2, P3 都在 t=0 到达,服务时间分别 3, 6, 5。给出调度顺序。

**解**:
- t=0-2:P1 在队列 1 用 2,未完成,降级到队列 2
- t=2-4:P2 在队列 1 用 2,未完成,降级到队列 2
- t=4-6:P3 在队列 1 用 2,未完成,降级到队列 2
- t=6-8:P1 在队列 2 用 2(剩 1),未完成,降级到队列 3
- t=8-12:P2 在队列 2 用 4(剩 2),未完成,降级到队列 3
- t=12-16:P3 在队列 2 用 4(剩 1),未完成,降级到队列 3
- t=16-:三个都在队列 3,RR 完成

(具体顺序依实现,核心是降级机制)

## 2.9 真题陷阱(15 条)

1. **进程 vs 程序**:进程动态,程序静态
2. **PCB 是进程唯一标志**:不是程序,不是代码
3. **五态转换**:阻塞**不能**直接到运行
4. **就绪 → 阻塞 不允许**:就绪进程不执行,无法请求 I/O
5. **线程是 CPU 调度单位**:进程是资源分配单位
6. **用户级线程**:单进程内并发,不能多核并行;系统调用阻塞整个进程
7. **内核级线程**:多核可并行;系统调用阻塞单个线程
8. **管道**:半双工,固定缓冲,写满阻塞
9. **SJF 平均等待最短**:但可能饥饿长作业
10. **SRTF 是抢占式 SJF**:新进程剩余短则抢占
11. **HRRN 公式**:R = 1 + 等待/服务,非抢占
12. **RR 时间片**:太小切换开销大,太大变 FCFS
13. **多级反馈队列**:综合最优,适应性好
14. **进程切换开销**:直接(寄存器)+ 间接(Cache 失效)
15. **挂起状态**:进程被换出到磁盘(七态)

## 2.13 延伸知识

### 2.13.1 Linux 进程管理

- `task_struct`(PCB):几百字节,包含进程所有信息
- `clone()` 系统调用:创建线程(Linux 线程 = 共享地址空间的进程)
- CFS 调度器(完全公平调度):基于红黑树,虚拟运行时间

### 2.13.2 Linux 进程状态

- R(Running)、S(Sleep)、D(Disk sleep)、T(Stopped)、Z(Zombie)
- D 状态(不可中断睡眠):等 I/O,不能被信号中断
- Z 状态(僵尸):已退出但父进程未 wait

### 2.13.3 Windows 进程管理

- EPROCESS(内核进程对象)+ PEB(进程环境块)
- 纤程(Fiber):用户级线程,比线程更轻
- 作业(Job):进程组,资源限制

### 2.13.4 协程(Coroutine)

- 用户态轻量级"线程"
- 主动让出(yield)而非抢占
- 例:Go goroutine、Python async/await、Lua coroutine
- 优点:切换开销极小,单线程内并发

## 2.14 本章习题

1. 进程的五个状态及转换条件是什么?哪些转换不允许?
2. PCB 包含哪些内容?为什么 PCB 是进程唯一标志?
3. 简述进程与线程的区别。
4. 用户级线程和内核级线程的区别?系统调用时分别发生什么?
5. 进程通信的五种方式及特点?
6. 比较 FCFS、SJF、HRRN、RR 四种调度算法的优缺点。
7. 给定四个进程(P1-P4,到达 0/1/2/3,服务 8/4/9/5),用 SJF 计算平均周转时间。

### 习题答案

1. **五态**:创建 → 就绪 ↔ 运行 → 终止,运行 ↔ 阻塞。**不允许**:阻塞 → 运行(必须先就绪);就绪 → 阻塞(就绪进程不执行)。

2. **PCB 内容**:进程标识、处理机状态、调度信息、控制信息。**唯一标志**:进程存在与否看 PCB 是否存在,OS 通过 PCB 管理进程,无 PCB 则进程不存在。

3. 进程是资源分配单位,线程是 CPU 调度单位。线程共享进程资源,切换开销小,通信直接共享内存,但一个线程崩溃整个进程崩溃。

4. **用户级线程**:用户库管理,系统调用阻塞整个进程,单 CPU 内并发不能并行。**内核级线程**:内核管理,系统调用阻塞单个线程,多核可并行。

5. 共享存储(最快,需信号量)、消息传递(直接/间接)、管道(半双工,固定缓冲)、信号(异步通知)、套接字(跨网络)。

6. **FCFS**:简单公平,但护航效应。**SJF**:平均等待最短,但长作业饥饿。**HRRN**:综合 FCFS 和 SJF,不饥饿,但计算开销大。**RR**:响应快,但切换开销大。

7. SJF 顺序:P1(0-8)→P2(8-12)→P4(12-17)→P3(17-26)。周转:P1=8, P2=11, P4=14, P3=24。平均 = 14.25。
