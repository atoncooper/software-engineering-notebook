## 4.1 概念

### 4.1.1 死锁

**死锁**(Deadlock):多个进程因竞争资源而造成的一种僵局,若无外力干预,所有进程都永远无法推进。

### 4.1.2 饥饿

**饥饿**(Starvation):进程长期得不到资源,无法执行(但不是死锁,因资源可能释放给其他进程)。

### 4.1.3 活锁

**活锁**(Livelock):进程不断改变状态,但无法前进(像两人让路,同向避让)。

### 4.1.4 死锁 vs 饥饿 vs 活锁

| 项 | 死锁 | 饥饿 | 活锁 |
|----|------|------|------|
| 原因 | 资源竞争 + 环路等待 | 调度策略偏向 | 互相避让 |
| 状态 | 全部阻塞 | 长期等待 | 不断变化 |
| 解除 | 必须外力 | 可能自解 | 可能自解 |
| 进展 | 完全停滞 | 偶尔进展 | 完全停滞 |
| 必要条件 | 四条件 | 无特定条件 | 无特定条件 |

---

## 4.2 四必要条件(必背)

死锁发生的**四个必要条件**(全部满足才会死锁):

1. **互斥**(Mutual Exclusion):资源一次只能被一个进程使用
2. **请求保持**(Hold and Wait):进程持有资源并申请新资源
3. **不剥夺**(No Preemption):资源不能被强制剥夺
4. **循环等待**(Circular Wait):存在进程-资源的循环等待链

> **必要条件**:四条**全部**满足才会死锁,破坏任意一条即可预防。

```
       互斥  ──→  请求保持  ──→  循环等待
                      ↓
                   不剥夺
                      
   四条件全满足 → 死锁
   破坏任一 → 预防死锁
```

---

## 4.3 处理策略

| 策略 | 时机 | 代价 | 代表 |
|------|------|------|------|
| **预防** | 事前破坏四条件 | 资源利用率低 | 资源顺序编号 |
| **避免** | 分配前判断安全性(银行家) | 计算开销大 | 银行家算法 |
| **检测与解除** | 死锁后检测 | 需中止进程 | 资源分配图 |
| **鸵鸟** | 忽略,概率低 | 死锁则重启 | Unix/Linux |

**严格性**:预防 > 避免 > 检测 > 鸵鸟
**资源利用率**:鸵鸟 > 检测 > 避免 > 预防

## 4.4 预防

破坏四条件:

| 条件 | 破坏方法 | 缺点 |
|------|----------|------|
| **互斥** | 共享(SPOOLing 技术) | 部分资源不可共享(如磁带机) |
| **请求保持** | 一次性申请全部资源 | 利用率低 |
| **不剥夺** | 申请不到则释放已持有 | 复杂,适合易保存资源 |
| **循环等待** | 资源顺序编号,按序申请 | 限制多,编号困难 |

### 4.4.1 破坏互斥

- **SPOOLing 技术**:把独占设备改为共享设备(打印机虚拟化)
- 例:打印机本互斥,SPOOLing 把打印请求缓存到磁盘,多进程可同时"打印"
- **限制**:部分资源本质不可共享(磁带机、卡片机)

### 4.4.2 破坏请求保持

- **一次性申请**:进程开始前申请所有资源
- 优点:简单
- 缺点:
  - 资源利用率低(可能长期占用但不使用)
  - 可能饥饿(资源不足时一直等)

### 4.4.3 破坏不剥夺

- 申请不到新资源时,**释放已持有资源**
- 适合易保存资源(CPU、内存)
- 不适合难保存资源(打印机、磁带)

### 4.4.4 破坏循环等待(资源顺序编号)

- 所有资源**顺序编号**(R1 < R2 < ... < Rn)
- 进程只能申请**比已持有更大编号**的资源
- 释放时按递减顺序

**例**:资源 R1(printer)、R2(tape)、R3(disk)
- 进程若已持有 R2,只能申请 R3,不能申请 R1
- 避免循环

**缺点**:
- 编号困难(新增资源需重新编号)
- 限制多(可能需先释放再申请)

## 4.5 避免(银行家算法)

### 4.5.1 数据结构

设 n 个进程,m 种资源:

- **Available[m]**:各类资源**可用**数
- **Max[n][m]**:进程 i 对资源 j 的**最大需求**
- **Allocation[n][m]**:进程 i **已分配**资源 j 数
- **Need[n][m]**:进程 i **还需**资源 j 数 = Max - Allocation
- **Request[n][m]**:本次请求

> **必背公式**:**Need = Max - Allocation**

### 4.5.2 安全性算法

```
1. Work = Available; Finish[i] = false for all i
2. 找一个 i 使 Finish[i]==false 且 Need[i] <= Work
3. 若找到:
     Work += Allocation[i]
     Finish[i] = true
     转 2
4. 若所有 Finish == true,则安全(存在安全序列);否则不安全
```

**安全序列**:能找到使所有进程完成的执行顺序。安全序列不唯一。

### 4.5.3 银行家算法流程

进程 $P_i$ 请求资源 Request[i]:

```
1. 若 Request[i] > Need[i]:出错(请求超过最大需求)
2. 若 Request[i] > Available:等待(资源不足)
3. 试探分配:
   Available -= Request[i]
   Allocation[i] += Request[i]
   Need[i] -= Request[i]
4. 执行安全性算法:
   - 安全:正式分配
   - 不安全:回滚,进程等待
```

### 4.5.4 安全状态

- **安全状态**:存在安全序列,**不会死锁**
- **不安全状态**:**可能**死锁(但不一定死锁)

> **关键三句话**:
> - 安全状态一定**不**死锁
> - 不安全状态**不一定**死锁
> - 死锁一定在不安全状态

```
┌────────────────────────────────┐
│           所有状态              │
│  ┌──────────────────────┐      │
│  │   不安全状态          │      │
│  │  ┌──────────────┐    │      │
│  │  │  死锁状态     │    │      │
│  │  └──────────────┘    │      │
│  └──────────────────────┘      │
│                                 │
│  (安全状态 = 不安全状态之外)   │
└────────────────────────────────┘
```

### 4.5.5 完整例题

**【例 1】安全性判断**

5 个进程 P0-P4,3 种资源 A/B/C,Available = (10, 5, 7):

| 进程 | Max(A,B,C) | Allocation(A,B,C) | Need(A,B,C) |
|------|-----------|-------------------|-------------|
| P0 | (7,5,3) | (0,1,0) | (7,4,3) |
| P1 | (3,2,2) | (2,0,0) | (1,2,2) |
| P2 | (9,0,2) | (3,0,2) | (6,0,0) |
| P3 | (2,2,2) | (2,1,1) | (0,1,1) |
| P4 | (4,3,3) | (0,0,2) | (4,3,1) |

总分配 = (7, 2, 5),Available = (10-7, 5-2, 7-5) = (3, 3, 2)

**安全性算法**:
- Work = (3, 3, 2),Finish = [F, F, F, F, F]
- 找 Need ≤ Work:
  - P1.Need=(1,2,2) ≤ (3,3,2) ✓
  - Work += Allocation[P1] = (3+2, 3+0, 2+0) = (5, 3, 2);Finish[P1]=T
- 找下一个:
  - P3.Need=(0,1,1) ≤ (5,3,2) ✓
  - Work += (2,1,1) = (7, 4, 3);Finish[P3]=T
- 找下一个:
  - P0.Need=(7,4,3) ≤ (7,4,3) ✓
  - Work += (0,1,0) = (7, 5, 3);Finish[P0]=T
- 找下一个:
  - P2.Need=(6,0,0) ≤ (7,5,3) ✓
  - Work += (3,0,2) = (10, 5, 5);Finish[P2]=T
- 找下一个:
  - P4.Need=(4,3,1) ≤ (10,5,5) ✓
  - Work += (0,0,2) = (10, 5, 7);Finish[P4]=T

**安全序列**:< P1, P3, P0, P2, P4 >,系统安全。

### 4.5.6 银行家算法请求处理例题

**【例 2】** 接上例,P1 请求 Request[1] = (1, 0, 2)。

**步骤 1**:Request[1] = (1,0,2) ≤ Need[1] = (1,2,2) ✓
**步骤 2**:Request[1] = (1,0,2) ≤ Available = (3,3,2) ✓
**步骤 3**:试探分配:
- Available = (3-1, 3-0, 2-2) = (2, 3, 0)
- Allocation[1] = (2+1, 0+0, 0+2) = (3, 0, 2)
- Need[1] = (1-1, 2-0, 2-2) = (0, 2, 0)

**步骤 4**:安全性检查:
- Work = (2, 3, 0)
- P1.Need=(0,2,0) ≤ (2,3,0) ✓ → Work += (3,0,2) = (5, 3, 2)
- P3.Need=(0,1,1) ≤ (5,3,2) ✓ → Work += (2,1,1) = (7, 4, 3)
- P0.Need=(7,4,3) ≤ (7,4,3) ✓ → Work += (0,1,0) = (7, 5, 3)
- P2.Need=(6,0,0) ≤ (7,5,3) ✓ → Work += (3,0,2) = (10, 5, 5)
- P4.Need=(4,3,1) ≤ (10,5,5) ✓ → Work += (0,0,2) = (10, 5, 7)

**安全序列**:< P1, P3, P0, P2, P4 >,系统安全,正式分配。

## 4.6 检测与解除

### 4.6.1 资源分配图

- **顶点**:进程 P、资源 R
- **边**:
  - **申请边** P → R:进程申请资源
  - **分配边** R → P:资源分配给进程
- 资源 R 中方格数 = 实例数,分配边从方格指向进程

```
   ┌─□─□─□─R1     (3 个实例)
   │  │
   ↓  ↓
   P1 P2
   ↑
   │
   R2
```

### 4.6.2 死锁定理

**化简资源分配图**:

1. 找不孤立的进程 P,其**所有申请都能满足**(申请边数 ≤ 资源可用数)
2. 删去 P 的所有边(申请 + 分配),P 变孤立
3. 重复,直到无法化简
4. **若能完全化简(无剩余边),无死锁;否则有死锁**

### 4.6.3 解除方法

| 方法 | 说明 |
|------|------|
| **资源剥夺** | 挂起部分进程,剥夺资源给其他进程 |
| **撤销进程** | 强制终止部分进程(按优先级、代价最小原则) |
| **进程回滚** | 回到某个检查点,重新执行 |

**撤销策略**:
- 撤销所有死锁进程(代价大)
- 逐个撤销,直到死锁解除(每次选代价最小)
- 代价衡量:进程优先级、已运行时间、还需时间、资源数

## 4.7 真题精解

### 【2016 选择】死锁四条件

**题目**:下列哪个不是死锁的必要条件?

A. 互斥  B. 请求保持
C. 不剥夺  D. 优先级反转

**答案**:**D**

**解析**:死锁四必要条件:互斥、请求保持、不剥夺、循环等待。优先级反转是同步问题,不是死锁条件。

### 【2017 选择】安全 vs 不安全

**题目**:关于安全状态和不安全状态,下列正确的是?

A. 不安全状态一定死锁
B. 安全状态可能死锁
C. 不安全状态可能死锁
D. 死锁可能在安全状态

**答案**:**C**

**解析**:
- 安全状态一定不死锁(B、D 错)
- 不安全状态**可能**死锁(不一定死锁)(A 错,C 对)

### 【2019 综合】银行家算法推演

**题目**:见 4.5.5 例 1,判断系统是否安全,给出安全序列。

**答**:见 4.5.5 节。安全序列 < P1, P3, P0, P2, P4 >。

### 【2020 选择】死锁 vs 饥饿

**题目**:下列描述正确的是?

A. 死锁一定饥饿  B. 饥饿一定死锁
C. 死锁和饥饿互不相关  D. 死锁进程一定阻塞

**答案**:**A**

**解析**:
- 死锁进程全部阻塞,长期得不到资源 → 一定饥饿(A 对,D 对,但 A 更全面)
- 饥饿未必死锁(B 错)
- 死锁是饥饿的特例(C 错)

### 【2023 综合】资源分配图化简

**题目**:给出资源分配图,用死锁定理判断是否死锁。

**答**:见 4.6.2 节。若能完全化简,无死锁;否则有死锁。

## 4.8 真题陷阱(15 条)

1. **四必要条件全部满足才死锁**:破坏任一即可预防
2. **安全状态一定不死锁**;不安全未必死锁
3. **死锁一定在不安全状态**
4. **银行家算法**:试探分配 + 安全性检查
5. **Need = Max - Allocation** 必背公式
6. **死锁定理**:资源分配图不可化简 → 死锁
7. **死锁 vs 饥饿**:死锁一定饥饿,饥饿未必死锁
8. **资源顺序编号**:预防循环等待
9. **一次性申请**:预防请求保持
10. **SPOOLing**:破坏互斥(打印机虚拟化)
11. **鸵鸟策略**:Unix/Linux 实际采用
12. **安全序列不唯一**:能找到一条即可
13. **银行家算法每次请求都需安全性检查**
14. **死锁检测**:资源分配图 + 死锁定理
15. **撤销进程代价**:优先级、运行时间、资源数

## 4.9 易混淆点深辨析

### 4.9.1 死锁 vs 饥饿 vs 活锁

| 维度 | 死锁 | 饥饿 | 活锁 |
|------|------|------|------|
| 进展 | 完全停滞 | 偶尔进展 | 完全停滞 |
| 状态 | 全阻塞 | 长期等待 | 不断变化 |
| 解除 | 外力 | 可能自解 | 可能自解 |
| 关系 | 死锁必饥饿 | 饥饿未必死锁 | 独立 |

### 4.9.2 安全 vs 不安全 vs 死锁

| 状态 | 是否死锁 | 是否可能死锁 |
|------|----------|--------------|
| 安全 | 否 | 否 |
| 不安全 | 不一定 | 是 |
| 死锁 | 是 | — |

### 4.9.3 四种处理策略对比

| 策略 | 时机 | 严格性 | 资源利用率 |
|------|------|--------|------------|
| 预防 | 事前 | 最严 | 最低 |
| 避免 | 分配前 | 严 | 中 |
| 检测 | 死锁后 | 松 | 高 |
| 鸵鸟 | 忽略 | 最松 | 最高 |

### 4.9.4 破坏四条件的方法

| 条件 | 破坏方法 | 实例 |
|------|----------|------|
| 互斥 | SPOOLing 共享 | 打印机 |

| 不剥夺 | 释放已持有 | CPU 抢占 |

## 4.12 延伸知识

### 4.12.1 Linux 死锁检测

- **lockdep**:内核锁依赖检测器,运行时检测潜在死锁
- **hung task**:检测长时间阻塞的进程
- **NMI 看门狗**:检测 CPU 死锁

### 4.12.2 数据库死锁

- 数据库事务的锁等待可能死锁
- **等待图**(Wait-For Graph):节点是事务,边是等待关系,有环则死锁
- **解除**:回滚代价最小的事务

### 4.12.3 分布式死锁

- **Chandy-Misra-Haas 算法**:分布式死锁检测
- **超时机制**:简单但可能误判
- **集中式检测**:一个节点收集全局信息

### 4.12.4 Coffman 条件

死锁四必要条件即 **Coffman 条件**(1971 年 Coffman 等提出):
1. 互斥
2. 占有并等待
3. 不可剥夺
4. 循环等待

4. 资源顺序编号如何预防死锁?有什么缺点?
5. 死锁和饥饿的区别?
6. 给定 5 进程 3 资源的银行家问题(见 4.5.5),P4 请求 (3, 3, 0) 能否分配?
7. 资源分配图化简规则?死锁定理?

### 习题答案

1. **四条件**:互斥、请求保持、不剥夺、循环等待。**必要**:四条全满足才**可能**死锁,但不是四条全满足就一定死锁(还需实际发生资源竞争)。

2. **安全状态**:存在安全序列,一定不死锁。**不安全状态**:可能死锁(不一定死锁)。**死锁**:一定在不安全状态。关系:安全 ⊂ 不安全 ⊂ 死锁(死锁是不安全状态的子集)。

3. 见 4.5.3 节。流程:请求 ≤ Need 检查 → 请求 ≤ Available 检查 → 试探分配 → 安全性检查 → 安全则正式分配,不安全则回滚。

4. **资源顺序编号**:所有资源编号,进程只能申请比已持有更大编号的资源。**缺点**:编号困难(新增资源需重新编号),限制多(可能需先释放再申请)。

5. **死锁**:全部阻塞,必须外力解除,四条件全满足。**饥饿**:长期得不到资源,可能自解,无特定条件。死锁必饥饿,饥饿未必死锁。

6. P4 请求 (3,3,0):
   - ≤ Need[P4]=(4,3,1) ✓
   - ≤ Available=(3,3,2) ✓
   - 试探分配:Available=(0,0,2),Allocation[P4]=(3,3,2),Need[P4]=(1,0,1)
   - 安全性检查:Work=(0,0,2),找 Need ≤ Work 的进程:
     - P1.Need=(1,2,2) > (0,0,2) ✗
     - P3.Need=(0,1,1) > (0,0,2) ✗
     - P0.Need=(7,4,3) > (0,0,2) ✗
     - P2.Need=(6,0,0) > (0,0,2) ✗
     - P4.Need=(1,0,1) > (0,0,2) ✗
   - 无法找到,不安全,回滚,P4 等待。

7. 见 4.6.2 节。化简规则:找所有申请都能满足的进程,删去其所有边,重复直到无法化简。**死锁定理**:能完全化简则无死锁,否则有死锁。
