## 3.1 基本概念

### 3.1.1 临界资源

**临界资源**(Critical Resource):一次仅允许一个进程使用的资源。
- 例:打印机、磁带机、共享变量、共享文件

### 3.1.2 临界区

**临界区**(Critical Section):进程中访问临界资源的代码段。

```
┌────────────────────────────────────┐
│  entry section    // 进入区        │
│  critical section // 临界区        │
│  exit section     // 退出区        │
│  remainder section // 剩余区       │
└────────────────────────────────────┘
```

### 3.1.3 临界区四条件(必背)

1. **空闲让进**:无进程在临界区,有进程申请则进入
2. **忙则等待**:有进程在临界区,其他等待
3. **有限等待**:等待时间有限,不饥饿
4. **让权等待**:等不到就**释放 CPU**,避免忙等

### 3.1.4 同步与互斥

| 概念 | 含义 | 信号量初值 |
|------|------|-----------|
| **互斥** | 排他访问临界资源 | 1 |
| **同步** | 进程间按一定顺序执行(有先后依赖) | 0 |

## 3.2 软件实现

### 3.2.1 单标志法

```c
int turn = 0;   // 谁的 turn

P0: while (turn != 0);   // 等
    临界区;
    turn = 1;

P1: while (turn != 1);   // 等
    临界区;
    turn = 0;
```

**缺点**:必须**交替**进入,违反"空闲让进"(P0 用完临界区但不再用,P1 也不能进,因为 turn 还在 P1)。

### 3.2.2 双标志先检查

```c
bool flag[2] = {false, false};

P0: while (flag[1]);   // 检查 P1
    flag[0] = true;    // 标记自己想进
    临界区;
    flag[0] = false;

P1: while (flag[0]);
    flag[1] = true;
    临界区;
    flag[1] = false;
```

**缺点**:同时检查通过后都进入,违反"忙则等待"。
- 时序:P0 检查 flag[1]=false → P1 检查 flag[0]=false → P0 置 flag[0]=true → P1 置 flag[1]=true → 都进入

### 3.2.3 双标志先修改

```c
P0: flag[0] = true;    // 先标记
    while (flag[1]);   // 再检查
    临界区;
    flag[0] = false;

P1: flag[1] = true;
    while (flag[0]);
    临界区;
    flag[1] = false;
```

**缺点**:同时置 true 后互相等待,违反"空闲让进"。

### 3.2.4 Peterson 算法(必背)

结合 flag 与 turn:

```c
bool flag[2] = {false, false};
int turn;

P0: flag[0] = true;
    turn = 1;                      // 让给 P1
    while (flag[1] && turn == 1);  // 等
    临界区;
    flag[0] = false;

P1: flag[1] = true;
    turn = 0;
    while (flag[0] && turn == 0);
    临界区;
    flag[1] = false;
```

**满足条件**:空闲让进、忙则等待、有限等待。
**不满足**:让权等待(仍忙等,while 循环不释放 CPU)。

**原理**:
- flag[i]=true 表示 Pi 想进
- turn 表示"让给谁":P0 设 turn=1 表示"礼让 P1 先"
- while 等待条件:对方想进 **且** turn 指向对方 → 让对方先

## 3.3 硬件实现

### 3.3.1 关中断

进入临界区前关中断,退出时开。

```c
disable_interrupts();
临界区;
enable_interrupts();
```

- **优点**:简单
- **缺点**:
  - **多核失效**(只关本核中断,其他核仍可进入)
  - **不安全**(用户进程不能关中断,特权指令)
  - 关中断期间可能丢失中断

### 3.3.2 TestAndSet(TSL)

**原子操作**(硬件保证):

```c
bool TestAndSet(bool *lock) {
    bool old = *lock;
    *lock = true;
    return old;
}
```

**使用**:

```c
while (TestAndSet(&lock));   // 忙等获取
临界区;
lock = false;                // 释放
```

### 3.3.3 Swap / XCHG

```c
void Swap(bool *a, bool *b) {
    bool t = *a; *a = *b; *b = t;
}
```

**使用**:

```c
bool key = true;
while (key) Swap(&lock, &key);   // lock 初值 false
临界区;
lock = false;
```

**原理**:Swap 把 lock(false) 和 key(true) 交换,key 变 false 退出循环,lock 变 true 占用。

### 3.3.4 硬件实现优缺点

| 优点 | 缺点 |
|------|------|
| 简单 | 忙等(违反让权等待) |
| 多核可用 | 饥饿可能(无序等待) |
| 适用于任意进程数 | 优先级反转风险 |

## 3.4 信号量

### 3.4.1 整型信号量

```c
int S;

void wait(int S) {     // P 操作
    while (S <= 0);    // 忙等
    S--;
}

void signal(int S) {   // V 操作
    S++;
}
```

**缺点**:仍违反"让权等待"(while 忙等)。

### 3.4.2 记录型信号量(今天常用)

```c
typedef struct {
    int value;
    struct process *L;   // 等待队列
} semaphore;

void wait(semaphore S) {     // P
    S.value--;
    if (S.value < 0) {
        block(S.L);          // 阻塞,让出 CPU
    }
}

void signal(semaphore S) {   // V
    S.value++;
    if (S.value <= 0) {
        wakeup(S.L);         // 唤醒一个等待进程
    }
}
```

**关键性质**:
- `value` 初值代表**初始资源数**
- `value < 0` 时,`|value|` = **等待进程数**
- 满足"让权等待"(block 让出 CPU)

### 3.4.3 P/V 操作三种用法

| 用法 | 初值 | P 位置 | V 位置 |
|------|------|--------|--------|
| **互斥** | 1 | 临界区前 | 临界区后 |
| **同步** | 0 | 后继操作前 | 前驱操作后 |
| **资源计数** | N(资源数) | 申请资源 | 释放资源 |

### 3.4.4 P/V 操作关键规则(必背)

1. **互斥 P 不能包围同步 P**(否则死锁)
2. **多个 P 操作的顺序**:**先 P 同步信号量,后 P 互斥信号量**
3. **V 操作顺序**一般无关(但为避免死锁仍需注意)

**反例**(生产者-消费者死锁):

```c
// 错误顺序!
void producer() {
    P(mutex);       // 先 P 互斥(错!)
    P(empty);       // 再 P 同步
    ...
}
// 死锁:生产者持 mutex 等 empty,消费者等 mutex
```

**正确**:

```c
void producer() {
    P(empty);       // 先 P 同步
    P(mutex);       // 后 P 互斥
    ...
}
```

### 3.4.5 AND 型信号量

一次 P 操作申请多个资源,要么全得,要么一个不得(避免死锁)。

```c
void Swait(semaphore *S, int n) {
    while (true) {
        // 检查所有信号量
        bool all = true;
        for (i = 0; i < n; i++) if (S[i].value <= 0) { all = false; break; }
        if (all) {
            for (i = 0; i < n; i++) S[i].value--;
            return;
        }
        // 否则阻塞
    }
}
```

## 3.5 五大经典模型

### 3.5.1 生产者-消费者(必背)

**单生产者单消费者 + 有界缓冲区(N 个槽位)**:

```c
semaphore mutex = 1;    // 互斥访问缓冲区
semaphore empty = N;    // 空槽数(同步)
semaphore full  = 0;    // 满槽数(同步)

void producer() {
    while (1) {
        生产产品;
        P(empty);       // 同步:等空槽
        P(mutex);       // 互斥
        放入产品;
        V(mutex);
        V(full);        // 同步:通知消费者
    }
}

void consumer() {
    while (1) {
        P(full);        // 同步:等满槽
        P(mutex);       // 互斥
        取出产品;
        V(mutex);
        V(empty);       // 同步:通知生产者
    }
}
```

> **致命错误**:把 `P(mutex)` 放在 `P(empty)` 之前,会**死锁**:
> - 生产者持 mutex 等 empty
> - 消费者等 mutex(无法消费,empty 不增加)
> - 永久死锁

**多生产者多消费者**:再加一个互斥信号量区分不同生产者/消费者。

### 3.5.2 读者-写者

#### 读者优先(读者可并发,写者独占)

```c
semaphore rw = 1;       // 读写互斥
semaphore mutex = 1;    // readcount 互斥
int readcount = 0;

void reader() {
    P(mutex);
    readcount++;
    if (readcount == 1) P(rw);   // 第一个读者锁写
    V(mutex);
    读;
    P(mutex);
    readcount--;
    if (readcount == 0) V(rw);   // 最后一个读者解锁
    V(mutex);
}

void writer() {
    P(rw);
    写;
    V(rw);
}
```

**特点**:读者可并发,写者需等所有读者完成。**写者可能饥饿**(只要有读者陆续到达)。

#### 写者优先(增加 wmutex 阻止新读者)

```c
semaphore rw = 1, wmutex = 1, mutex = 1, rsem = 1;
int readcount = 0, writecount = 0;

void writer() {
    P(wmutex);
    writecount++;
    if (writecount == 1) P(rsem);   // 第一个写者阻止新读者
    V(wmutex);
    P(rw);
    写;
    V(rw);
    P(wmutex);
    writecount--;
    if (writecount == 0) V(rsem);
    V(wmutex);
}

void reader() {
    P(rsem);      // 写者优先时阻塞
    P(mutex);
    readcount++;
    if (readcount == 1) P(rw);
    V(mutex);
    V(rsem);
    读;
    P(mutex);
    readcount--;
    if (readcount == 0) V(rw);
    V(mutex);
}
```

**特点**:写者到达后,新读者必须等所有写者完成。

### 3.5.3 哲学家进餐

5 个哲学家,5 根筷子。**死锁场景**:5 人同时拿左筷子,再都拿右筷子 → 都等不到右筷子。

**避免死锁的三种方案**:

#### 方案 1:限制人数(最多 4 人同时拿筷子)

```c
semaphore room = 4;     // 限制 4 人
semaphore chopstick[5] = {1,1,1,1,1};

void philosopher(int i) {
    P(room);
    P(chopstick[i]);
    P(chopstick[(i+1)%5]);
    吃;
    V(chopstick[(i+1)%5]);
    V(chopstick[i]);
    V(room);
}
```

#### 方案 2:奇偶号相反方向(奇数先左,偶数先右)

```c
void philosopher(int i) {
    if (i % 2 == 1) {
        P(chopstick[i]);
        P(chopstick[(i+1)%5]);
    } else {
        P(chopstick[(i+1)%5]);
        P(chopstick[i]);
    }
    吃;
    // 释放顺序无关
}
```

#### 方案 3:同时拿两根(用 mutex 保证原子)

```c
semaphore mutex = 1;
void philosopher(int i) {
    P(mutex);
    P(chopstick[i]);
    P(chopstick[(i+1)%5]);
    V(mutex);
    吃;
    V(chopstick[i]);
    V(chopstick[(i+1)%5]);
}
```

### 3.5.4 吸烟者问题

3 个吸烟者,各缺一种材料;供应者每次随机提供两种材料,凑齐的人吸烟。

```c
semaphore offer1 = 0;   // 烟纸+火柴
semaphore offer2 = 0;   // 烟纸+胶水
semaphore offer3 = 0;   // 火柴+胶水
semaphore finish = 0;
semaphore mutex = 1;

void supplier() {
    while (1) {
        int r = rand() % 3;
        if (r == 0) V(offer1);
        else if (r == 1) V(offer2);
        else V(offer3);
        P(finish);
    }
}

void smoker1() {  // 有烟纸
    P(offer2);  // 等火柴+胶水
    吸烟;
    V(finish);
}
// 类似 smoker2, smoker3
```

### 3.5.5 理发师睡觉

理发店有 N 把椅子,理发师在椅子上等顾客。

```c
semaphore customers = 0;    // 等待顾客数
semaphore barbers = 0;      // 空闲理发师数
semaphore mutex = 1;
int waiting = 0;            // 等待顾客数

void barber() {
    while (1) {
        P(customers);       // 等顾客
        P(mutex);
        waiting--;
        V(barbers);         // 通知顾客可理发
        V(mutex);
        理发;
    }
}

void customer() {
    P(mutex);
    if (waiting < N) {
        waiting++;
        V(customers);      // 通知理发师
        V(mutex);
        P(barbers);        // 等理发师就绪
        坐下理发;
    } else V(mutex);    // 店满离开
}
```

## 3.6 前驱图同步

**前驱图**:节点表示操作,有向边表示"先于"。

**实现**:每条边对应一个信号量(初值 0)。前驱操作完成后 V,后继操作开始前 P。

**例**:

```
S1 → S2, S1 → S3, S2 → S4, S3 → S4
```

```
       S1
      /  \
     S2   S3
      \  /
       S4
```

```c
semaphore a = 0, b = 0, c = 0, d = 0;

void S1() { ...; V(a); V(b); }
void S2() { P(a); ...; V(c); }
void S3() { P(b); ...; V(d); }
void S4() { P(c); P(d); ...; }
```

**规则**:
- 每条边 i→j 对应一个信号量 s_ij(初值 0)
- 节点 i 完成后,V 所有出边信号量
- 节点 j 开始前,P 所有入边信号量

**题目**:下列哪种实现违反"让权等待"?

A. 记录型信号量  B. Peterson 算法
C. block/wakeup 原语  D. AND 型信号量

**答案**:**B**

**解析**:
- 记录型信号量用 block 让出 CPU(A 满足)
- Peterson 算法用 while 忙等,**违反**让权等待(B 违反)

- AND 型信号量通常也用 block(D 满足)

**答**:在读者优先基础上加 rsem,让写者通过 rsem 阻止新读者进入。见 3.5.2 写者优先代码。

## 3.8 真题陷阱(18 条)

1. **四条件**:空闲让进、忙则等待、有限等待、让权等待
2. **让权等待**:忙等违反此条,如 TSL、Peterson、整型信号量
3. **Peterson 满足前三个**,不满足让权等待
4. **关中断**:多核失效、用户进程不能用(特权指令)
5. **P 操作顺序**:**先 P 同步,后 P 互斥**(否则死锁)
6. **生产者-消费者死锁**:mutex 先 P 会死锁
7. **记录型信号量 value**:**负数绝对值 = 等待进程数**
8. **读者优先**:第一个读 P(rw),最后读 V(rw);**写者可能饥饿**
9. **写者优先**:用 rsem 阻止新读者;**读者可能饥饿**
10. **哲学家避免死锁**:限制人数 / 奇偶相反 / 同时拿
11. **前驱图**:每条边一个信号量,前驱 V,后继 P
12. **V 操作顺序**:一般无关,但避免唤醒后立即阻塞可调整顺序
13. **block/wakeup 原语**:让权等待的实现
14. **同步信号量初值 0**:前驱完成后 V,后继 P 等待
15. **互斥信号量初值 1**:保证排他访问
16. **资源信号量初值 N**:N 个资源
17. **AND 型信号量**:一次申请多个,避免死锁
18. **吸烟者问题**:三个 offer 信号量 + finish

## 3.9 易混淆点深辨析

### 3.9.1 同步 vs 互斥

| 维度 | 同步 | 互斥 |
|------|------|------|
| 关系 | 先后依赖 | 排他访问 |
| 信号量初值 | 0 | 1 |
| P 位置 | 后继操作前 | 临界区前 |
| V 位置 | 前驱操作后 | 临界区后 |

### 3.9.2 整型 vs 记录型信号量

| 维度 | 整型 | 记录型 |
|------|------|--------|
| 等待方式 | 忙等 | block 阻塞 |
| 让权等待 | 违反 | 满足 |
| value | 非负 | 可负(|负|=等待数) |
| 实际应用 | 不用 | 现代 OS |

### 3.9.3 读者优先 vs 写者优先

| 维度 | 读者优先 | 写者优先 |
|------|----------|----------|
| 读者并发 | 是 | 是(已有读者) |
| 写者 | 等所有读者 | 优先 |
| 饥饿 | 写者 | 读者 |
| 实现 | 简单 | 加 rsem |

### 3.9.4 哲学家三种方案对比

| 方案 | 机制 | 优点 | 缺点 |
|------|------|------|------|
| 限制人数 | room=4 | 简单 | 并发度降低 |
| 奇偶相反 | 顺序不同 | 不降并发 | 实现略复杂 |
| 同时拿 | mutex | 原子性 | mutex 成瓶颈 |

## 3.12 延伸知识

### 3.12.1 Linux 信号量

- **内核信号量**:`struct semaphore`,down/up
- **自旋锁**(spinlock):忙等,适用于持有时间极短的临界区
- **互斥锁**(mutex):`struct mutex`,睡眠锁
- **RCU**(Read-Copy-Update):读不加锁,写复制后更新

### 3.12.2 优先级反转

**问题**:低优先级进程持有锁,高优先级进程等锁,中优先级进程抢占低优先级 → 高优先级被中优先级间接阻塞。

**解决**:
- **优先级继承**:低优先级继承高优先级(临时)
- **优先级上限**:锁有上限优先级,持锁者提升到上限

### 3.12.3 自旋锁 vs 互斥锁

| 锁类型 | 等待方式 | 适用 |
|--------|----------|------|
| 自旋锁 | 忙等 | 持有时间极短(<上下文切换开销) |
| 互斥锁 | 睡眠 | 持有时间较长 |

### 3.12.4 现代同步原语

- **futex**(Fast Userspace Mutex):用户态快速路径 + 内核态慢速路径
- **条件变量**(condition variable):配合互斥锁,等待条件成立
- **读写锁**(rwlock):多读单写
- **顺序锁**(seqlock):写优先的读写锁

## 3.13 本章习题

1. 临界区管理的四条件是什么?Peterson 满足哪些?
2. 解释为什么 P 操作要"先同步后互斥"。
3. 写出生产者-消费者的完整代码,说明 empty/full/mutex 的作用。
4. 读者优先 vs 写者优先,各自如何实现?哪个会饥饿?
5. 哲学家进餐问题避免死锁的三种方案?
6. 记录型信号量 value = -5 表示什么?
7. 给定前驱图 S1→S2, S1→S3, S2→S4, S3→S4,用信号量实现。
8. 理发师问题中,customers 和 barbers 信号量分别表示什么?

### 习题答案

1. **四条件**:空闲让进、忙则等待、有限等待、让权等待。Peterson 满足前三个,**不满足让权等待**(while 忙等)。

2. 若先 P 互斥,后 P 同步:进程可能持互斥锁后等同步信号量,而同步信号量需其他进程释放(但其他进程需先获得互斥锁才能进入),死锁。先 P 同步,获取资源后再 P 互斥,避免死锁。

3. 见 3.5.1 节。**empty**:空槽数(同步),初值 N。**full**:满槽数(同步),初值 0。**mutex**:缓冲区互斥,初值 1。

4. **读者优先**:第一个读者 P(rw),最后一个读者 V(rw)。读者可并发,写者可能饥饿。**写者优先**:加 rsem,写者到达后阻止新读者进入。已有读者可继续,但新读者需等写者完成。读者可能饥饿。

5. **限制人数**(room=4)、**奇偶相反**(奇数先左,偶数先右)、**同时拿两根**(mutex 保证原子)。

6. 资源已用完,且有 5 个进程在等待。

7. 见 3.6 节代码。四个信号量 a, b, c, d(初值 0)。S1 完成后 V(a) V(b);S2 P(a) 后执行,V(c);S3 P(b) 后执行,V(d);S4 P(c) P(d) 后执行。

8. **customers**:等待的顾客数(同步,初值 0)。理发师 P(customers) 等顾客来。**barbers**:空闲的理发师数(同步,初值 0)。顾客 P(barbers) 等理发师就绪。
