## 0. 定义

**线性一致性(Linearizability)**:并发对象的一种正确性条件。所有操作看起来在某个"原子时刻"瞬间发生,且操作之间的 real-time 偏序被保留。

又称:原子一致性(Atomic Consistency)、强一致性(Strong Consistency)。

---

## 1. 形式化模型

### 1.1 操作历史(History)

一个**历史** $H$ 是一组操作,每个操作 $op$ 由:

- 调用事件 $inv(op)$
- 响应事件 $resp(op)$
- 操作间隔 $[inv, resp]$ 称为操作区间

历史是事件的序列。

### 1.2 完成历史

- **Complete subhistory** $H|complete$:只保留已完成(有 $resp$)的操作
- 通常分析时假设历史是 complete 的(未完成的可以补完成或丢弃)

### 1.3 顺序规范(Sequential Specification)

对象 $x$ 的顺序规范 $S(x)$ 是该对象在单线程下所有合法操作的序列。

如寄存器(变量)的规范:read 返回最近 write 的值。

### 1.4 等价与等价历史

- **等价历史(Equivalent)** $H \equiv H'$:对每个节点 $i$,$H|i = H'|i$(每节点看到的操作序列相同)
- **顺序历史(Sequential History)**:每个 $inv$ 紧跟对应 $resp$,无交错

### 1.5 real-time 偏序

操作 $op_1$ **先于** $op_2$($op_1 \prec_H op_2$):

$$
resp(op_1) \text{ 在 } inv(op_2) \text{ 之前}
$$

即 $op_1$ 的响应早于 $op_2$ 的调用。这是 real-time 偏序(非重叠)。

---

## 2. 线性一致定义

**定义**(Herlihy-Wing 1990):

历史 $H$ 是线性一致的,当且仅当存在一个等价的顺序历史 $S$(即 $S \equiv H$),满足:

1. **顺序规范合法**:对每个对象 $x$,$S|x \in S(x)$(每个对象单独看是合法顺序行为)
2. **real-time 偏序保留**:对任意 $op_1, op_2$,若 $op_1 \prec_H op_2$,则 $op_1 \prec_S op_2$(在 $S$ 中 $op_1$ 仍在 $op_2$ 之前)

### 2.1 直觉

- 所有操作"线性化"为一个全局顺序
- 这个顺序对所有节点一致
- real-time 发生在前 → 线性顺序也在前
- 并发操作(区间重叠)的相对顺序可任选

### 2.2 线性化点(Linearization Point)

每个操作在线性顺序中的"瞬间时刻",介于 $inv$ 和 $resp$ 之间。

- 对单变量读/写:线性化点通常在调用后、响应前
- 对复杂操作(如 CAS):通常在算法执行的关键步骤

---

## 3. 与其他一致性模型对比

| 模型 | 约束 | 强度 |
|------|------|------|
| Linearizability | 全局顺序 + real-time 偏序保留 | 最强(单对象) |
| Sequential Consistency | 全局顺序(不要求 real-time) | 次强 |
| Causal Consistency | 因果保留(无并发因果) | 中 |
| Read-Your-Writes | 客户端读到自己写 | 弱 |
| Eventual Consistency | 最终收敛 | 最弱 |

### 3.1 Linearizability vs Sequential

- Linearizability 保留 real-time 偏序
- Sequential 不保留(允许 reorder 不重叠的操作)
- 例:同机房写 $w_1$,1ms 后另一节点读 $r$ → Linearizability 要求 $r$ 看到 $w_1$,Sequential 不要求

### 3.2 局部性(Locality)

**Theorem**(Herlihy-Wing):

> 若 $H|x$ 对每个对象 $x$ 都是线性一致的,则 $H$ 整体线性一致。

这是 Linearizability 的"组合性":多对象线性一致 → 整体线性一致。

**Sequential Consistency 不满足 Locality**(单对象顺序一致不保证多对象组合顺序一致)。

Locality 是工程意义重大的性质:可以独立验证每个对象的线性一致。

---

## 4. 线性一致的代价

### 4.1 CAP 中的 C 就是 Linearizability

CAP 定理中的 "C" 是 Linearizability(单对象),详见 [[21-2-学术附录-CAP形式化]]。

### 4.2 性能代价

- 线性一致需要协调(共识或 Quorum)
- 跨 DC 延迟高 → 高延迟
- 跨对象线性一致 → 2PC 或更强(事务)

### 4.3 实现实例

| 系统 | 线性一致范围 |
|------|------------|
| ZK/etcd | 单 key 写 + 同步读 |
| Spanner | 跨 key 事务(External Consistency) |
| Redis 单实例 | 单线程执行 |
| Dynamo/Cassandra | 可调,默认最终一致 |

## 5. 验证线性一致

### 5.1 Wing-Gong 算法

给定历史 $H$,检查是否线性一致:

1. 构造所有可能的顺序化(满足 real-time 偏序)
2. 对每个顺序,验证是否符合对象规范
3. 存在一个合法顺序 → 线性一致

复杂度 NP-hard,实际用启发式(如 WGL algorithm)。

### 5.2 Jepsen 测试

Kyle Kingsbury 的 Jepsen 框架用随机化测试 + 形式化验证,发现多个系统(如 Cassandra、MongoDB 早期版本)的线性一致 bug。

```clojure
;; Jepsen 风格的检查
(defn linearizable? [history]
  (let [sequential-histories (enumerate-sequential-extensions history)]
    (some valid-spec? sequential-histories)))
```

## 6. 经典案例

### 6.1 寄存器的线性一致

操作:
- $w_0$: write(0) → ack
- $w_1$: write(1) → ack
- $r$: read → value

合法顺序(线性一致):

```
w_0 → w_1 → r (r = 1)
w_0 → r → w_1 (r = 0)
```

不合法:

```
w_0 → w_1 → r (r = 0) ✗ (违反 read-after-write)
```

### 6.2 CAS(Compare-And-Swap)

```
CAS(old, new): if value == old then value := new; return true
                else return false
```

线性化点在比较+替换的瞬间(原子的)。

### 6.3 Quorum 系统

$N$ 个副本,$W$ 写确认,$R$ 读返回。$W + R > N$ 保证线性一致(读写有交集),但**注意**:

- 仅 Quorum 不保证线性一致(并发读写仍有问题)
- 需配合版本号 + 同步读修复

详见 [[04-复制]] 和 [[08-2-存储-Dynamo]]。

## 7. 与 Sequential 的形式化区分

**反例**:Sequential 一致但非 Linearizable

```
Node A: w(x, 1)
        resp

Node B:        r(x) → 0
                resp
```

real-time:$w \prec r$(w 响应在 r 调用之前)

Sequential 视角:全局顺序 $w \to r$ 合法(r 应读到 1)→ 该顺序违反规范 → 非 Sequential
等价视角:全局顺序 $r \to w$ 合法(r 读 0,然后 w 写 1)→ Sequential 一致

但 Linearizability 要求 $w \prec r$ → $w$ 必须在 $r$ 前 → $r$ 应读到 1 → 实际读到 0 → 非 Linearizable

故该历史 Sequential 一致但非 Linearizable。$\square$

## 8. 速查表

```
Linearizability 形式化:
  H 线性一致 ⟺ 存在等价顺序历史 S:
    (1) S|x 满足对象规范
    (2) real-time 偏序保留 (op1 ≺_H op2 ⇒ op1 ≺_S op2)

特性:
  Locality (多对象各自线性一致 ⇒ 整体线性一致)
  Sequential 不满足 Locality
  
vs Sequential:
  Linearizability 保留 real-time 偏序
  Sequential 不保留

代价:
  CAP 中的 C
  需协调 (共识/Quorum/2PC)
  跨 DC 高延迟

实现:
  ZK/etcd (单 key)
  Spanner (跨 key, External)
  Redis 单实例

验证:
  Wing-Gong 算法 (NP-hard)
  Jepsen 随机化测试
```
