# 标记规范

> 全仓标记统一约定，避免含义漂移。

---

## 1. 标记含义

| 标记 | 含义 | 使用场景 | 频次控制 |
|------|------|---------|---------|
| ⭐ | 高频面试 | 面试要点标题、核心概念、必考点 | 每章 5-10 处 |
| 🔥 | 工程重点 | 生产关键、调优要点、实战陷阱 | 每章 3-8 处 |
| 📜 | 经典论文 | 论文引用、原始出处 | 论文清单必标；每章引用处必标 |
| ⚠️ | 易错点 | 常见误解、生产陷阱、边界问题 | 每章 3-6 处 |
| 🎓 | 学术深度 | 定理、证明、下界、形式化模型 | 仅用于学术小节标题 |
| 🏭 | 工业实战 | 真实系统、事故、调优、容量规划 | 仅用于工业小节标题 |

---

## 2. 使用规则

### 2.1 不叠加

- ❌ 错误：`⭐🔥 Raft 选举流程`
- ✅ 正确：`⭐ Raft 选举流程`（在正文中用「生产关键」补充说明）

### 2.2 🎓 与 🏭 仅作小节标题前缀

```markdown
## 5.3 🎓 学术深度          ← 小节标题
### 5.3.1 FLP 不可能定理    ← 子标题不用再加 🎓

## 5.4 🏭 工业实战          ← 小节标题
### 5.4.1 etcd 实现         ← 子标题不用再加 🏭
```

### 2.3 ⭐ / 🔥 / ⚠️ / 📜 内联使用

- `⭐` 用在面试要点卡片标题前：`### ⭐ Q1：CAP 怎么理解？`
- `🔥` 用在工业调优要点前：`- 🔥 Kafka 的 acks=all 配合 min.insync.replicas 才安全`
- `⚠️` 用在易错点前：`- ⚠️ Redis SETNX 不加 NX+EX 会丢锁`
- `📜` 用在论文引用前：`- 📜 [Lamport 1978] *Time, Clocks...*`

### 2.4 引用格式

- 论文：`📜 [作者 年份] *标题* —— 一句话贡献`
- 文档：`🔗 [系统名 文档标题](URL)（版本 v1.2.3, 访问于 2026-06-23）`
- 书籍：`📖 DDIA 第 N 章 "..."`

---

## 3. 频次控制原则

- ⭐ 不滥标：只标真正高频的考点，标记过多失去信号价值
- 🔥 不滥用：标工程实战中真正影响生产的问题
- ⚠️ 不虚标：必须给出「误解 / 陷阱」的具体描述
- 📜 不漏标：所有论文引用必须标 📜，便于溯源

---

## 4. 其他约定

### 4.1 章节状态标记（用于 README 索引表）

| 标记 | 含义 |
|------|------|
| 🚧 | 写作中 |
| ✅ | 完成 |
| 📝 | 仅骨架 |
| 🔍 | 待 review |

### 4.2 章节内容深度标记

| 标记 | 含义 |
|------|------|
| 🎓 | 学术深度小节（面试可跳过） |
| 🏭 | 工业实战小节 |
| 🔧 | 实操 / 调优步骤 |
| 📊 | 容量估算 / 性能数据 |
| 🧪 | 实验 / 复现步骤 |

---

## 5. 维护

- 写作中发现新需求标记，先在本文件登记，再使用
- review 时检查每章标记频次是否符合 §3 原则
