## 0. 概述

**故障检测器(Failure Detector, FD)**:作为异步系统的"神谕"(Oracle),帮助绕过 FLP 不可能性。

Chandra-Toueg 1996 引入 FD 抽象,证明:

- 某些 FD 实现共识(在异步 + Crash 模型下)
- 不同 FD 之间有"等价性"(可互推导)
- **最终弱故障检测器 $\diamondsuit W$ 是共识的最弱 FD**

---

## 1. 故障检测器模型

### 1.1 FD 抽象

每个节点 $p$ 维护一个**怀疑集** $\mathcal{D}_p$:本地认为"已故障"的节点集合。

FD 通过输出 $\mathcal{D}_p$ 给算法使用,本身可错(怀疑错了 / 漏怀疑)。

### 1.2 完整性(Completeness)

- **强完整性(SC)**:每个崩溃节点最终被所有诚实节点永久怀疑
- **弱完整性(WC)**:每个崩溃节点最终被某个诚实节点永久怀疑

### 1.3 准确性(Accuracy)

- **强准确性**:诚实节点永不被(任何人)怀疑(任何时刻)
- **弱准确性**:存在某个诚实节点永不被(任何人)怀疑(任何时刻)
- **最终强准确性($\diamondsuit S$)**:存在时刻 $t$,之后诚实节点永不被怀疑
- **最终弱准确性($\diamondsuit W$)**:存在时刻 $t$,之后存在某个诚实节点永不被怀疑

### 1.4 八种 FD 组合

| FD | 完整性 | 准确性 |
|----|--------|--------|
| Perfect $P$ | Strong | Strong |
| Strong $S$ | Strong | Weak |
| Perfect Eventually $\diamondsuit P$ | Strong | Eventual Strong |
| Weak Eventually $\diamondsuit W$ | Strong | Eventual Weak |
| ... | ... | ... |

最弱但有用:$\diamondsuit W$(最终弱准确性 + 强完整性)。

---

## 2. 共识等价性

### 2.1 Chandra-Toueg 共识算法

**Theorem**(CT 1996):在异步 + Crash 模型下,加上 $\diamondsuit W$ FD + 多数派($n \ge 2f+1$),可达成共识。

算法核心:

1. Rotating Coordinator:每轮换一个协调者
2. 协调者发提议,等多数派 ACK
3. 用 FD 跳过"怀疑已崩"的协调者
4. $\diamondsuit W$ 保证最终有一个诚实协调者不被怀疑,成功推进

### 2.2 共识 ⟺ $\diamondsuit W$

**Theorem**(CTH 1996):

> 共识 ⟺ $\diamondsuit W$(在异步 + Crash + 多数派下)。

即:

- 有 $\diamondsuit W$ → 可共识(CT 算法)
- 可共识 → 可实现 $\diamondsuit W$(把"被决策为崩溃"作为怀疑)

故 $\diamondsuit W$ 是**最弱的 FD**(不能再弱)。

---

## 3. $\diamondsuit W$ 是最弱 FD 的证明

### 3.1 直觉

若 FD $\mathcal{D}$ 足以实现共识,则 $\mathcal{D}$ 必须能"模拟"出 $\diamondsuit W$ 的行为。

### 3.2 归约

假设 $\mathcal{D}$ 实现共识算法 $\mathcal{A}$。用 $\mathcal{A}$ 构造 $\diamondsim W$:

- 节点 $p$ 维护一个"信任度" ranking,基于 $\mathcal{D}$ 的历史输出
- 把 ranking 最高的节点当作"不被怀疑"的节点
- 由共识 termination,最终某个诚实节点必须被多数派"信任"
- 该节点即满足 $\diamondsuit W$ 的"某个诚实节点"

详细见 CHT 1996 论文。

### 3.3 等价类

FD 分等价类(可互模拟):

$$
\text{Consensus} \equiv \diamondsuit W \equiv \diamondsuit S \equiv \diamondsuit P \equiv \Omega
$$

(都是异步 + Crash + 多数派下的等价 FD)

其中 $\Omega$(Eventual Leader Election)是最简形式:最终所有诚实节点同意一个诚实 leader。

---

## 4. $\Omega$ 等价性

### 4.1 $\Omega$ 抽象

**$\Omega$**(Chandra-Toueg):每个节点 $p$ 维护一个 leader 候选 $\Omega_p$。

- **Eventual Leadership**:存在时刻 $t$,之后所有诚实节点的 $\Omega_p$ 都指向同一个诚实节点

### 4.2 $\Omega$ 与共识互导

**$\Omega$ → 共识**:用 $\Omega$ 选 leader,跑 Paxos-like 算法。

**共识 → $\Omega$**:用共识决策"当前 leader",保证最终一致。

故 $\Omega \equiv \diamondsuit W \equiv$ 共识。

### 4.3 工程意义

Raft / Multi-Paxos 本质都在实现 $\Omega$(Leader Election)。这是共识的最简抽象。

## 5. 实现故障检测器

### 5.1 心跳(Heartbeat)

每个节点周期发心跳,接收方维护"最后心跳时间":

```
若 now - last_heartbeat > timeout:
    怀疑 p
```

### 5.2 Accrual FD(自适应)

Phi Accrual FD(Hayashibara 2004):

- 不输出"是/否",而输出"怀疑度 $\phi$"
- $\phi$ 基于心跳间隔的历史统计(对数正态分布)
- $\phi$ 越大,越确信崩溃
- 应用层按需设阈值

详见 [[14-故障与容错]]。

### 5.3 不同语言下 FD 实现

**Java**(Akka):
```java
PhiAccrualFailureDetector detector = new PhiAccrualFailureDetector(
    8.0,   // threshold
    Duration.ofMillis(100),  // acceptable-heartbeat-pause
    Duration.ofSeconds(3),   // monitored-by-default
    Clock.systemDefaultZone()
);
```

**Go**(自定义):
```go
type PhiAccrualFD struct {
    history      []time.Duration
    historyMutex sync.Mutex
}

func (fd *PhiAccrualFD) Phi(lastInterval time.Duration) float64 {
    fd.historyMutex.Lock()
    defer fd.historyMutex.Unlock()
    
    fd.history = append(fd.history, lastInterval)
    if len(fd.history) > 1000 {
        fd.history = fd.history[1:]
    }
    
    mean := avg(fd.history)
    stdDev := stddev(fd.history, mean)
    
    return -math.Log10(math.Exp(-float64(lastInterval-mean) / (stdDev + 1)))
}
```

**Python**:
```python
import math
from collections import deque
from statistics import mean, stdev

class PhiAccrualDetector:
    def __init__(self, threshold=8.0, window=1000):
        self.threshold = threshold
        self.history = deque(maxlen=window)
    
    def phi(self, interval_ms):
        self.history.append(interval_ms)
        if len(self.history) < 2:
            return 0.0
        m = mean(self.history)
        s = stdev(self.history) if len(self.history) > 1 else 1.0
        return -math.log10(math.exp(-(interval_ms - m) / (s + 1)))
    
    def is_suspected(self, interval_ms):
        return self.phi(interval_ms) > self.threshold
```

## 6. 工程意义

### 6.1 Paxos / Raft 隐式用 $\Omega$

- Raft Leader Election = 实现 $\diamondsuit W$ / $\Omega$
- 选举成功 → 推进日志
- 选举失败 → 等待新一轮

### 6.2 部分同步假设

工程系统假设"网络最终稳定":

- 大部分时间 $t$ 内,网络稳定 → 心跳准
- 短暂网络抖动 → 误怀疑,但不影响 correctness,只影响 liveness

### 6.3 工业级 FD

- **ZK**:Session timeout + 心跳
- **etcd**:Raft heartbeat + election timeout
- **Cassandra**:Phi Accrual FD(Gossip 传播)
- **K8s**:Liveness/Readiness Probe

## 7. 速查表

```
FD 属性:
  Completeness: 强/弱 (崩溃节点最终被怀疑)
  Accuracy: 强/弱/最终强/最终弱

8 种 FD:
  P (Perfect)          = SC + SA
  S (Strong)           = SC + WA
  ◇P (Eventually P)   = SC + ◇SA
  ◇W (Eventually W)   = SC + ◇WA  ← 最弱有用

等价类 (异步 + Crash + 多数派):
  Consensus ≡ ◇W ≡ ◇S ≡ ◇P ≡ Ω
  Ω = Eventual Leader Election

实现:
  Heartbeat + Timeout
  Phi Accrual (自适应, 统计)
  
工业:
  ZK/etcd: 心跳 + 超时
  Cassandra: Phi Accrual
  K8s: Liveness/Readiness Probe

意义:
  绕过 FLP (加 FD = 加同步假设)
  Paxos/Raft 隐式实现 Ω
```
