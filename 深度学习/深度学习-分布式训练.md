## 一、问题定义

### 1.1 单卡瓶颈

- **显存**:A100 80GB,175B 模型仅权重 FP16 就 350GB
- **算力**:单 A100 312 TFLOPS,训练 GPT-3 需 3.14e23 FLOPs,单卡 32 年
- **数据**:万亿 token 训练,单卡吞吐 50K token/s,需 7600 卡·天/TB

### 1.2 分布式训练目标

- **显存**:模型拆分到多卡
- **算力**:多卡并行计算,缩放训练时间
- **数据**:多卡并行处理数据,提高吞吐

### 1.3 关键挑战

| 挑战 | 说明 |
|------|------|
| 通信开销 | 梯度同步占训练时间 30-50% |

| 数值稳定性 | BF16 累积误差 |
| 超参缩放 | batch size 变化需调 LR |

- **预训练**:GPT-4 / LLaMA-3 / Claude,数千卡,数月
- **微调**:LoRA / QLoRA,单卡或小集群

## 二、数据并行(Data Parallelism, DP)

### 2.1 基本思路

每张卡持有完整模型副本,处理不同 batch,前向后用梯度平均同步。

```
GPU 0: batch 0 → 前向 → 反向 → grad 0 ┐
GPU 1: batch 1 → 前向 → 反向 → grad 1 ┼→ AllReduce → 平均 grad → 各卡更新
GPU 2: batch 2 → 前向 → 反向 → grad 2 ┤
GPU 3: batch 3 → 前向 → 反向 → grad 3 ┘
```

### 2.2 同步 vs 异步 🎓

**同步 SGD**:
$$
\theta_{t+1} = \theta_t - \eta \cdot \frac{1}{N} \sum_{i=1}^N \nabla L_i(\theta_t)
$$

等价于大 batch 训练,数学清晰,但慢卡拖累全局。

**异步 SGD**:
$$
\theta_{t+1} = \theta_t - \eta \cdot \nabla L_i(\theta_t)
$$

每卡独立更新参数服务器,无等待,但有"梯度陈旧"(stale gradient)问题——慢卡返回的梯度对应旧参数。

**实践**:同步 SGD 主流,异步在小批量场景或网络差时考虑。

### 2.3 Ring AllReduce 🎓

参数服务器瓶颈在中心节点带宽。Ring AllReduce 让每卡只与左右邻居通信,带宽最优。

**Ring 结构**:

```
GPU0 ⇄ GPU1 ⇄ GPU2 ⇄ GPU3 ⇄ GPU0
```

**两阶段**:
1. **Scatter-Reduce**:每卡分 N 块,逐步累加,最终每卡持有一块的完整和
2. **AllGather**:广播完整和到所有卡

**通信量**:$O(N \cdot \text{model size})$,与卡数 $N$ 无关(带宽最优)。

PyTorch 默认用 NCCL 实现 Ring AllReduce。

### 2.4 PyTorch DDP

```python
import torch
import torch.distributed as dist
import torch.multiprocessing as mp
from torch.nn.parallel import DistributedDataParallel as DDP
from torch.utils.data import DataLoader, DistributedSampler

def train(rank, world_size):
    # 初始化进程组
    dist.init_process_group("nccl", rank=rank, world_size=world_size)
    torch.cuda.set_device(rank)
    
    # 模型:每卡一份完整副本
    model = MyModel().cuda(rank)
    model = DDP(model, device_ids=[rank], output_device=rank)
    
    # 数据: DistributedSampler 自动切分
    sampler = DistributedSampler(dataset, num_replicas=world_size, rank=rank, shuffle=True)
    loader = DataLoader(dataset, batch_size=64, sampler=sampler, num_workers=4, pin_memory=True)
    
    optimizer = torch.optim.AdamW(model.parameters(), lr=1e-3)
    
    for epoch in range(10):
        sampler.set_epoch(epoch)  # 重要!每 epoch 重洗
        for x, y in loader:
            x, y = x.cuda(rank), y.cuda(rank)
            loss = model(x, y)
            loss.backward()  # DDP 自动在 backward 时做 allreduce
            optimizer.step()
            optimizer.zero_grad()
    
    dist.destroy_process_group()

# 启动:torchrun --nproc_per_node=8 train.py
# 或 Python API
mp.spawn(train, args=(8,), nprocs=8)
```

**关键点**:
- `DistributedSampler` 切分数据,确保各卡不重复
- `set_epoch(epoch)` 必须调用,否则每 epoch 顺序相同
- DDP 在 `backward()` 时自动通信,`forward()` 无需关心
- 用 `torchrun` 启动,自动管理进程

### 2.5 DDP 的显存模型 🎓

单卡显存:
- 模型权重:$P$ 字节(FP16: $2 \times N_{params}$)
- 梯度:$P$ 字节
- 优化器状态(AdamW FP32):$2P$ 字节(动量 + 方差,FP32)
- 激活:$B \times T \times d \times L \times \text{dtype}$

175B 模型 BF16 + AdamW FP32 优化器状态:
- 权重 350GB + 梯度 350GB + 优化器 1400GB = **2.1TB**
- A100 80GB 远远不够

→ 必须 ZeRO/FSDP 或模型并行。

## 三、ZeRO 与 FSDP ⭐

### 3.1 ZeRO 三阶段 🎓

**Zero Redundancy Optimizer**(Rajbhandari et al. 2020)逐级切分训练状态:

| 阶段 | 切分内容 | 单卡显存(175B) |
|------|---------|----------------|
| Stage 0 | 不切(纯 DDP) | 2.1TB |
| Stage 1 | 优化器状态 | 1.4TB |
| Stage 2 | + 梯度 | 700GB |
| Stage 3 | + 模型权重 | 175GB |
| Offload | + CPU 卸载 | <100GB |

**通信代价**:
- Stage 1/2:额外 AllReduce 梯度,与 DDP 相当
- Stage 3:前向/反向各一次 AllGather 权重,通信量 2x

**结论**:Stage 3 用通信换显存,适合超大模型。

### 3.2 FSDP(Fully Sharded Data Parallel)

PyTorch 原生实现 ZeRO Stage 3,API 与 DDP 类似:

```python
from torch.distributed.fsdp import FullyShardedDataParallel as FSDP
from torch.distributed.fsdp import ShardingStrategy, MixedPrecision, CPUOffload

model = MyModel().cuda()

# FSDP 配置
fsdp_config = {
    'sharding_strategy': ShardingStrategy.FULL_SHARD,  # ZeRO-3
    'mixed_precision': MixedPrecision(
        param_dtype=torch.bfloat16,
        reduce_dtype=torch.bfloat16,
        buffer_dtype=torch.bfloat16,
    ),
    'cpu_offload': CPUOffload(offload_params=False),  # Stage 3 + CPU offload
    'limit_all_gathers': True,  # 防止显存爆
    'forward_prefetch': True,   # 预取下一层
    'use_orig_params': True,    # 兼容性
}

model = FSDP(model, **fsdp_config)

# 训练循环与 DDP 一致
for x, y in loader:
    loss = model(x, y)
    loss.backward()
    optimizer.step()
    optimizer.zero_grad()
```

### 3.3 FSDP 关键技巧

1. **混合精度**:BF16 计算,FP32 累积
2. **Activation Checkpointing**:用计算换显存
3. **Gradient Accumulation**:模拟大 batch
4. **CPU Offload**:权重卸载到 CPU(慢但能跑)
5. **MinBlockSize**:控制分片粒度

```python
from torch.distributed.algorithms._checkpoint.checkpoint_wrapper import (
    checkpoint_wrapper, CheckpointImpl, apply_activation_checkpointing
)
from torch.distributed.fsdp.wrap import size_based_auto_wrap_policy

# 自动包装子模块
model = FSDP(
    model,
    auto_wrap_policy=size_based_auto_wrap_policy(min_num_params=1e6),
    activation_checkpointing_policy=...,  # 子模块类
    ...
)
```

## 四、张量并行(Tensor Parallelism, TP)

### 4.1 思路

把单层的权重矩阵切分到多卡,每卡计算部分结果,通信同步。

### 4.2 列切分(Column Parallel) 🎓

$$
Y = X W, \quad W = [W_1; W_2; ...; W_N]
$$

每卡持 $W_i$,计算 $Y_i = X W_i$,各卡得 $Y$ 的不同列。

```
GPU 0: W₁ → Y₁ = X W₁ ┐
GPU 1: W₂ → Y₂ = X W₂ ┼→ Y = [Y₁; Y₂; ...; Y_N]
...                     │
GPU N: W_N → Y_N = X W_N ┘
```

不需要通信即可得 $Y$,但下一层若需完整 $Y$ 需 AllGather。

### 4.3 行切分(Row Parallel) 🎓

$$
Y = X W, \quad X = [X_1; X_2; ...; X_N]
$$

每卡持 $W$ 的对应行,计算 $Y_i = X_i W_i$,AllReduce 求和得 $Y$。

### 4.4 MLP 的 TP 组合 🎓

Megatron-LM 经典做法:列切 + 行切交替,只需一次 AllReduce:

```
Input X ─→ [Column Parallel Linear] ─→ GeLU ─→ [Row Parallel Linear] ─→ Output Y
                                       │                        │
                                       各卡独立计算              AllReduce 求和
```

通信量:仅一次 AllReduce,与隐藏维度成正比。

### 4.5 Attention 的 TP

Multi-Head Attention 天然适合 TP:每卡负责若干 head,无需通信直到最后拼接。

### 4.6 Megatron-LM 实现

```python
class ColumnParallelLinear(nn.Linear):
    """列切分:权重按输出维度切"""
    def __init__(self, in_features, out_features, world_size, rank):
        assert out_features % world_size == 0
        self.out_per_partition = out_features // world_size
        super().__init__(in_features, self.out_per_partition)
        self.rank = rank
        self.world_size = world_size
    
    def forward(self, x):
        return F.linear(x, self.weight, self.bias)  # 各卡算自己那份


class RowParallelLinear(nn.Linear):
    """行切分:权重按输入维度切,前向需 AllReduce"""
    def __init__(self, in_features, out_features, world_size, rank):
        assert in_features % world_size == 0
        self.in_per_partition = in_features // world_size
        super().__init__(self.in_per_partition, out_features)
        self.rank = rank
    
    def forward(self, x):
        out = F.linear(x, self.weight, self.bias)  # 各卡算部分和
        dist.all_reduce(out)  # 求和得完整结果
        return out


class MegatronMLP(nn.Module):
    """MLP: ColumnParallel → GELU → RowParallel,只一次 AllReduce"""
    def __init__(self, d_model, d_ff, world_size):
        super().__init__()
        self.fc1 = ColumnParallelLinear(d_model, d_ff, world_size, ...)
        self.fc2 = RowParallelLinear(d_ff, d_model, world_size, ...)
        self.gelu = nn.GELU()
    
    def forward(self, x):
        # x: (B, T, d_model),每卡持有完整 x
        h = self.fc1(x)         # (B, T, d_ff / N),无需通信
        h = self.gelu(h)
        out = self.fc2(h)       # (B, T, d_model),AllReduce
        return out
```

### 4.7 TP 的限制

- **要求节点内 NVLink**:跨节点 TP 通信开销大
- **TP 切分大小**:典型 8(单节点 8 卡)
- **不平衡问题**:某些层切不动(LayerNorm / 偏置)

## 五、流水线并行(Pipeline Parallelism, PP)

### 5.1 思路

把模型按层切分到多卡,数据流式穿过:

```
GPU 0: layer 1-4   ─→ 隐状态 ─→ GPU 1: layer 5-8 ─→ ... ─→ GPU N: layer 29-32
```

### 5.2 简单流水线的气泡问题 🎓

```
GPU0: F0 F1 F2 F3 ──────────── B0 B1 B2 B3 ────────
GPU1: ──── F0 F1 F2 F3 ──── B0 B1 B2 B3 ────
GPU2: ──────────── F0 F1 F2 F3 ──── B0 B1 B2 B3
GPU3: ──────────────────── F0 F1 F2 F3 B0 B1 B2 B3
                                       ↑
                                   气泡(空等)
```

气泡占比:$1 - 1/N$,$N$ 卡时浪费严重。

### 5.3 GPipe:微批次切分

把一个 batch 切成 $M$ 个 micro-batch,流水线填满:

```
GPU0: M0 M1 M2 M3 ──────── B0 B1 B2 B3
GPU1: ──── M0 M1 M2 M3 ──── B0 B1 B2 B3
GPU2: ──────────── M0 M1 M2 M3 B0 B1 B2 B3
GPU3: ──────────────────── M0 M1 M2 M3 B0 B1 B2 B3
气泡 = (N-1) / (M+N-1) → M 大时气泡可忽略
```

### 5.4 1F1B(One Forward One Backward)

交错 forward 和 backward,减少激活显存:

```
GPU0: F0 F1 F2 F3 B0 B1 B2 B3  (激活只缓存部分 micro-batch)
GPU1:    F0 F1 B0 F2 B1 F3 B2 B3
...
```

Megatron-LM 默认 1F1B。

### 5.5 PP 实现(PyTorch + torch.distributed.pipeline)

```python
from torch.distributed.pipeline.sync import Pipe

# 模型按层切分到 List[nn.Sequential]
model = nn.Sequential(
    nn.Linear(d, d), nn.ReLU(),  # GPU 0
    nn.Linear(d, d), nn.ReLU(),  # GPU 1
    nn.Linear(d, d), nn.ReLU(),  # GPU 2
    nn.Linear(d, num_classes),   # GPU 3
)

# 包装为流水线
model = Pipe(model, chunks=8)  # 8 个 micro-batch

# 训练与普通模型一致
output = model(input)
loss = criterion(output, target)
loss.backward()
```

### 5.6 PP 与 TP 组合

典型 Megatron 设置:
- PP = 4(深度方向 4 阶段)
- TP = 8(每阶段 8 卡张量并行)
- DP = N / (PP × TP)(数据并行)

## 六、3D 并行 ⭐

### 6.1 三维组合

```
数据并行(DP) × 张量并行(TP) × 流水线并行(PP) = 总卡数
```

**例**:1024 卡训练 GPT-3 175B:
- TP = 8(单节点 NVLink)
- PP = 8(8 阶段流水线)
- DP = 16(数据并行)

### 6.2 拓扑优化 🎓

| 并行 | 通信模式 | 适合网络 |
|------|---------|---------|
| DP | AllReduce 梯度,大通信 | 跨节点(IB) |
| TP | AllReduce 激活,频繁 | 节点内(NVLink) |
| PP | P2P 隐状态,小通信 | 跨节点可接受 |

**最佳实践**:
- TP 放节点内(NVLink 200GB/s)
- DP 跨节点(IB 50GB/s)
- PP 介于其间

### 6.3 Megatron-LM 3D 并行示例


## 七、通信优化

### 7.1 计算通信重叠


- **PowerSGD**:低秩近似梯度

- **TF32**:A100 默认,19-bit mantissa

### 7.4 TopK 稀疏化

只发梯度绝对值最大的 K%,精度损失需补偿。

### 7.6 通信原语对比

| 原语 | 含义 | PyTorch |
|------|------|---------|
| Broadcast | 一卡数据广播 | `dist.broadcast` |

## 八、混合精度训练

### 8.1 FP32 vs FP16 vs BF16 🎓

| 类型 | 指数位 | 尾数位 | 范围 | 精度 |
|------|--------|--------|------|------|
| FP32 | 8 | 23 | ±1e38 | 高 |
| FP16 | 5 | 10 | ±65504 | 低 |
| BF16 | 8 | 7 | ±1e38 | 低 |

**FP16 问题**:范围小,易上溢;精度低,易下溢。需要 loss scaling。
**BF16 优势**:范围同 FP32,无需 loss scaling,精度虽低但训练稳定。

### 8.2 AMP(Automatic Mixed Precision)

```python
from torch.cuda.amp import autocast, GradScaler

scaler = GradScaler()  # FP16 需要

for x, y in loader:
    optimizer.zero_grad()
    
    with autocast(dtype=torch.bfloat16):  # BF16
        logits = model(x)
        loss = criterion(logits, y)
    
    # BF16 不需 scaler
    loss.backward()
    optimizer.step()
```

```python
# FP16 需 GradScaler
with autocast(dtype=torch.float16):
    logits = model(x)
    loss = criterion(logits, y)

scaler.scale(loss).backward()
scaler.step(optimizer)
scaler.update()
```

### 8.3 工业实践

- **A100 / H100**:BF16 默认,稳定
- **V100**:FP16,需 loss scaling
- **大模型训练**:BF16 主流
- **推理**:INT8 / FP8 / INT4

### 9.1 大模型训练的故障率

- **LLaMA-2**:2048 卡,训练 21 天,数十次重启

### 9.2 Checkpoint 策略

```python
import os
import torch.distributed.checkpoint as dcp

def save_checkpoint(model, optimizer, scheduler, epoch, step, path):
    """分布式 checkpoint(并行保存)"""
    state = {
        'model': model.state_dict(),
        'optimizer': optimizer.state_dict(),
        'scheduler': scheduler.state_dict(),
        'epoch': epoch,
        'step': step,
    }
    
    # 传统:全卡保存到 rank 0(慢)
    if dist.get_rank() == 0:
        torch.save(state, path)
    
    # 现代:分布式并行保存(快 10x)
    dcp.save(state, checkpoint_id=path)


def load_checkpoint(path, model, optimizer, scheduler):
    state = torch.load(path)
    model.load_state_dict(state['model'])
    optimizer.load_state_dict(state['optimizer'])
    scheduler.load_state_dict(state['scheduler'])
    return state['epoch'], state['step']
```

### 9.3 检查点格式

| 格式 | 优点 | 缺点 |
|------|------|------|
| PyTorch native | 简单 | 慢,单卡瓶颈 |
| `torch.distributed.checkpoint` | 并行保存,快 | API 复杂 |
| Safetensors | 安全,加载快 | 需转换 |
| Megatron-LM 格式 | 适配 3D 并行 | 仅 Megatron |

## 十一、性能调优

### 11.1 MFU(Model FLOPs Utilization)

$$
\text{MFU} = \frac{\text{实际 FLOPS}}{\text{理论峰值 FLOPS}}
$$

- A100 BF16 理论:312 TFLOPS
- 训练 GPT-3 MFU:30-50% 算优秀
- 通信密集场景 MFU < 20%


```
   ↓
```

## 十三、常见陷阱与最佳实践 ⚠️

### 13.1 训练陷阱

| 陷阱 | 表现 | 解决 |
|------|------|------|
| 没设 set_epoch | 每 epoch 数据相同 | sampler.set_epoch(epoch) |
| AllReduce 死锁 | 部分卡未触发 | 确保所有 rank 一致的 forward/backward |
| 显存碎片 | OOM 但显存有空 | `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True` |
| DDP 桶过大 | 通信延迟 | `bucket_cap_mb=25` |
| 优化器状态未切分 | ZeRO 不生效 | 用 FSDP 而非裸 DDP |
| 检查点格式不兼容 | 重启失败 | 用 `torch.distributed.checkpoint` |
| NCCL 超时 | 跨节点训练卡死 | `NCCL_TIMEOUT=1800` |

### 13.2 最佳实践

1. **小规模验证**:单卡跑通后再分布式
2. **预训练小模型**:用小模型验证并行配置
3. **频繁 checkpoint**:宁可慢不要丢
4. **监控到位**:TensorBoard + Prometheus
5. **故障演练**:模拟卡死,验证恢复
6. **资源隔离**:训练集群独占,避免干扰

## 十五、面试速答 ⭐

- **DP vs DDP**:DP 单进程多线程(性能差),DDP 多进程,每卡一进程
- **Ring AllReduce**:带宽最优,通信量与卡数无关
- **ZeRO 三阶段**:Stage1 切优化器,Stage2 +梯度,Stage3 +权重
- **FSDP**:PyTorch 原生 ZeRO-3 实现
- **TP 切分**:列切(各卡算不同列),行切(各卡算部分和)
- **PP 气泡**:简单 PP 气泡 1-1/N,GPipe 切微批次缓解
- **3D 并行**:DP × TP × PP,TP 节点内,DP 跨节点
- **BF16 vs FP16**:BF16 范围同 FP32,无需 loss scaling
- **MFU**:Model FLOPs Utilization,30-50% 算优秀
- **大模型训练成本**:LLaMA-2 70B 约 $2.3M,GPT-3 约 $5M

1. [基础] 解释 DP、TP、PP 三种并行的区别。
2. [基础] 为什么 Ring AllReduce 比参数服务器高效?
3. [基础] ZeRO 三个阶段分别切分什么?通信代价如何?
4. [中等] 设计一个 70B 模型的训练方案,显存如何分配?
5. [中等] 解释 Megatron-LM 的 TP 切分原理。
6. [中等] 流水线气泡占比如何推导?如何缓解?
7. [中等] BF16 和 FP16 在训练中的差异?
8. [中等] 大模型训练如何处理故障?
9. [进阶] 设计一个 3D 并行方案,TP/PP/DP 如何分配?
10. [进阶] 分析 MFU 的瓶颈,如何优化到 50%?
11. [进阶] 解释 FlashAttention 的原理,如何减少显存。
12. [进阶] 训练中遇到 NaN 如何排查?
13. [进阶] MoE 模型的分布式训练有何特殊挑战?

**答题要点(Q9)**:
- TP=8:节点内,利用 NVLink 200GB/s,通信频繁需高带宽
- PP=4:跨节点可接受,P2P 通信量小
- DP=N/(TP×PP):剩余卡做数据并行,AllReduce 跨节点
- 总卡数 = TP × PP × DP,例 256 卡:8×4×8
- 优化:GPipe 微批次缓解气泡,1F1B 减少激活显存
- 通信:TP AllReduce 激活 + DP AllReduce 梯度 + PP P2P 隐状态
