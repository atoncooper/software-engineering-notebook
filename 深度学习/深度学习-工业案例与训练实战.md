## 1. GPT-3:175B 参数训练全解析

### 1.1 训练目标

- **OpenAI 2020 年发布**,论文 "Language Models are Few-Shot Learners"
- **目标**: 验证 Scaling Law,用更多数据 + 更大模型实现 few-shot 学习,无需微调
- **意义**: 开启 LLM 时代,证明"规模就是能力"

### 1.2 模型架构

| 维度 | GPT-3 175B |
|------|------------|
| 层数 | 96 |
| 隐藏维度 | 12288 |
| 注意力头数 | 96 |
| 上下文长度 | 2048 |
| 参数量 | 175B |
| 词表 | 50257 (BPE) |
| 激活函数 | GeLU |
| 位置编码 | 学习式 |
| Norm | Layer Norm (Pre-LN) |

### 1.3 训练数据

| 数据集 | Tokens | 占比 |
|--------|--------|------|
| Common Crawl (过滤) | 410B | 60% |
| WebText2 | 19B | 22% |
| Books1 | 12B | 8% |
| Books2 | 55B | 8% |
| Wikipedia | 3B | 3% |
| **总计** | **~500B** | 100% |

**数据清洗**:
- Common Crawl 45TB 原始 → 570GB 清洁 (1.27% 保留率)
- 用分类器过滤低质量 (与 WebText 相似度)
- n-gram 去重
- 测试集 leakage 检测

### 1.4 训练配置

```
模型: 175B 参数
精度: FP16 (混合精度)
Batch Size: 3.2M tokens (动态,从 32K 增长)
学习率: 6e-5 (余弦衰减,前 0.5B warmup)
权重衰减: 0.1
梯度裁剪: 1.0
序列长度: 2048

硬件: 1024 片 NVIDIA V100 32GB
通信: InfiniBand 100 Gbps
优化器: Adam
训练步数: ~170K
训练时长: 34 天
```

### 1.5 成本核算

```
GPU 时: 1024 × 34 × 24 = 835,584 V100-hours
单价: ~$1.5/h (云端 V100)
小计: $1,253,376

电力: ~250 kW × 34d × 24h × $0.1/kWh = $20,400
人力: 5 工程师 × 2 月 × $30K/月 = $300,000
实验浪费 (失败/调参): ~3× 主训练 = $3,760,000
─────────────────────────────────────────
估算总成本: ~$5M (实际估计 $4.6M - $10M)
```

### 1.6 训练问题

- **Loss Spike**: 大模型训练常见,论文未详细披露,业界推测:
  - 数据 batch 偶发异常
  - 数值精度溢出
  - 通过降低学习率 + 回退 checkpoint 解决
- **硬件故障**: 1024 GPU 平均每天 1-2 个故障,自动迁移
- **通信瓶颈**: AllReduce 在千卡规模下成为主要瓶颈

### 1.7 评估结果

| 任务 | GPT-3 175B (zero-shot) | 之前 SOTA (微调) |
|------|-------------------------|-------------------|
| LAMBADA | 76.2% | 68.0% |
| HellaSwag | 78.9% | 85.0% |
| TriviaQA | 64.3% | 68.0% |
| MMLU | 43.9% | 89.8% |
| HumanEval | 0% (zero) | - |

**关键发现**: few-shot 表现随模型规模持续提升,175B 仍未饱和。

### 1.8 复盘与启示

**成功要素**:
1. Scaling Law 验证 (规模 + 数据 > 架构创新)
2. 数据质量决定上限 (高质量过滤)
3. 大规模训练工程能力

**未解决问题**:
1. 幻觉 (Hallucination)
2. 推理能力弱 (GSM8K 仅 17%)
3. 长上下文限制 (2048)
4. 不可解释性

## 2. LLaMA-2 70B:开源大模型训练

### 2.1 训练目标

- **Meta 2023 年 7 月发布**,论文 "LLaMA 2: Open Foundation and Fine-Tuned Chat Models"
- **目标**: 训练开源商用大模型,与 GPT-3.5 对标
- **关键**: 全开源权重 + 完整训练细节,推动生态

### 2.2 模型架构

| 维度 | LLaMA-2 70B |
|------|-------------|
| 层数 | 80 |
| 隐藏维度 | 8192 |
| 注意力头数 | 64 |
| KV 头数 | 8 (GQA) |
| 上下文长度 | 4096 |
| 参数量 | 70B |
| 词表 | 32000 (SentencePiece) |
| 激活函数 | SwiGLU |
| 位置编码 | RoPE |
| Norm | RMSNorm (Pre-RMSNorm) |

**与 LLaMA-1 区别**:
- 上下文 2048 → 4096
- MHA → GQA (Grouped Query Attention) 降推理成本
- 训练数据 1T → 2T tokens
- 加 RLHF (Chat 版)

### 2.3 训练数据

| 数据 | Tokens |
|------|--------|
| 公开网络 (CC, GitHub, Books, Wikipedia) | 2.0T |
| 多语言 (除英语外 20+ 语言) | 5% |
| 高质量过滤: 重复率 / 安全 / 质量分类器 | - |

### 2.4 训练配置

```
预训练 (Pre-training):
  模型: 70B
  精度: BF16
  Batch Size: 4M tokens (动态增长)
  学习率: 3e-4 (余弦衰减, warmup 2000 步)
  权重衰减: 0.1
  梯度裁剪: 1.0
  序列长度: 4096

硬件: 2048 片 NVIDIA A100 80GB
通信: InfiniBand 400 Gbps
优化器: AdamW (β1=0.9, β2=0.95)
训练步数: ~170K
训练时长: 21 天

并行策略:
  - 数据并行: 8
  - 张量并行: 8

```

```

单价: ~$2.5/h (A100 80G)
小计: $2,580,480

集群构建: ~$200M (含基础设施)
分摊到此项目: ~$5M
电力: ~$200K
人力: 30 人 × 6 月 × $30K/月 = $5.4M
─────────────────────────────────────────
估算总成本: ~$10M - $20M

按 token 计: 2T tokens, 每 1M tokens ~ $5-10
```

### 2.6 训练问题

**问题 1: Loss Spike**
- 训练中期出现 20+ 次 loss 突然飙升
- **原因**: 数据 batch 异常 + 梯度爆炸
- **解决**: 
  - 自动检测,回退到上一个稳定 checkpoint
  - 跳过问题 batch
  - 降低学习率 1.1× 后再恢复

**问题 2: 通信瓶颈**
- 2048 卡 AllReduce 通信占 30-40% 时间
- **解决**: 
  - 用 GQA 替代 MHA,KV Cache 减半
  - 3D 并行减少通信量
  - Overlap 计算与通信

**问题 3: 硬件故障**
- 平均每天 1-2 卡故障
- **解决**:
  - 自动检测 + 隔离
  - 训练状态保存到独立存储
  - 30 分钟内自动恢复

### 2.7 RLHF 微调 (Chat 版)

```

  数据: 27,540 条高质量对话
  epoch: 2

阶段 2: Reward Model
  数据: 1,018K 比较对 (用户提示 + 2 模型回答 + 偏好)
  模型: 70B (与主模型同架构)
  准确率: 70% (验证集)

阶段 3: PPO 强化学习
  Actor: 70B
  Critic: 70B (独立)
  Reward Model: 70B (冻结)
  Iteration: 2000
  Batch: 512 prompts
  KL 散度惩罚: 0.01 (防漂移)
```

## 3. Megatron-LM 1T:千亿参数训练工程

### 3.1 训练目标

- **NVIDIA 2022 年论文**, "Efficient Large-Scale Language Model Training on GPU Clusters"
- **目标**: 验证千卡规模 + 张量并行 + 流水线并行的训练效率
- **意义**: 提出 3D 并行 (DP × TP × PP),成为大模型训练事实标准

### 3.2 模型架构

| 模型 | 层数 | 隐藏 | 头数 | 参数 |
|------|------|------|------|------|
| 175B (GPT-3 复现) | 96 | 12288 | 96 | 175B |
| 530B | 105 | 20480 | 160 | 530B |
| 1T | 128 | 25600 | 160 | 1T |

### 3.3 训练配置 (1T)

```
硬件: 3072 片 A100 80GB
集群: Selene (NVIDIA 内部 DGX SuperPOD)
通信: NVLink 8 卡内 + InfiniBand 400 跨节点

3D 并行配置:
  - 张量并行 (TP): 8 (节点内)
  - 流水线并行 (PP): 64
  - 数据并行 (DP): 6
  - 总: 8 × 64 × 6 = 3072

精度: BF16
Batch Size: 1536 (micro-batch)
Sequence Length: 2048
训练步数: ~270K
训练时长: 8 天
```

### 3.4 性能分析

```
理论 FLOPs: 1T 模型 × 270K 步 × 1536 batch × 2048 seq × 6 ≈ 6e23 FLOPs
实际 GPU 时: 3072 × 8 × 24 = 589,824 A100-hours
理论 GPU 时: 6e23 / (312e12 × 4) = 480,000 hours
MFU: 480K / 590K = 81% (业内顶级)
```

### 3.5 关键技术

#### 3.5.1 张量并行 (Megatron-LM)

```python
# Column Parallel Linear
class ColumnParallelLinear(nn.Module):
    def __init__(self, in_features, out_features, tp_size):
        super().__init__()
        self.tp_size = tp_size
        self.out_per_partition = out_features // tp_size
        # 每卡只存一部分权重
        self.weight = nn.Parameter(torch.empty(
            self.out_per_partition, in_features
        ))

    def forward(self, x):
        # x 在所有卡相同 (g halo)
        out = F.linear(x, self.weight)  # [batch, out_per_partition]
        return out  # 不需 all-gather,后续 RowParallel 处理

class RowParallelLinear(nn.Module):
    def __init__(self, in_features, out_features, tp_size):
        super().__init__()
        self.in_per_partition = in_features // tp_size
        self.weight = nn.Parameter(torch.empty(
            out_features, self.in_per_partition
        ))

    def forward(self, x):
        # x 已按列切分
        out_partial = F.linear(x, self.weight)  # [batch, out]
        out = all_reduce(out_partial)  # 跨卡求和
        return out
```

#### 3.5.2 流水线并行 (1F1B)

```
传统 GPipe: 所有 batch 前向,再反向。气泡大。
1F1B (One Forward One Backward):
  - 早期填满流水线
  - 稳定阶段: 1 前向 + 1 反向交替
  - 气泡减少 50%+

Stage 1: F1 F2 F3 F4 B1 F5 B2 F6 B3 F7 B4 ...
Stage 2:    F1 F2 F3 B1 F4 B2 F5 B3 F6 B4 ...
Stage 3:       F1 F2 B1 F3 B2 F4 B3 F5 B4 ...
Stage 4:          F1 B1 F2 B2 F3 B3 F4 B4 ...
```

### 3.6 工程优化

**1. Sequence Parallelism**: 
- LayerNorm 和 dropout 在序列维度切分
- 减少 8× 激活显存

**2. Selective Activation Recompute**:
- 只重计算 LayerNorm + dropout (省 70% 重算)
- 激活显存降 5×

**3. 通信优化**:
- Overlap 计算与通信 (前向计算时启动下一个 all-reduce)
- Bucket 通信 (合并小消息)

**4. BF16 优化**:
- 用 BF16 替代 FP16 (无溢出,精度与 FP32 相当)

### 3.7 故障恢复

```
检查点频率: 每 1000 步一次
检查点大小: 1T 模型 + 优化器 ≈ 8 TB
保存耗时: ~5 分钟
存储: 分布式文件系统 (Lustre)

恢复策略:
  - 3072 卡中单卡故障: 不重启,跳过该卡 (DDP fallback)
  - 多卡故障: 回退最近 checkpoint,自动恢复
  - 平均恢复时间: 10 分钟
```

### 3.8 复盘启示

**工程价值**:
- 3D 并行成为事实标准 (LLaMA/Qwen/Mistral 都用)
- 张量并行 + 流水线并行配合最优
- MFU 81% 是顶级水准 (大多团队仅 30-50%)

**实战建议**:
- TP=8 (节点内 NVLink)
- PP 根据层数定 (L / PP 整除,微批次均衡)
- DP 根据总卡数: DP = 总卡数 / (TP × PP)

## 4. GPT-4:推测架构与训练成本

### 4.1 背景

- **OpenAI 2023 年 3 月发布**,论文未公开技术细节
- **GPT-4 Technical Report 仅给能力描述,无架构/训练细节**

### 4.2 推测架构

```
模型类型: Mixture of Experts (MoE)
总参数: ~1.8T
激活参数: ~280B (top-2 expert, 8 expert)
层数: ~120
隐藏维度: ~18000
注意力头数: ~128
专家数: 8 (每层)
专家隐藏维度: ~8192
上下文长度: 8K - 128K (随版本扩展)

### 4.3 训练成本推测

业内一致推测:
```
硬件: ~25000 A100 100G, 训练 100 天
GPU 时: 25000 × 100 × 24 = 60,000,000 A100-hours
单价: $2.5/h
小计: $150,000,000

电力 + 数据中心: ~$10M
人力 (200 人 × 6 月 × $30K): $36M
实验浪费 (5×): $50M
─────────────────────────────────────────
估算总成本: ~$200M (行业内普遍引用 $63M - $200M)

### 4.4 关键技术推测

**1. MoE 路由**:
- top-2 expert,每 token 激活 280B

**2. 多模态**:

**3. RLHF + RLAIF**:

**4. 长上下文**:
- 8K → 32K → 128K 渐进
- Rotary 位置编码 + 外推技巧

**5. 推理优化**:
- 推测用 Speculative Decoding
- FP8 量化 (H100 原生支持)

### 4.5 评估能力

## 5. AlphaFold 2:科学 AI 的突破

### 5.1 训练目标

- **DeepMind 2020 年 11 月发布**,论文 "Highly accurate protein structure prediction with AlphaFold"
- **目标**: 解决 50 年悬而未决的蛋白质折叠问题
- **意义**: CASP14 比赛 92.4 GDT,达到实验精度

### 5.2 模型架构

```
输入: 氨基酸序列 (1D) + 多序列对齐 (MSA)
↓
Evoformer (48 块)
  - MSA 表示: [s, r, c] (序列 × 残基 × 通道)
  - Pair 表示: [r, r, c] (残基对)
  - 信息双向交换
↓
Structure Module
  - Invariant Point Attention (IPA)
  - 8 块
  - 3D 几何感知
↓
输出: 3D 坐标 + 置信度 (pLDDT)
```

### 5.3 训练配置

```
数据: PDB 17 万蛋白质结构 + UniRef 序列数据库
精度: BF16
Batch Size: 128
学习率: 1e-3 (warmup + 衰减)
训练步数: ~200K

硬件: 128 TPUv3
训练时长: ~几天 (具体未披露)

损失函数:
  - FAPE (Frame Aligned Point Error): 几何感知损失
  - LDDT: 局部距离差异
  - 蒸馏: 用预测结果重新训练
```

### 5.4 关键创新

**1. Evoformer**:
- MSA 和 Pair 表示交替更新
- 用 attention 捕捉长程依赖
- Axial attention 处理 3D 体积

**2. Invariant Point Attention (IPA)**:
- SE(3) 等变
- 直接操作 3D 坐标
- 比传统 attention 更高效

**3. Recycling**:
- 输出回输入,迭代 3 次
- 训练时随机 1-3 次循环

**4. MSA 处理**:
- 用 PSSM (位置特异得分矩阵) 压缩
- 处理 100K+ 序列对齐

### 5.5 评估结果

```
CASP14 (2020) 比赛:
  AlphaFold 2: 92.4 GDT (中位数)
  第二名: ~75 GDT
  
按目标分类:
  - 单域蛋白: ~95 GDT (实验精度)
  - 多域蛋白: ~85 GDT
  - 大蛋白复合物: ~70 GDT (仍有挑战)
```

### 5.6 复盘启示

**科学 AI 价值**:
- 50 年难题,1 年解决
- 已开源 AlphaFold DB (2 亿+ 蛋白质结构)
- 加速生物医药研发

## 6. CLIP:对比学习与多模态

### 6.1 训练目标

- **OpenAI 2021 年发布**,论文 "Learning Transferable Visual Models From Natural Language Supervision"
- **目标**: 用对比学习对齐图像和文本,无需类别标签
- **意义**: 零样本图像分类 + 多模态基础

### 6.2 模型架构

```
图像编码器: ResNet-50 / ViT-L/14 / ViT-H/14
文本编码器: Transformer (12 层, 512 宽, 8 头)

输入: 4 亿图文对 (WIT, Web Image Text)
↓
图像编码 → 图像特征 [batch, 512]
文本编码 → 文本特征 [batch, 512]
↓
L2 归一化
↓
对比损失 (InfoNCE):
  L = -log(sim(img_i, txt_i) / Σ_j sim(img_i, txt_j))
```

### 6.3 训练配置

```
数据: 4 亿图文对 (WIT)
Batch Size: 32768 (极大,对比学习需要)
精度: FP16
学习率: 5e-4 (余弦衰减)
训练步数: ~32K

硬件: 256 片 V100
训练时长: ~12 天
总 GPU 时: 73,728 V100-hours
```

### 6.4 关键技术

**1. 大 Batch (32K)**:
- 对比学习靠大 batch 增多负样本
- 32K batch 远大于 ImageNet (256)

**2. 数据工程**:
- WIT (Web Image Text) 4 亿对
- 用检索 + 过滤,质量比 Conceptual Captions 高
- 文本长度 ~10 词

**3. 对称损失**:
- 图像→文本 + 文本→图像双向

**4. 学习率调度**:
- Warmup 2K → 余弦衰减

### 6.5 评估结果

**零样本 ImageNet 分类**: 76.2% (ViT-L/14)
**已超越 ResNet-50 监督学习 (76%)**

下游任务零样本:
- ObjectNet: 72%
- ImageNet-A: 50%
- ImageNet-R (rendition): 76%

### 6.6 复盘启示

**对比学习威力**:
- 无需标签,百万级数据自监督
- 学到通用表示

**多模态对齐**:
- CLIP 嵌入空间成为多模态基础
- Stable Diffusion 用 CLIP 文本编码
- 后续 BLIP, Flamingo, LLaVA 都基于

**工业应用**:

## 7. Stable Diffusion:扩散模型工程

### 7.1 训练目标

- **Stability AI 2022 年发布**,论文 "High-Resolution Image Synthesis with Latent Diffusion Models"
- **目标**: 用潜空间扩散 + 文本条件,生成高质量图像
- **意义**: 开源文生图革命

### 7.2 模型架构

```
文本编码器: CLIP ViT-L/14 (冻结)
↓ 文本嵌入 [77, 768]

VAE 编码器: 256×256×3 → 32×32×4 (潜空间)
↓
U-Net (潜空间扩散):
  - 输入: 潜表示 [B, 4, 32, 32]
  - 时间嵌入: t
  - 文本嵌入: cross-attention
  - 输出: 噪声预测 [B, 4, 32, 32]
↓
VAE 解码器: 32×32×4 → 256×256×3
```

### 7.3 训练配置

```
阶段 1: LDM 潜空间训练
  数据: LAION-5B 子集 (512×512 图文对)
  Batch Size: 2048
  学习率: 1e-4
  训练步数: ~280K

阶段 2: 文本到图像微调
  数据: LAION-Aesthetics (高质量子集)
  Batch Size: 1024
  训练步数: ~150K

硬件: 256 片 A100 80GB
训练时长: ~150 天 (累计)
总 GPU 时: ~900K A100-hours
成本估算: $600K - $1M
```

### 7.4 关键技术

**1. 潜空间扩散 (Latent Diffusion)**:
- 不在像素空间 (256×256×3 = 196K 维) 扩散
- 在 VAE 潜空间 (32×32×4 = 4K 维) 扩散
- **48× 计算节省**

**2. Cross-Attention 文本条件**:
- 文本嵌入注入 U-Net
- 支持任意长度文本

**3. Classifier-Free Guidance (CFG)**:
- 训练时随机丢弃文本 (10%)
- 推理时: ε = ε_uncond + w * (ε_cond - ε_uncond)
- w 控制文本影响强度

**4. 训练数据筛选**:
- LAION-5B (50 亿) → LAION-Aesthetics (600M)
- 美学评分 + 水印过滤 + 人脸比例

### 7.5 推理优化

```
基础推理 (50 步 DDIM): ~5s @ A100
加速方法:
  - 4 步蒸馏 (Consistency Model): 0.5s
  - LCM (Latent Consistency Model): 4 步,0.3s
  - TensorRT 优化: 2× 加速
  - xFormers: 减少显存 30%
```

### 7.6 复盘启示

**潜空间扩散威力**:
- 8×8×3 压缩,信息保留率高
- 训练 / 推理都加速
- 后续所有扩散模型标配

**开源生态**:
- Stable Diffusion 1.4 / 1.5 / 2.0 / XL
- 衍生模型: Midjourney (闭源) / DALL-E 3 (闭源) / FLUX
- LoRA 微调: 用户级定制

**伦理争议**:
- 版权 (训练数据未授权)
- 色情内容
- 深度伪造

- **Google 2018 年发布**,论文 "BERT: Pre-training of Deep Bidirectional Transformers for Language Understanding"

## 9. 训练失败模式与复盘

### 9.1 Loss Spike (损失尖峰)

**现象**: 训练 loss 突然飙升 10-1000×

**根因**:
1. 数据 batch 异常 (重复/极端文本)
2. 梯度爆炸 (数值溢出)
3. 学习率过高
4. 混合精度溢出

**应对**:
```python
# 1. 自动检测
if loss > 3 * moving_avg_loss:
    log_warning()
    skip_batch = True

# 2. 检查梯度范数
if grad_norm > 100:
    skip_batch = True

# 3. 自动回退
if loss > 10 * moving_avg_loss:
    restore_last_checkpoint()

# 4. 跳过 batch,继续
if skip_batch:
    optimizer.zero_grad()
    continue
```

**真实案例**: GPT-3 训练中遇到 ~20 次 spike,论文未披露细节。LLaMA-2 公开说"约 400 次训练失败"。

### 9.2 梯度爆炸 / 消失

**爆炸**: 梯度范数 → ∞,权重 → NaN
- 解决: 梯度裁剪 (max_norm=1.0), 检查学习率

**消失**: 梯度范数 → 0, 训练停滞
- 解决: 检查初始化, 用 Pre-LN, 用门控激活 (SwiGLU)

### 9.3 数据质量问题

**常见**:
1. 重复样本 (训练-测试泄漏)
2. 异常 token (乱码 / 超长 token)
3. 类别极不平衡
4. 标签错误

**应对**:
```python
# 数据质量检查
def check_data_quality(data_loader):
    for batch in data_loader:
        # 长度异常
        if batch['input_ids'].shape[1] > MAX_LEN:
            log_warning(f"Length overflow: {batch['input_ids'].shape}")
        # token 异常
        if (batch['input_ids'] >= VOCAB_SIZE).any():
            log_warning("Token ID overflow")
        # 重复
        if batch['input_ids'].duplicated().any():
            log_warning("Duplicate samples")
```

### 9.5 Checkpoint 损坏

**现象**: 加载检查点失败 / 训练恢复后 loss 异常

**应对**:
1. 保留 top-K 检查点 (不仅最新)
2. 验证检查点完整性 (load 后 forward 一次)
3. 跨节点备份 (防单点故障)
4. 检查点校验和 (checksum)

```python
def save_with_checksum(state, path):
    torch.save(state, path)
    # 计算校验和
    with open(path, 'rb') as f:
        checksum = hashlib.md5(f.read()).hexdigest()
    with open(path + '.md5', 'w') as f:
        f.write(checksum)

def verify_checkpoint(path):
    with open(path + '.md5') as f:
        expected = f.read()
    with open(path, 'rb') as f:
        actual = hashlib.md5(f.read()).hexdigest()
    if expected != actual:
        raise ValueError("Checkpoint corrupted")
```

def health_check():

## 11. 面试速答 ⭐

**Q1: 训练 70B 模型需要多少 GPU?多长时间?**

A: 取决于数据规模和并行策略。LLaMA-2 70B 用 2048 A100 训练 21 天 (2T tokens)。**单节点 8×A100 训完需 ~5 年**。**关键**: 大模型训练必须分布式,单节点不可行。

**Q2: Loss Spike 怎么处理?**

A: 五步:
1. 自动检测 (loss > 3× 平均值)
2. 跳过当前 batch,不更新权重
3. 记录 batch 内容,事后分析
4. 检查梯度范数,过大则裁剪
5. 严重时回退 checkpoint
**根因**: 通常是数据异常 + 学习率过高 + 混合精度溢出。

**Q3: 千卡训练如何保证不中断?**

A:
1. **检查点**: 每 1000 步存,跨节点备份
2. **故障检测**: 心跳 + GPU 健康 + NCCL 健康
3. **弹性训练**: torchrun --max-restarts=5,自动剔除故障节点
4. **数据备份**: 检查点存对象存储 (S3),本地仅缓存
5. **冗余**: 关键节点备机
**实际**: 1024 卡每天 1-2 故障,自动恢复时间 < 10 分钟。

**Q4: MFU 是什么?如何提升?**

A: MFU (Model FLOPs Utilization) = 实际 FLOPs / 峰值 FLOPs。A100 BF16 峰值 312 TFLOPs。
- 业内顶级: 50-55% (Megatron 1T 81% 是 BF16 实测)
- 普通团队: 30-40%
- 提升方法: 张量并行 + 流水线并行 + 重计算 + 通信 overlap + BF16 + FlashAttention
**关键**: 通信开销是最大瓶颈,占 30-50% 时间。

**Q5: 训练 70B 模型的成本构成?**

A:
- GPU 时 (60-70%): ~$2-5M
- 集群基础设施 (10-15%): ~$500K
- 人力 (10-15%): ~$500K-1M
- 数据采购 (5-10%): ~$200K
- 实验失败返工 (50-200%): ~$2-10M
**实际**: 70B 模型完整研发成本 $5-20M。

**Q6: 为什么大模型训练用 BF16 不用 FP16?**

A: BF16 (Brain Float 16) 优势:
1. **动态范围大**: 8 位指数 (FP16 是 5 位),与 FP32 相同
2. **不易溢出**: 大梯度不溢出
3. **精度低**: 7 位尾数 (FP16 是 10 位),但训练对精度不敏感
**实战**: BF16 训练几乎无 spike,FP16 训练 spike 频繁需 Loss Scaling。

**Q7: AlphaFold 与 LLM 训练的关键差异?**

A:
- **数据**: AlphaFold 用 PDB (17 万结构) + UniRef 序列;LLM 用网页 (万亿 token)
- **架构**: AlphaFold 含几何先验 (IPA, SE(3) 等变);LLM 是纯 Transformer
- **损失**: AlphaFold 是 FAPE 几何损失;LLM 是交叉熵
- **训练时长**: AlphaFold 几天 (128 TPU);LLM 几周 (千 GPU)
- **关键**: 科学 AI 融合领域知识,LLM 走纯数据驱动

**Q8: 训练-推理硬件选型差异?**

A:
- **训练**: H100/A100 80G, NVLink + IB, 大显存 + 高带宽
- **推理**: A10/L40S/H100, 单卡或小集群,显存可小 (量化后)
- **关键**: 训练算力优先,推理带宽优先
