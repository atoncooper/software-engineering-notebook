# Review 清单 · 云计算安全

> 单章 review 与全仓 review 的 checklist。

---

## 1. 单章 Review Checklist

完成每章后逐项检查：

### 1.1 结构完整性
- [ ] 十二节结构齐全（思维导图 → 问题定义 → 概念 → 原理 → 算法 → 工业对照 → 代码 → 陷阱 → 关系 → 面试速答 → 综合题 → 参考）
- [ ] 思维导图 ASCII 清晰、与正文一致
- [ ] 每节有小结或过渡

### 1.2 内容准确性
- [ ] 密码学/算法推导无错
- [ ] 标准引用条款号正确（NIST/ISO/GDPR）
- [ ] 云厂商服务名/术语无误（AWS/Azure/GCP/阿里云/华为云）
- [ ] 标记符号使用符合 [_标记规范.md](_标记规范.md)

### 1.3 工程化视角
- [ ] 工业实现对照表覆盖五家云厂商
- [ ] 配置示例含 Terraform / CLI 双版本（如适用）
- [ ] 生产级示例含标签、审计、最小权限
- [ ] 陷阱表覆盖常见误配、误用、误解

### 1.4 面试导向
- [ ] 面试速答表覆盖 8+ 高频问题
- [ ] 综合面试题 5+ 题，含答题要点
- [ ] 由浅入深排序

### 1.5 引用与链接
- [ ] 参考/延伸章节引用权威标准、论文、工具
- [ ] 跨文件链接使用相对路径
- [ ] 外部链接在脚注或参考节，不在正文嵌入

### 1.6 可读性
- [ ] 表格仅用于对比，非滥用
- [ ] ASCII 图优先于冗长文字
- [ ] 公式编号清晰
- [ ] 中英术语对照首次出现处提供

---

## 2. 全仓 Review Checklist

整仓 review 时检查：

### 2.1 一致性
- [ ] 符号统一（见 [_符号约定.md](_符号约定.md)）
- [ ] 术语统一（见 [_术语表.md](_术语表.md)）
- [ ] 标记使用统一（见 [_标记规范.md](_标记规范.md)）
- [ ] 章节编号连续无跳号
- [ ] 状态图例与实际完成度一致

### 2.2 覆盖度
- [ ] §1-§19 核心主题无遗漏
- [ ] 五家云厂商在各章节均有对照
- [ ] 合规框架覆盖国际 + 国内
- [ ] 事故案例库覆盖近 5 年重大事件

### 2.3 交叉引用
- [ ] 相关章节相互链接
- [ ] 与仓库其他子项目（分布式系统/数据库/机器学习）的关联章节已链接
- [ ] 无死链

### 2.4 时效性
- [ ] OWASP Top 10 / LLM Top 10 为最新版本
- [ ] CSA Treacherous 12 为最新版本
- [ ] 等保 2.0 / 关基保护条例引用准确
- [ ] 云厂商服务名无已废弃产品

### 2.5 可维护性
- [ ] 每章 600-1000 行（与分布式系统项目对齐）
- [ ] 大章节拆分为多文件（如 §20 工业案例按事故单文件）
- [ ] README 导航表与实际文件一致

---

## 3. Review 流程

```
1. 作者自检（按 §1 单章 Checklist）
2. 交叉检查（按 §2 全仓 Checklist 抽样 3 章）
3. 时效性更新（每季度检查外部标准变更）
4. 工业案例库每半年补充新事故
```
