## 一 问题定义

### 1.1 业务痛点

1. **合规碎片化**：跨国企业需同时满足 GDPR（欧盟）、CCPA（加州）、PIPL（中国）、LGPD（巴西），每家有不同数据处理要求。
2. **证据收集难**：审计员要求"过去 90 天所有 S3 桶未公开"，需从 CloudTrail + Config 历史回溯。
3. **持续合规**：传统"每年一次审计"模式失败——审计后变更频繁，合规状态漂移。
4. **多云一致**：AWS、Azure、GCP 配置项不同，统一策略难落地。
5. **责任边界**：SaaS 厂商的合规证书（SOC 2）→ 客户的责任从哪里开始？

### 1.2 云厂商差异

| 维度 | AWS | Azure | GCP | 阿里云 | 华为云 |
|------|-----|-------|-----|--------|--------|
| 合规中心 | Artifact | Service Trust Portal | Compliance Reports | 合规中心 | 合规中心 |
| Policy 引擎 | SCP + Config | Azure Policy | Org Policy | RAM Control | SCP |
| 内置标准 | CIS、PCI、HIPAA、SOC | 同左 + 中国等保 | CIS、PCI、HIPAA | 等保、PCI | 等保、PCI |
| Audit Manager | Audit Manager | Compliance Manager | Compliance Reports Manager | - | - |
| 第三方审计 | AWS Artifact 下载 | STP 下载 | Reports 下载 | 阿里云合规 | 华为云合规 |

### 1.3 反模式

- ❌ 年度审计前临时补救，审计后立刻漂移。
- ❌ Policy-as-Code 仅在 CI 检查，未在云端持续执行（SCP）。
- ❌ 合规证书当作"安全免责"——SaaS SOC 2 ≠ 客户配置合规。
- ❌ 跨境数据传输未评估，数据出境违法。
- ❌ 等保 2.0 三级要求"日志保留 6 个月"，仅配置 90 天。

## 三 原理与机制

### 3.1 责任矩阵 🎓

**Shared Responsibility Matrix（按控制项分解）**：

| 控制项 | IaaS | PaaS | SaaS |
|--------|------|------|------|
| 物理安全 | 云厂商 | 云厂商 | 云厂商 |
| 网络基础设施 | 云厂商 | 云厂商 | 云厂商 |
| Hypervisor | 云厂商 | 云厂商 | 云厂商 |
| OS | 客户 | 云厂商 | 云厂商 |
| Runtime（JRE/Python） | 客户 | 客户 | 云厂商 |
| Application | 客户 | 客户 | 客户（配置） |
| Data | 客户 | 客户 | 客户 |
| IAM 配置 | 客户 | 客户 | 客户 |
| 日志开启 | 客户 | 客户 | 客户 |
| 加密配置 | 客户 | 客户 | 客户 |

**关键洞察**：即使 SaaS，客户仍需配置 IAM、审计、数据加密。SOC 2 证书覆盖的是"云厂商的责任部分"，客户责任部分需自己证明。

### 3.2 Policy-as-Code 模型 🎓

**形式化定义**：

Policy 系统是三元组 $(S, P, E)$：
- $S$：State（云资源当前状态）
- $P$：Policy（规则集合，如 OPA Rego）
- $E: S \times P \rightarrow \{Allow, Deny, Warn\}$：评估函数

**执行点（Enforcement Points）**：
1. **Pre-deployment**：CI/CD 阶段检查 IaC（Terraform Plan 输出）。
2. **Pre-apply**：Terraform Cloud / Atlantis apply 前检查。
3. **Runtime admission**：K8s Admission Controller、AWS Service Control Policy。
4. **Continuous**：CSPM 周期扫描，发现 drift。

**层级关系**：
```
SCP（账号级硬约束）
  └── IAM Policy（角色级权限）
       └── Resource Policy（资源级权限）
            └── Tags（成本归属、合规标识）
```

### 3.3 SCP 防护机制 🎓

**SCP（Service Control Policy）**：AWS Organizations 中的账号级硬约束。

**特性**：
- 即使 root 用户也受 SCP 约束。
- SCP 不授予权限，仅限制最大可用权限（过滤 IAM Policy 的并集）。
- 默认 FullAWSAccess SCP 附在每个账号，移除后该账号无任何权限。

**典型 SCP 模式**：

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "DenyAllExceptApprovedRegions",
      "Effect": "Deny",
      "Action": "*",
      "Resource": "*",
      "Condition": {
        "StringNotEquals": {
          "aws:RequestedRegion": ["us-east-1", "eu-west-1"]
        },
        "ArnNotLike": {
          "aws:PrincipalARN": "arn:aws:iam::*:role/AWSControlTowerExecution"
        }
      }
    },
    {
      "Sid": "DenyDisablingCloudTrail",
      "Effect": "Deny",
      "Action": ["cloudtrail:DeleteTrail", "cloudtrail:StopLogging", "cloudtrail:UpdateTrail"],
      "Resource": "*"
    },
    {
      "Sid": "DenyPublicS3",
      "Effect": "Deny",
      "Action": ["s3:PutBucketPublicAccessBlock"],
      "Resource": "*",
      "Condition": {
        "StringEquals": {
          "s3:PublicAccessBlockConfiguration.BlockPublicPolicy": "false"
        }
      }
    }
  ]
}
```

### 3.4 等保 2.0 与云 🎓

**等保 2.0 等级划分**：
- 第一级：自主保护级（一般信息）
- 第二级：指导保护级（一般业务）
- 第三级：监督保护级（重要业务，关键基础设施最低）
- 第四级：强制保护级（关键基础设施）
- 第五级：专控保护级（特殊）

**云上等保 2.0 三级要求（节选）**：
- 8.1.3 网络通信：VPC 隔离、安全域划分、流量监控
- 8.1.4 边界防护：防火墙、IPS、防 DDoS
- 8.1.5 访问控制：IAM、双因素、最小权限
- 8.1.6 入侵防范：HIDS、EDR、CWPP
- 8.1.7 恶意代码防范：反病毒、YARA
- 8.1.8 安全审计：日志保留 ≥ 6 个月、不可篡改
- 8.1.9 数据完整性：哈希校验
- 8.1.10 数据保密性：传输+存储加密
- 8.1.11 数据备份：异地+定期恢复演练

### 3.5 GDPR 数据流 🎓

**GDPR 关键条款**：
- Art. 5：处理原则（合法性、目的限制、最小化、准确性、存储限制、完整性）
- Art. 6：合法性基础（同意、合同、合法利益等）
- Art. 7：同意管理
- Art. 12-14：透明度与告知
- Art. 15-22：数据主体权利（访问、更正、删除、限制、可携带、反对）
- Art. 25：隐私设计（Privacy by Design）
- Art. 28：数据处理者协议（DPA）
- Art. 30：处理活动记录（ROPA）
- Art. 32：安全处理（加密、密钥管理、灾备）
- Art. 33-34：数据泄露 72h 通知
- Art. 35：DPIA（高风险处理影响评估）
- Art. 44-50：跨境传输（SCC、BCR、 adequacy decision）

**数据流**：

```
Data Subject（数据主体）
    ↓ 同意 / 合同
Data Controller（控制者，如电商）
    ↓ DPA 协议
Data Processor（处理者，如 AWS）
    ↓ SCC 标准合同条款
Sub-Processor（子处理者，如 SaaS 依赖）
```

## 四 算法/流程

### 4.1 合规检查流水线

```
function COMPLIANCE_PIPELINE:
    # 1. 资源采集
    resources = CSPM.scan_all_accounts()  # 跨账号扫描
    
    # 2. 规则评估
    findings = []
    for rule in COMPLIANCE_RULES:
        for resource in resources:
            result = rule.evaluate(resource)
            if result.non_compliant:
                findings.append({
                    "rule_id": rule.id,
                    "standard": rule.standard,  # PCI 3.4, 等保 8.1.10
                    "resource": resource.arn,
                    "severity": rule.severity,
                    "evidence": result.evidence,
                })
    
    # 3. 严重性分级
    critical = [f for f in findings if f.severity == "CRITICAL"]
    high = [f for f in findings if f.severity == "HIGH"]
    
    # 4. 自动修复（部分规则）
    for finding in critical + high:
        if finding.rule.auto_remediation:
            remediate(finding)
    
    # 5. 通知
    notify_scc(findings)  # Security Command Center / Security Hub
    
    # 6. 证据归档
    archive_to_worm(findings)  # 审计证据保留
```

```python
def evaluate_opa(policy_file, input_data):
    """OPA 策略评估"""
    import subprocess
    result = subprocess.run(
        ["opa", "eval", "-d", policy_file, "-i", "-", "data.deny"],
        input=json.dumps(input_data),
        capture_output=True,
        text=True,
    )
    output = json.loads(result.stdout)
    return output["result"][0]["expressions"][0]["value"]
```

### 4.5 数据出境评估

```
function CROSS_BORDER_ASSESS(data_flow):
    # 数据出境评估（中国《数据出境安全管理办法》）
    risk = 0
    
    # 1. 数据类型
    if data_flow.contains_personal_info:
        risk += 30
    if data_flow.contains_important_data:
        risk += 50
    if data_flow.contains_state_secret:
        risk += 100  # 禁止出境
    
    # 2. 数据量
    if data_flow.volume > "1TB":
        risk += 20
    
    # 3. 接收国保护水平
    if data_flow.destination in ADEQUACY_COUNTRIES:
        risk -= 20
    elif data_flow.destination in RESTRICTED_COUNTRIES:
        risk += 40
    
    # 4. 接收方资质
    if data_flow.receiver.has_cert("ISO27001"):
        risk -= 10
    if data_flow.receiver.has_signed_scc:
        risk -= 10
    
    # 5. 是否需申报
    if risk >= 50:
        return "需要申报网信办"
    elif risk >= 30:
        return "需要签订 SCC + 备案"
    else:
        return "可自由流动"
```

### 6.1 教学示例：等保 2.0 检查脚本

```python
import boto3

class DosjonComplianceChecker:
    """等保 2.0 三级自评（节选）"""

    def __init__(self):
        self.aws = boto3.client("config")
        self.cloudtrail = boto3.client("cloudtrail")
        self.s3 = boto3.client("s3")
        self.kms = boto3.client("kms")

    def check_8_1_5_access_control(self):
        """8.1.5 访问控制：检查 IAM MFA、最小权限"""
        iam = boto3.client("iam")
        findings = []

        # 检查 root MFA
        summary = iam.get_account_summary()
        if summary["SummaryMap"]["AccountMFAEnabled"] == 0:
            findings.append({"control": "8.1.5", "severity": "HIGH",
                             "issue": "Root account MFA not enabled"})

        # 检查 IAM User 无 MFA
        users = iam.list_users()["Users"]
        for user in users:
            mfa = iam.list_mfa_devices(UserName=user["UserName"])["MFADevices"]
            if not mfa and user["UserName"] not in ["break-glass"]:
                findings.append({"control": "8.1.5", "severity": "MEDIUM",
                                 "issue": f"User {user['UserName']} has no MFA"})

        return findings

    def check_8_1_8_audit_log(self):
        """8.1.8 安全审计：日志保留 ≥ 6 个月"""
        trails = self.cloudtrail.describe_trails()["trailList"]
        findings = []
        for trail in trails:
            bucket = trail["S3BucketName"]
            # 检查桶 lifecycle 配置
            try:
                lifecycle = self.s3.get_bucket_lifecycle_configuration(Bucket=bucket)
                max_days = 0
                for rule in lifecycle["Rules"]:
                    if "Expiration" in rule:
                        max_days = max(max_days, rule["Expiration"].get("Days", 0))
                    if "Transition" in rule:
                        for t in rule["Transition"]:
                            if t["StorageClass"] in ["GLACIER", "DEEP_ARCHIVE"]:
                                max_days = max(max_days, t.get("Days", 0))
                if max_days < 180:
                    findings.append({"control": "8.1.8", "severity": "HIGH",
                                     "issue": f"Trail {trail['Name']} log retention {max_days} < 180 days"})
            except ClientError:
                findings.append({"control": "8.1.8", "severity": "HIGH",
                                 "issue": f"Trail {trail['Name']} bucket has no lifecycle"})
        return findings

    def check_8_1_10_data_encryption(self):
        """8.1.10 数据保密性：传输+存储加密"""
        findings = []
        # S3 桶加密
        buckets = self.s3.list_buckets()["Buckets"]
        for bucket in buckets:
            try:
                enc = self.s3.get_bucket_encryption(Bucket=bucket["Name"])
            except ClientError:
                findings.append({"control": "8.1.10", "severity": "HIGH",
                                 "issue": f"Bucket {bucket['Name']} not encrypted"})
        return findings
```

```python
class CrossBorderDataTransfer:
    """中国数据出境合规评估"""

    def assess(self, data_flow):
        risk_score = 0
        requirements = []

        # 1. 数据类型评估
        if data_flow["contains_personal_info"]:
            risk_score += 30
            requirements.append("需要数据主体同意或合法性基础")

        if data_flow["contains_important_data"]:
            risk_score += 50
            requirements.append("必须申报网信办")

        if data_flow["contains_state_secret"]:
            risk_score += 100
            requirements.append("禁止出境")

        # 2. 数据量评估
        if data_flow["volume_gb"] > 1000000:  # 100万以上个人信息
            risk_score += 30
            requirements.append("必须申报网信办（超过 100 万 PI）")

        # 3. 接收方资质
        if data_flow["receiver_iso27001"]:
            risk_score -= 10
        if data_flow["receiver_signed_scc"]:
            risk_score -= 10

        # 4. 决定
        if risk_score >= 50:
            return {
                "decision": "BLOCK",
                "reason": "需网信办审批",
                "requirements": requirements,
            }
        elif risk_score >= 30:
            return {
                "decision": "CONDITIONAL",
                "reason": "需签 SCC + 风险评估",
                "requirements": requirements,
            }
        else:
            return {
                "decision": "ALLOW",
                "reason": "符合出境条件",
                "requirements": requirements,
            }
```

## 七 常见陷阱与最佳实践

### 7.1 陷阱表 ⚠️

| 陷阱 | 描述 | 后果 | 规避 |
|------|------|------|------|
| 合规漂移 | 审计后变更未跟踪 | 下次审计失败 | 持续合规（CSPM）+ 自动修复 |
| 责任边界模糊 | 以为 SOC 2 覆盖一切 | 客户部分不合规 | 责任矩阵清晰化 |
| SCP 不应用 | SCP 仅写不附加 | 等于没保护 | 附加到 OU 并测试 |
| 日志保留不足 | 90 天后自动删 | 等保 / SOX 不合规 | WORM + 冷归档 7 年 |
| 跨境数据传输未评 | 数据出境违法 | 监管处罚 | DPIA + SCC + 网信办申报 |
| 审计员无云经验 | 要求"防火墙日志" | 审计走形式 | 选择云审计经验丰富的所 |
| 等保测评仅纸面 | 不验证实际配置 | 测评报告与实际脱节 | 自动化证据收集 |
| DPA 未签 | 用了 SaaS 但无 DPA | GDPR 违规 | SaaS 入门关卡 DPA 签署 |
| 第三方供应商监控 | 供应商合规证书过期 | 风险蔓延 | 年度复核 + TPRM 流程 |
| 密评只过密码算法 | 忽略密钥管理流程 | 密评失败 | KMS 全流程符合 GM/T 0054 |

### 7.2 最佳实践

1. **持续合规**：CSPM 实时扫描 + 自动修复，取代年度审计模式。
2. **Policy-as-Code 多层**：SCP（账号级）+ IAM（角色级）+ Config Rules（资源级）+ OPA（K8s）。
3. **责任矩阵文档化**：每个控制项明确"云厂商 / 客户"责任，与审计员对齐。
4. **证据自动化**：CloudTrail + Config 自动归档 WORM 桶，Audit Manager 持续评估。
5. **跨云统一**：Sentinel / Terraform Cloud 跨云策略，OPA 跨 K8s 集群。
6. **数据出境前置评估**：每个数据流做 DPIA，签 SCC，必要时申报网信办。
7. **TPRM 流程**：第三方供应商年度复核，证书过期即停用。
8. **审计员协作**：选择有云经验的所（如普华永道、安永），定期沟通。
9. **员工培训**：年度合规培训（GDPR、PIPL、等保），LMS 留记录。
10. **演练验证**：年度 IR 演练符合 PCI-DSS 12.10.1 要求。

## 九 面试速答 ⭐

**Q1：等保 2.0 三级要求是什么？**
等保 2.0 三级对应"监督保护级"，关键基础设施最低要求。云上要求：VPC 隔离、IAM 双因素、HIDS、日志保留 6 个月、传输+存储加密、异地备份、年度测评。

**Q2：GDPR 数据泄露通知时限？**
GDPR Art. 33 要求知悉后 72 小时内向监管机构通知；Art. 34 要求高风险时通知数据主体。需准备 IR 流程能 72h 内完成评估、通知。

**Q3：SCP 和 IAM Policy 区别？**
SCP 是账号级硬约束（Organization 层），即使 root 也受约束；IAM Policy 是角色级权限。SCP 不授予权限，仅限制最大可用权限的并集。

**Q4：跨云统一策略怎么做？**
1) Terraform + Sentinel（apply 前检查）；2) OPA 跨 K8s；3) 自研 Policy 引擎翻译到各云原生 Policy（SCP / Azure Policy / GCP Org Policy）。完全统一困难，需抽象。

**Q5：数据出境评估流程？**
1) 识别数据类型（PI/重要数据/国家秘密）；2) 评估数据量；3) 评估接收方资质（ISO 27001、SCC）；4) 评估接收国保护水平；5) 必要时申报网信办；6) 签 SCC + 备案。

**Q6：SOC 2 Type II 和 Type I 区别？**
Type I 是某时间点的设计有效性（一次性）；Type II 是 6-12 个月的运行有效性（持续）。客户应要求云厂商提供 Type II。

**Q7：PCI-DSS 卡数据环境范围怎么界定？**
所有接触 PAN（Primary Account Number）的系统都属于 CDE。可用网络隔离（VPC + SG）+ Tokenization（替换 PAN 为 token）缩小 CDE 范围，降低合规成本。

**Q8：FedRAMP High 和 Low 区别？**
High baseline 适合高敏感数据（执法、军事），413 个控制项；Low baseline 适合低敏感数据，125 个控制项。云厂商需经 3PAO 评估，授权后联邦机构可使用。

**Q9：PIPL 和 GDPR 区别？**
PIPL 适用中国境内处理 PI（含境外向境内提供），更强调"处理者"义务；GDPR 区分 Controller/Processor。PIPL 跨境传输更严格（重要数据须申报），GDPR 用 SCC/BCR。

**Q10：审计证据保留多久？**
SOX 7 年；PCI-DSS 1 年（日志）+ 90 天（实时）；HIPAA 6 年；等保 6 个月（日志）+ 长期（变更记录）；GDPR 处理活动记录至处理结束。

## 十 综合面试题

1. **设计题**：金融 SaaS 公司需通过 SOC 2 + PCI-DSS + 等保三级，如何设计统一合规体系？
   要点：1) 共同控制项识别（IAM、加密、日志、IR）；2) 一次实施，多框架映射（CSPM）；3) Audit Manager 持续评估 SOC 2；4) CDE 隔离 + Tokenization 缩小 PCI 范围；5) 等保 6 个月日志保留统一；6) 多框架证据归档 WORM 桶。

2. **场景题**：欧盟客户数据需传输到中国分析，怎么合规？
   要点：1) Schrems II 判决后 SCC 不足，需补充措施（加密、密钥本地）；2) 中国 PIPL 数据出境评估；3) 双向合规：GDPR 出境 + PIPL 入境；4) 数据最小化（仅必要字段）；5) 评估香港、新加坡作为中转；6) 法律咨询必备。

3. **原理题**：SCP 如何防止账号被攻破后做破坏？
   要点：1) SCP 限制最大权限，即使 root 也受约束；2) 禁用区域、禁用服务（如禁止新 Region 启动）；3) 禁止禁用 CloudTrail/Config/GuardDuty；4) 禁止公开 S3；5) 禁止删除 KMS Key（防止加密粉碎）；6) 禁止 LeaveOrganization（防止脱离集中治理）。

4. **场景题**：审计员要求"过去 90 天所有 IAM 变更都有审批"，怎么证明？
   要点：1) CloudTrail 记录所有 IAM API 调用；2) JIRA/ServiceNow 工单关联 IAM 变更（tag）；3) Config History 记录资源配置变更；4) 交叉验证：每个 IAM 变更必须有对应工单号；5) Audit Manager 自动收集；6) 缺工单的变更即异常。

5. **设计题**：跨国企业多云统一合规怎么做？
   要点：1) CloudHealth / Terraform Cloud 跨云策略；2) 共同标准（CIS Benchmark）跨云映射；3) 各云原生 Policy 引擎执行（SCP / Azure Policy / GCP Org Policy）；4) CSPM 集中检测（Wiz / Orca）；5) 证据归档统一 WORM；6) 合规团队跨云培训。

6. **对比题**：等保 2.0 和 ISO 27001 区别？
   要点：1) 等保是中国强制（关键基础设施），ISO 是国际自愿；2) 等保有等级划分（1-5），ISO 是单一标准；3) 等保三级约 200 项，ISO 27001 Annex A 93 项；4) 等保需测评机构，ISO 需认证机构；5) 等保更具体（如日志 6 个月），ISO 更框架。

7. **场景题**：S3 桶意外公开导致客户数据泄露，怎么应对合规？
   要点：1) 立即关闭公开；2) CloudTrail 查公开期间所有 GetObject 调用；3) 评估泄露范围（哪些客户、哪些数据）；4) GDPR 72h 通知监管；5) 通知数据主体（如适用）；6) SCP 禁止公开 S3 防再犯；7) 复盘 + 责任追究；8) 文档化 IR 流程符合 PCI 12.10。

8. **原理题**：Policy-as-Code 在哪几个点强制？
   要点：1) Pre-commit（开发者本地）；2) CI（Pull Request 检查）；3) Pre-apply（Terraform Plan 后）；4) Runtime admission（K8s Admission、SCP）；5) Continuous（CSPM 持续扫描）；6) Drift detection（配置变更后）。多层防护深度。

9. **设计题**：年度合规审计怎么自动化？
   要点：1) Audit Manager 持续评估，每月生成报告；2) CSPM + Security Hub 集中 finding；3) CloudTrail + Config 自动归档；4) Lambda 自动生成审计报告；5) 审计员在线访问审计门户；6) 缺失证据自动标红，提前补救。

10. **原理题**：TPRM（第三方风险管理）在云场景怎么做？
    要点：1) SaaS 入门评估：SOC 2 Type II、ISO 27001、DPA；2) 年度复核：证书是否过期、是否有 incident；3) 子处理者审查：SaaS 依赖哪些云厂商、是否合规；4) 退出机制：数据导出 + 销毁证明；5) 监控：BitSight、SecurityScorecard 持续评分；6) 合同条款：审计权、违约责任。

### 事故案例 🏭
- **Capital One（2019）**: 被罚款 1.9 亿美元（美国），启示合规配置失误代价巨大。
- **Anthem（2018）**: HIPAA 违规罚款 1600 万美元，启示 PHI 加密必备。
- **Equifax（2017）**: PCI 罚款 7 亿美元，启示漏洞管理 + 卡数据 Tokenization。
- **滴滴（2022）**: PIPL 违规罚款 80.26 亿元，启示数据出境合规。
- **Marriott（2020）**: GDPR 罚款 1840 万英镑，启示第三方供应商管理。
