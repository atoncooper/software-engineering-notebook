## 一、问题定义

### 1.1 解决什么问题

数据安全的三个核心问题：

1. **机密性** — 数据不被未授权访问
2. **完整性** — 数据不被未授权修改
3. **可用性** — 数据可用

云上额外的挑战：
- 物理介质不受控（CSP 工程师可能接触）
- 多租户共享存储
- 跨境数据流动
- 备份和快照也要加密

🔥 **典型事故**：
- 阿里云 2010：未授权访问导致用户数据泄露
- Code Spaces 2014：DDoS + 控制台被入侵，备份被删，公司倒闭
- Morgan Stanley 2017：内部员工未加密客户数据

### 1.2 与传统数据安全的差异

| 维度 | 传统 | 云 |
|------|------|-----|
| 加密硬件 | 自管 HSM | 云 KMS / CloudHSM |
| 密钥管理 | 单一 | 信封加密 + 层级 |
| 数据位置 | 机房内可控 | 多区域 + 多副本 |
| 备份 | 自管 | CSP 备份 + 跨区域 |
| 销毁 | 物理销毁 | 逻辑删除 (加密删除) |
| 取证 | 全盘镜像 | 仅租户视图 |
| 跨境 | 不存在 | GDPR / 等保 |

## 三、原理与机制

### 3.1 直觉：三态加密

```
数据生命周期:
   生成 ──► 传输 ──► 存储 ──► 处理 ──► 归档/销毁
            │         │         │
         in        at       in
        transit   rest     use
            │         │         │
          TLS      KMS      机密计算
         mTLS      HSM      SGX/SEV/Nitro
```

### 3.2 信封加密 (Envelope Encryption)

🎓 **核心思想**：用 CMK 加密 DEK，DEK 加密数据。CMK 永不出 KMS。

```
加密流程:
1. 应用调用 KMS: GenerateDataKey(CMK_ID)
   └─► 返回: DEK_plaintext + DEK_encrypted_by_CMK

2. 应用用 DEK_plaintext 加密数据 (本地 AES)
   └─► encrypted_data

3. 应用存储: encrypted_data + DEK_encrypted_by_CMK

4. 应用丢弃 DEK_plaintext (内存)

解密流程:
1. 应用读取: encrypted_data + DEK_encrypted_by_CMK
2. 调用 KMS: Decrypt(DEK_encrypted_by_CMK)
   └─► KMS 检查 IAM 权限 → 返回 DEK_plaintext
3. 应用用 DEK_plaintext 解密数据
```

🔥 **优势**：
- CMK 永不离开 KMS（HSM 内）
- DEK 可随处存储（已加密）
- 撤销 CMK 即可让所有 DEK 无法解密
- KMS 调用次数少（每次只需解密 DEK）

### 3.3 形式化：加密安全性

🎓 **IND-CPA (Indistinguishability under Chosen Plaintext Attack)**：
$$
\forall m_1, m_2: |Pr[A(E(m_1))=1] - Pr[A(E(m_2))=1]| < negl(\lambda)
$$

即攻击者无法区分两个明文的密文。现代 AES-GCM 满足 IND-CPA。

🎓 **IND-CCA2**：选择密文攻击下的不可区分性。GCM 模式满足，CBC 不满足。

### 3.4 机密计算模型

```
┌─────────────────────────────────────┐
│  普通 VM                            │
│  ┌─────────────────────────────┐    │
│  │  应用 (明文)                  │    │
│  └─────────────────────────────┘    │
│  Hypervisor (CSP 可见)              │
└─────────────────────────────────────┘

┌─────────────────────────────────────┐
│  Confidential VM (SGX/SEV/Nitro)    │
│  ┌─────────────────────────────┐    │
│  │  Enclave (加密内存)           │    │
│  │  应用 + DEK (明文)            │    │
│  └─────────────────────────────┘    │
│  Hypervisor (无法看到 Enclave)      │
└─────────────────────────────────────┘
```

🔥 **核心保证**：CSP 工程师、宿主 OS、Hypervisor 都无法看到 Enclave 内的数据。

### 3.5 数据分级

| 等级 | 类型 | 示例 | 加密要求 | 访问要求 |
|------|------|------|----------|----------|
| L4 | 极敏感 | 密钥、医疗记录 | KMS + HSM + 机密计算 | MFA + JIT + 审计 |
| L3 | 敏感 | PII、财务数据 | KMS 加密 | IAM Role + MFA |
| L2 | 内部 | 内部文档 | KMS 加密 | IAM 认证 |
| L1 | 公开 | 营销材料 | 可选加密 | 公开 |

## 四、算法 / 流程

### 4.1 AES-GCM 加密

```
输入: 明文 P (n 字节), 密钥 K (256 位), Nonce IV (96 位), AAD (附加认证数据)
输出: 密文 C, Tag T (128 位)

1. 生成密钥流: KS = AES_CTR(K, IV, n)
2. 加密: C = P ⊕ KS
3. 计算 Tag: T = GHASH(AAD || C, H) ⊕ E(K, IV||0^31||1)
   其中 H = E(K, 0^128), GHASH 为多项式哈希
4. 输出 (C, T)

解密:
1. 重新计算 Tag T', 验证 T == T' (防篡改)
2. 解密: P = C ⊕ AES_CTR(K, IV, n)
```

### 4.2 KMS 密钥轮换

```
输入: CMK ID, 轮换周期 T (默认 1 年)

每 T 时间:
1. KMS 在 HSM 内生成新版本 backing key
2. 旧 backing key 保留 (用于解密旧密文)
3. 新加密用新 backing key
4. CMK ARN 不变 (应用无感)

撤销:
1. 禁用 CMK → 立即不能解密新请求
2. 删除 CMK → 7-30 天等待期
3. 等待期后 backing key 销毁 → 数据永久不可解密
```

### 4.3 数据生命周期

```
创建 → 使用 → 共享 → 归档 → 销毁
  │      │       │       │       │
  分级   DLP    Token   冷存储   CMK 删除
  加密   审计    化     WORM    备份删除
```

### 6.2 生产级版（工程）：完整数据保护

```python
# tools/data_protection.py
"""生产级数据加密 + 分级 + 审计"""
import boto3
import json
from cryptography.fernet import Fernet
from typing import Dict, Any

kms = boto3.client('kms')
s3 = boto3.client('s3')
macie = boto3.client('macie2')

# ============================================
# 1. 信封加密工具
# ============================================
class EnvelopeEncryption:
    def __init__(self, cmk_id: str):
        self.cmk_id = cmk_id
        self.kms = boto3.client('kms')
    
    def encrypt_data(self, plaintext: bytes, context: Dict) -> Dict:
        """信封加密: KMS 生成 DEK,本地加密数据"""
        # 1. 生成 DEK
        response = self.kms.generate_data_key(
            KeyId=self.cmk_id,
            KeySpec='AES_256',
            EncryptionContext=context  # 附加上下文 (绑定业务)
        )
        
        dek_plaintext = response['Plaintext']
        dek_encrypted = response['CiphertextBlob']
        
        # 2. 本地加密 (用 Fernet,内置 AES-128-CBC + HMAC)
        # 生产应使用 AES-GCM
        f = Fernet(Fernet.generate_key())
        ciphertext = f.encrypt(plaintext)
        
        # 3. 立即清除明文 DEK
        del dek_plaintext
        
        return {
            'ciphertext': ciphertext,
            'encrypted_dek': dek_encrypted,
            'context': context
        }
    
    def decrypt_data(self, encrypted: Dict) -> bytes:
        """解密: KMS 解密 DEK,本地解密数据"""
        # 1. 解密 DEK
        response = self.kms.decrypt(
            CiphertextBlob=encrypted['encrypted_dek'],
            EncryptionContext=encrypted['context']
        )
        dek_plaintext = response['Plaintext']
        
        # 2. 本地解密
        f = Fernet(Fernet.generate_key())  # 实际应保存 fernet key
        plaintext = f.decrypt(encrypted['ciphertext'])
        
        del dek_plaintext
        return plaintext


# ============================================
# 2. 数据分级自动检测
# ============================================
DATA_CLASSIFICATION_RULES = {
    'L4_secret': {
        'patterns': [
            r'\b\d{16,19}\b',           # 信用卡号
            r'\b\d{3}-\d{2}-\d{4}\b',    # SSN
            r'-----BEGIN.*PRIVATE KEY-----',
        ],
        'action': 'encrypt_with_hsm',
        'regions_restricted': True
    },
    'L3_pii': {
        'patterns': [
            r'\b[\w.+-]+@[\w-]+\.[\w.-]+\b',  # 邮箱
            r'\b\d{11}\b',                     # 手机号
            r'\b\d{15}|\d{18}\b',              # 身份证
        ],
        'action': 'encrypt_with_kms',
        'retention_days': 365
    },
    'L2_internal': {
        'patterns': [r'internal\.'],
        'action': 'encrypt_with_managed_key',
        'retention_days': 90
    },
    'L1_public': {
        'patterns': [],
        'action': 'none'
    }
}


def classify_data(data: str) -> str:
    """根据模式匹配自动分级"""
    import re
    for level, rules in DATA_CLASSIFICATION_RULES.items():
        for pattern in rules['patterns']:
            if re.search(pattern, data):
                return level
    return 'L1_public'


# ============================================
# 3. Macie 数据发现 (扫描 S3 敏感数据)
# ============================================
def setup_macie_classification(bucket: str):
    """配置 Macie 扫描桶内敏感数据"""
    macie.create_classification_job(
        name=f"scan-{bucket}",
        jobType='SCHEDULED',
        s3JobDefinition={
            'bucketDefinitions': [{
                'accountId': boto3.client('sts').get_caller_identity()['Account'],
                'buckets': [bucket]
            }]
        },
        scheduleFrequency={'dailySchedule': {}},
        initialRun=True
    )


# ============================================
# 4. 数据访问审计
# ============================================
def audit_kms_usage():
    """通过 CloudTrail 审计 KMS 使用"""
    cloudtrail = boto3.client('cloudtrail')
    
    events = cloudtrail.lookup_events(

            'AttributeKey': 'EventSource',
            'AttributeValue': 'kms.amazonaws.com'
        }],
        MaxResults=50
    )
    
    for ev in events.get('Events', []):
        ct = json.loads(ev['CloudTrailEvent'])
        print(f"{ct['eventTime']} | {ct['sourceIpAddress']} | "
              f"{ct.get('userIdentity',{}).get('arn','')} | "
              f"{ct['eventName']} | key={ct.get('requestParameters',{}).get('keyId','')}")


# ============================================
# 5. CMK 撤销 (emergency)
# ============================================
def emergency_revoke_key(key_id: str):
    """紧急撤销 CMK (无法解密所有用此 key 加密的数据)"""
    # 1. 禁用 (立即生效)
    kms.disable_key(KeyId=key_id)
    print(f"Key {key_id} disabled")
    
    # 2. 计划删除 (7-30 天等待期)
    kms.schedule_key_deletion(
        KeyId=key_id,
        PendingWindowInDays=7  # 最短等待期
    )
    print(f"Key {key_id} scheduled for deletion in 7 days")
    
    # 3. 告警通知
    sns = boto3.client('sns')
    sns.publish(
        TopicArn='arn:aws:sns:us-east-1:123:key-revocation-alerts',
        Subject='EMERGENCY: CMK Revoked',
        Message=f'CMK {key_id} has been disabled and scheduled for deletion'
    )
```

### 6.3 Tokenization 实现

```python
# tools/tokenization.py
"""Tokenization: 用 token 替代敏感数据,真实数据存保险库"""

import hashlib
import secrets
import json
from typing import Dict

class Tokenizer:
    def __init__(self, vault_store):
        self.vault = vault_store  # 实际应为 KMS 加密的 DynamoDB
    
    def tokenize(self, pii: str, context: Dict = None) -> str:
        """将 PII 转为 token,真实值存入保险库"""
        # 生成随机 token
        token = f"tok_{secrets.token_urlsafe(32)}"
        
        # 加密 PII 后存入保险库
        encrypted_pii = self._encrypt(pii, context)
        self.vault[token] = {
            'encrypted_value': encrypted_pii,
            'context': context,
            'created_at': time.time()
        }
        return token
    
    def detokenize(self, token: str, context: Dict = None) -> str:
        """用 token 取回 PII (需验证 context)"""
        if token not in self.vault:
            raise ValueError("Invalid token")
        
        record = self.vault[token]
        # 验证 context (用途限制)
        if context and not self._check_context(record['context'], context):
            raise PermissionError("Context mismatch")
        
        return self._decrypt(record['encrypted_value'])


# 用法: 数据库只存 token,不存真实 PII
# user.email = tokenize("alice@example.com", {"purpose": "marketing"})
# 真实邮箱只在 marketing 流程中 detokenize
```

## 七、常见陷阱与最佳实践 ⚠️

| 陷阱 | 后果 | 对策 |
|------|------|------|
| 用 AWS managed key 而非 CMK | 密钥控制弱 | 用 CMK + 自定义策略 |
| 不开 KMS 轮换 | 密钥长期暴露 | 启用自动轮换 (1 年) |
| DEK 明文存内存 | 内存 dump 泄露 | 用完即清,加 ASLR |
| KMS 调用过度 | 费用高 + 限流 | 用 bucket key + 缓存 DEK |
| 备份不加密 | 备份泄露 = 数据泄露 | 备份用独立 CMK |
| 跨区域复制用同一 CMK | 一损俱损 | 各区域独立 CMK |
| 撤销 CMK 没等待期 | 误删无法恢复 | 设 7-30 天等待期 |
| Tokenization 当加密用 | 不可逆但保险库可被攻破 | 高敏感数据仍需加密 |
| 不分级一刀切加密 | 成本高 + 性能差 | 按分级差异化处理 |
| 跨境数据流动违规 | GDPR 罚款 | 数据驻留 + 传输加密 |
| 删除是逻辑删除 | 加密删除才能真删 | 删 CMK + 删备份 |
| PII 出现在日志 | 日志泄露 PII | 脱敏 + Macie 扫描 |

### 7.1 工程重点 (🔥)

1. **信封加密** — 大数据用 DEK，DEK 用 CMK 加密
2. **CMK 强制轮换** — 1 年自动轮换
3. **HSM 用于 L4 数据** — 密钥不出硬件
4. **机密计算用于极敏感场景** — SGX/SEV/Nitro
5. **Tokenization 替代直接存储 PII** — 数据库只有 token
6. **数据分级驱动策略** — 不同等级不同处理
7. **不可变备份** — WORM + 加密 + 跨区域

## 九、面试速答 ⭐

| 问 | 答 |
|----|-----|
| 加密三态 | at rest (KMS) / in transit (TLS) / in use (机密计算) |
| 信封加密 | CMK 加密 DEK，DEK 加密数据，CMK 永不出 KMS |
| KMS vs HSM | KMS 多租户共享；HSM 单租户独占 (FIPS 140-2 L3) |
| CMK 轮换 | 默认 1 年自动轮换，旧 backing key 保留可解密旧密文 |
| Tokenization vs Encryption | Token 不可逆,保险库控制;加密可逆但密钥控制 |
| 机密计算 | SGX/SEV-SNP/Nitro Enclave,CSP 不可见 |
| AES-GCM vs CBC | GCM 是 AEAD (加密+认证),CBC 需额外 MAC |
| BYOK vs HYOK | BYOK 自带密钥存 CSP;HYOK 密钥仍在自有 HSM |
| 数据分级 | L4 极敏感/L3 敏感 PII/L2 内部/L1 公开 |
| 删除 CMK 后果 | 等待期后所有用此 key 加密的数据永久不可解密 |

## 十、综合面试题

1. **设计一个生产级数据加密架构（多服务 + 多区域 + 合规）。**
   - 要点：分级体系；KMS CMK 每区域独立；信封加密减少 KMS 调用；HSM 用于 L4；机密计算用于极敏感；备份加密 + 不可变；Macie 扫描 PII；跨区域密钥独立。

2. **解释信封加密及为什么云上必用。**
   - 要点：CMK 加密 DEK，DEK 加密数据；CMK 不出 KMS（HSM 内）；DEK 可随处存（已加密）；KMS 调用少；撤销 CMK 即可让所有数据不可解密。

3. **机密计算解决了什么问题？哪些场景必用？**
   - 要点：保护"使用中"数据，CSP/Hypervisor 不可见；必用场景：金融风控模型、医疗 AI、密钥处理、跨组织联合分析。

4. **如何检测和防止 PII 泄露到日志？**
   - 要点：应用层脱敏（中间件）；Macie 扫描 S3 日志桶；CloudWatch Logs 订阅 Lambda 过滤；日志保留期短；告警 + 自动删除。

5. **GDPR Art. 32 要求"适当的技术和组织措施"，云上如何落地？**
   - 要点：加密 at rest + in transit；密钥管理 + 轮换；MFA + 最小权限；日志 + 审计；定期渗透测试；DPA 协议；数据驻留 + 跨境控制。

6. **KMS 密钥撤销后数据还能解密吗？**
   - 不能。CMK 撤销（禁用 + 删除）后，所有用此 CMK 加密的 DEK 无法解密，进而所有数据不可解密。等待期 7-30 天用于纠错。

7. **Tokenization 相比加密有什么优势？**
   - 优势：数据库只存 token，泄露无影响；可按用途生成多 token；可撤销单个 token；符合 PCI-DSS 不能存 PAN 的要求。
   - 劣势：需要保险库基础设施；detokenize 有性能开销。

8. **如何实现跨区域数据加密复制？**
   - 要点：每区域独立 CMK；跨区域复制时重新加密（用目标区域 CMK）；或用 KMS Multi-Region Key（共享 backing key，但有风险）；备份独立加密。

9. **数据库 TDE 与磁盘加密有何不同？**
   - TDE：数据库引擎层加密，逻辑备份也加密，防磁盘丢失；
   - 磁盘加密：存储层加密，逻辑备份不加密，防物理丢失；
   - 推荐两者都用。

10. **如何防止内部员工查看生产数据？**
    - 要点：生产数据 Tokenization；IAM JIT + 审批；数据库审计日志；字段级加密 + 密钥分级；Macie 检测异常访问；脱敏环境给开发。
