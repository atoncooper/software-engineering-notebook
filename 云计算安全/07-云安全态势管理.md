# §7 - 云安全态势管理 (CSPM)

> 一句话定位：CSPM 自动检测云配置面错误，是"配置即代码"时代的安全基线扫描器。

## 一、问题定义

### 1.1 解决什么问题

Gartner 调研：**99% 的云安全事故是配置错误导致的**。

CSPM 解决三个核心问题：

1. **检测** — 当前云配置是否安全
2. **漂移** — 配置是否偏离基线
3. **修复** — 自动化纠正

🔥 **典型 CSPM 防不住的事故**：
- Capital One 2019：WAF + SG 配置错误 (CSPM 可检测)
- 阿里云 2022：未授权 RDS 暴露公网 (CSPM 可检测)
- MongoDB Atlas 2020：白名单 0.0.0.0/0 (CSPM 可检测)

### 1.2 CSPM 与其他工具的边界

| 工具 | 关注面 | 时机 |
|------|--------|------|
| **CSPM** | 配置面 (基础设施) | 部署后 + 持续 |
| **CWPP** | 运行时 (工作负载) | 运行中 |
| **CIEM** | 权限面 (IAM) | 持续分析 |
| **KSPM** | K8s 配置面 | 部署后 |
| **SAST/DAST** | 应用代码 | CI 阶段 |

### 1.3 云厂商差异概述

| 概念 | AWS | Azure | GCP | 阿里云 | 华为云 |
|------|-----|-------|-----|--------|--------|
| CSPM | Security Hub | Defender for Cloud | Security Command Center | 配置审计 + 安全中心 | Config + TMS |
| 合规框架 | CIS / PCI / HIPAA | CIS / PCI / ISO | CIS / PCI | CIS / 等保 | 等保 / CIS |

## 三、原理与机制

### 3.1 CSPM 工作机制

```
   云账号 (AWS/Azure/GCP/...)
       │
       ▼ 1. API 拉取配置
   ┌─────────────┐
   │  CSPM 引擎   │
   │             │
   │ 2. 规则匹配  │ ← CIS Benchmark / CSA CCM / 自定义
   │ 3. 严重度评级│
   │ 4. 漂移检测   │ ← 对比基线
   └──────┬──────┘
          │
          ▼
   ┌─────────────┐
   │  仪表盘      │ ← 可视化
   │  告警        │
   │  工单        │
   │  自动修复    │
   └─────────────┘
```

### 3.2 CIS Benchmark 层级

```
CIS Benchmark
  └─ Category (e.g., Identity and Access Management)
      └─ Recommendation (e.g., 1.3 Ensure MFA is enabled for all IAM users)
          └─ Control (自动化检测脚本/规则)
              └─ Result: Pass / Fail / Error
                  └─ Severity: Critical / High / Medium / Low
```

### 3.3 错误配置 Top 10 (CSA Treacherous 12 + 实战)

| 排名 | 错误配置 | 后果 | CIS 控制 |
|------|----------|------|----------|
| 1 | S3 桶公开 | 数据泄露 | CIS AWS 2.1 |
| 2 | SG 0.0.0.0/0 SSH | 远程入侵 | CIS AWS 4.1 |
| 3 | Root 账号有 access key | 全账号沦陷 | CIS AWS 1.4 |
| 4 | MFA 未启用 | 凭证泄露无防护 | CIS AWS 1.2 |
| 5 | 公开 RDS | 数据泄露 | CIS AWS 6.1 |
| 6 | CloudTrail 关闭 | 审计缺失 | CIS AWS 2.7 |
| 7 | KMS 密钥未轮换 | 长期暴露 | CIS AWS 2.8 |
| 8 | EBS 未加密 | 数据泄露 | CIS AWS 3.1 |
| 9 | 安全组过于宽松 | 攻击面大 | CIS AWS 4.x |
| 10 | IAM 策略 *:* | 权限蔓延 | CIS AWS 1.20 |

### 3.4 漂移检测模型

```
基线 (期望):
  bucket: encryption=aws:kms, public_block=true

实际 (拉取):
  bucket: encryption=none, public_block=false

漂移: encryption, public_block

告警: HIGH (公开+未加密)
```

### 3.5 自动修复模型

```
检测到违规 (Finding)
   │
   ├─ 1. 通知 (邮件/IM/工单)
   ├─ 2. 标记资源 (Tag: auto-remediate=true)
   ├─ 3. Lambda/Function 自动修复:
   │      - 关闭 S3 公开访问
   │      - 加密 EBS
   │      - 修改 SG 规则
   └─ 4. 例外白名单 (业务有正当理由)
```

## 四、算法 / 流程

### 4.1 CSPM 检测算法

```
输入: 云资源集合 R, 规则集 S
输出: Findings 列表

for r in R:
    for s in S:
        if s.resource_type == r.type:
            result = s.evaluate(r)
            if result == FAIL:
                findings.append({
                    'resource': r.arn,
                    'rule': s.id,
                    'severity': s.severity,
                    'remediation': s.remediation
                })
return findings
```

### 4.2 漂移检测算法

```
输入: 当前配置 C, 基线 B
输出: 漂移项 D

for key in B:
    if key not in C:
        D.append({key, 'missing'})
    elif C[key] != B[key]:
        D.append({key, B[key], C[key], 'changed'})

# 新增字段
for key in C:
    if key not in B:
        D.append({key, C[key], 'added'})
```

### 4.3 修复决策树

```
Finding F
   │
   ├─ 严重度 Critical?
   │     ├─ Yes → 立即自动修复 + 告警
   │     └─ No → 进入下一步
   ├─ 资源标记 production?
   │     ├─ Yes → 仅告警 + 工单 (避免影响业务)
   │     └─ No → 自动修复
   ├─ 有例外白名单?
   │     ├─ Yes → 标记 exception, 不操作
   │     └─ No → 修复
```

# check_iam_wildcard.py
import json
import boto3

def handler(event, context):
    """检测 IAM 策略是否含 *:* 权限"""
    config_item = event['configItem']
    policy_doc = json.loads(config_item['configuration']['policyDocument'])
    
    for statement in policy_doc.get('Statement', []):
        if statement.get('Effect') == 'Allow':
            actions = statement.get('Action', [])
            if isinstance(actions, str):
                actions = [actions]
            
            for action in actions:
                if action == '*':
                    return {
                        'compliance_type': 'NON_COMPLIANT',
                        'annotation': f"Policy contains wildcard * action"
                    }
    
    return {
        'compliance_type': 'COMPLIANT',
        'annotation': 'No wildcard actions'
    }

```python
# tools/cspm_custom_checks.py
"""自定义 CSPM 检测规则"""
import boto3
import json
from typing import List, Dict

class CSPMChecker:
    def __init__(self):
        self.aws = boto3.client
        self.findings = []
    
    def check_iam_user_no_mfa(self) -> List[Dict]:
        """检测 IAM 用户未启用 MFA"""
        iam = self.aws('iam')
        users = iam.list_users()['Users']
        
        for user in users:
            mfa = iam.list_mfa_devices(UserName=user['UserName'])
            if not mfa['MFADevices']:
                self.findings.append({
                    'rule': 'iam-user-mfa-required',
                    'severity': 'HIGH',
                    'resource': user['Arn'],
                    'description': f"IAM user {user['UserName']} has no MFA"
                })
    
    def check_s3_public_buckets(self):
        """检测 S3 桶公开访问"""
        s3 = self.aws('s3')
        buckets = s3.list_buckets()['Buckets']
        
        for b in buckets:
            try:
                acl = s3.get_bucket_acl(Bucket=b['Name'])
                for grant in acl['Grants']:
                    if grant['Grantee']['Type'] == 'Group':
                        uri = grant['Grantee'].get('URI', '')
                        if 'AllUsers' in uri or 'AuthenticatedUsers' in uri:
                            self.findings.append({
                                'rule': 's3-no-public-access',
                                'severity': 'CRITICAL',
                                'resource': b['Name'],
                                'description': f"S3 bucket {b['Name']} is public"
                            })
            except Exception as e:
                pass
    
    def check_security_groups_open_ssh(self):
        """检测 SG 开放 SSH 给公网"""
        ec2 = self.aws('ec2')
        sgs = ec2.describe_security_groups()['SecurityGroups']
        
        for sg in sgs:
            for rule in sg.get('IpPermissions', []):
                if rule.get('FromPort') == 22:
                    for cidr in rule.get('IpRanges', []):
                        if cidr['CidrIp'] == '0.0.0.0/0':
                            self.findings.append({
                                'rule': 'no-unrestricted-ssh',
                                'severity': 'HIGH',
                                'resource': sg['GroupId'],
                                'description': f"SG {sg['GroupName']} opens SSH to 0.0.0.0/0"
                            })
    
    def check_root_no_access_key(self):
        """检测 root 账号是否有 access key"""
        iam = self.aws('iam')
        summary = iam.get_account_summary()['SummaryMap']
        
        if summary.get('AccountAccessKeysPresent', 0) > 0:
            self.findings.append({
                'rule': 'no-root-access-key',
                'severity': 'CRITICAL',
                'resource': 'root',
                'description': 'Root account has access key'
            })
    
    def run_all_checks(self):
        self.check_iam_user_no_mfa()
        self.check_s3_public_buckets()
        self.check_security_groups_open_ssh()
        self.check_root_no_access_key()
        return self.findings
```

## 七、常见陷阱与最佳实践 ⚠️

| 陷阱 | 后果 | 对策 |
|------|------|------|
| 只部署不修复 | 海量 finding 无人理 | 严重度分级 + 自动修复 + 工单 |
| 全部自动修复 | 业务中断 (误判) | 生产环境仅告警,Dev 自动修复 |
| 例外白名单失控 | 真问题被掩盖 | 例外需审批 + 定期复审 |
| 漂移检测缺失 | 配置改了不知道 | IaC + Config 持续对比 |
| 只查云原生 | 漏 K8s/应用配置 | 加 KSPM + 应用扫描 |
| 单一 CSPM 厂商 | 厂商盲区 | 多工具交叉 (Prowler + Security Hub) |
| 不做 IaC 扫描 | 问题部署到云上才发现 | Shift Left (tfsec + Checkov) |
| Finding 不去重 | 海量告警疲劳 | 聚合 + 严重度排序 |
| 不区分环境 | Dev 噪音淹没生产 | 按环境/账号分策略 |
| 控制项过多 | 实施疲劳 | 优先 Critical/High |

### 7.1 工程重点 (🔥)

1. **CIS Benchmark 为基线** — 业界共识
2. **生产仅告警,Dev 自动修** — 避免影响业务
3. **例外需审批** — 控制白名单蔓延
4. **持续漂移检测** — IaC + Config 对比
5. **多账号聚合视图** — 单点查看全局
6. **Shift Left** — IaC 阶段拦截
7. **严重度分级** — 优先处理 Critical

## 十、综合面试题

1. **设计一个生产级 CSPM 治理架构。**
   - 要点:Security Hub + 多账号聚合;CIS Benchmark + 自定义规则;严重度分级 + 自动修复;工单系统;例外审批流程;IaC Shift Left;持续漂移检测。

2. **如何处理海量 CSPM finding?**
   - 要点:按严重度过滤 (Critical 优先);按账号/环境分组;去重聚合;例外白名单;自动修复减量;定期清理过期 finding。

3. **CSPM 如何防止 Capital One 类事故?**
   - 要点:检测 WAF 配置错误;检测 EC2 SG 过宽;检测 IAM Role 资源 *;检测 S3 桶策略;Shift Left IaC 扫描。

4. **解释 Shift Left 及其与 CSPM 的关系。**
   - 要点:Shift Left 把检测移到 CI/IaC 阶段;CSPM 是部署后兜底;两者结合实现预防+检测;Checkov/tfsec 在 CI 阶段拦截。

5. **多云场景下如何统一 CSPM?**
   - 要点:多云 CSPM (Wiz/Prisma);统一规则映射 (CIS Cross-Cloud);策略即代码 (OPA);配置标准化 (Terraform)。

6. **KSPM 与 K8s NetworkPolicy 的关系?**
   - 要点:KSPM 检测 NetworkPolicy 配置 (是否有 deny-all);NetworkPolicy 是控制机制;KSPM 验证控制是否正确部署。

7. **CSPM 自动修复的风险与缓解?**
   - 要点:误判导致业务中断;缓解:生产仅告警+工单;Dev 全自动;dry-run 模式;回滚机制;例外白名单。

8. **如何衡量 CSPM 成熟度?**
   - 要点:控制项覆盖率;finding 平均修复时间 (MTTR);例外率;漂移频率;Shift Left 拦截率;合规分数趋势。

9. **CSPM 如何检测 IAM 权限蔓延?**
   - 要点:与 CIEM 重叠;分析 IAM 策略 vs 实际使用 (CloudTrail);标记未使用权限;推荐收敛;Access Analyzer 跨账号检测。

10. **CIS Benchmark 与企业自定规则如何取舍?**
    - 要点:CIS 作为基线;企业自定更严 (业务场景);合规驱动 (PCI/HIPAA);按风险排序;定期复审。
