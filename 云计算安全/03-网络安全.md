> 一句话定位：网络隔离是云安全的物理栅栏，但 SDN 时代网络配置都通过 API 完成——配置错误就是漏洞。

## 一、问题定义

### 1.1 解决什么问题

云网络安全的特殊性：

1. **网络是软件定义的 (SDN)** — 配置即资源，API 创建即生效
2. **多租户共享底层** — 隔离由 CSP 保证，但配置由租户负责
3. **公网可达性** — 一个错误配置就暴露全世界
4. **流量加密默认开启但可选关闭** — mTLS / TLS / PrivateLink
5. **跨账号跨区域流量** — 复杂的流量路径

🔥 **典型事故**：
- Capital One 2019：WAF SSRF + SG 过宽
- 阿里云 2022：未授权 RDS 公网暴露
- 多家 MongoDB Atlas 2020：白名单设为 0.0.0.0/0

### 1.2 与传统网络的差异

| 维度 | 传统网络 | 云网络 |
|------|----------|--------|
| 边界 | 物理防火墙 | VPC + SG + NACL |
| 配置 | CLI / Console | API / IaC |
| 拓扑 | 静态 | 弹性 (按需创建) |
| 加密 | 可选 (内部可信) | 默认 TLS / mTLS |
| 监控 | NetFlow / SPAN | VPC Flow Logs |
| 多租户 | VLAN | VPC / Namespace |
| 公网 | NAT / PAT | IGW / NAT GW / LB |

### 1.3 云厂商差异概述

| 概念 | AWS | Azure | GCP | 阿里云 | 华为云 |
|------|-----|-------|-----|--------|--------|
| VPC | VPC | VNet | VPC | VPC | VPC |
| 安全组 | Security Group | NSG | Firewall | 安全组 | 安全组 |
| NACL | Network ACL | N/A (NSG 覆盖) | N/A | 网络 ACL | 网络 ACL |
| WAF | AWS WAF | Azure WAF | Cloud Armor | WAF | WAF |
| DDoS | Shield Standard/Advanced | DDoS Protection | Cloud Armor | Anti-DDoS | AAD |
| PrivateLink | PrivateLink | Private Link | Private Service Connect | PrivateLink | ELB |

## 三、原理与机制

### 3.1 直觉：VPC = 软件定义的"机房"

```
传统机房:
┌─────────────────────────────┐
│  防火墙 (硬件)                │
│  ├─ DMZ 区                    │
│  ├─ App 区                    │
│  └─ DB 区                     │
└─────────────────────────────┘

云上 VPC:
┌─────────────────────────────┐
│  VPC (10.0.0.0/16)            │
│  ├─ public subnet (有 IGW)     │
│  ├─ private subnet (无 IGW)    │
│  ├─ mgmt subnet                │
│  └─ SG + NACL 控制流量          │
└─────────────────────────────┘
```

### 3.2 安全组 (SG) vs NACL

| 维度 | SG | NACL |
|------|-----|------|
| 状态 | 有状态 (返回流量自动放行) | 无状态 (需双向规则) |
| 规则 | 仅 Allow (默认拒绝) | Allow + Deny |
| 关联 | ENI / 实例 | 子网 |
| 评估 | 全部规则合并 | 按编号顺序匹配 |
| 用途 | 实例级精细控制 | 子网级粗粒度边界 |
| 跨账号 | 引用其他账号 SG | 不能引用 |

⚠️ **常见误区**：NACL 因为无状态，配置 TCP 不仅要源端口还要临时端口范围 (1024-65535)。

### 3.3 形式化：网络分段的安全不变量

🎓 **零信任网络不变量**：
$$
\forall p_1, p_2 \in Pods: Default(p_1 \xrightarrow{allow} p_2) = False
$$
$$
Allow(p_1 \to p_2) \iff \exists Rule: (p_1.label \to p_2.label, port) \in NP
$$

(NetworkPolicy 显式允许才放行)

### 3.4 WAF 工作机制

```
客户端 → CloudFront/CDN → WAF → ALB → EC2/ECS

WAF 检查内容:
├─ L7 规则 (SQL Injection, XSS)
├─ Rate Limiting (100 req/5min/IP)
├─ Geo Blocking (拒绝指定国家)
├─ Bot 防护 (JS Challenge)
├─ IP Reputation (恶意 IP)
└─ Custom Rules (基于 Header/URI/Query)
```

## 四、算法 / 流程

### 4.1 SG 流量评估

```
输入: 数据包 (src_ip, dst_ip, src_port, dst_port, protocol, direction)
输出: Allow / Deny

1. 查 dst 实例的 SG (inbound rules)
2. for each rule r:
     if r.protocol match AND r.port match AND r.source match:
         return Allow
3. return Deny (默认拒绝)

# 状态化: 返回流量自动 Allow (无需对应 outbound 规则)
```

### 4.2 NACL 评估 (按编号)

```
输入: 数据包
输出: Allow / Deny

1. 按 rule number 升序遍历
2. 第一条匹配的 rule 决定 (Allow 或 Deny)
3. 无匹配 → 默认 Deny (rule * )
4. 返回流量也需匹配 (无状态)
```

### 4.3 DDoS 防护三层架构

```
L1: 边缘 (CloudFront/Shield) — 流量清洗
   ├─ Anycast 网络分散流量
   ├─ 地理过滤
   └─ SYN cookie / Challenge

L2: 区域 (WAF + ALB)
   ├─ Rate limit per IP
   ├─ Bot 防护
   └─ 应用层规则

L3: 主机 (EC2/SG)
   ├─ SG 收紧
   ├─ conntrack 表保护
   └─ 应用限流
```

resource "aws_network_acl" "db" {

    rule_no    = 200

  scope       = "REGIONAL"

    allow {}

    name     = "sql-injection"
    priority = 1
    action { block {} }

      sqli_match_statement {
        field_to_match { body {} }

          priority = 0
          type     = "URL_DECODE"

      }
    }

      cloudwatch_metrics_enabled = true
      sampled_requests_enabled   = true
      metric_name                = "sql-injection"

    name     = "xss"
    priority = 2
    action { block {} }
    
    statement {
      xss_match_statement {
        field_to_match { body {} }
        text_transformation { priority = 0; type = "URL_DECODE" }
      }
    }

      cloudwatch_metrics_enabled = true
      sampled_requests_enabled   = true

## 七、常见陷阱与最佳实践 ⚠️

| 陷阱 | 后果 | 对策 |
|------|------|------|
| SG 用 0.0.0.0/0 开 SSH | 全网爆破 | 🔥 仅限堡垒机 IP |
| RDS 公网可访问 | 数据泄露 | private subnet + 安全组收紧 |
| 不开 VPC Flow Logs | 事故无法取证 | 🔥 Flow Logs → S3 (不可变) |
| NACL 配置忘返端口 | 应用不通 | 临时端口 1024-65535 双向 |
| NAT GW 单 AZ | AZ 故障断网 | 多 AZ NAT GW + 路由 |
| 跨 VPC 用公网 | 流量费 + 暴露 | VPC Peering / PrivateLink |
| 不区分 IGW 和 NAT GW | private 子网也公网可达 | private 子网不绑 IGW |
| WAF 用默认规则 | 漏报多 | 启用托管规则 + 自定义规则 + 限流 |
| 没有 DDoS 防护 | 大流量打挂业务 | Shield Advanced / Cloud Front 前置 |
| K8s 不用 NetworkPolicy | Pod 互通无隔离 | 默认 deny + 显式 allow |
| 不监控异常流量 | 横向移动无感知 | VPC Flow Logs + GuardDuty |
| mTLS 不轮换证书 | 长期暴露 | cert-manager 自动轮换 |

### 7.1 工程重点 (🔥)

1. **三层子网** — public / private / db 严格分离
2. **SG 优先于 NACL** — 实例级精控
3. **Flow Logs 强制开** — 取证必需
4. **0.0.0.0/0 仅 80/443** — 其他端口收紧
5. **NAT GW 多 AZ** — 避免 AZ 故障断网
6. **WAF + Shield** — DDoS + L7 防护
7. **K8s NetworkPolicy 默认拒绝** — 零信任网络

## 十、综合面试题

1. **设计一个生产级 VPC 架构（多 AZ + 三层子网 + 高可用）。**
   - 要点：3 AZ；public/private/db/mgmt 子网；IGW + NAT GW 多 AZ；路由表分层；SG 引用；NACL 兜底；Flow Logs 强制开。

2. **Capital One 事故中网络层失误是什么？**
   - 要点：WAF SSRF 让攻击者访问元数据服务；SG 允许 WAF → S3 流量过宽（应限定 bucket）；应该用 IMDSv2 + 收紧 SG + VPC Endpoint。

3. **如何实现零信任网络？**
   - 要点：身份 + 设备 + 上下文 + 微分段；K8s NetworkPolicy 默认拒绝；mTLS 服务间认证；BeyondCorp 模型；持续验证。

4. **解释 BGP 劫持及云上防护。**
   - 要点：攻击者宣告更优 BGP 路由劫持流量；云上通过 RPKI / BGPsec 防护；CSP 内部网络不受影响；多云备份可降风险。

5. **DDoS 攻击类型与防护策略。**
   - 要点：L3/4 (SYN flood, 反射放大) 用 Anycast + CloudFront；L7 (HTTP flood, Slowloris) 用 WAF + Rate Limit；应用层用 circuit breaker。

6. **K8s NetworkPolicy 默认允许还是拒绝？**
   - 默认允许；需用 `default-deny-all` 策略改为拒绝；CNI 必须支持（Calico/Cilium）。

7. **跨 VPC 通信的几种方式及适用场景。**
   - 要点：VPC Peering (一对一简单)；TGW (多对多 + 路由)；PrivateLink (私有访问服务)；VPN/Direct Connect (混合云)。

8. **WAF 的规则集如何设计？**
   - 要点：托管规则 (OWASP Top 10)；自定义规则 (业务白名单)；Rate Limit；Geo Block；机器人挑战；规则按优先级。

9. **如何检测横向移动？**
   - 要点：VPC Flow Logs + 异常端口；GuardDuty 发现异常连接；K8s NetworkPolicy + Falco；EDR + 行为分析。

10. **mTLS 在 Service Mesh 中如何实现？**
    - 要点：Istio/Linkerd sidecar 注入；cert-manager 签发证书；SPIFFE 身份；自动轮换；零信任服务间通信。
