## 一 问题定义

### 1.1 业务痛点

1. **单点依赖**：单区域部署，区域故障即业务全瘫（2021 OVH 火灾、2023 AWS us-east-1 故障）。
2. **备份可篡改**：传统备份管理员可删，勒索软件第一目标就是备份。
3. **RTO/RPO 不达标**：业务承诺 4 小时 RTO，实际备份恢复需 24 小时。
4. **演练不足**：备份"我以为能恢复"，真实切换才发现问题。
5. **勒索软件进化**：双重勒索（加密+公开），即使有备份也要付赎金防公开。

### 1.2 灾难类型

| 类型 | 频率 | 影响 | 案例 |
|------|------|------|------|
| 区域级故障 | 罕见 | 大范围 | AWS us-east-1（2023） |
| 可用区故障 | 偶尔 | 中范围 | AWS us-east-1a（2017） |
| 服务故障 | 较常见 | 单服务 | Azure AD（2021） |
| 网络故障 | 常见 | 局部 | BGP 路由（2024） |
| 数据丢失 | 偶尔 | 严重 | GitLab（2017） |
| 勒索软件 | 上升 | 灾难性 | Colonial Pipeline（2021） |
| 内部破坏 | 罕见 | 灾难性 | Twitter 前员工（2022） |
| 厂商倒闭 | 罕见 | 灾难性 | Code Spaces（2014） |
| 战争 / 政策 | 上升 | 区域性 | 俄乌冲突（2022） |

### 1.3 反模式

- ❌ 备份存同区域同桶，区域故障即丢。
- ❌ 备份桶管理员可删，勒索软件第一目标。
- ❌ 演练只到 "备份成功"，没到"恢复成功"。
- ❌ DR 计划文档化但无人执行过。
- ❌ RPO 声称 0（同步），实际跨区异步复制有延迟。
- ❌ 勒索软件防御只装 EDR，无不可变备份。

## 三 原理与机制

### 3.1 RPO / RTO 模型 🎓

**形式化定义**：

- $RPO$：可接受数据丢失量（时间窗口）。
  - $RPO = 0$：零数据丢失（同步复制）。
  - $RPO = 1h$：最多丢失 1 小时数据（异步复制间隔）。
- $RTO$：可接受业务中断时间（恢复时间）。
  - $RTO = 0$：零中断（active-active）。
  - $RTO = 4h$：最多 4 小时恢复。

**DR 模式与 RPO/RTO 对应**：

| 模式 | RPO | RTO | 成本 |
|------|-----|-----|------|
| Backup & Restore | 小时-天 | 天 | 低 |
| Pilot Light | 分钟-小时 | 小时 | 中 |
| Warm Standby | 秒-分钟 | 分钟 | 中高 |
| Multi-Site Active-Active | 0-秒 | 接近 0 | 高 |

### 3.2 跨区域复制 🎓

**S3 Cross-Region Replication（CRR）**：

```
源桶 us-east-1
    ↓ 异步复制（秒级延迟）
目标桶 eu-west-1
```

**RPO**：秒级（依赖对象大小），新增对象 15 秒内复制。
**注意**：删除操作默认不复制（防止源桶被删时目标桶也丢）；版本控制保护误删。

**DynamoDB Global Tables**：

```
us-east-1 表 ↔ eu-west-1 表 ↔ ap-northeast-1 表
三方双向同步
```

**RPO**：秒级（最终一致性）。
**注意**：冲突写入由系统决定（last-writer-wins），应用需幂等。

**Aurora Global Database**：

```
主集群 us-east-1
    ↓ 异步复制（< 1 秒）
只读副本 eu-west-1, ap-northeast-1
```

**RPO**：< 1 秒。
**RTO**：分钟级（提升只读副本为主）。

**RDS Multi-AZ**：

```
主 us-east-1a
    ↓ 同步复制
备 us-east-1b
```

**RPO**：0（同步）。
**RTO**：60-120 秒（自动 failover）。

### 3.3 不可变备份机制 🎓

**3-2-1 备份规则**：
- 3 份副本（生产 + 2 备份）
- 2 种媒介（如磁盘 + 云）
- 1 份异地（防区域灾难）

**3-2-1-1-0 规则（云时代升级）**：
- 3 份副本
- 2 种媒介
- 1 份异地
- 1 份离线 / Air Gap
- 0 错误（演练验证）

**WORM 桶不可变性**：

```
Backup Vault (S3 + Object Lock COMPLIANCE)
    - 不可删除（直到到期）
    - 不可修改
    - root 也不能删
    - 加 KMS 加密
```

**勒索软件防御关键**：
- 即使攻击者拿到 admin 凭证，备份桶仍不可删（COMPLIANCE 模式）。
- 备份服务账号与生产账号隔离（不同 AWS 账号）。
- KMS Key 禁用 = 加密粉碎（紧急情况）。

### 3.4 勒索软件杀伤链 🎓

```
1. Initial Access（初始访问）
   - 钓鱼邮件
   - RDP 暴力破解
   - 漏洞利用（VPN、Active Directory）
   - 第三方供应链

2. Persistence & Privilege Escalation（持久化与提权）
   - 创建账号
   - Mimikatz 抓凭证
   - Kerberoasting
   - 利用 ZeroLogon / PrintNightmare

3. Discovery & Lateral Movement（发现与横向移动）
   - 网络扫描
   - BloodHound 图谱
   - PSExec / WMI / SMB 横向
   - Cobalt Strike beacon

4. Collection & Exfiltration（收集与外泄）
   - 压缩敏感数据
   - Rclone / mega.io 外传
   - 双重勒索准备

5. Encryption（加密）
   - 部署 LockBit / BlackCat / ALPHV
   - 加密文件系统
   - 删除备份（VSS shadow copy）
   - 删除备份服务账号

6. Extortion（勒索）
   - 留勒索信
   - 双重勒索：付钱解密 + 不公开数据
   - 三重勒索：+ DDoS
```

**防御关键点**：
- **入口**：钓鱼防护（邮件网关、MFA）、补丁管理（VPN/AD 漏洞）。
- **横向**：网络分段、EDR 检测 Mimikatz/PSExec、最小权限。
- **备份**：WORM 不可变 + Air Gap + 跨账号 + 跨区域。
- **响应**：IR Playbook + 隔离 + 不要付赎金（鼓励攻击）。

### 3.5 DR 演练级别 🎓

**演练级别**：

| 级别 | 类型 | 频率 | 目的 |
|------|------|------|------|
| L1 | 桌面推演 | 季度 | 文档审查、流程梳理 |
| L2 | 模拟演练 | 半年 | 测试部分流程，无真实切换 |
| L3 | 故障注入 | 季度 | Chaos Engineering，注入故障 |
| L4 | 真实切换 | 年度 | 真实 failover + failback |

**Chaos Engineering 工具**：
- AWS Fault Injection Service（FIS）
- Gremlin
- Chaos Monkey（Netflix）
- Chaos Mesh（K8s）
- Litmus

### 4.1 DR 切换流程

```
function DISASTER_RECOVERY_FAILOVER(disaster_event):
    # 1. 灾难确认
    if not is_disaster(disaster_event):
        return
    
    # 2. 通知决策
    notify_incident_commander(disaster_event)
    decision = await_decision()  # 人工决策是否切换
    
    if decision == "FAILOVER":
        # 3. 切换 DNS
        dns.update_records(primary=dns.secondary)
        
        # 4. 提升备份为主
        db.promote_read_replica(secondary)
        
        # 5. 启动完整应用栈
        terraform.apply(dr_workspace)
        
        # 6. 流量切换
        load_balancer.redirect(secondary)
        
        # 7. 验证
        health_check = verify_service()
        
        if health_check:
            notify("Failover successful")
        else:
            rollback()
    
    elif decision == "WAIT":
        monitor_primary()
```

### 4.4 WORM 备份生命周期

```
function BACKUP_LIFECYCLE():
    # 1. 每日备份
    daily_backup = create_backup(production_data)
    
    # 2. 上传到 WORM 桶
    s3.put_object(
        bucket="backup-worm",
        key=f"daily/{date}/backup.zip",

            "Mode": "COMPLIANCE",
            "RetainUntilDate": now + 365 days,  # 1 年保留
        },
    )
    
    # 3. 异地复制
    s3.replicate_to(
        source="backup-worm-us-east-1",
        target="backup-worm-eu-west-1",
    )
    
    # 4. 跨账号（防 admin 误删）
    s3.replicate_to(
        source="backup-worm-us-east-1",
        target="backup-worm-disaster-account",  # 不同 AWS 账号
    )
    
    # 5. 月度验证
    if date.day == 1:
        verify_backup(f"daily/{yesterday}/backup.zip")
    
    # 6. 长期归档（年度）
    if date.day == 1 and date.month == 1:
        archive_to_glacier(
            key=f"yearly/{date.year}/backup.zip",
            retention=2555 days,  # 7 年（SOX）
        )
```

## 六 代码/配置示例

### 6.1 教学示例：S3 跨区复制 + WORM

```python
import boto3
import json
from datetime import datetime, timedelta

class ImmutableBackup:
    """不可变备份"""

    def __init__(self, primary_bucket, dr_bucket, dr_account_role):
        self.s3 = boto3.client("s3")
        self.primary = primary_bucket
        self.dr = dr_bucket
        self.dr_role = dr_account_role  # 跨账号 Role

    def backup(self, data, retention_days=365):
        timestamp = datetime.utcnow().strftime("%Y%m%d-%H%M%S")
        key = f"daily/{timestamp}/backup.json"

        # 1. 上传到主桶（COMPLIANCE 模式）
        self.s3.put_object(
            Bucket=self.primary,
            Key=key,
            Body=json.dumps(data).encode(),
            ContentType="application/json",
            ServerSideEncryption="aws:kms",
            SSEKMSKeyId="alias/backup-cmk",
            ObjectLockMode="COMPLIANCE",
            ObjectLockRetainUntilDate=datetime.utcnow() + timedelta(days=retention_days),
        )

        # 2. 跨账号复制到 DR 桶
        sts = boto3.client("sts")
        dr_creds = sts.assume_role(
            RoleArn=self.dr_role,
            RoleSessionName="backup-replication",
        )["Credentials"]

        dr_s3 = boto3.client("s3", aws_access_key_id=dr_creds["AccessKeyId"],
                             aws_secret_access_key=dr_creds["SecretAccessKey"],
                             aws_session_token=dr_creds["SessionToken"])

        dr_s3.put_object(
            Bucket=self.dr,
            Key=key,
            Body=json.dumps(data).encode(),
            ServerSideEncryption="aws:kms",
            ObjectLockMode="COMPLIANCE",
            ObjectLockRetainUntilDate=datetime.utcnow() + timedelta(days=retention_days),
        )

        return {"primary": f"s3://{self.primary}/{key}", "dr": f"s3://{self.dr}/{key}"}

    def restore(self, backup_key, target_bucket):
        """恢复（需 WORM 期内）"""
        self.s3.copy_object(
            CopySource={"Bucket": self.primary, "Key": backup_key},
            Bucket=target_bucket,
            Key=backup_key,
        )
```

### 6.2 生产级 Terraform：完整 DR 方案

```hcl
# variables.tf
variable "primary_region" { default = "us-east-1" }
variable "dr_region"      { default = "us-west-2" }
variable "primary_account_id" {}
variable "dr_account_id" {}

# primary 备份桶（WORM + KMS）
resource "aws_s3_bucket" "backup_primary" {
  bucket = "${var.project}-backup-primary"
  provider = aws.primary
}

resource "aws_s3_bucket_object_lock_configuration" "backup_primary" {
  bucket = aws_s3_bucket.backup_primary.id
  rule {
    default_retention {
      mode  = "COMPLIANCE"
      days  = 365
    }
  }
}

resource "aws_s3_bucket_versioning" "backup_primary" {
  bucket = aws_s3_bucket.backup_primary.id
```

### 6.4 DR 演练 Playbook

```python
class DRDrillPlaybook:
    """DR 演练剧本"""

    def quarterly_tabletop(self):
        """季度桌面推演"""
        scenarios = [
            "AWS us-east-1 完全故障",
            "数据库被勒索软件加密",
            "内部员工作恶删除生产数据",
            "DNS 被劫持",
            "KMS Key 被禁用",
        ]
        for scenario in scenarios:
            self.run_tabletop(scenario)

    def semi_annual_simulation(self):
        """半年模拟演练"""
        # 1. 在 DR 区域恢复备份
        restored = self.restore_to_dr(backup_id="latest")
        
        # 2. 验证业务功能
        smoke_tests = self.run_smoke_tests(restored)
        
        # 3. 测量 RTO
        rto_actual = measure_rto(start_time, end_time)
        
        # 4. 测量 RPO
        rpo_actual = measure_rpo(backup_time, restore_time)
        
        # 5. 报告
        report = {
            "scenario": "Quarterly DR simulation",
            "rto_target": "4 hours",
            "rto_actual": rto_actual,
            "rpo_target": "1 hour",
            "rpo_actual": rpo_actual,
            "smoke_tests": smoke_tests,
            "issues": identify_issues(),
        }
        return report

    def annual_failover(self):
        """年度真实切换"""
        # 1. 通知业务
        notify_business("DR drill scheduled")
        
        # 2. DNS 切换到 DR
        dns.failover_to_dr()
        
        # 3. 业务在 DR 运行 1 小时
        sleep(3600)
        
        # 4. 验证
        if not verify_business_normal():
            emergency_failback()
        
        # 5. 切回 primary
        dns.failback_to_primary()
        
        # 6. 复盘报告
        generate_report()
```

## 七 常见陷阱与最佳实践

### 7.1 陷阱表 ⚠️

| 陷阱 | 描述 | 后果 | 规避 |
|------|------|------|------|
| 备份同区同桶 | 同区域 | 区域故障即丢 | 跨区复制 + 跨账号 |
| 备份桶可删 | GOVERNANCE 或无锁 | 勒索删备份 | COMPLIANCE + 跨账号 |
| 演练只到备份 | 不测恢复 | 恢复时才发现问题 | 真实恢复测试 |
| DR 文档无人执行 | 仅纸面 | 真灾难时瘫痪 | 年度真实切换 |
| RPO 声称 0 | 实际异步 | 数据丢失 | 测量实际 RPO |
| 单一 KMS Key | 加密 + 备份共用 | Key 删除全丢 | 备份用独立 Key |
| 备份服务账号权限大 | Admin 权限 | 被攻破即删备份 | 最小权限 + 跨账号 |
| DNS 无 health check | 主备都死 | 流量仍指主 | Health check + 自动 failover |
| Failover 不测试 | 切换失败 | RTO 不达标 | 季度演练 |
| 勒索只装 EDR | 无不可变备份 | 备份被删 | WORM + Air Gap |

### 7.2 最佳实践

1. **3-2-1-1-0 规则**：3 份副本、2 媒介、1 异地、1 离线、0 错误。
2. **WORM COMPLIANCE**：备份桶 COMPLIANCE 模式 + 跨账号 + 跨区。
3. **演练常态化**：季度桌面、半年模拟、年度真实切换。
4. **RPO/RTO 测量**：实际测量，不只看 SLA。
5. **多区域 Active-Active**：关键业务跨区部署，DNS 自动 failover。
6. **KMS 独立**：备份 KMS 与生产 KMS 独立，防加密粉碎影响备份。
7. **Air Gap**：核心备份离线 / 物理隔离，勒索软件不可达。
8. **混沌工程**：FIS / Gremlin 注入故障，验证韧性。
9. **勒索防御**：EDR + 不可变备份 + IR + 不要付赎金。
10. **业务连续性**：BCP 文档化 + 人员培训 + 通信预案。

## 九 面试速答 ⭐

**Q1：RPO 和 RTO 区别？**
RPO（Recovery Point Objective）：可接受数据丢失量（时间），如 RPO=1h 表示最多丢 1 小时数据。RTO（Recovery Time Objective）：可接受业务中断时间（恢复时间），如 RTO=4h 表示最多 4 小时恢复。

**Q2：DR 4 种模式？**
1) Backup & Restore（备份恢复）：低成本，RPO/RTO 小时-天；2) Pilot Light（试点）：核心服务最小运行，RTO 30 分钟-4 小时；3) Warm Standby（暖备）：完整环境缩小规模，RTO 10-30 分钟；4) Multi-Site Active-Active（多活）：RTO 接近 0，成本最高。

**Q3：3-2-1-1-0 备份规则？**
3 份副本、2 种媒介、1 份异地、1 份离线（Air Gap）、0 错误（演练验证）。云时代升级自 3-2-1，增加 Air Gap（防勒索）和演练验证。

**Q4：勒索软件双重勒索？**
传统勒索：加密数据索要赎金解密。双重勒索：先外泄数据，再加密，威胁不付钱就公开。三重勒索：再加 DDoS。即使有备份，攻击者仍可威胁公开数据。

**Q5：备份桶为什么要 COMPLIANCE 模式？**
GOVERNANCE 模式有 bypass 权限的人可删（含 admin）。COMPLIANCE 模式到期前任何人都不能删，包括 root。勒索软件拿到 admin 也不能删备份，是关键防御。

**Q6：备份为什么要跨账号？**
单账号内 admin 可删任何资源（含 WORM 桶配置）。跨账号后，攻击者拿到主账号凭证，DR 账号仍安全。跨账号 + 跨区 + WORM = 三重防御。

**Q7：DR 演练频率？**
季度桌面推演（文档审查、流程梳理）；半年模拟演练（部分流程测试）；年度真实切换（真实 failover + failback）。Chaos Engineering 可更频繁注入小故障。

**Q8：Aurora Global Database 跨区 DR？**
主集群 + 跨区只读副本，异步复制 < 1 秒延迟。灾难时提升只读副本为主，RTO < 1 分钟。RPO < 1 秒（依赖复制延迟）。

**Q9：勒索软件入口？**
钓鱼邮件（最常见）、RDP 暴力破解、VPN/AD 漏洞（ZeroLogon、PrintNightmare）、第三方供应链、被盗凭证。防御：MFA + 补丁 + EDR + 不可变备份。

**Q10：为什么不要付赎金？**
1) 鼓励攻击者继续；2) 不一定解密（30% 概率不付）；3) 数据已外泄仍可能被卖；4) 法律禁止（OFAC 制裁名单）；5) 有备份就不需要付。建议：预防 + 不可变备份 + IR + 报警。

## 十 综合面试题

1. **设计题**：电商 SaaS 平台需 4 小时 RTO、15 分钟 RPO，如何设计 DR？
   要点：1) 跨区部署（us-east-1 + us-west-2）；2) Aurora Global Database（RPO < 1s）；3) S3 CRR（应用数据）；4) EKS 跨区（应用层）；5) Route53 Health Check + Failover（RTO 5 分钟）；6) WORM 备份（每日 + 跨账号）；7) 季度演练；8) 实际成本：单区 ×2 + 备份存储。

2. **场景题**：发现生产数据库被勒索软件加密，怎么办？
   要点：1) 立即隔离受影响实例；2) 切断网络防横向；3) 不要付赎金；4) 从 WORM 备份恢复（验证完整后）；5) CloudTrail 查攻击路径；6) rotate 所有凭证；7) 评估数据外泄（双重勒索）；8) 通知监管（GDPR 72h）；9) 复盘 + 加固。

3. **原理题**：S3 Object Lock COMPLIANCE 和 GOVERNANCE 区别？
   要点：COMPLIANCE 模式到期前任何人都不能删，包括 root，强合规；GOVERNANCE 模式有 `s3:BypassGovernanceRetention` 权限可绕过，治理用。备份桶用 COMPLIANCE，合规要求强制；日常误删保护用 GOVERNANCE。

4. **场景题**：AWS us-east-1 故障，业务需切换到 us-west-2，怎么做？
   要点：1) Route53 Health Check 自动检测（60s）；2) DNS Failover 到 DR；3) 提升 Aurora 只读副本为主；4) EKS 跨区部署已运行（Warm Standby）；5) 验证业务功能；6) 故障恢复后 failback；7) 测试数据一致性；8) 复盘改进。

5. **设计题**：备份桶防勒索软件怎么设计？
   要点：1) WORM COMPLIANCE 模式 365 天；2) 跨账号复制（DR 账号）；3) 跨区复制（防区域灾难）；4) 独立 KMS Key（防加密粉碎）；5) 备份服务账号最小权限；6) SCP 禁止删除桶；7) CloudTrail 监控 DeleteObject 尝试；8) 月度恢复测试。

6. **对比题**：AWS Backup 和 Veeam 怎么选？
   要点：1) AWS Backup：原生、S3/EBS/RDS/DynamoDB 一致体验、低成本；2) Veeam：跨云、虚拟机、物理机、Air Gap；3) 全 AWS → AWS Backup；4) 多云/混合云 → Veeam；5) 关键数据两者结合：AWS Backup + Veeam Air Gap。

7. **原理题**：Chaos Engineering 怎么做？
   要点：1) 假设（"AZ 故障业务仍可用"）；2) 注入故障（FIS 终止 EC2、网络延迟）；3) 监控指标（错误率、延迟）；4) 验证假设；5) 修复发现的问题；6) 渐进式（先测试环境，后生产）；7) 自动化（定期执行）；8) GameDay（团队演练）。

8. **场景题**：DR 演练发现 RTO 8 小时（目标 4 小时），怎么改进？
   要点：1) 分析瓶颈（备份恢复慢？DNS 切换慢？应用启动慢？）；2) 优化：增量备份、并行恢复、预热 DR 实例；3) 自动化（Terraform + Ansible）；4) 升级 DR 模式（Pilot Light → Warm Standby）；5) 重测；6) 持续优化至达标。

9. **设计题**：金融系统 RPO=0（零数据丢失）怎么做？
   要点：1) 同步复制（RDS Multi-AZ，主备同步）；2) 跨区同步（Aurora Global 同步复制，性能开销大）；3) Quorum 写入（多数派确认）；4) 两阶段提交（2PC，分布式事务）；5) 应用幂等；6) 故障切换后冲突解决（last-writer-wins 或人工）；7) 成本高，仅核心交易系统。

10. **原理题**：勒索软件怎么删备份？怎么防？
    要点：1) 攻击者拿到 admin 后尝试：DeleteObject、DeleteBucket、删除 VSS shadow copy、禁用备份服务；2) 防御：WORM COMPLIANCE（不可删）、跨账号（凭证隔离）、Air Gap（网络隔离）、SCP 禁止删除桶、CloudTrail 监控 DeleteObject 异常、独立 KMS（加密粉碎防护）。
