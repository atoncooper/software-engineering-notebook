# §8 - 工作负载保护平台 (CWPP)

> 一句话定位：CWPP 是工作负载的运行时守护者——从镜像扫描到行为基线，覆盖容器、VM、Serverless 全生命周期。
>
> 标记：⭐高频 🔥工程重点 📜论文/标准 ⚠️易错点 🎓学术深度 🏭工业实战

## 一、问题定义

### 1.1 解决什么问题

工作负载运行时面临的风险：

1. **已知漏洞利用** — CVE 未及时修复
2. **未知攻击** — 0day + 异常行为
3. **配置漂移** — 运行时被修改
4. **横向移动** — 容器间逃逸
5. **数据外泄** — 异常网络连接

🔥 **典型场景**：
- 容器内启动 shell (挖矿/后门)
- 异常外连 (C2 服务器)
- 文件被篡改 (植入 webshell)
- 系统调用异常 (容器逃逸)

### 1.2 CWPP 与 CSPM 的边界

| 维度 | CSPM | CWPP |
|------|------|------|
| 关注面 | 配置面 | 运行时 |
| 时机 | 部署后扫描 | 运行中监控 |
| 检测对象 | 云资源 (S3/SG/IAM) | 工作负载 (容器/VM) |
| 数据源 | 云 API | 内核事件 / Agent |
| 响应 | 修改配置 | 隔离/终止进程 |

### 1.3 云厂商差异概述

| 概念 | AWS | Azure | GCP | 阿里云 | 华为云 |
|------|-----|-------|-----|--------|--------|
| CWPP | Inspector | Defender for Servers | Event Threat Detection | HSS | HSS |
| 容器保护 | Inspector + GuardDuty | Defender for Containers | GKE Security | 容器服务安全 | HSS 容器版 |
| EDR | System Manager | Defender for Endpoint | Chronicle | 堡垒机 + EDR | 堡垒机 |
| 漏洞扫描 | Inspector | Defender Vulnerability Mgmt | Container Analysis | 漏洞扫描 | VSS |

## 三、原理与机制

### 3.1 Agent vs Agentless

```
Agent 模式:
   宿主机
   ├─ Container 1 (含 Agent sidecar)
   ├─ Container 2 (含 Agent sidecar)
   └─ Container 3 (含 Agent sidecar)
   
   优势: 实时 + 内核事件 + 详细数据
   劣势: 资源开销 + 部署维护

Agentless 模式:
   云 API
   ↓
   CWPP 扫描
   ├─ 配置检查
   ├─ 镜像扫描
   └─ 快照分析
   
   优势: 无侵入 + 易部署
   劣势: 非实时 + 看不到运行时
```

🔥 **现代趋势**：Agentless 用于扫描 (镜像/配置)，Agent 用于运行时 (行为/异常)。

### 3.2 eBPF 工作机制

```
   应用 (用户态)
       │
       │ syscall (open/read/exec/...)
       ▼
   ┌─────────────┐
   │  内核       │
   │  ┌─────────┐│
   │  │ syscall ││
   │  │  hook   ││  ← eBPF 程序挂载点
   │  └─────────┘│
   │      │      │
   │      ▼      │
   │  ┌─────────┐│
   │  │ eBPF    ││  ← 安全规则 (Falco/Tetragon)
   │  │ program ││
   │  └─────────┘│
   │      │      │
   │      ▼      │
   │  事件上报    │
   └─────────────┘
       │
       ▼
   CWPP 引擎 (用户态)
```

🔥 **eBPF 优势**：
- 内核级可见 (所有 syscall)
- 极低开销 (1-3% CPU)
- 无需修改应用
- 无需 sidecar

### 3.3 行为基线学习

```
学习阶段 (7-14 天):
   ├─ 收集所有 syscall
   ├─ 收集网络连接
   ├─ 收集文件访问
   ├─ 收集进程树
   └─ 聚类分析 → 正常模式

检测阶段:
   新事件 vs 基线
   ├─ 匹配 → 正常
   └─ 偏离 → 异常 → 告警

示例:
   基线: nginx 容器只读 /var/www, 只连 80/443
   异常: nginx 突然执行 /bin/bash (异常)
   异常: nginx 突然连 1.2.3.4:4444 (C2)
```

### 3.4 容器逃逸检测

| 逃逸路径 | 检测信号 |
|---------|----------|
| privileged 容器 + 内核漏洞 | syscall: mount, setns |
| 挂载 /var/run/docker.sock | 文件访问 docker.sock |
| 挂载宿主 / | mount syscall |
| CAP_SYS_ADMIN | capability 变更 |
| 内核漏洞利用 (Dirty COW) | 异常 mmap/mprotect |

## 四、算法 / 流程

### 4.1 漏洞管理流程

```
1. 镜像扫描 (CI/CD 阶段)
   ├─ 解压镜像 layer
   ├─ 识别包 (OS/语言依赖)
   ├─ 查询 CVE 数据库
   └─ 输出漏洞 + 严重度 + 修复版本

2. 运行时扫描 (部署后)
   ├─ Agent 定期扫描容器内包
   ├─ 比对 CVE 数据库
   └─ 标记工作负载

3. 修复优先级 (EPSS + 业务影响)
   ├─ EPSS (Exploit Prediction): 利用概率
   ├─ CISA KEV: 已知被利用
   ├─ 业务暴露面: 公网/内部
   ├─ 数据敏感度
   └─ 综合评分 → 优先级

4. 修复
   ├─ 镜像更新 (重新构建)
   ├─ 滚动部署
   └─ 验证
```

### 4.2 运行时检测流程

```
事件源 (syscall / 网络 / 文件)
   │
   ▼
规则匹配 (Falco/Tetragon 规则)
   │
   ├─ 命中 → 计算严重度
   │         ├─ Critical: 终止进程 + 隔离容器
   │         ├─ High: 告警 + 工单
   │         └─ Medium: 仅记录
   └─ 未命中 → 行为基线比对
              ├─ 偏离 > 阈值 → 异常告警
              └─ 正常 → 丢弃
```

### 4.3 FIM 完整性检查

```
基线: 文件 hash + 元数据
   /etc/nginx/nginx.conf: hash=abc, mtime=...
   /usr/bin/nginx: hash=def, mtime=...

定期检查 (每 5 分钟):
   当前 hash vs 基线 hash
   ├─ 一致 → ✓
   └─ 不一致 → 告警 (可能被篡改)

   新文件出现 → 告警 (可能植入)
   文件被删 → 告警 (可能清理痕迹)
```

```python
# tools/cwpp_finding_processor.py
"""处理 CWPP finding,优先级排序 + 自动响应"""
import boto3
import json
from datetime import datetime

inspector = boto3.client('inspector2')
securityhub = boto3.client('securityhub')

class FindingProcessor:
    def __init__(self):
        self.cisa_kev = self._load_cisa_kev()
    
    def _load_cisa_kev(self):
        """加载 CISA KEV (已知被利用漏洞)"""
        # 实际从 https://www.cisa.gov/known-exploited-vulnerabilities
        return set(['CVE-2021-44228', 'CVE-2021-26855', ...])
    
    def compute_priority(self, finding: dict) -> str:
        """综合 EPSS + CISA KEV + 业务影响 计算优先级"""
        cve = finding.get('vulnerability', {}).get('id', '')
        cvss = finding.get('inspectorScore', 0)
        epss = self._get_epss(cve)
        is_kev = cve in self.cisa_kev
        is_public = finding.get('resource', {}).get('public', False)
        
        # 优先级矩阵
        if is_kev and is_public and cvss >= 9:
            return 'P0'   # 立即修复
        elif is_kev or (cvss >= 9 and is_public):
            return 'P1'   # 24 小时内
        elif cvss >= 7:
            return 'P2'   # 7 天内
        elif cvss >= 4:
            return 'P3'   # 30 天内
        else:
            return 'P4'   # 季度
        
        # EPSS 调整
        if epss > 0.5:   # 50% 利用概率
            return max(self._priority_num(prev) - 1, 0)
    
    def _get_epss(self, cve: str) -> float:
        """从 EPSS API 获取利用概率"""
        # https://epss.cyentia.com
        import requests
        r = requests.get(f"https://api.epss.cyentia.com/v1?cve={cve}")
        return float(r.json()['data'][0]['epss'])
    
    def auto_remediate(self, finding: dict):
        """自动响应 (P0 级别)"""
        if finding['priority'] == 'P0':
            # 1. 隔离 EC2 实例
            if finding['resourceType'] == 'EC2':
                self._isolate_ec2(finding['resourceId'])
            
            # 2. 终止可疑 Pod
            elif finding['resourceType'] == 'Pod':
                self._terminate_pod(finding)
            
            # 3. 阻断网络
            self._block_egress(finding)
            
            # 4. 通知
            self._notify(finding)
    
    def _isolate_ec2(self, instance_id: str):
        """隔离 EC2 (修改 SG 拒绝所有流量)"""
        ssm = boto3.client('ssm')
        ssm.send_command(
            InstanceIds=[instance_id],
            DocumentName='AWS-RunShellScript',
            Parameters={'commands': [
                # 应用隔离 SG
                f"aws ec2 modify-instance-attribute --instance-id {instance_id} "
                f"--groups sg-isolation"
            ]}
        )
```

```yaml
# .github/workflows/ci-cwpp.yml
name: CI with CWPP

on: [push, pull_request]

jobs:
  image-scan:
    runs-on: ubuntu-latest
    steps:
    - uses: actions/checkout@v4
    
    # 构建镜像
    - uses: docker/build-push-action@v5
      with:
        context: .
        tags: myapp:${{ github.sha }}
        load: true
    
    # Trivy 扫描
    - name: Trivy Scan
      uses: aquasecurity/trivy-action@master
      with:
        image-ref: myapp:${{ github.sha }}
        format: json
        exit-code: 1
        severity: CRITICAL,HIGH
        ignore-unfixed: true
    
    # Grype 扫描 (交叉验证)
    - name: Grype Scan
      uses: anchore/scan-action@v3
      with:
        image: myapp:${{ github.sha }}
        fail-build: true
        severity-cutoff: high
    
    # 上传 SBOM
    - name: Generate SBOM
      run: |
        curl -sSfL https://raw.githubusercontent.com/anchore/syft/main/install.sh | sh
        syft myapp:${{ github.sha }} -o spdx-json > sbom.spdx.json
    
    - uses: actions/upload-artifact@v4
      with:
        name: sbom
        path: sbom.spdx.json
    
    # 推送 (扫描通过后才推)
    - uses: docker/build-push-action@v5

        context: .
```

## 七、常见陷阱与最佳实践 ⚠️

| 陷阱 | 后果 | 对策 |
|------|------|------|
| Agent 资源开销大 | 影响业务 | 调 resource limit;eBPF 优先 |
| 行为基线太短 | 误报多 | 至少 7-14 天学习期 |
| 规则过于严格 | 业务中断 | 先 alert 模式,稳定后 enforce |
| 镜像扫描仅 OS 包 | 漏应用依赖 | 加语言层扫描 (npm/pip/maven) |
| 仅 push 时扫描 | 跑了几天才发现 CVE | 持续扫描 + KEV 监控 |
| 修复优先级只看 CVSS | 修复错重点 | 加 EPSS + 业务暴露面 |
| Agent 版本不统一 | 漏洞不一 | 集中管理 + 自动更新 |
| 不收集 syscall | 看不到运行时 | 用 eBPF (Falco/Tetragon) |
| 容器逃逸未检测 | 横向移动 | 部署 Tetragon 阻断 |
| 异常外连未告警 | 数据外泄 | 网络白名单 + 异常检测 |

### 7.1 工程重点 (🔥)

1. **eBPF 优先** — 低开销 + 内核可见
2. **Agentless + Agent 结合** — 扫描 + 运行时
3. **EPSS + KEV** — 修复优先级
4. **行为基线 7-14 天** — 减少误报
5. **Critical 自动响应** — 隔离 + 告警
6. **持续扫描** — 不只 push 时
7. **SBOM 持久化** — 漏洞响应可追溯

## 十、综合面试题

1. **设计一个生产级 CWPP 架构。**
   - 要点:Agentless (Inspector) + Agent (Falco/Tetragon);镜像 CI 扫描 + 持续运行时;行为基线 + 规则;EPSS 优先级;P0 自动隔离。

2. **eBPF 如何工作?为什么适合运行时安全?**
   - 要点:内核可编程;syscall hook;低开销 (无 sidecar);无需改应用;Tetragon/Falco 实现。

3. **如何检测容器逃逸?**
   - 要点:Tetragon 阻断 mount/setns syscall;Falco 规则检测 docker.sock 访问;CAP_SYS_ADMIN 检测;privileged 容器禁用。

4. **漏洞修复优先级如何决定?**
   - 要点:CVSS + EPSS + CISA KEV + 业务暴露面 + 数据敏感度;综合评分而非单看 CVSS。

5. **行为基线学习如何减少误报?**
   - 要点:7-14 天学习;聚类分析;分级告警 (Critical 阻断,High 告警,Medium 记录);持续调整。

6. **Agent 部署的挑战?**
   - 要点:资源开销;版本管理;多 OS 支持;Sidecar vs DaemonSet;升级影响业务。

7. **如何处理 CWPP 海量告警?**
   - 要点:严重度过滤;聚合去重;基线过滤;例外白名单;自动响应减量;SLO 修复时限。

8. **Wiz 等 Agentless CWPP 为何流行?**
   - 要点:无侵入部署;分钟级上手;API + 快照分析;但非实时;现代趋势是 Agentless 扫描 + Agent 运行时结合。

9. **Serverless 函数如何 CWPP?**
   - 要点:无 Agent 概念;依赖云厂商 API;CloudTrail + 函数日志;IAM 行为分析;依赖扫描。

10. **CWPP 与 EDR 的边界?**
    - 要点:EDR 关注端点 (PC/笔记本);CWPP 关注服务器/容器;现代趋势融合 (XDR);CWPP 更关注云原生特性。
