## 22.4 原理与机制

### 22.4.1 标准的层级

🎓 **金字塔模型**:

```
              法律法规(强制)
              │
          ├─GDPR / PIPL / 等保
          │
              行业标准(半强制)
              │
          ├─HIPAA / SOX / FedRAMP
          │
              国际标准(自愿)
              │
          ├─ISO 27001 / NIST SP 800-53
          │
              最佳实践(参考)
              │
          ├─CIS Benchmark / CSA CCM
          │
              技术规范(实施)
              │
          └─RFC / OWASP / MITRE
```

### 22.4.2 标准之间的关系

🎓 **互补与重叠**:

- **ISO 27001** vs **NIST SP 800-53**: ISO 是国际通用框架,NIST 是美国联邦标准,两者 80% 重叠,ISO 更抽象,NIST 更具体;
- **CSA CCM** vs **CIS Benchmark**: CCM 是控制框架(应做什么),CIS 是配置基线(怎么做);
- **PCI DSS** vs **ISO 27001**: PCI 是支付卡专用,ISO 是通用,PCI 满足 ISO 大部分要求;
- **等保 2.0** vs **ISO 27001**: 等保是中国法规,ISO 是国际标准,等保更严格,要求本地化。

## 22.10 面试速答 ⭐

**1 分钟答案**:

> 云安全标准按层级:国际标准(ISO/NIST) > 国家法规(GDPR/等保) > 行业标准(PCI/HIPAA) > 实施规范(CIS/OWASP)。学习路径:先 CIS Benchmark(配置),再 NIST 800-53(控制),最后 ISO 27001(体系)。学术必读:Paxos、Raft、PBFT、BeyondCorp。

**3 个高频速答**:

1. **NIST SP 800-207 零信任**: PE+PA+PEP 三组件,持续验证,微分段;
2. **SLSA**: 4 级供应链,从 L1 文档到 L4 双人审核;
3. **ISO 27001**: ISMS 标准,PDCA 循环,114 个控制项。

**答题要点(Q10 Paxos)**:

Paxos 核心思想:
- 三种角色:Proposer、Acceptor、Learner;
- 两阶段:Prepare-Promise、Accept-Accepted;
- Quorum:多数派 Acceptor 同意;
- 关键不变量:已选定的提案不被覆盖;
- 容错:n ≥ 2f+1 容忍 f 个故障;
- 活锁:多个 Proposer 互相打断,需选主解决;
- 应用:Chubby、Spanner、ZooKeeper(Zab 类 Paxos)。
