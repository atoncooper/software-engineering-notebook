## 一、问题定义

### 1.1 解决什么问题

拿到一个串行算法,如何系统化地把它变成并行算法?常见三种失败路径:

1. **直接套模板**:看到循环就 `#pragma omp parallel for`,结果加速比 1.2x——因为存在数据依赖;
2. **过度并行**:把每个操作都并行,通信开销淹没计算;
3. **选错模型**:本该用 MPI 跨节点,却用 OpenMP 单机,扩展性封顶。

本章给出**系统化设计流程**(Foster 方法)+ **理论分析工具**(PRAM/BSP/LogP)+ **可复用模式**(划分/分治/流水/波前),让你在设计阶段就能预估并行度与瓶颈。

### 1.2 与其他章的关系

- §1 §2 给了物理基础与性能定律;
- 本章给出**算法层**的设计与分析工具;
- §4 §5 §6 是这些模式在具体编程模型下的落地。

## 三、原理与机制

### 3.1 Foster 设计方法 🎓

四步法:

```
1. Partitioning (划分)
   把问题数据和计算拆成最小独立单元
   → 产出:任务图(节点=任务,边=依赖)

2. Communication (通信)
   分析任务间数据流动
   → 局部性强的合并,通信多的标记

3. Agglomeration (聚合)
   把小任务合并成大任务
   → 平衡通信开销与并行度

4. Mapping (映射)
   把聚合后任务分配到处理器
   → 考虑负载均衡与 locality
```

**示例**:矩阵乘 $C = AB$
- 划分:$C_{ij}$ 每个元素一个任务,共 $n^2$ 任务;
- 通信:每任务需 $A$ 的第 $i$ 行、$B$ 的第 $j$ 列;
- 聚合:把 $k\times k$ 个 $C_{ij}$ 合并为一个块任务(减少通信);
- 映射:块任务按 2D 网格分配到 $P$ 个处理器。

### 3.2 PRAM 模型 📜🎓

**Parallel Random Access Machine**:理论模型,$P$ 个处理器共享内存,同步执行。

按**读/写冲突**策略分四子模型:

| 模型 | 同时读 | 同时写 |
|------|--------|--------|
| EREW | 互斥 | 互斥 |
| CREW | 并发 | 互斥 |
| ERCW | 互斥 | 并发 |
| CRCW | 并发 | 并发(需规则:COMMON/MAX/PRIORITY) |

**复杂度度量**:
- Work $W$ = 总操作数;
- Depth $D$ = 关键路径;
- 并行度 $\Phi = W/D$;
- $T_P \ge \max(W/P, D)$。

**典型算法复杂度**(CRCW PRAM):

| 算法 | Work $W$ | Depth $D$ |
|------|----------|-----------|
| 前缀和(Blelloch) | $O(n)$ | $O(\log n)$ |
| 排序(Cole) | $O(n\log n)$ | $O(\log n)$ |
| 矩阵乘 | $O(n^3)$ | $O(\log n)$ |
| BFS(单源) | $O(V+E)$ | $O(\log V)$ |

### 3.3 BSP 模型 📜

**Bulk Synchronous Parallel**(Valiant 1990):用**超步(Superstep)** 抽象并行执行。

```
Superstep 1 → Barrier → Superstep 2 → Barrier → ...
```

每超步内:
- 处理器独立计算 $w_i$;
- 发送 $h_i$ 字节通信;
- 全局同步,延迟 $L$。

**单超步时间**:
$$
T_{\text{superstep}} = w + g \cdot h + L
$$
- $w = \max_i w_i$:最慢处理器计算时间;
- $h = \max_i(\text{send}_i, \text{recv}_i)$:最大通信量;
- $g$:带宽倒数;
- $L$:同步延迟。

**总时间**:
$$
T_{\text{BSP}} = \sum_s (w_s + g \cdot h_s + L)
$$

🔥 **工程意义**:BSP 是 Pregel、Flink 的理论根基——每超步结束同步,易容错易调试。

### 3.4 LogP 模型 📜

**LogP** = (L, o, g, P):
- $L$:网络延迟(单消息端到端);
- $o$:处理器收发开销(占用 CPU 时间);
- $g$:带宽倒数(连续消息最小间隔);
- $P$:处理器数。

**约束**:任一时间在途消息数 $\le \lceil L/g \rceil$(容量限制)。

**与 BSP 对比**:

| 维度 | BSP | LogP |
|------|-----|------|
| 同步 | 全局 barrier | 无 barrier,异步 |
| 通信 | 超步批量 | 单消息细粒度 |
| 适合 | 批处理(Pregel) | 细粒度 MPI |

### 3.5 四大设计模式

#### 模式 1:划分(Partitioning)

把数据/任务切成**独立**子集,各处理器独立处理。

```
数据 [a0 a1 a2 ... a999]
  → P=4 划分
处理器0: [a0..a249]
处理器1: [a250..a499]
处理器2: [a500..a749]
处理器3: [a750..a999]
```

**适用**:MapReduce、向量加、数据并行训练(DP)。
**复杂度**:$T_P = T_1/P$(理想),无通信。

#### 模式 2:分治(Divide & Conquer)

递归拆分到基线,各自求解,合并结果。

```
solve(problem):
    if base: return serial_solve(problem)
    (left, right) = split(problem)
    parallel: l = solve(left); r = solve(right)
    return merge(l, r)
```

**适用**:归并排序、矩阵乘(Strassen)、FFT。
**复杂度**(归并排序):
- $W = O(n\log n)$
- $D = O(\log^2 n)$(每层归并 $O(\log n)$)
- $\Phi = n/\log n$

#### 模式 3:流水(Pipeline)

任务分 $k$ 阶段,每阶段一个处理器,数据流过流水线。

```
t:  1  2  3  4  5  6  7
P1: A  B  C  D  .  .  .
P2: .  A  B  C  D  .  .
P3: .  .  A  B  C  D  .
P4: .  .  .  A  B  C  D
```

**适用**:CPU 流水线、指令流水、视频转码、训练的 PP(流水并行)。
**复杂度**:稳态吞吐 $1/\max(t_i)$,启动开销 $k-1$。

#### 模式 4:波前(Wavefront)

按依赖关系**分层推进**,同一层可并行,层间串行。

```
依赖图:           波前分层:
A → C → E          层0: A B
B → C              层1: C
B → D → E          层2: D
                   层3: E
```

**适用**:DP(动态规划)、图像处理(高斯-塞德尔迭代)、LU 分解。
**复杂度**:层数 = 关键路径长度 $D$。

### 3.6 依赖分析与 DAG 调度

任何并行算法都可建模为 **DAG**(任务图):
- 节点 = 任务;
- 边 = 依赖。

**调度目标**:$P$ 个处理器上最小化 makespan。
$$
T_P \ge \max(W/P, D)
$$

**调度策略**:
- **静态**:编译时分配(适合规则 DAG,如矩阵乘);
- **动态**:运行时分配(适合不规则 DAG,如图算法);
- **工作偷取**(TBB/Cilk):每处理器维护队列,闲时从别人队尾偷。

### 3.7 工作偷取(Work Stealing)🔥

```
每处理器 p 有本地双端队列 deque_p:
  - p 自己 push/pop 本地任务(从尾)
  - 其他处理器偷 p 的任务(从头)

调度:
  while not done:
      if local deque 非空:
          task = pop_tail(local)
          execute(task)
      else:
          victim = random processor
          task = pop_head(victim.deque)
          if task: execute(task)
          else: yield
```

🔥 **性质**:Work-Stealing 调度下 $E[T_P] = O(T_1/P + T_\infty)$,渐近最优。TBB、Cilk、Ray 都用此策略。

## 四、算法 / 流程

### 4.1 Blelloch 并行 Prefix Sum

**输入**:数组 $x[0..n-1]$
**输出**:$y[i] = \sum_{j\le i} x[j]$

**两阶段**:

**阶段 1:Up-Sweep(Reduce)** — 构建求和树
```
for d in 0..log2(n)-1:
    parallel for i in 0..n/2^(d+1)-1:
        x[2^(d+1)*(i+1)-1] += x[2^(d+1)*i + 2^d - 1]
```

**阶段 2:Down-Sweep(Distribute)** — 分发前缀
```
x[n-1] = 0
for d in log2(n)-1..0:
    parallel for i in 0..n/2^(d+1)-1:
        t = x[2^(d+1)*i + 2^d - 1]
        x[2^(d+1)*i + 2^d - 1] = x[2^(d+1)*(i+1)-1]
        x[2^(d+1)*(i+1)-1] += t
```

**复杂度**:
- $W = O(n)$ — 每元素被加 $O(1)$ 次;
- $D = O(\log n)$ — 树深;
- $\Phi = n/\log n$。

🔥 **vs 朴素并行**:朴素并行 $y[i] = \sum_{j\le i} x[j]$ 用 $i$ 次加法,$W = O(n^2)$。Blelloch 是**工作最优**。

### 4.2 Foster 方法应用于 Jacobi 迭代

```
1. 划分:
   网格点 (i,j) 每个一个任务
2. 通信:
   每任务需上下左右 4 邻居
3. 聚合:
   把 k×k 网格合并为一个块(减少 halo 通信)
4. 映射:
   块按 2D 网格分配到 P 个处理器
   → 通信模式:最近邻交换(halo swap)
```

## 六、代码示例

### 6.1 最小可运行版(教学):Blelloch Prefix Sum

```cpp
// file: blelloch_scan.cpp
// 编译: g++ -O2 -fopenmp blelloch_scan.cpp -o scan
// 运行: ./scan
#include <vector>
#include <cstdio>
#include <omp.h>

// 简化版:单线程实现展示算法结构(并行版用 OpenMP task)
void blelloch_scan(std::vector<int>& x, int n) {
    // Up-sweep
    for (int d = 0; (1 << d) < n; ++d) {
        int step = 1 << (d + 1);
        #pragma omp parallel for
        for (int i = 0; i < n; i += step) {
            int left = i + (1 << d) - 1;
            int right = i + step - 1;
            if (right < n) x[right] += x[left];
        }
    }
    // Set root to 0
    x[n - 1] = 0;
    // Down-sweep
    for (int d = static_cast<int>(log2(n)) - 1; d >= 0; --d) {
        int step = 1 << (d + 1);
        #pragma omp parallel for
        for (int i = 0; i < n; i += step) {
            int left = i + (1 << d) - 1;
            int right = i + step - 1;
            if (right < n) {
                int t = x[left];
                x[left] = x[right];
                x[right] += t;
            }
        }
    }
}

int main() {
    const int n = 16;
    std::vector<int> x(n);
    for (int i = 0; i < n; ++i) x[i] = i + 1;
    
    printf("Input:  ");
    for (int i = 0; i < n; ++i) printf("%d ", x[i]);
    printf("\n");
    
    blelloch_scan(x, n);
    
    printf("Scan:   ");
    for (int i = 0; i < n; ++i) printf("%d ", x[i]);
    printf("\n");
    // 预期(inclusive→exclusive): 0 1 3 6 10 15 21 28 36 45 55 66 78 91 105 120
    return 0;
}
```

### 6.2 手把手:OpenMP task 实现并行分治归并排序

```cpp
// file: parallel_mergesort.cpp
// 编译: g++ -O2 -fopenmp parallel_mergesort.cpp -o pms
// 运行: ./pms
#include <vector>
#include <algorithm>
#include <cstdio>
#include <omp.h>

void merge(std::vector<int>& a, int lo, int mid, int hi) {
    std::vector<int> tmp(a.begin() + lo, a.begin() + hi);
    int i = 0, j = mid - lo, k = lo;
    while (i < mid - lo && j < hi - lo) {
        a[k++] = (tmp[i] <= tmp[j]) ? tmp[i++] : tmp[j++];
    }
    while (i < mid - lo) a[k++] = tmp[i++];
    while (j < hi - lo) a[k++] = tmp[j++];
}

void parallel_mergesort(std::vector<int>& a, int lo, int hi, int depth) {
    if (hi - lo < 1000) {
        std::sort(a.begin() + lo, a.begin() + hi);
        return;
    }
    int mid = lo + (hi - lo) / 2;
    if (depth < 4) {  // 限制递归深度避免 task 爆炸
        #pragma omp task shared(a)
        parallel_mergesort(a, lo, mid, depth + 1);
        #pragma omp task shared(a)
        parallel_mergesort(a, mid, hi, depth + 1);
        #pragma omp taskwait
    } else {
        parallel_mergesort(a, lo, mid, depth + 1);
        parallel_mergesort(a, mid, hi, depth + 1);
    }
    merge(a, lo, mid, hi);
}

int main() {
    const int n = 1 << 20;
    std::vector<int> a(n);
    for (int i = 0; i < n; ++i) a[i] = (i * 16807) % n;
    
    double t0 = omp_get_wtime();
    #pragma omp parallel
    {
        #pragma omp single
        parallel_mergesort(a, 0, n, 0);
    }
    double t1 = omp_get_wtime();
    
    bool ok = std::is_sorted(a.begin(), a.end());
    printf("n=%d sorted=%d time=%.2fms threads=%d\n",
           n, ok, (t1-t0)*1000, omp_get_max_threads());
    return 0;
}
```

🔥 **要点**:
- `#pragma omp task` 创建任务,`taskwait` 等待子任务;
- 必须在 `parallel` 区域的 `single` 块内启动递归;
- 设递归深度阈值避免任务爆炸(每 task 有开销)。

### 6.3 手把手:Foster 方法应用于矩阵乘

```cpp
// file: matmul_foster.cpp
// 演示 2D 块划分 + halo 通信思路
// 编译: g++ -O3 -fopenmp matmul_foster.cpp -o mm
#include <vector>
#include <cstdio>
#include <omp.h>

void matmul_2d_block(const std::vector<float>& A,
                     const std::vector<float>& B,
                     std::vector<float>& C,
                     int n, int bs) {
    // bs = block size; 每 OpenMP 线程处理一个 bs×bs 块
    #pragma omp parallel for collapse(2) schedule(static)
    for (int bi = 0; bi < n; bi += bs) {
        for (int bj = 0; bj < n; bj += bs) {
            // 块内计算 C[bi:bi+bs][bj:bj+bs]
            for (int bk = 0; bk < n; bk += bs) {
                for (int i = bi; i < bi + bs; ++i) {
                    for (int k = bk; k < bk + bs; ++k) {
                        float a = A[i * n + k];
                        for (int j = bj; j < bj + bs; ++j) {
                            C[i * n + j] += a * B[k * n + j];
                        }
                    }
                }
            }
        }
    }
}

int main() {
    const int n = 1024, bs = 32;
    std::vector<float> A(n*n, 1.0f), B(n*n, 2.0f), C(n*n, 0.0f);
    
    double t0 = omp_get_wtime();
    matmul_2d_block(A, B, C, n, bs);
    double t1 = omp_get_wtime();
    
    double flops = 2.0 * n * n * n;
    printf("Time=%.2fms GFLOPS=%.1f\n", (t1-t0)*1000, flops/(t1-t0)/1e9);
    return 0;
}
```

🔥 **Foster 分析**:
- **划分**:$n^2$ 个 $C_{ij}$ 任务;
- **通信**:每任务需 $A$ 一行 + $B$ 一列 → $O(n)$ 数据;
- **聚合**:$bs \times bs$ 块合并,块内复用 $A$ 行 $B$ 列,通信降为 $O(n/bs)$;
- **映射**:`collapse(2)` 把块任务均匀分给线程。

## 七、常见陷阱与最佳实践 ⚠️

| 陷阱 | 后果 | 对策 |
|------|------|------|
| 朴素 prefix sum | $W=O(n^2)$ 工作爆炸 | 用 Blelloch,工作最优 |
| 递归无深度阈值 | task 爆炸,调度开销 > 计算 | 设 depth 阈值,深处转串行 |
| 划分粒度太细 | 通信/调度开销主导 | 聚合到合理块大小 |
| 流水线不平衡 | 最慢阶段决定吞吐 | 拆分慢阶段,或加 buffer |
| 波前有长串行链 | $D$ 大,并行度低 | 重排依赖,寻找更宽波前 |
| 用 BSP 模型分析细粒度 MPI | 高估同步开销 | 改用 LogP |
| 工作偷取队列无锁实现错误 | 数据竞争 | 用 lock-free deque(Cilk THE 算法) |

## 十、综合面试题

1. **基础**:用 Foster 方法分析并行矩阵乘的设计。
   - 答:划分 $n^2$ 个 $C_{ij}$ 任务;通信每任务需 $A$ 行 $B$ 列;聚合为 $bs\times bs$ 块复用数据;映射按 2D 网格分配处理器。

2. **进阶**:Blelloch scan 为何比朴素并行 scan 更优?
   - 答:朴素 $y[i]=\sum_{j\le i}x[j]$ 每元素 $O(i)$ 加法,$W=O(n^2)$。Blelloch 用树形 up-sweep + down-sweep,每元素被加 $O(1)$ 次,$W=O(n)$,且 $D=O(\log n)$,渐近最优。

3. **深度**:证明 Work-Stealing 调度的 $E[T_P] = O(T_1/P + T_\infty)$。
   - 答:关键引理——每处理器本地任务被偷前最多被偷 1 次。总偷取次数 $\le T_\infty \cdot P$(因关键路径上的任务必须串行完成,每串行步最多产生 $P-1$ 次偷取)。work $T_1$ 均摊到 $P$ 个处理器为 $T_1/P$,加上 $O(T_\infty)$ 偷取开销,得 $E[T_P] = O(T_1/P + T_\infty)$。详见 Blumofe & Leiserson 1999。

4. **设计**:用波前模式并行化高斯-塞德尔迭代。
   - 答:网格点 $(i,j)$ 依赖 $(i-1,j)$ 和 $(i,j-1)$,波前按反对角线分层:层 $k = i+j$。同层所有点可并行计算,层间串行。$D = O(n+m)$,$\Phi = \min(n,m)$。

5. **工程**:MapReduce 的 map/reduce 对应 Foster 哪两步?
   - 答:map = 划分(每 mapper 处理独立 split);shuffle = 通信(数据按 key 重分布);reduce = 聚合(同 key 数据合并)。映射由 scheduler 负责(数据本地性)。

6. **学术**:比较 PRAM-CRCW 与 EREW 下 prefix sum 的深度下界。
   - 答:CRCW(允许并发写)下深度 $O(\log n)$;EREW(互斥读写)下深度仍 $O(\log n)$,但 work 不同:CRCW 可达 $O(n)$,EREW 需 $O(n\log n)$ 因不能并发读。Blelloch 在 EREW 下达到 $O(n)$ work、$O(\log n)$ depth,最优。
