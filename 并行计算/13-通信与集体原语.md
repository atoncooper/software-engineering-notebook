## 一、问题定义

### 1.1 解决什么问题

分布式训练中，每个 GPU 算完自己的梯度后，必须**让所有 GPU 看到相同梯度**才能用 SGD 同步更新——这就是 AllReduce。

在 1024 卡规模下，AllReduce 通信量可达数百 GB，通信时间占训练时间 30-50%。所以：

1. 选什么算法？（Ring / Tree / Recursive Doubling）
2. 通信复杂度怎么算？（$\alpha$-$\beta$ 模型）
3. 怎么和计算重叠？（overlap）
4. 怎么选 NCCL 参数？

本章是 §14 分布式训练的根基。

### 1.2 点对点 vs 集合

| 类型 | 通信模式 | 复杂度 | 典型场景 |
|------|----------|--------|----------|
| 点对点 | 1-to-1 | $O(1)$ | Pipeline Parallel |
| Broadcast | 1-to-all | 见下 | 参数初始化 |
| Reduce | all-to-1 | 见下 | 梯度规约到 rank 0 |
| AllReduce | all-to-all | 见下 | DDP 梯度同步 |
| AllGather | all-to-all | 见下 | ZeRO-3 / TP |
| ReduceScatter | all-to-all | 见下 | ZeRO-2/3 |
| All-to-All | all-to-all | $O(N)$ | MoE expert routing |

## 三、原理与机制

### 3.1 $\alpha$-$\beta$ 通信模型 🎓

任何通信时间建模为：
$$
T(m) = \alpha + \frac{m}{\beta}
$$
- $\alpha$：启动延迟（软件栈 + 协议握手）；
- $m/\beta$：数据传输时间。

**关键直觉**：
- 小消息 → 延迟主导 → 关注 $\alpha$；
- 大消息 → 带宽主导 → 关注 $\beta$。

### 3.2 AllReduce 的本质

**输入**：每个 rank $i$ 有向量 $x_i$（长度 $n$）。
**输出**：每个 rank 都得到 $y = \sum_{i=0}^{P-1} x_i$。

**最朴素实现**：rank 0 收集所有 $x_i$ 求和，再广播——rank 0 是瓶颈，带宽 $\beta/P$ 被浪费。

### 3.3 Ring AllReduce 📜🔥

**两阶段**：

**阶段 1：ReduceScatter（带宽最优）**
- $P$ 个 rank 排成环；
- 将 $x_i$ 分成 $P$ 段 $x_i[0..P-1]$；
- 经过 $P-1$ 轮，每轮每 rank 接收一段、累加、发往下家；
- 结束后 rank $i$ 持有 $\sum_j x_j[i]$（即规约结果的第 $i$ 段）。

**阶段 2：AllGather**
- 再 $P-1$ 轮，每 rank 把自己的段沿环传播；
- 结束后每 rank 都有完整规约结果。

**复杂度**：
- 每轮每 rank 发送 $n/P$ 字节；
- 总通信量（每 rank）：$(P-1) \cdot \frac{n}{P} \cdot 2 \approx 2n$ 字节；
- 时间：
$$
T_{\text{ring}} = 2(P-1)\alpha + \frac{2(P-1)}{P} \cdot \frac{n}{\beta}
$$

🔥 **关键性质**：**带宽利用率最优**——每 rank 始终在收发，理论带宽利用率 100%。延迟随 $P$ 线性增长（$2(P-1)\alpha$）。

### 3.4 Tree AllReduce

**两阶段**：
1. **Reduce**：从叶到根，每节点接收子节点结果并规约，对数 $\log_2 P$ 轮；
2. **Broadcast**：从根到叶，对数 $\log_2 P$ 轮。

**复杂度**：
$$
T_{\text{tree}} = 2\log_2 P \cdot \alpha + 2\log_2 P \cdot \frac{n}{\beta}
$$

🔥 **关键性质**：**延迟最优**（对数），但带宽利用率差——根节点瓶颈，每轮只有少数节点在传。

### 3.5 Recursive Doubling 🎓

每轮配对翻倍：
- 第 0 轮：rank 0↔1, 2↔3, ...；
- 第 1 轮：rank 0-1 ↔ 2-3, ...；
- 第 $k$ 轮：距离 $2^k$ 的 rank 配对。

每轮每对交换 $n$ 字节并累加。$\log_2 P$ 轮。

**复杂度**：
$$
T_{\text{rd}} = \log_2 P \cdot \alpha + \log_2 P \cdot \frac{n}{\beta}
$$

但每对每轮传 $n$ 字节，比 Ring 慢 $\frac{P}{2\log P}$ 倍（带宽利用率低）。常用于小消息。

### 3.6 三种算法对比

| 算法 | 延迟 $\alpha$ 项 | 带宽 $\beta$ 项 | 适用 |
|------|------------------|-----------------|------|
| Ring | $2(P-1)\alpha$ | $\frac{2(P-1)}{P}\cdot\frac{n}{\beta}$ | 大消息，$P$ 不极大 |
| Tree | $2\log_2 P \cdot \alpha$ | $2\log_2 P \cdot \frac{n}{\beta}$ | 小消息，根瓶颈 |
| Recursive Doubling | $\log_2 P \cdot \alpha$ | $\log_2 P \cdot \frac{n}{\beta}$ | 小消息，Power-of-2 |

🔥 **NCCL 实测策略**：自动按消息大小切换——小消息 Tree/RD，大消息 Ring。

### 3.7 ReduceScatter 与 AllGather 的关系

```
AllReduce = ReduceScatter + AllGather

ReduceScatter:  x_i  →  rank i 持有 sum_j x_j 的第 i 段
AllGather:      各段  →  所有 rank 拼成完整结果

Ring ReduceScatter: (P-1) 轮，每轮 n/P
Ring AllGather:     (P-1) 轮，每轮 n/P
合计: 2(P-1) 轮, 2(P-1)/P · n 字节   ← 与 Ring AllReduce 一致
```

**ZeRO-2/3** 就是显式拆出 ReduceScatter：每 rank 只保留自己负责的梯度段，省显存。

## 四、算法 / 流程

### 4.1 Ring AllReduce 伪代码

```
# 输入: x_i (rank i 的数据, 长度 n, 分 P 段)
# 阶段 1: ReduceScatter
for k in 0..P-2:
    send_chunk = (i - k) mod P
    recv_chunk = (i - k - 1) mod P
    send x[send_chunk] to rank (i+1) mod P
    recv tmp from rank (i-1) mod P
    x[recv_chunk] += tmp
# 阶段 2: AllGather
for k in 0..P-2:
    send_chunk = (i - k + 1) mod P
    recv_chunk = (i - k) mod P
    send x[send_chunk] to rank (i+1) mod P
    recv x[recv_chunk] from rank (i-1) mod P
```

### 4.2 复杂度汇总

| 原语 | Ring 时间 | Tree 时间 |
|------|-----------|-----------|
| Broadcast | $(P-1)\alpha + \frac{P-1}{P}\frac{n}{\beta}$ | $\log_2 P \cdot (\alpha + n/\beta)$ |
| Reduce | 同上 | 同上 |
| AllReduce | $2(P-1)\alpha + \frac{2(P-1)}{P}\frac{n}{\beta}$ | $2\log_2 P (\alpha + n/\beta)$ |
| ReduceScatter | $(P-1)\alpha + \frac{P-1}{P}\frac{n}{\beta}$ | $\log_2 P (\alpha + n/(P\beta))$ |
| AllGather | 同 ReduceScatter | 同上 |
| All-to-All | $P\alpha + \frac{P-1}{P}\frac{n}{\beta}$（per node） | — |

## 六、代码示例

### 6.1 最小可运行版（教学）：纯 Python Ring AllReduce

```python
# file: ring_allreduce.py
# 4 进程运行: 
#   mpirun -np 4 python ring_allreduce.py
# 或用 torchrun:
#   torchrun --nproc_per_node=4 ring_allreduce.py
import os, socket, pickle, threading
import numpy as np

def allreduce_ring(rank, size, send_sock, recv_sock, data):
    # data: np.array 长度 n，分为 size 段
    n = data.shape[0]
    chunk = n // size
    # 阶段1: ReduceScatter
    for k in range(size - 1):
        send_idx = (rank - k) % size
        recv_idx = (rank - k - 1) % size
        send_chunk = data[send_idx*chunk:(send_idx+1)*chunk].copy()
        send_sock.sendall(pickle.dumps(send_chunk))
        tmp = pickle.loads(recv_sock.recv(8192))
        data[recv_idx*chunk:(recv_idx+1)*chunk] += tmp
    # 阶段2: AllGather
    for k in range(size - 1):
        send_idx = (rank - k + 1) % size
        recv_idx = (rank - k) % size
        send_chunk = data[send_idx*chunk:(send_idx+1)*chunk].copy()
        send_sock.sendall(pickle.dumps(send_chunk))
        tmp = pickle.loads(recv_sock.recv(8192))
        data[recv_idx*chunk:(recv_idx+1)*chunk] = tmp
    return data

# 简化：用 PyTorch 直接演示更实用
```

### 6.2 手把手：PyTorch DDP 全流程

```python
# file: ddp_demo.py
# 运行: torchrun --nproc_per_node=4 ddp_demo.py
import os
import torch
import torch.nn as nn
import torch.distributed as dist
from torch.nn.parallel import DistributedDataParallel as DDP

def setup():
    dist.init_process_group(backend="nccl")
    local_rank = int(os.environ["LOCAL_RANK"])
    torch.cuda.set_device(local_rank)
    return local_rank

def cleanup():
    dist.destroy_process_group()

def main():
    rank = setup()
    # 1. 模型 + DDP 包装
    model = nn.Linear(4096, 4096).cuda()
    model = DDP(model, device_ids=[rank])
    
    # 2. 数据并行：每 rank 不同 batch
    torch.manual_seed(42 + rank)  # 不同 seed 造不同数据
    x = torch.randn(64, 4096).cuda()
    y = torch.randn(64, 4096).cuda()
    
    opt = torch.optim.SGD(model.parameters(), lr=0.01)
    loss_fn = nn.MSELoss()
    
    for step in range(5):
        opt.zero_grad()
        out = model(x)
        loss = loss_fn(out, y)
        loss.backward()  # DDP 自动在 backward 时插入 AllReduce
        opt.step()
        if rank == 0:
            print(f"step {step} loss {loss.item():.4f}")
    
    # 3. 演示显式 AllReduce
    grad = torch.ones(4096, device="cuda")
    dist.all_reduce(grad, op=dist.ReduceOp.SUM)
    print(f"[rank {rank}] AllReduce result first elem: {grad[0].item()} (expected {dist.get_world_size()})")
    
    cleanup()

if __name__ == "__main__":
    main()
```

🔥 **DDP 关键点**：
- `loss.backward()` 时 DDP 自动插入 gradient AllReduce；
- 使用 **gradient bucketing**：把梯度分组，组内就绪即开始 AllReduce，与 backward 计算重叠；
- 通信后端：`nccl`（GPU）/ `gloo`（CPU/跨机 fallback）。

### 6.4 手把手：实测 AllReduce 带宽

```python
# file: nccl_bench.py
# 运行: torchrun --nproc_per_node=8 nccl_bench.py
import os, time, torch
import torch.distributed as dist

def bench_allreduce(size_mb, iters=20):
    n = size_mb * 1024 * 1024 // 4  # float32
    data = torch.randn(n, device="cuda")
    # 预热
    for _ in range(5):
        dist.all_reduce(data)
    torch.cuda.synchronize()
    
    t0 = time.time()
    for _ in range(iters):
        dist.all_reduce(data)
    torch.cuda.synchronize()
    t1 = time.time()
    
    # 每次通信: 2*size_mb 字节（reduce+gather）
    bytes_per_op = 2 * size_mb * 1024 * 1024
    bw = bytes_per_op * iters / (t1 - t0) / 1e9
    return bw

if __name__ == "__main__":
    dist.init_process_group("nccl")
    rank = dist.get_rank()
    for sz in [1, 8, 64, 256, 1024]:
        bw = bench_allreduce(sz)
        if rank == 0:
            print(f"AllReduce {sz:4d} MB: {bw:6.1f} GB/s")

dist.destroy_process_group()
```

AllReduce 1024 MB:  780.1 GB/s    ← 接近 NVLink 带宽极限

## 七、常见陷阱与最佳实践 ⚠️

| 陷阱 | 后果 | 对策 |
|------|------|------|
| 小消息用 Ring | 延迟主导，慢 | 用 Tree/Recursive Doubling（NCCL 自动） |
| 不预热度量 | 通信开销污染结果 | 至少 5-10 轮预热 |
| 不设 `NCCL_SOCKET_IFNAME` | 选错网卡 | 多网卡环境必设 |
| CPU 0 占满 | NCCL 通信线程被挤 | 绑核时留 CPU 给 NCCL |
| AllReduce 串行 | 计算通信不重叠 | 用 bucketing / 异步 |
| GPU 0 当 root | GPU 0 显存/算力压力 | 用 rank-balanced Tree |
| 跨 rack 不感知拓扑 | 多跳网络 | 用 NCCL topo 文件 |
| 超大消息不分块 | 单次占满缓冲 | 分块 + 流水 |
| NCCL_TIMEOUT 太短 | 大模型初始化被杀 | 调大到 600-1800s |
| `dist.barrier()` 滥用 | 串行点拖慢训练 | 只在必要时同步 |

## 十、综合面试题

1. **基础**：8 卡 H100 NVLink 全互联，1GB AllReduce 理论时间？
   - 答：Ring 模型 $T = 2\cdot 7\alpha + \frac{2\cdot 7}{8}\cdot \frac{1\text{GB}}{900\text{GB/s}}$。$\alpha \approx 1\mu s$，$T \approx 14\mu s + 1.94\text{ms} \approx 1.95\text{ms}$。实际因 NVSwitch 全互联可降到 ~1.3ms。

2. **进阶**：1024 卡训练，AllReduce 占总时间 40%。怎么降到 20%？
   - 答：(1) 增大 batch 减少通信频率；(2) 梯度累积；(3) 用 ZeRO-2/3 把 AllReduce 拆成 ReduceScatter（通信量减半）；(4) 计算通信 overlap（DDP bucketing）；(5) 拓扑感知 NCCL 配置；(6) 考虑分层 AllReduce（机架内 Ring + 跨机架 Tree）。

3. **深度**：Ring AllReduce 为什么带宽最优？证明。
   - 答：带宽最优指每 rank 在每轮都在收发（不空闲）。Ring 中每 rank 同时收一段、发一段，链路占用率 100%。Tree 中只有少数节点在某轮收发，根节点上行带宽 = 整体聚合带宽，其他节点上行带宽被浪费。Ring 的总通信量 $2(P-1)n/P$，每 rank 实际占用带宽时间 $\frac{2(P-1)n/P}{\beta}$，与 $P$ 无关（除 $\frac{P-1}{P}$）——加 P 不增带宽需求。

4. **设计**：MoE 训练中 All-to-All 通信如何优化？
   - 答：(1) 用 expert parallel 把 token 路由到对应 expert 所在 GPU；(2) All-to-All 通信按 expert 分组；(3) 用 NCCL `all_to_all_single`；(4) 与计算 overlap（先 router 计算 → 异步 All-to-All → expert FFN）；(5) top-k 路由减少通信量；(6) DeepSeek 用 shared expert 减少路由专家数。

5. **工程**：DDP 训练在 8 卡上正常，扩到 64 卡时 NCCL 卡住。怎么排查？
   - 答：(1) `NCCL_DEBUG=INFO` 看拓扑初始化；(2) 检查所有节点 `NCCL_SOCKET_IFNAME` 一致；(3) 检查 IB 驱动 `ibstat`；(4) 检查防火墙端口；(5) `NCCL_TIMEOUT` 调大看是否超时；(6) 用 `nccl-tests` 单独测通信排除 PyTorch 因素；(7) 检查 GPU 间 P2P 是否可用 `nvidia-smi topo -m`。

6. **学术**：比较 Ring 与 Halving-Doubling AllReduce 的复杂度。
   - 答：Ring 时间 $2(P-1)\alpha + 2\frac{P-1}{P}\frac{n}{\beta}$。Halving-Doubling 时间 $\log_2 P \cdot \alpha + 2\frac{P-1}{P}\frac{n}{\beta}$。带宽项相同（都带宽最优），但 Halving-Doubling 延迟对数——更优。代价：需要 power-of-2 的 P，且配对节点跨距大，对拓扑不友好。NCCL 实际用 Ring 是因为它拓扑友好（环邻居物理邻近）。
