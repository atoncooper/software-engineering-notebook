### 1.1 解决什么问题

## 三、原理与机制

### 3.1 BLAS 层次结构 📜

BLAS 按算术强度分三层:

| 层 | 操作示例 | 复杂度 | 算术强度 | 受限于 |
|----|----------|--------|----------|--------|
| BLAS-1 | $y = \alpha x + y$(axpy) | $O(n)$ | $O(1)$ | 带宽 |
| BLAS-2 | $y = Ax + y$(GEMV) | $O(n^2)$ | $O(1)$ | 带宽 |
| BLAS-3 | $C = AB + C$(GEMM) | $O(n^3)$ | $O(n)$ | 算力 |

🔥 **关键**:BLAS-3 算术强度高,能跑满算力;BLAS-1/2 带宽受限,效率低。LAPACK 的核心优化就是**把 BLAS-2 升级为 BLAS-3**(分块算法)。

### 3.2 GEMM 并行的本质

$C = AB$,$n\times n$ 矩阵,$P$ 个处理器:

- **总计算**:$W = 2n^3$ FLOP;
- **总数据**:$3n^2$ 元素(读 A、B,写 C);
- **理想并行**:$T_P = 2n^3/P$;
- **挑战**:每 $C_{ij}$ 需 $A$ 一行 + $B$ 一列,通信模式复杂。

### 3.3 Cannon 算法 📜🎓

**2D 网格** $P = p\times p$,每处理器持 $n/p \times n/p$ 块。

**初始对齐**:processor $(i,j)$ 的 A 块左移 $i$ 步,B 块上移 $j$ 步。
```
对齐前:                     对齐后(初始偏移):
A[i][j]  B[i][j]            A[i][(i+j)%p]  B[(i+j)%p][j]
```

**主循环**($p$ 步):
```
for k in 0..p-1:
    本地 C += A * B            # 块乘
    A 左移 1 步               # 与左邻居交换
    B 上移 1 步               # 与上邻居交换
```

**复杂度**:
- 计算:$2n^3/P$;
- 通信:每步 2 次近邻交换,每块 $n^2/P^2$ 字节;
- 总通信:$2 \cdot p \cdot 2 \cdot n^2/P^2 = 4n^2/\sqrt{P}$;
- 通信/计算比:$\frac{4n^2/\sqrt{P}}{2n^3/P} = \frac{2\sqrt{P}}{n}$。

🔥 **Cannon 优势**:通信仅与近邻,适合 mesh/torus 拓扑;通信量 $O(n^2/\sqrt{P})$ 是稠密 GEMM 下界。

### 3.4 DNS 算法(Dekel-Nassimi-Sahni)🎓

**3D 网格** $P = p\times p\times p$,每处理器持 $C_{ij}$ 的部分和。

- A 沿 $k$ 维广播,B 沿 $k$ 维广播;
- processor $(i,j,k)$ 计算 $A_{ik} \cdot B_{kj}$ 的部分;
- 沿 $k$ 维 reduce 得 $C_{ij}$。

**复杂度**:
- 计算:$2n^3/P$(每处理器 $n^3/P^3 \times p = n^3/P^2$ 次?实际 $2n^3/P$ 当 $P=p^3$);
- 通信:$O(n^2/P^{2/3})$。

**优势**:通信更少($P^{1/3}$ vs $P^{1/2}$);**劣势**:需 $p^3$ 处理器,扩展性差。

### 3.5 Fox 算法 📜

Cannon 的变体,用**广播**代替 B 的移位:

```
for k in 0..p-1:
    对角块 A[i][(i+k)%p] 广播给同行
    C += A_broadcast * B
    B 上移 1 步
```

**复杂度**:同 Cannon,但广播操作在某些拓扑(如胖树)更高效。

### 3.6 三算法对比

| 算法 | 拓扑 | 通信量 | 处理器数 | 适用 |
|------|------|--------|----------|------|
| Cannon | mesh/torus | $O(n^2/\sqrt{P})$ | $p^2$ | 2D 网格硬件 |
| Fox | 胖树 | $O(n^2/\sqrt{P})$ | $p^2$ | 支持高效广播 |
| DNS | 3D mesh | $O(n^2/P^{2/3})$ | $p^3$ | 大 $P$,通信敏感 |

🔥 **ScaLAPACK 默认用 Cannon/Fox 变体**(2D 块循环分布)。

### 3.7 块循环分布(Block Cyclic) 🎓

ScaLAPACK 的数据分布:
- 矩阵分为 $mb \times nb$ 的块;
- 块按 2D 循环分配到 $p_r \times p_c$ 网格;
- 类似循环数组下标 mod $p$。

```
A[0][0] → P[0][0]   A[0][1] → P[0][1]   ...
A[1][0] → P[1][0]   A[1][1] → P[1][1]   ...
A[2][0] → P[0][0]   A[2][1] → P[0][1]   ...   ← 循环
```

**优势**:
- 负载均衡(尤其 LU/QR 分解时上三角变稀疏);
- 块大小 $mb$ 平衡局部性与负载均衡。

### 3.8 SpMV 并行 🎓

稀疏矩阵向量乘 $y = Ax$:
- $A$ 用 CSR(行压缩)存储;
- 按行划分给各处理器;
- 每行独立计算,无依赖;
- 跨行需 $x$ 的非本地元素 → 通信。

```
CSR 格式:
values:    [a01 a02 a11 a12 a13 a22 a30 ...]
col_idx:   [1   2   1   2   3   2   0   ...]
row_ptr:   [0   2   5   6   ...]   # 每行起始位置
```

**并行 SpMV 挑战**:
- **行不均**:有些行非零元素多,负载不均;
- **向量化**:行内非零元素少,难以填满 SIMD lane;
- **x 通信**:跨行访问 $x$ 的非本地段。

**优化**:lightSpMV(一行一 warp)、SELL-C-σ(切片+排序)。

### 3.9 Cholesky 分解并行 🎓

$A = LL^T$($A$ 对称正定)。算法:
```
for j in 0..n-1:
    A[j][j] = sqrt(A[j][j])
    for i in j+1..n-1:
        A[i][j] /= A[j][j]
    for i in j+1..n-1:
        for k in j+1..i:
            A[i][k] -= A[i][j] * A[k][j]
```

**依赖分析**(波前模式,见 §3 §4):
- 第 $j$ 步更新第 $j$ 列,再更新右下子矩阵;
- $A[i][k]$ 的更新依赖 $A[i][j]$ 和 $A[k][j]$;
- **并行度**:第 $j$ 步可并行更新 $O((n-j)^2)$ 元素。

**块 Cholesky**:把 $j$ 循环分块,内部用 BLAS-3,提高算术强度。

## 四、算法 / 流程

### 4.1 Cannon 算法伪代码

```
# P = p×p 处理器,每处理器持 (n/p)×(n/p) 块
# 初始对齐
for i in 0..p-1:
    A[i][j] 左移 i 步  (j 是列号)
for j in 0..p-1:
    B[i][j] 上移 j 步

# 主循环
for k in 0..p-1:
    C_local += A_local * B_local
    A_local 左移 1 步
    B_local 上移 1 步
```

### 4.2 块 Cholesky 流程

```
for blk in 0..n/bs-1:
    # 1. 对角块分解(串行或小并行)
    POTRF(A[blk][blk])
    # 2. 广播对角块到本列
    TRSM(A[blk][blk] → A[blk+1:][blk])
    # 3. 更新尾部子矩阵(并行)
    SYRK(A[blk+1:][blk])  # 对角块
    GEMM(A[blk+1:][blk], A[blk+1:][blk]^T → A[blk+1:][blk+1:])
```

## 六、代码示例

### 6.1 最小可运行版(教学):MPI Cannon 算法

```cpp
// file: cannon_mpi.cpp
// 简化版:2x2 处理器网格,n=4 矩阵
// 编译: mpicxx -O2 cannon_mpi.cpp -o cannon
// 运行: mpirun -np 4 ./cannon
#include <mpi.h>
#include <vector>
#include <cmath>
#include <cstdio>

int main(int argc, char** argv) {
    MPI_Init(&argc, &argv);
    int rank, size;
    MPI_Comm_rank(MPI_COMM_WORLD, &rank);
    MPI_Comm_size(MPI_COMM_WORLD, &size);
    
    int p = (int)sqrt((double)size);
    if (p * p != size) {
        if (rank == 0) printf("Need square number of procs\n");
        MPI_Finalize();
        return 1;
    }
    
    const int N = 4;          // 矩阵大小
    const int nb = N / p;     // 每块大小
    
    // 2D 笛卡尔拓扑
    int dims[2] = {p, p};
    int periods[2] = {1, 1};  // 周期(用于移位)
    MPI_Comm cart;
    MPI_Cart_create(MPI_COMM_WORLD, 2, dims, periods, 0, &cart);
    
    int coords[2];
    MPI_Cart_coords(cart, rank, 2, coords);
    
    // 本地块(nb×nb)
    std::vector<double> A(nb*nb, 1.0 + rank);
    std::vector<double> B(nb*nb, 1.0 + rank);
    std::vector<double> C(nb*nb, 0.0);
    
    // 初始对齐:A 左移 coords[0] 步,B 上移 coords[1] 步
    int src, dst;
    MPI_Cart_shift(cart, 1, -coords[0], &src, &dst);
    MPI_Sendrecv_replace(A.data(), nb*nb, MPI_DOUBLE, dst, 0, src, 0, cart, MPI_STATUS_IGNORE);
    MPI_Cart_shift(cart, 0, -coords[1], &src, &dst);
    MPI_Sendrecv_replace(B.data(), nb*nb, MPI_DOUBLE, dst, 0, src, 0, cart, MPI_STATUS_IGNORE);
    
    // Cannon 主循环
    for (int k = 0; k < p; ++k) {
        // C += A * B
        for (int i = 0; i < nb; ++i)
            for (int j = 0; j < nb; ++j)
                for (int k2 = 0; k2 < nb; ++k2)
                    C[i*nb+j] += A[i*nb+k2] * B[k2*nb+j];
        
        // A 左移 1,B 上移 1
        MPI_Cart_shift(cart, 1, -1, &src, &dst);
        MPI_Sendrecv_replace(A.data(), nb*nb, MPI_DOUBLE, dst, 0, src, 0, cart, MPI_STATUS_IGNORE);
        MPI_Cart_shift(cart, 0, -1, &src, &dst);
        MPI_Sendrecv_replace(B.data(), nb*nb, MPI_DOUBLE, dst, 0, src, 0, cart, MPI_STATUS_IGNORE);
    }
    
    // 取消对齐(略)
    
    printf("[rank %d coords=(%d,%d)] C[0]=%.1f\n", rank, coords[0], coords[1], C[0]);
    
    MPI_Comm_free(&cart);
    MPI_Finalize();
    return 0;
}
```

🔥 **Cannon 要点**:
- `periods={1,1}` 创建周期拓扑,移位自动 wrap;
- 初始对齐用负 shift;
- 每步 `Sendrecv_replace` 原子交换,无死锁。

### 6.2 手把手:cuBLAS GEMM vs 手写对比

```cpp
// file: cublas_vs_manual.cu
// 编译: nvcc -O3 -arch=sm_80 -lcublas cublas_vs_manual.cu -o cb
#include <cublas_v2.h>
#include <cuda_runtime.h>
#include <cstdio>
#include <chrono>

#define CK(x) do { auto _e=(x); if(_e!=cudaSuccess){printf("err %d\n",__LINE__);exit(1);}} while(0)

// 手写朴素 GEMM(参考)
__global__ void naive_gemm(const float* A, const float* B, float* C, int n) {
    int i = blockIdx.y * blockDim.y + threadIdx.y;
    int j = blockIdx.x * blockDim.x + threadIdx.x;
    if (i < n && j < n) {
        float s = 0;
        for (int k = 0; k < n; ++k) s += A[i*n+k] * B[k*n+j];
        C[i*n+j] = s;
    }
}

int main() {
    const int n = 1024;
    float *hA = new float[n*n], *hB = new float[n*n], *hC = new float[n*n];
    for (int i = 0; i < n*n; ++i) { hA[i] = 0.001f; hB[i] = 0.001f; }
    
    float *dA, *dB, *dC;
    CK(cudaMalloc(&dA, n*n*sizeof(float)));
    CK(cudaMalloc(&dB, n*n*sizeof(float)));
    CK(cudaMalloc(&dC, n*n*sizeof(float)));
    CK(cudaMemcpy(dA, hA, n*n*sizeof(float), cudaMemcpyHostToDevice));
    CK(cudaMemcpy(dB, hB, n*n*sizeof(float), cudaMemcpyHostToDevice));
    
    cudaEvent_t s, e; cudaEventCreate(&s); cudaEventCreate(&e);
    
    // === 1. 朴素手写 ===
    dim3 block(16, 16), grid((n+15)/16, (n+15)/16);
    cudaEventRecord(s);
    for (int t = 0; t < 10; ++t) naive_gemm<<<grid, block>>>(dA, dB, dC, n);
    cudaEventRecord(e); CK(cudaDeviceSynchronize());
    float ms1 = 0; cudaEventElapsedTime(&ms1, s, e);
    
    // === 2. cuBLAS ===
    cublasHandle_t h;
    cublasCreate(&h);
    float alpha = 1.0f, beta = 0.0f;
    cudaEventRecord(s);
    for (int t = 0; t < 10; ++t)
        cublasSgemm(h, CUBLAS_OP_N, CUBLAS_OP_N,
                    n, n, n, &alpha, dA, n, dB, n, &beta, dC, n);
    cudaEventRecord(e); CK(cudaDeviceSynchronize());
    float ms2 = 0; cudaEventElapsedTime(&ms2, s, e);
    
    double flops = 2.0 * n * n * n * 10;
    printf("Naive:  %.1f ms,  %.1f GFLOP/s\n", ms1, flops/(ms1/1000)/1e9);
    printf("cuBLAS: %.1f ms,  %.1f GFLOP/s\n", ms2, flops/(ms2/1000)/1e9);
    
    cublasDestroy(h);
    delete[] hA; delete[] hB; delete[] hC;
    CK(cudaFree(dA)); CK(cudaFree(dB)); CK(cudaFree(dC));
    return 0;
}
```

**典型输出**(A100):
```
Naive:  850 ms,   2.5 TFLOP/s
cuBLAS: 0.95 ms, 2250 TFLOP/s   ← 900 倍!Tensor Core + 自动 tiling
```

🔥 **结论**:别手写 GEMM,用 cuBLAS。手写只为学习,生产永远用库。

### 6.3 手把手:并行 SpMV(CSR + OpenMP)

```cpp
// file: spmv_omp.cpp
// 编译: g++ -O3 -fopenmp spmv_omp.cpp -o spmv
#include <vector>
#include <random>
#include <cstdio>
#include <omp.h>

// CSR 矩阵
struct CSRMatrix {
    int rows, cols;
    std::vector<double> values;
    std::vector<int> col_idx;
    std::vector<int> row_ptr;
};

CSRMatrix gen_sparse(int n, double density) {
    CSRMatrix m; m.rows = m.cols = n;
    m.row_ptr.push_back(0);
    std::mt19937 rng(42);
    std::uniform_real_distribution<> prob(0, 1);
    std::uniform_real_distribution<> val(-1, 1);
    for (int i = 0; i < n; ++i) {
        for (int j = 0; j < n; ++j) {
            if (prob(rng) < density) {
                m.values.push_back(val(rng));
                m.col_idx.push_back(j);
            }
        }
        m.row_ptr.push_back(m.values.size());
    }
    return m;
}

void spmv(const CSRMatrix& A, const std::vector<double>& x,
          std::vector<double>& y) {
    #pragma omp parallel for schedule(static)
    for (int i = 0; i < A.rows; ++i) {
        double s = 0;
        for (int k = A.row_ptr[i]; k < A.row_ptr[i+1]; ++k) {
            s += A.values[k] * x[A.col_idx[k]];
        }
        y[i] = s;
    }
}

int main() {
    const int N = 20000;
    const double density = 0.001;  // 0.1% 非零
    auto A = gen_sparse(N, density);
    std::vector<double> x(N, 1.0), y(N, 0.0);
    
    double t0 = omp_get_wtime();
    for (int it = 0; it < 100; ++it) spmv(A, x, y);
    double t1 = omp_get_wtime();
    
    long nnz = A.values.size();
    double flops = 2.0 * nnz * 100;
    printf("SpMV N=%d nnz=%ld time=%.3fs GFLOPS=%.1f\n",
           N, nnz, t1-t0, flops/(t1-t0)/1e9);
    return 0;
}
```

🔥 **SpMV 优化要点**:
- `schedule(static)` 因 CSR 行划分通常均衡;
- 行内循环不可并行(归约);
- 若行不均,改用动态调度或 lightSpMV(一行一 warp)。

### 6.4 生产级版(工程):ScaLAPACK Cholesky

```fortran
! file: scalapack_chol.f90
! 编译: mpifort -O3 -lscalapack -lblas scalapack_chol.f90 -o chol
! 运行: mpirun -np 4 ./chol
program chol_demo
    use mpi
    implicit none
    integer, parameter :: N = 1000, NB = 64
    integer :: ctxt, myrow, mycol, nprow, npcol, info
    integer :: desc(9), lld, ierr
    real(8), allocatable :: A(:,:)
    
    call BLACS_PINFO(info, ierr)
    nprow = 2; npcol = 2
    call BLACS_GET(-1, 0, ctxt)
    call BLACS_GRIDINIT(ctxt, 'R', nprow, npcol)
    call BLACS_GRIDINFO(ctxt, nprow, npcol, myrow, mycol)
    
    ! 本地块大小
    lld = N / nprow + NB
    allocate(A(lld, lld))
    
    ! 初始化 A(略:对称正定)
    
    ! 构造描述符
    call DESCINIT(desc, N, N, NB, NB, 0, 0, ctxt, lld, info)
    
    ! 并行 Cholesky 分解
    call PDPOTRF('L', N, A, 1, 1, desc, info)
    
    if (info == 0) print *, 'Cholesky success on rank', myrow*npcol+mycol
    
    call BLACS_GRIDEXIT(ctxt)
    call BLACS_EXIT(0)
end program
```

🔥 **ScaLAPACK 要点**:
- 用 BLACS 管理进程网格;
- `DESCINIT` 描述块循环分布;
- `PDPOTRF` 是并行 Cholesky(P = Parallel,D = Double);
- 内部自动用 Cannon/Fox 做 GEMM。

### 6.5 手把手:用 MKL 调 BLAS-3

// file: mkl_gemm.cpp
// 编译: g++ -O3 -mkl mkl_gemm.cpp -o mg
#include <mkl.h>
#include <chrono>
#include <cstdio>
#include <vector>

int main() {
    const int n = 4096;
    std::vector<float> A(n*n, 0.1f), B(n*n, 0.1f), C(n*n, 0.0f);
    
    float alpha = 1.0f, beta = 0.0f;
    
    auto t0 = std::chrono::high_resolution_clock::now();
    cblas_sgemm(CblasRowMajor, CblasNoTrans, CblasNoTrans,
                n, n, n, alpha, A.data(), n, B.data(), n, beta, C.data(), n);
    auto t1 = std::chrono::high_resolution_clock::now();
    
    double ms = std::chrono::duration<double, std::milli>(t1-t0).count();
    double flops = 2.0 * n * n * n;
    printf("MKL SGEMM %dx%d: %.1f ms, %.1f GFLOP/s\n",
           n, n, ms, flops/(ms/1000)/1e9);
    
    // 多线程控制
    mkl_set_num_threads(8);
    return 0;
}

## 七、常见陷阱与最佳实践 ⚠️

| 陷阱 | 后果 | 对策 |
|------|------|------|
| 手写 GEMM | 比 cuBLAS 慢 100-1000x | 用 cuBLAS/MKL/OpenBLAS |
| 用 BLAS-1/2 代替 BLAS-3 | 带宽受限,效率 <10% | 分块升级到 BLAS-3 |
| Cannon 用非周期拓扑 | 边界 wrap 错 | 用 `periods={1,1}` |
| ScaLAPACK 块大小不当 | 负载不均或通信过多 | $mb=64$~256 起步 |
| SpMV 行不均 | 慢行拖累 | 动态调度或 lightSpMV |
| Cholesky 不分块 | 并行度低 | 块 Cholesky(BLAS-3) |
| 假设矩阵对称 | 数值错 | 显式存储对称部分 |
| 不查矩阵条件数 | 数值不稳定 | 先做条件数估计 |
| 用 FP32 解线性方程组 | 精度不够 | 用 FP64 或迭代精化 |
| Tensor Core 用 FP32 数据 | 不触发 TC | 用 FP16/BF16 输入 |

## 十、综合面试题

1. **基础**:为什么 BLAS-3 比 BLAS-1/2 更适合并行?
   - 答:BLAS-3 算术强度 $O(n)$,带宽不敏感,能跑满算力;BLAS-1/2 算术强度 $O(1)$,带宽受限,加核帮助有限。LAPACK 通过分块把 BLAS-2 升级为 BLAS-3。

2. **进阶**:Cannon 算法在 $p\times p$ 网格上跑 $n\times n$ GEMM,通信量多少?为什么是下界?
   - 答:每步 2 次近邻交换,每块 $n^2/p^2$,共 $p$ 步,总通信 $4n^2/p = O(n^2/\sqrt{P})$。下界论证:每处理器需"看到"$O(n^2/P^{1/2})$ 数据(A 行 + B 列的局部),Cannon 达此下界。

3. **深度**:比较 Cannon、Fox、DNS 的适用场景。
   - 答:Cannon 适合 mesh/torus 物理拓扑(如超算);Fox 适合支持高效广播的胖树;DNS 通信量更小 $O(n^2/P^{2/3})$ 但需 $p^3$ 处理器,适合超大 $P$ 且内存充裕。ScaLAPACK 默认用 Cannon/Fox 变体(2D)。

4. **设计**:设计一个 GPU 上的并行 SpMV,处理行不均问题。
   - 答:(1) 用 CSR 格式;(2) 对短行(非零元素 < 32)用一行一 warp,内部归约;(3) 对长行用多 warp 协作,块内归约;(4) 用 `__syncthreads` 同步;(5) 也可用 ELLPACK 格式向量化。参考 cuSPARSE `csrmm`。

5. **工程**:cuBLAS GEMM 在 H100 上跑 4096×4096 FP16,实测 800 TFLOP/s,理论峰值 989 TFLOP/s。差距来源?
   - 答:(1) 矩阵非 8 倍数对齐致 padding;(2) Tensor Core 16×16×16 tile 末尾不满;(3) HBM 带宽未饱和;(4) kernel launch overhead(小矩阵);(5) 没用 split-K 减少归约。改用 8192 矩阵可到 950+ TFLOP/s。

6. **学术**:证明稠密 GEMM 并行通信下界 $O(n^2/\sqrt{P})$。
   - 答:每处理器输出 $n^2/P$ 个 $C_{ij}$,每个需 $A$ 一行($n$ 元素)和 $B$ 一列($n$ 元素)。若所有 $A$ 行/B 列都本地,需 $O(n^2)$ 内存/处理器,不符。由 Loomis-Whitney 不等式,$P$ 处理器总内存 $M$ 下,每处理器至少通信 $\Omega(n^2/\sqrt{P})$(当 $M = O(n^2/P)$)。Cannon 达此下界。
