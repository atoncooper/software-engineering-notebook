## 一、问题定义

### 1.1 解决什么问题

单卡训练 LLM 不可能：
- **显存墙**：175B 参数 FP16 = 350GB，单 H100 80GB 装不下；
- **算力墙**：单卡训练 175B 需要 100+ 年；
- **通信墙**：千卡 AllReduce 占 30-50% 时间。

工业界用 **4 维并行 + 显存优化** 解决：
1. **数据并行 DP**：切 batch，每卡完整模型 → 受显存限制；
2. **张量并行 TP**：切矩阵，每卡部分权重 → 适合节点内 NVLink；
3. **流水并行 PP**：切层，每卡部分层 → 适合跨节点；
4. **专家并行 EP**：切 expert（MoE）→ 稀疏激活；
5. **ZeRO/FSDP**：参数/梯度/优化器状态分片到所有卡；
6. **Activation Checkpointing**：用算力换显存。

### 1.2 显存账本（175B 参数，Adam，FP16+FP32）

| 项 | 大小 | 说明 |
|----|------|------|
| 参数 (FP16) | 350 GB | $175\text{B} \times 2$ |
| 梯度 (FP16) | 350 GB | 同上 |
| 优化器状态 (FP32 AdamW) | 1400 GB | $175\text{B} \times 8$（参数 FP32 + 动量 FP32 + 方差 FP32） |
| 激活 (seq 2048, bs 32, 96 层) | ~700 GB | 反向重算前 |
| **总计** | **~2.8 TB** | 单卡 80GB 显存的 35 倍 |

🔥 **ZeRO-3 + Activation Checkpoint + TP + PP 才能跑通**。

## 三、原理与机制

### 3.1 数据并行 DP 📜

每 GPU 持有**完整模型**，处理**不同 batch**：
```
GPU0: batch0 → forward → loss0 → backward → grad0
GPU1: batch1 → forward → loss1 → backward → grad1
...
↓ AllReduce(grad)  # 所有 GPU 梯度同步
↓ 各自 optimizer.step()
```

**通信**：每步 1 次 AllReduce（梯度），$O(\text{参数量})$。

**显存**：每卡 = 全量参数 + 全量梯度 + 全量优化器状态 = **2.8TB / 8 ≈ 350GB**（仍然装不下）。

### 3.2 ZeRO：渐进式分片 📜🎓

DeepSpeed 的 ZeRO 把训练状态分片到所有 GPU：

| 阶段 | 分片对象 | 通信原语 | 显存节省 |
|------|----------|----------|----------|
| ZeRO-1 | 优化器状态 | AllReduce 梯度 + AllGather 参数更新 | 4x |
| ZeRO-2 | + 梯度 | ReduceScatter 梯度 + AllGather 参数 | 8x |
| ZeRO-3 | + 参数 | AllGather 参数（前向+反向） + ReduceScatter 梯度 | $N$ x |

**ZeRO-3 工作流**：
```
前向：
  for 每一层:
    AllGather(参数段) → 完整参数
    forward → 激活
    丢弃参数（释放显存）
反向：
  for 每一层（逆序）:
    AllGather(参数段) → 完整参数
    backward → 梯度
    ReduceScatter(梯度) → 自己段的梯度
    丢弃参数
更新：
  优化器状态分片，各自更新自己段
```

**通信开销**：与 DP 相同（仍 AllReduce 等价量），但显存随 $P$ 线性下降。

### 3.3 FSDP：PyTorch 的 ZeRO-3 📜

PyTorch 2.x 内置 FSDP，是 ZeRO-3 的工程化实现：
- `FlatParameter`：把模块参数压平为一维张量；
- `FSDP.wrap(model)`：分模块包装；
- 前向/反向自动 AllGather/ReduceScatter；
- 支持 `CPUOffload`（参数/优化器状态卸载到 CPU）；
- 支持 `ShardingStrategy.FULL_SHARD`（ZeRO-3）或 `SHARD_GRAD_OP`（ZeRO-2）。

### 3.4 张量并行 TP（Megatron） 📜🎓

**核心思想**：把大矩阵乘切到多 GPU。

**列并行（Column Parallel）**：
$$
Y = XW,\quad W = [W_1, W_2, \dots, W_P],\quad Y_i = XW_i
$$
每 GPU 持有 $W_i$（一列），输出 $Y_i$（不需要通信，直到下一步 AllReduce）。

**行并行（Row Parallel）**：
$$
Y = XW,\quad X = [X_1, \dots, X_P],\quad W = \begin{bmatrix} W_1 \\ \vdots \\ W_P \end{bmatrix},\quad Y = \sum_i X_i W_i
$$
每 GPU 持有 $W_i$（一行），输出需 AllReduce 求和。

**MLP 并行模式**：
```
X → [ColumnParallel: W1] → GeLU → [RowParallel: W2] → AllReduce → 输出
              ↓                       ↓
        每 GPU 独立              AllReduce 才合并
```

🔥 **关键性质**：一个 MLP 块只需 **1 次 AllReduce**（在 RowParallel 后）。Attention 类似（QKV 列并行，输出投影行并行）。

**通信量**：每层 2 次 AllReduce（前向 + 反向），$O(\text{hidden}^2)$——适合 NVLink 全互联（节点内 8 卡）。

### 3.5 流水并行 PP 📜

把模型按层切到多 GPU：
```
GPU0: layer 0-23
GPU1: layer 24-47
GPU2: layer 48-71
GPU3: layer 72-95
```

micro-batch 依次流过：GPU0 → GPU1 → GPU2 → GPU3。

**朴素 PP（GPipe 调度）**：所有 micro-batch 前向完，再所有反向。
- Bubble = (P-1) / (P-1+M)，M = micro-batch 数；
- M=4, P=4 → bubble = 60%（浪费大）。

**1F1B 调度**：前向 1 个 + 反向 1 个 交替，**减少激活显存**：
```
stage 0: F0 F1 F2 F3 B0 B1 B2 B3
stage 1:    F0 F1 F2 B0 F3 B1 B2 B3
stage 2:       F0 F1 B0 F2 B1 F3 B2 B3
stage 3:          F0 B0 F1 B1 F2 B2 F3 B3
```

**Interleaved 1F1B**：每 GPU 持有 $V$ 段（不连续层），交错调度，bubble 减为 $\frac{1}{V}$ 倍：
$$
\text{bubble} = \frac{(P-1)}{V \cdot M + P - 1}
$$
$V=4, M=8, P=4$ → bubble = 8.8%。

### 3.6 专家并行 EP（MoE）📜

MoE 层：输入 token 路由到 top-k 专家。EP 把不同 expert 放不同 GPU：
```
GPU0: expert 0,1
GPU1: expert 2,3
...
```

**通信**：每层 MoE 一次 All-to-All（token 重分布到 expert 所在 GPU），处理后再 All-to-All 回原 GPU。

DeepSeek-V3 用 **shared expert**（每 token 必经）+ **routed expert**（top-k），减少路由专家数。

### 3.7 序列并行 SP 📜

Megatron Sequence Parallel：把 sequence 维度切到多 GPU。LayerNorm/Dropout 等**不依赖跨 token** 的算子可并行。Attention 需要 AllGather 恢复完整 sequence。

**目的**：减少激活显存（激活随 seq 长度切分到 P 卡）。

### 3.8 3D 并行：DP × TP × PP

**典型配置**（1024 卡训练 175B）：
- $P_D = 16$（数据并行 16 路）；
- $P_T = 8$（张量并行 8 路，单节点 NVLink）；
- $P_P = 8$（流水并行 8 路，跨节点）；
- 总 GPU = $16 \times 8 \times 8 = 1024$。

**分配原则**：
- TP 放节点内（NVLink 高带宽，TP 通信量最大）；
- PP 跨节点（PP 通信量小，仅边界激活）；
- DP 跨所有剩余 GPU（DP 通信 AllReduce 梯度，可与计算 overlap）。

## 四、算法 / 流程

### 4.1 FSDP 训练循环伪代码

```
for batch in dataloader:
    for layer in fsdp_model:
        # 前向
        AllGather(layer.params)        # 拼参数
        out = layer.forward(x)
        Free(layer.params)             # 释放
    loss = criterion(out, y)
    
    for layer in reversed(fsdp_model):
        # 反向
        AllGather(layer.params)
        grad = layer.backward(grad_out)
        ReduceScatter(grad)            # 每卡留自己段
        Free(layer.params)
    
    optimizer.step()                   # 各卡更新自己段
```

### 4.2 MFU 计算

$$
\text{MFU} = \frac{\text{实测 FLOP/step}}{\text{GPU 峰值 FLOP/s} \times \text{step 时间} \times \text{GPU 数}}
$$

**175B 模型**：每步 FLOP $\approx 6 \times \text{参数数} \times \text{tokens} = 6 \times 175\text{B} \times B \times L$。
- $B=32$, $L=2048$ → 每步 $6 \times 175 \times 32 \times 2048 \approx 6.9 \times 10^{13}$ FLOP/卡；
- H100 FP16 峰值 989 TFLOP/s；
- MFU=50% → step 时间 $\approx 6.9\times10^{13}/(989\times10^{12}\times 0.5) \approx 140$ ms。

🏭 **业界基线**：
- GPT-3 175B on V100：MFU ~36%；
- LLaMA-2 70B on A100：MFU ~45%；
- LLaMA-3 70B on H100：MFU ~55%；
- DeepSeek-V3 671B on H800：MFU ~50%（MoE 难度高）。

## 六、代码示例

### 6.1 最小可运行版（教学）：PyTorch FSDP

```python
# file: fsdp_demo.py
# 运行: torchrun --nproc_per_node=8 fsdp_demo.py
import os
import torch
import torch.nn as nn
import torch.distributed as dist
from torch.distributed.fsdp import FullyShardedDataParallel as FSDP
from torch.distributed.fsdp import ShardingStrategy, MixedPrecision, CPUOffload
from torch.distributed.fsdp.wrap import size_based_auto_wrap_policy
from functools import partial

class TransformerBlock(nn.Module):
    def __init__(self, d=4096):
        super().__init__()
        self.attn = nn.MultiheadAttention(d, 32, batch_first=True)
        self.norm1 = nn.LayerNorm(d)
        self.ffn = nn.Sequential(
            nn.Linear(d, 4*d), nn.GELU(), nn.Linear(4*d, d)
        )
        self.norm2 = nn.LayerNorm(d)
    def forward(self, x):
        a, _ = self.attn(x, x, x, need_weights=False)
        x = self.norm1(x + a)
        x = self.norm2(x + self.ffn(x))
        return x

class MyModel(nn.Module):
    def __init__(self, n_layers=12, d=4096, vocab=32000):
        super().__init__()
        self.embed = nn.Embedding(vocab, d)
        self.blocks = nn.ModuleList([TransformerBlock(d) for _ in range(n_layers)])
        self.head = nn.Linear(d, vocab)
    def forward(self, x):
        x = self.embed(x)
        for b in self.blocks: x = b(x)
        return self.head(x)

def setup():
    dist.init_process_group("nccl")
    torch.cuda.set_device(int(os.environ["LOCAL_RANK"]))

def main():
    setup()
    rank = dist.get_rank()
    
    model = MyModel().cuda()
    
    # === FSDP 配置 ===
    mp = MixedPrecision(
        param_dtype=torch.bfloat16,
        reduce_dtype=torch.bfloat16,
        buffer_dtype=torch.bfloat16,
    )
    auto_wrap = partial(size_based_auto_wrap_policy, min_num_params=1_000_000)
    
    model = FSDP(
        model,
        sharding_strategy=ShardingStrategy.FULL_SHARD,  # ZeRO-3
        auto_wrap_policy=auto_wrap,                      # 大模块自动 wrap
        mixed_precision=mp,
        cpu_offload=CPUOffload(offload_params=False),    # 可设 True 做 ZeRO-Offload
        device_id=torch.cuda.current_device(),
    )
    
    opt = torch.optim.AdamW(model.parameters(), lr=1e-4)
    
    # 模拟数据
    for step in range(5):
        torch.manual_seed(42 + step + rank)
        x = torch.randint(0, 32000, (4, 2048), device="cuda")  # 每 GPU 一个 batch
        y = torch.randint(0, 32000, (4, 2048), device="cuda")
        
        opt.zero_grad()
        out = model(x)
        loss = nn.functional.cross_entropy(out.view(-1, 32000), y.view(-1))
        loss.backward()
        opt.step()
        
        if rank == 0:
            print(f"step {step} loss {loss.item():.4f}")
    
    dist.destroy_process_group()

if __name__ == "__main__":
    main()
```

🔥 **FSDP 关键参数**：
- `ShardingStrategy.FULL_SHARD`：ZeRO-3；
- `SHARD_GRAD_OP`：ZeRO-2；
- `NO_SHARD`：纯 DDP；
- `mixed_precision`：BF16 训练（H100/A100 推荐）；
- `auto_wrap_policy`：参数量超阈值的子模块自动 wrap（避免 wrap 太碎或太整）；
- `cpu_offload`：参数/优化器状态卸载 CPU（节省显存但变慢 2-3x）。

### 6.2 手把手：Megatron 张量并行

```python
# file: megatron_tp.py（伪代码示意，实际用 Megatron-LM 库）
import torch
import torch.nn as nn
import torch.distributed as dist

class ColumnParallelLinear(nn.Module):
    """列并行：W 切列，每 GPU 持有 W_i，输出 Y_i = X @ W_i"""
    def __init__(self, in_features, out_features, tp_size, rank):
        super().__init__()
        assert out_features % tp_size == 0
        self.out_per = out_features // tp_size
        self.weight = nn.Parameter(torch.empty(self.out_per, in_features))
        nn.init.normal_(self.weight)
        self.rank = rank
        self.tp_size = tp_size
    def forward(self, x):
        # x: [B, in], weight: [out_per, in]
        return torch.nn.functional.linear(x, self.weight)  # [B, out_per]

class RowParallelLinear(nn.Module):
    """行并行：W 切行，输入 X 切列，输出 AllReduce"""
    def __init__(self, in_features, out_features, tp_size, rank):
        super().__init__()
        assert in_features % tp_size == 0
        self.in_per = in_features // tp_size
        self.weight = nn.Parameter(torch.empty(out_features, self.in_per))
        nn.init.normal_(self.weight)
        self.rank = rank
        self.tp_size = tp_size
    def forward(self, x):
        # x: [B, in_per], weight: [out, in_per]
        out = torch.nn.functional.linear(x, self.weight)  # [B, out]
        dist.all_reduce(out)  # 跨 GPU 求和
        return out

class MLP(nn.Module):
    """Megatron MLP: ColumnParallel → GeLU → RowParallel → AllReduce"""
    def __init__(self, d, tp_size, rank):
        super().__init__()
        self.fc1 = ColumnParallelLinear(d, 4*d, tp_size, rank)
        self.fc2 = RowParallelLinear(4*d, d, tp_size, rank)
    def forward(self, x):
        h = self.fc1(x)        # [B, 4d/tp]
        h = torch.nn.functional.gelu(h)
        out = self.fc2(h)      # [B, d], 自动 AllReduce
        return out
```

🔥 **Megatron TP 要点**：
- 一次 MLP 块只需 1 次 AllReduce（fc2 后）；
- Attention 类似：QKV 列并行，输出投影行并行，1 次 AllReduce；
- TP 适合节点内 NVLink（8 卡），跨节点带宽不够。

## 七、常见陷阱与最佳实践 ⚠️

| 陷阱 | 后果 | 对策 |
|------|------|------|
| TP 跨节点 | 跨 IB 带宽不够，TP 通信成瓶颈 | TP 限制在节点内（NVLink） |
| PP micro-batch 太少 | bubble 占比大 | $M \geq 4P$，用 Interleaved 1F1B |
| 不用 Activation Checkpoint | 激活显存爆 | selective recompute（只对重激活层） |
| FSDP 模块 wrap 太碎 | AllGather 次数过多 | 用 `auto_wrap_policy` 按参数量阈值 |
| FSDP wrap 太整 | 单次 AllGather 过大 | 平衡 |
| 梯度累积时忘记 no_sync | 累积阶段也 AllReduce | 用 `model.no_sync()` context |
| BF16 不用 | 数值精度问题或损失算力 | H100/A100 用 BF16，V100 用 FP16+GradScaler |
| LayerNorm 用 FP32 | 数值不稳 | LayerNorm 内部强制 FP32 |
| AllReduce 串行 | 计算通信不重叠 | 用 DDP bucketing / FSDP 反向分块 |
| EP 负载不均 | 某专家过载 | DeepSeek 风格 loss-free auxiliary |
| 大 batch 学习率没调 | 训练发散 | LR 线性 scaling + warmup |

## 十、综合面试题

1. **基础**：为什么 TP 通常只用在节点内 8 卡？
   - 答：TP 每层 2 次 AllReduce，通信量 $O(\text{hidden}^2)$，对带宽要求高。节点内 NVLink 900GB/s，跨节点 IB 50GB/s，差 18 倍。跨节点 TP 会被通信淹没。

2. **进阶**：训练 70B 模型在 64 张 A100 上，怎么配并行策略？
   - 答：$P_T=8$（节点内 TP），$P_P=1$（70B 单节点 TP+ZeRO-3 可装下），$P_D=8$（8 节点数据并行）。用 FSDP ZeRO-3 + activation checkpoint + BF16。MFU 目标 45%+。

3. **深度**：ZeRO-3 与 TP 都是切参数，区别是什么？什么时候选谁？
   - 答：(1) 通信时机：ZeRO-3 每层前向 AllGather 参数用完即弃；TP 全程持有部分参数，前向反向都有 AllReduce。(2) 通信量：ZeRO-3 总通信量与 DP 相同（参数量级），TP 通信量随层增多线性增。(3) 选 ZeRO-3：模型中等（<100B）、追求易用；选 TP：超大模型（>100B）、追求极致 MFU。

4. **设计**：1024 卡训 175B，bubble 20%。如何降到 10%？
   - 答：(1) 增大 micro-batch 数 $M$（bubble $\propto 1/M$）；(2) Interleaved 1F1B 增 $V$；(3) 减 $P_P$（PP 是 bubble 来源）；(4) 用 1F1B + Selective Activation Checkpoint 减显存腾空间给 $M$；(5) PP 跨节点带宽优化。

5. **工程**：FSDP 训练在 step 100 时 OOM。怎么排查？
   - 答：(1) 看是否 activation 显存（加 checkpoint）；(2) 看是否 wrap 太整（一次 AllGather 过大）；(3) 看是否没用 BF16；(4) 看 CPU offload 是否启用；(5) 看 batch 是否过大；(6) 看是否有梯度累积误用导致多步显存叠加；(7) 用 `torch.cuda.memory._dump_snapshot` 看 fragmentation。

6. **学术**：证明 ZeRO-3 通信量与 DP 相同。
   - 答：DP 每步一次 AllReduce（梯度），通信量 $2(P-1)/P \cdot n \approx 2n$（Ring）。ZeRO-3：前向每层 AllGather 参数（$n$ 字节，但用完弃），反向每层 AllGather 参数 + ReduceScatter 梯度。一层的 AllGather + ReduceScatter 等价于一次 AllReduce。所以总通信量与 DP 相同，但 ZeRO-3 显存减 $P$ 倍。代价：通信次数随层数增多（每层一次 AllGather），但每次通信量小，可 overlap。
