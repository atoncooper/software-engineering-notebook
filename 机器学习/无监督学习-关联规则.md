# 无监督学习 —— 关联规则

> 关联规则挖掘是从交易数据中找"经常一起出现"的项集与"若 A 则 B"的规则。
> 它是购物篮分析、交叉销售、推荐召回、欺诈模式挖掘的经典工具。
> 本文按 **支持度/置信度/提升度 → Apriori → FP-Growth → 关联规则生成 → 评估与陷阱** 顺序展开。

---


## 一、问题定义

### 1.1 基本概念

- **项集（itemset）** $I = \{i_1, \dots, i_m\}$，全体项的集合。
- **交易（transaction）** $T \subseteq I$，一笔交易含若干项。
- **交易数据库** $D = \{T_1, \dots, T_n\}$。
- **关联规则** $A \to B$，$A, B \subset I$，$A \cap B = \emptyset$。$A$ 为前件（antecedent），$B$ 为后件（consequent）。

### 1.2 目标

找出所有满足**支持度 ≥ min_sup** 且**置信度 ≥ min_conf** 的规则。

典型应用：
- 购物篮：{尿布, 啤酒} 经典案例
- 交叉销售：买 A 的人倾向买 B
- 推荐召回：用户历史 → 候选 item
- 异常：罕见但高置信规则 = 可疑模式

---

## 二、核心指标

### 2.1 支持度（Support）

项集 $X$ 的支持度 = 含 $X$ 的交易占比：

$$
\text{supp}(X) = \frac{|\{T \in D : X \subseteq T\}|}{|D|}
$$

规则 $A \to B$ 的支持度 = $\text{supp}(A \cup B)$。

**意义**：衡量项集/规则的**统计显著性**。支持度太低说明偶然现象，无价值。

### 2.2 置信度（Confidence）

规则 $A \to B$ 的置信度 = 含 $A$ 的交易中也含 $B$ 的比例：

$$
\text{conf}(A \to B) = \frac{\text{supp}(A \cup B)}{\text{supp}(A)} = P(B \mid A)
$$

**意义**：衡量规则的**强度**，但**忽略 $B$ 的先验频率**。若 $B$ 本身就频繁（如热销品），任何 $A \to B$ 置信度都高，但无信息量。

### 2.3 提升度（Lift）

$$
\text{lift}(A \to B) = \frac{\text{conf}(A \to B)}{\text{supp}(B)} = \frac{P(A \cap B)}{P(A)P(B)}
$$

**意义**：衡量 $A$ 与 $B$ 的**相关性**（独立时 lift=1）：
- $\text{lift} > 1$：$A$ 促进 $B$（正相关）
- $\text{lift} = 1$：$A, B$ 独立
- $\text{lift} < 1$：$A$ 抑制 $B$（负相关）

### 2.4 杠杆率（Leverage）

$$
\text{leverage}(A \to B) = P(A \cap B) - P(A)P(B)
$$

**意义**：$A, B$ 共现频率超过独立期望的绝对量。范围 $[-1, 1]$，0 = 独立。

### 2.5 确信度（Conviction）

$$
\text{conv}(A \to B) = \frac{1 - \text{supp}(B)}{1 - \text{conf}(A \to B)}
$$

**意义**：衡量规则**违反的频次**。若 $A \to B$ 完全独立，conv = 1；规则越强 conv 越大；$\text{conf} = 1$ 时 conv = $\infty$。比 lift 对方向更敏感（$A \to B$ 与 $B \to A$ 不同）。

### 2.6 指标对比

| 指标 | 公式 | 优点 | 局限 |
|------|------|------|------|
| Support | $P(A \cap B)$ | 显著性、可剪枝 | 忽略方向 |
| Confidence | $P(B\|A)$ | 直观强度 | 忽略 $B$ 先验 |
| Lift | $P(A \cap B)/[P(A)P(B)]$ | 衡量相关性 | 对称，不分方向；稀有项 lift 易虚高 |
| Leverage | $P(A \cap B) - P(A)P(B)$ | 绝对量、可解释 | 量纲敏感 |
| Conviction | $\frac{1-P(B)}{1-P(B\|A)}$ | 方向性、对违反敏感 | $P(B)=1$ 时无定义 |

### 2.7 陷阱：高置信度 ≠ 有用

举例：买彩票 $A$ → 中奖 $B$，置信度 = $P(B\mid A) = P(B)$（假设两者独立）。若 $B$ 极罕见，置信度低；但若 $B$ 很常见，置信度高也不说明 $A$ 有因果作用。**必须配合 lift 看**。

## 三、频繁项集挖掘：Apriori

### 3.1 Apriori 性质（反单调性）

**性质**：若项集 $X$ 频繁，则其所有子集都频繁；若 $X$ 非频繁，则其所有超集都非频繁。

**证明**：$\text{supp}(X) \le \text{supp}(Y)$ 当 $Y \subseteq X$（含 $X$ 的交易必含 $Y$）。

**意义**：用 $k-1$ 频繁项集构造 $k$ 候选时，只要某 $(k-1)$ 子集非频繁，该 $k$ 候选必非频繁，可剪枝。

### 3.2 算法

```
输入: D, min_sup
1. L_1 = { 频繁 1-项集 }
2. for k = 2, 3, ...:
   a. C_k = 候选生成(L_{k-1})     # 连接 + 剪枝
   b. 扫描 D 统计 C_k 中每个候选项集的支持度
   c. L_k = { X ∈ C_k : supp(X) ≥ min_sup }
   d. 若 L_k 为空: break
3. 返回 ⋃_k L_k
```

**候选生成**：连接 $L_{k-1}$ 与自身，要求前 $k-2$ 项相同；然后剪去任何 $(k-1)$ 子集不在 $L_{k-1}$ 的候选。

### 3.3 复杂度

- 每轮扫描 $D$ 一次，共 $O(k_{\max})$ 次。
- 候选数最坏 $O(2^m)$（$m$ 为项数），但 Apriori 剪枝大幅削减。
- 适合**稀疏交易、min_sup 较高**场景。

### 3.4 Apriori 的瓶颈

- 多次扫库（I/O 开销大）。
- 候选生成仍可能爆炸（min_sup 低时）。
- FP-Growth 用压缩结构避免这两点。

## 四、频繁项集挖掘：FP-Growth

### 4.1 思想

不产生候选，用 **FP-Tree**（Frequent Pattern Tree）压缩交易数据，递归在树上挖模式。

### 4.2 FP-Tree 构造

1. 第一遍扫描：统计 1-项集频次，按频次降序排序（同频按字典序）。
2. 第二遍扫描：每笔交易按上述顺序排序后插入树。共享前缀 → 压缩。
3. 每个节点维护**计数**；每个项维护**头表**（header table）链所有该项节点。

**例子**：

```
交易数据库（min_sup=2）:
T1: {A, B, C, D}
T2: {A, B, C}
T3: {A, C, D}
T4: {B, C, D}
T5: {A, B, C, D}

频次: A:4, B:4, C:5, D:4 → 排序 C, A, B, D

FP-Tree (节点:计数):
        root
         │
         C:5
        / \
     A:4   B:1 (来自 T4)
      │     │
     B:3   D:1
      │
     D:3
```

### 4.3 FP-Growth 递归挖

对每个项（自底向上），找其**条件模式基**（conditional pattern base）= 树中所有到该项的路径前缀 + 计数。

构造**条件 FP-Tree**，递归挖频繁项集。

```
FP-Growth(Tree, α):
  if Tree 是单路径:
    枚举路径上项集组合，每个并入 α 形成频繁项集
  else:
    for each 项 i in Tree 头表 (自底向上):
      β = α ∪ {i}
      输出 β
      构造 β 的条件模式基
      构造 β 的条件 FP-Tree（仅保留频次 ≥ min_sup 的项）
      if 条件树非空:
        FP-Growth(条件树, β)
```

### 4.4 Apriori vs FP-Growth

| | Apriori | FP-Growth |
|---|---------|-----------|
| 扫描数据库 | $k$ 次 | 2 次 |
| 候选生成 | 需要 | 不需要 |
| 内存 | 候选列表 | FP-Tree（可能大但压缩） |
| 复杂度 | $O(k \cdot |D| \cdot \text{候选数})$ | $O(|D| \cdot \text{路径长})$ 每递归层 |
| 适合 | min_sup 较高 | min_sup 较低、稠密 |
| 缺点 | 多次 I/O | 树构造内存大；递归调用开销 |

### 4.5 工程实践

- **并行化**：FP-Growth 难并行（条件树间依赖），有 PFP-Growth 划分项集并行。
- **稀疏数据**：Apriori 常够用；稠密低 min_sup 用 FP-Growth。
- **流式数据**：有 FP-Stream 等近似算法。

## 五、关联规则生成

### 5.1 从频繁项集生成规则

对每个频繁项集 $Z$（$|Z| \ge 2$），枚举非空真子集 $A$，规则 $A \to Z \setminus A$，计算置信度，保留 $\ge$ min_conf 的规则。

$$
\text{conf}(A \to Z \setminus A) = \frac{\text{supp}(Z)}{\text{supp}(A)}
$$

### 5.2 置信度的反单调性

若 $A \subseteq A' \subseteq Z$：

$$
\text{conf}(A \to Z \setminus A) \le \text{conf}(A' \to Z \setminus A')
$$

（因为 $\text{supp}(A) \ge \text{supp}(A')$ 而分子同为 $\text{supp}(Z)$）

**剪枝**：若规则 $A \to Z \setminus A$ 不满足 min_conf，则 $A$ 的所有超集作为前件的规则也不满足，可剪枝。

### 5.3 规则数量爆炸

$|Z| = k$ 时有 $2^k - 2$ 条候选规则。需配合 min_conf、min_lift、规则数上限剪枝。

### 5.4 多最小支持度

不同项设不同 min_sup（如热门商品阈值高、长尾商品阈值低），避免长尾项被埋没。引入"最小项支持度"概念。

## 六、评估与陷阱

### 6.1 规则质量综合评估

| 指标 | 阈值经验 |
|------|----------|
| Support | $\ge 0.01$（依数据规模） |
| Confidence | $\ge 0.5$ 视任务 |
| Lift | $> 1.2$ 才有意义（远离 1） |
| Conviction | $> 1.5$ |
| Leverage | $> 0.01$ |

不应只看单一指标，需组合判断。

### 6.2 常见陷阱

| 陷阱 | 后果 | 对策 |
|------|------|------|
| 只看置信度 | 热门品虚高 | 配 lift / conviction |
| min_sup 太低 | 规则爆炸、计算慢 | 渐进下调，先粗筛 |
| 忽略时间顺序 | "买啤酒→买尿布"可能是同时而非因果 | 加时序约束（序列模式） |
| 类别失衡 | 多数类规则掩盖少数类 | 分层挖掘或加权 |
| 大量冗余规则 | {A,B}→C 与 {A}→C 重复 | 闭项集 / 极大项集 |
| 误当因果 | 相关 ≠ 因果 | 仅作线索，需 A/B 验证 |
| 单维规则局限 | 忽略用户特征 | 多维关联规则（含属性维度） |

### 6.3 闭项集与极大项集

- **闭项集（closed）**：$X$ 闭 ⟺ 不存在超集 $Y \supset X$ 与 $X$ 同支持度。压缩冗余。
- **极大项集（maximal）**：$X$ 极大 ⟺ 不存在频繁超集。最压缩，但丢失支持度信息。
- 工程：先用闭项集压缩，再生成规则。

### 6.4 负关联规则

$A \to \neg B$：含 $A$ 时不含 $B$ 的概率高。lift < 1 时关注。需扩展指标定义。

## 七、序列模式与扩展

### 7.1 序列模式挖掘

交易带时间戳，找**有序**模式：先买 A → 后买 B → 后买 C。

代表算法：GSP、PrefixSpan、SPADE。

应用：用户行为路径、患者就诊序列、网页浏览路径。

### 7.2 多维关联规则

维度扩展到商品属性：

> 性别=女 ∧ 年龄段=青年 → 商品=化妆品

需把属性作为项处理，或用多维挖掘算法。

### 7.3 量化关联规则

属性是数值时（如"年龄 > 30 → 余额 > 10000"）。需分箱静态化或动态分箱。

### 7.4 图关联 / 子图模式

在图数据中找频繁子图（如分子结构、社交三元组）。算法：gSpan、FSG。

## 八、Python 实现

### 8.1 从零实现 Apriori

```python
from itertools import combinations
from collections import defaultdict
from typing import Iterable

def _get_support(transactions: list[frozenset], itemset: frozenset) -> float:
    count = sum(1 for t in transactions if itemset.issubset(t))
    return count / len(transactions)

def apriori(transactions: list[frozenset], min_support: float = 0.1):
    n = len(transactions)
    items = {i for t in transactions for i in t}

    # L1
    L1 = [frozenset([i]) for i in items
          if _get_support(transactions, frozenset([i])) >= min_support]

    all_freq = dict()
    Lk = L1
    k = 1
    while Lk:
        for itemset in Lk:
            all_freq[itemset] = _get_support(transactions, itemset)
        # 生成 C_{k+1}: 自连接 L_k 取前 k-1 项相同
        C_next = set()
        for i in range(len(Lk)):
            for j in range(i + 1, len(Lk)):
                union = Lk[i] | Lk[j]
                if len(union) == k + 1:
                    # 剪枝: 所有 k-子集必须频繁
                    if all(frozenset(s) in all_freq
                           for s in combinations(union, k)):
                        C_next.add(union)
        # 扫描计数
        Lk = [c for c in C_next
              if _get_support(transactions, c) >= min_support]
        k += 1
    return all_freq


def generate_rules(freq_itemsets: dict, min_conf: float = 0.5):
    rules = []
    for itemset, supp in freq_itemsets.items():
        if len(itemset) < 2:
            continue
        for k in range(1, len(itemset)):
            for antecedent in combinations(itemset, k):
                A = frozenset(antecedent)
                B = itemset - A
                supp_A = freq_itemsets[A]
                conf = supp / supp_A
                if conf >= min_conf:
                    supp_B = freq_itemsets[B]
                    lift = conf / supp_B
                    rules.append({
                        "rule": f"{set(A)} -> {set(B)}",
                        "support": supp,
                        "confidence": conf,
                        "lift": lift,
                    })
    return sorted(rules, key=lambda r: r["lift"], reverse=True)


def test_apriori_finds_frequent_pairs():
    transactions = [
        frozenset(["bread", "milk"]),
        frozenset(["bread", "diaper", "beer", "egg"]),
        frozenset(["milk", "diaper", "beer", "cola"]),
        frozenset(["bread", "milk", "diaper", "beer"]),
        frozenset(["bread", "milk", "diaper", "cola"]),
    ]
    freq = apriori(transactions, min_support=0.6)
    assert frozenset(["bread"]) in freq
    assert frozenset(["milk"]) in freq
    assert frozenset(["bread", "milk"]) in freq
    rules = generate_rules(freq, min_conf=0.7)
    assert any("bread" in r["rule"] and "milk" in r["rule"] for r in rules)
```

## 九、实战案例：购物篮分析

```python
"""
零售购物篮：找出交叉销售候选规则。
"""
import pandas as pd
from mlxtend.preprocessing import TransactionEncoder
from mlxtend.frequent_patterns import fpgrowth, association_rules

# 模拟交易（实际场景从订单明细 SQL 拉取）
orders = [
    [f"item_{i}" for i in row]
    for row in [
        [1, 2, 5], [2, 4], [2, 3], [1, 2, 4], [1, 3],
        [2, 3], [1, 3], [1, 2, 3, 5], [1, 2, 3],
    ]
]

te = TransactionEncoder()
df = pd.DataFrame(te.fit(orders).transform(orders), columns=te.columns_)

# 1. 频繁项集 (FP-Growth)
freq = fpgrowth(df, min_support=0.2, use_colnames=True)

# 2. 生成规则，按 lift 排序
rules = association_rules(freq, metric="lift", min_threshold=1.2)
rules = rules.sort_values("lift", ascending=False)

# 3. 业务过滤
# - 置信度 >= 0.6
# - 后件为高毛利商品
high_margin = {"item_5"}
strong = rules[
    (rules["confidence"] >= 0.6) &
    (rules["consequents"].apply(lambda s: bool(s & high_margin)))
]
print(strong[["antecedents", "consequents", "support",
              "confidence", "lift"]])
```

**典型应用**：
- 推荐召回：用户加购 A，召回强规则后件 B。
- 页面布局：将高 lift 商品放邻近。
- 促销组合：满减活动包高 lift 商品。
- 长尾激活：用热门品 → 长尾品的规则带量。

## 十、常见陷阱

| 陷阱 | 后果 | 对策 |
|------|------|------|
| 只看 confidence | 热门品规则虚高 | 配 lift / conviction |
| min_sup 过低 | 候选爆炸、计算不可行 | 渐进扫，或用 FP-Growth |
| 把相关当因果 | 业务误判 | 仅作线索，A/B 验证 |
| 规则冗余 | {A,B}→C 与 {A}→C 重复 | 用闭项集 |
| 忽略时间维度 | 把同时购买当因果序列 | 序列模式 |
| 长尾项被埋 | min_sup 全局一致过于严苛 | 多最小支持度 |
| 数据稀疏（用户-商品矩阵） | 大部分项支持度极低 | 先协同过滤召回，再关联规则 |
| 误用 lift | 偶然共现的稀有对 lift 虚高 | 加 support 下限 |
| 单维规则局限 | 仅商品维度，忽略用户属性 | 多维关联 |

## 十一、与其他方法的关系

| 方法 | 关系 |
|------|------|
| Apriori ↔ FP-Growth | 同目标不同策略：候选 vs 压缩树 |
| 关联规则 ↔ 协同过滤 | ItemCF 的"共同购买"统计即关联规则；规则可作召回源 |
| 关联规则 ↔ 决策树 | 决策树路径本质是带类别的关联规则 |
| 关联规则 ↔ 贝叶斯 | lift = $P(A \cap B)/[P(A)P(B)]$ 即贝叶斯相关度 |
| 关联规则 ↔ 因果推断 | 相关 ≠ 因果，需 SCM / do-calculus 进一步验证 |
| 闭项集 ↔ 概念格 | 闭项集形成概念格，与形式概念分析同构 |
| 序列模式 ↔ RNN | RNN 可学序列模式，关联规则为显式规则版本 |

## 十二、面试速答

| 问 | 答 |
|----|-----|
| 三大指标定义？ | supp=$P(A\cap B)$，conf=$P(B\|A)$，lift=conf/$P(B)$。 |
| 为何不能只看 confidence？ | 忽略 $B$ 先验频率，热门品规则虚高。 |
| Apriori 性质？ | 反单调性：非频繁项集的超集必非频繁。 |
| Apriori vs FP-Growth？ | Apriori 多次扫库 + 候选生成；FP-Growth 两次扫库 + 压缩树，无候选。 |
| FP-Tree 的核心思想？ | 共享前缀压缩交易，递归挖条件模式基。 |
| Lift 的范围与含义？ | $[0, \infty)$，1=独立，>1 正相关，<1 负相关。 |
| Conviction 与 Lift 区别？ | Conv 有方向性（A→B ≠ B→A），Lift 对称。 |
| 闭项集与极大项集？ | 闭：无同支持度超集；极大：无频繁超集。极大压缩更强但丢支持度信息。 |
| 关联规则与因果的关系？ | 仅相关，不蕴含因果，需进一步验证。 |
| 序列模式与关联规则区别？ | 序列模式考虑时间顺序，关联规则视为同事务集。 |
| 多最小支持度为何？ | 全局阈值埋没长尾项，按项类别设阈值。 |
| 关联规则如何用于推荐？ | 强规则作召回源：用户历史 → 后件候选。 |

## 十三、综合面试题

1. **推导 Apriori 反单调性。**
   - $Y \subseteq X$ ⟹ 含 $X$ 的交易必含 $Y$ ⟹ $\text{supp}(X) \le \text{supp}(Y)$。
   - 若 $X$ 非频繁（$\text{supp}(X) < \text{min\_sup}$），则 $\text{supp}(Y) < \text{min\_sup}$ 时 $Y$ 也非频繁。
   - 逆否：$Y$ 频繁 ⟹ $X$ ... 不一定；正命题是 $X$ 频繁 ⟹ 所有子集频繁。

2. **为何 lift > 1 不等于因果？**
   - Lift 仅衡量 $P(A \cap B) > P(A)P(B)$，即统计相关。
   - 混杂因素 C 可能同时导致 A 和 B，去 C 条件后 lift 可能消失甚至反转（辛普森悖论）。
   - 因果需干预 $P(B \mid \text{do}(A))$，关联规则无干预机制。

3. **FP-Growth 为何比 Apriori 快？**
   - Apriori 多次扫库（每轮一次）+ 候选生成爆炸。
   - FP-Growth 两次扫库构造压缩树，递归挖模式时不需重新扫原始数据，仅在条件树上工作。
   - 缺点：树内存大；稠密数据上树可能近原始数据大小。

4. **置信度的反单调性证明。**
   - $A \subseteq A' \subseteq Z$，$\text{conf}(A \to Z \setminus A) = \text{supp}(Z)/\text{supp}(A)$。
   - $\text{supp}(A) \ge \text{supp}(A')$（$A' \supseteq A$ 含得少）。
   - 故 $\text{conf}(A \to Z \setminus A) \le \text{conf}(A' \to Z \setminus A')$。
   - 用于规则生成剪枝。

5. **何时用 Apriori 何时用 FP-Growth？**
   - min_sup 高、数据稀疏：Apriori 简单够用。
   - min_sup 低、数据稠密：FP-Growth 避免候选爆炸。
   - 流式 / 分布式：PFP-Growth 划分项集并行。
   - 内存极受限：Apriori 多扫盘，FP-Growth 需树常驻内存。

6. **如何处理关联规则的冗余？**
   - 闭项集：保留所有"被超集以同支持度包含"的代表。
   - 极大项集：仅保留最长频繁项集（丢支持度）。
   - 规则冗余：若规则 R1 的前件 ⊂ R2 前件且置信度相等，R1 冗余。
   - 工具：`mlxtend.frequent_patterns` 有 `closed=True` / `maximal=True` 选项。

7. **设计一个跨品类推荐系统用关联规则。**
   - 离线：用历史订单跑 FP-Growth，按品类 / 用户分群分别挖掘规则，存 Redis。
   - 在线：用户当前购物车 / 浏览序列 → 查匹配前件 → 召回后件 → 与协同过滤结果融合排序。
   - 评估：CTR、CVR、A/B 测试提升。
   - 注意冷启动：新商品无规则，用内容相似度补位。

8. **关联规则与协同过滤的本质差异？**
   - 关联规则：显式规则"若 A 则 B"，全局长尾有效，可解释。
   - 协同过滤：隐式向量相似，个性化强但黑箱。
   - 实践：CF 召回 + 关联规则补充解释 + 业务强规则（如配件）。

9. **如何把多维属性引入关联规则？**
   - 把用户属性（年龄、性别）和商品作为项共同出现在"事务"中：`{男, 30-40岁, 买手机}`。
   - 规则如 `性别=男 ∧ 年龄=30-40 → 买手机`。
   - 注意：属性项和商品项混合，需调整 min_sup 阈值（属性项可能极频繁，需提高）。

10. **量化关联规则如何处理？**
    - 静态分箱：把数值属性分为区间（年龄 20-30、30-40），转为类别项。
    - 动态分箱：根据目标优化分箱边界。
    - 统计关联：用相关系数 / 回归分析，不强制离散化。

## 十四、公式速查卡

| 公式 | 表达式 |
|------|--------|
| 支持度 | $\text{supp}(X) = \|{T : X \subseteq T}\| / \|D\|$ |
| 置信度 | $\text{conf}(A \to B) = \text{supp}(A \cup B)/\text{supp}(A)$ |
| 提升度 | $\text{lift}(A \to B) = \text{conf}(A \to B)/\text{supp}(B)$ |
| 杠杆率 | $\text{leverage} = P(A \cap B) - P(A)P(B)$ |
| 确信度 | $\text{conv} = (1 - \text{supp}(B))/(1 - \text{conf}(A \to B))$ |
| 反单调性 | $Y \subseteq X \Rightarrow \text{supp}(Y) \ge \text{supp}(X)$ |
