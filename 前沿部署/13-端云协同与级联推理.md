# 13 - 端云协同与级联推理

> 端云协同是隐私 vs 性能矛盾的最优解：端侧小模型处理简单请求，云端大模型处理复杂请求。本章梳理级联推理（cascade）原理、路由策略、隐私保护、降级机制，以及 Apple Intelligence、Google Gemini Nano 等工业实践。

## 二、问题定义与边界

### 2.1 解决什么

- **级联推理原理**：端侧小模型 + 云端大模型
- **路由策略**：复杂度分类器、阈值
- **隐私保护**：数据分级、端侧强制
- **降级机制**：网络故障、云端不可用

### 2.2 不解决什么

- 不深入端侧推理（12 章）
- 不覆盖云端推理（03-09 章）

## 三、直觉解释

### 3.1 为什么需要端云协同

```
纯云端:
  - 延迟: 300ms TTFT + 100ms 网络 = 400ms
  - 隐私: 数据上传
  - 成本: 按 token 计费

纯端侧:
  - 延迟: 800ms (小模型慢)
  - 隐私: 完全本地
  - 成本: 0 (一次硬件)
  - 但: 模型小, 复杂任务不行

端云协同 (cascade):
  - 简单请求 (70%): 端侧, 200ms, 0 成本
  - 复杂请求 (30%): 云端, 400ms, $0.005/M token
  - 平均延迟: 0.7×200 + 0.3×400 = 260ms
  - 平均成本: 0.7×0 + 0.3×$0.005 = $0.0015/M token
  - 比纯云端: 延迟 -35%, 成本 -70%
```

### 3.2 级联推理模式

```
模式 1: 端侧优先 + 云端兜底
  端侧 → 置信度高 → 返回
       → 置信度低 → 云端 → 返回

模式 2: 并行
  端侧 + 云端 同时启动
  端侧先返回 → 用端侧
  云端后返回 → 丢弃 (或用云端)

模式 3: 分阶段
  端侧草稿 → 云端润色
  端侧分类 → 云端专精

模式 4: Speculative (投机)
  端侧生成 k token → 云端验证
  接受猜对部分 + 云端补全
```

### 3.3 路由策略

```
1. 规则路由
   if "代码" in prompt: cloud
   elif "数学" in prompt: cloud
   else: edge

2. 复杂度分类器
   - 训练分类器 (BERT-small)
   - 输入: prompt
   - 输出: simple / complex
   - 简单 → 端侧, 复杂 → 云端

3. 置信度路由
   - 端侧生成 + 置信度
   - 置信度 > 阈值 → 返回
   - 否则 → 云端

4. 长度路由
   - 短输出 (< 100 token) → 端侧
   - 长输出 → 云端
```

## 四、核心概念与架构

### 4.1 Cascade 架构

```
[Client] → [Router]
              │
              ├──→ [Edge Model (1B)] ──→ 简单请求返回
              │                          │
              │                          ↓ (置信度低)
              └──→ [Cloud Model (70B)] ──→ 复杂请求返回
```

### 4.2 复杂度分类器

```python
class ComplexityRouter:
    def __init__(self):
        # 训练复杂度分类器
        # 标签: simple / complex
        self.classifier = load_classifier()

    def route(self, prompt):
        complexity = self.classifier(prompt)

        if complexity == "simple":
            return "edge"
        else:
            return "cloud"

# 训练数据准备
def prepare_training_data():
    # 1. 收集 prompt + 端侧/云端输出
    data = []
    for prompt in prompts:
        edge_output = edge_model.generate(prompt)
        cloud_output = cloud_model.generate(prompt)

        # 用 LLM judge 评估
        edge_quality = llm_judge(prompt, edge_output)
        cloud_quality = llm_judge(prompt, cloud_output)

        if edge_quality >= cloud_quality * 0.9:
            data.append((prompt, "simple"))  # 端侧够用
        else:
            data.append((prompt, "complex"))  # 需要云端

    return data
```

### 4.3 置信度路由

```python
class ConfidenceRouter:
    def __init__(self, threshold=0.7):
        self.edge_model = load_edge_model()
        self.cloud_client = CloudLLMClient()
        self.threshold = threshold

    def infer(self, prompt):
        # 1. 端侧生成 + 置信度
        edge_output, confidence = self.edge_model.generate_with_confidence(prompt)

        if confidence > self.threshold:
            return edge_output, "edge"

        # 2. 置信度低, 转云端
        cloud_output = self.cloud_client.generate(prompt)
        return cloud_output, "cloud"
```

### 4.4 隐私分级路由

```python
class PrivacyAwareRouter:
    def __init__(self):
        self.sensitivity_classifier = load_sensitivity_classifier()

    def route(self, prompt, user_context):
        sensitivity = self.sensitivity_classifier(prompt)

        if sensitivity == "public":
            # 公开信息, 可上云
            return "cloud-70b"

        elif sensitivity == "internal":
            # 内部, 私有云
            return "private-cloud-13b"

        elif sensitivity == "sensitive":
            # 敏感, 端侧
            return "edge-7b"

        else:  # confidential
            # 机密, 强制端侧小模型
            return "edge-1b-q4"

    def sensitivity_classifier(self, prompt):
        # 检测 PII (个人身份信息)
        if has_pii(prompt):
            return "sensitive"

        # 检测医疗/金融关键词
        if has_medical(prompt) or has_financial(prompt):
            return "sensitive"

        # 默认 internal
        return "internal"
```

### 4.5 降级机制

```python
class ResilientCascade:
    def __init__(self):
        self.edge = EdgeModel()
        self.cloud = CloudClient()
        self.network_monitor = NetworkMonitor()

    def infer(self, prompt):
        # 1. 检查网络
        if not self.network_monitor.is_cloud_reachable():
            # 网络故障, 强制端侧
            return self.edge.generate(prompt), "edge-fallback"

        # 2. 正常路由
        complexity = self.classifier(prompt)
        if complexity == "simple":
            return self.edge.generate(prompt), "edge"

        try:
            # 云端, 超时 5s
            return asyncio.wait_for(
                self.cloud.generate(prompt),
                timeout=5
            ), "cloud"
        except (TimeoutError, NetworkError):
            # 云端故障, 降级端侧
            return self.edge.generate(prompt), "edge-fallback"
```

## 六、底层原理

### 6.1 级联的成本数学

```
假设:
- 端侧: 0 成本, 200ms 延迟, 70% 请求
- 云端: $0.005/M token, 400ms 延迟, 30% 请求

平均延迟 = 0.7×200 + 0.3×400 = 260ms
平均成本 = 0.7×0 + 0.3×$0.005 = $0.0015/M token

对比纯云端:
- 延迟: 400ms → 260ms (-35%)
- 成本: $0.005 → $0.0015 (-70%)

对比纯端侧:
- 延迟: 200ms → 260ms (+30%, 但能处理复杂请求)
- 成本: 0 → $0.0015 (+$0.0015, 但质量好)
```

### 6.2 路由准确率影响

```
路由准确率 p:
- p=1.0 (完美路由): 简单去端侧, 复杂去云端
- p=0.9: 10% 误判
  - 简单误判到云端: 浪费成本
  - 复杂误判到端侧: 质量差

误判成本:
- 简单误判到云端: 多花 $0.005/M token (小)
- 复杂误判到端侧: 输出质量差 (大, 影响体验)

权衡: 宁可多送云端, 不可错过复杂
阈值调整: 复杂度分类器偏向 "complex"
```

### 6.3 网络感知路由

```
网络质量:
- WiFi/5G: 延迟 50ms, 云端可行
- 4G: 延迟 200ms, 云端慢
- 弱网/无网: 强制端侧

动态路由:
if network_quality == "good":
    use cascade (端侧 + 云端)
elif network_quality == "poor":
    edge only
else:  # offline
    edge only
```

## 七、代码与配置示例

### 7.1 完整端云协同实现

```python
# cascade_inference.py
import asyncio
from typing import Tuple

class CascadeInference:
    def __init__(self):
        # 端侧
        self.edge_model = EdgeLLM("llama-3.2-1b-q4")

        # 云端
        self.cloud_client = CloudLLMClient(
            endpoint="https://api.myorg.com/v1",
            model="llama-3.1-70b"
        )

        # 路由
        self.router = ComplexityRouter()
        self.privacy_router = PrivacyAwareRouter()

        # 监控
        self.network = NetworkMonitor()

    async def infer(self, prompt: str, user_id: str) -> Tuple[str, str]:
        """返回 (output, source)"""

        # 1. 隐私检查
        privacy_level = self.privacy_router.classify(prompt)
        if privacy_level == "confidential":
            # 强制端侧
            return await self.edge_model.generate(prompt), "edge-confidential"

        if privacy_level == "sensitive":
            # 端侧 7B (如果有)
            return await self.edge_model.generate(prompt), "edge-sensitive"

        # 2. 网络检查
        if not self.network.is_cloud_reachable():
            return await self.edge_model.generate(prompt), "edge-offline"

        # 3. 复杂度路由
        complexity = self.router.route(prompt)

        if complexity == "simple":
            # 端侧
            return await self.edge_model.generate(prompt), "edge"

        # 4. 云端 (复杂)
        try:
            return await asyncio.wait_for(
                self.cloud_client.generate(prompt),
                timeout=5.0
            ), "cloud"
        except (asyncio.TimeoutError, NetworkError):
            # 5. 降级端侧
            return await self.edge_model.generate(prompt), "edge-fallback"

# 使用
cascade = CascadeInference()
output, source = await cascade.infer("解释量子力学", user_id="u123")
print(f"Source: {source}, Output: {output}")
```

## 八、常见陷阱与调优

### 8.1 陷阱 1：路由分类器不准

**症状**：复杂请求被端侧处理，质量差。

**修复**：用 LLM judge 标注数据，定期重训分类器。

### 8.2 陷阱 2：网络故障频繁降级

**症状**：弱网场景云端超时多。

**修复**：网络感知路由，弱网直接端侧。

### 8.3 陷阱 3：端侧模型质量差

**症状**：端侧输出质量低，用户不满。

**修复**：用 3B 而非 1B，或调高置信度阈值（更多送云端）。

### 8.4 陷阱 4：隐私分类误判

**症状**：敏感数据上传云端。

**修复**：保守分类（宁错杀不放过），PII 检测必做。

### 8.5 调优 Checklist

- [ ] 复杂度分类器准确率 > 90%
- [ ] 隐私分级（PII/医疗/金融检测）
- [ ] 网络感知路由
- [ ] 云端超时 + 降级
- [ ] 监控路由分布
- [ ] A/B 测试端侧/云端质量

**效果**：
- 端侧 20 tokens/s

### 9.3 案例：微软 Copilot 端云协同

## 十一、面试速答

**Q1: 端云协同的核心思想？**

A: cascade 推理。端侧小模型处理简单请求（70%），云端大模型处理复杂请求（30%）。降低延迟（-35%）+ 成本（-70%）+ 保护隐私。

**Q2: 路由策略有哪些？**

A: 1) 规则路由（关键词）；2) 复杂度分类器（BERT-small）；3) 置信度路由（端侧生成 + 置信度阈值）；4) 长度路由（短输出端侧）；5) 隐私分级路由（PII/医疗/金融检测）。

**Q3: 隐私分级怎么做？**

A: 检测 PII（个人身份信息）、医疗、金融关键词。public → 公有云；internal → 私有云；sensitive → 端侧 7B；confidential → 端侧 1B。

**Q4: 网络故障如何降级？**

A: 1) 网络感知路由（弱网直接端侧）；2) 云端超时 5s；3) 降级端侧 fallback；4) 离线模式强制端侧。

**Q5: Apple Intelligence 的端云协同？**

A: 端侧 3B + 私有云 13B/70B + 公有云（需授权）。70% 端侧，25% 私有云，5% 公有云。隐私最优。

## 十三、故障复盘

### 13.1 案例 1：路由分类器不准

**背景**：2025 年某公司级联推理，复杂请求被端侧处理，质量差。

**背景**：2025 年某公司 1B 模型质量低，用户不满。
