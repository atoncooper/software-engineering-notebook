## 三、Character.AI 长对话架构

### 3.1 背景

Character.AI 是 AI 角色扮演平台, 用户与虚拟角色长对话, 月活千万级。

### 3.2 核心挑战

```
1. 长对话 KV Cache:
   - 单次对话可达 100K+ token
   - KV Cache 内存: 100K × 8KB = 800MB (单对话)
   - 千万级活跃对话: 8PB KV Cache
   - 不可能全内存

2. 推理路由:
   - 不同角色用不同模型
   - 同一对话必须路由到同一实例 (KV 连续性)
   - 用户付费 vs 免费, 不同优先级

3. 流式体验:
   - 用户期望即时响应
   - TTFT < 500ms
   - 持续流式输出

4. 多模态:
   - 文字 + 语音 + 图像
   - 跨模态 batch
```

### 3.3 架构推测

```
┌─────────────────────────────────────────────┐
│            Mobile / Web Client              │
└─────────────────┬───────────────────────────┘
                  │
                  ▼
┌─────────────────────────────────────────────┐
│         API Gateway                         │
│  - 鉴权 (用户/角色)                          │
│  - 限流 (per user)                           │
│  - 长连接 (WebSocket)                        │
└─────────────────┬───────────────────────────┘
                  │
                  ▼
┌─────────────────────────────────────────────┐
│      Conversation Router                    │
│  - 按 character_id 路由                      │
│  - 同一对话路由到同一实例 (KV 连续)          │
│  - 优先级调度 (付费 > 免费)                  │
└─────────────────┬───────────────────────────┘
                  │
        ┌─────────┴─────────┐
        ▼                   ▼
┌──────────────┐    ┌──────────────┐
│ Inference    │    │ Inference    │
│ Pool A       │    │ Pool B       │
│ (Character   │    │ (Character   │
│  Group 1)    │    │  Group 2)    │
│              │    │              │
│ GPU + KV     │    │ GPU + KV     │
│ Cache (内存) │    │ Cache (内存) │
└──────┬───────┘    └───────┬──────┘
       │                    │
       └────── KV Cache ────┘
              冷存 (SSD)
              (LRU 淘汰)
```

### 3.4 关键技术

```
1. KV Cache 分层
   - 热对话: 内存 (GPU)
   - 温对话: CPU 内存
   - 冷对话: SSD (LRU 淘汰)
   - 重新激活: 从 SSD 加载到 GPU

2. 会话保持
   - 按 character_id + user_id 一致性哈希
   - 同一对话始终路由到同一实例
   - 故障切换: KV Cache 重建 (冷启动)

3. 推理优化
   - PagedAttention (vLLM)
   - Prefix cache (角色 prompt 共享)
   - Continuous batching
   - INT8/FP8 量化

4. 流式输出
   - WebSocket / SSE
   - 首 token 优先
   - 增量解码

5. 多模型路由
   - 热门角色: 大模型 (高质量)
   - 长尾角色: 小模型 (低成本)
   - 付费用户: 优先大模型
```

### 3.5 性能基准（推测）

| 指标 | 数值 |
|------|------|
| 日活 | 1000万+ |
| 平均对话长度 | 20K token |
| TTFT P50 | 300ms |
| TTFT P99 | 800ms |
| 流式吞吐 | 50 tokens/s |
| KV Cache 命中率 | 95%+ |
| GPU 利用率 | 70%+ |

### 3.6 可借鉴经验

1. **KV 分层**: 长对话场景必须
2. **会话保持**: 一致性哈希 + 故障重建
3. **多模型路由**: 成本优化
4. **流式优先**: 用户体验关键

## 四、Midjourney 异步图像生成架构

### 4.1 背景

Midjourney 是 AI 图像生成平台, Discord 集成 + 异步任务模式, 用户量百万级。

### 4.2 核心挑战

```
1. 异步任务:
   - 图像生成耗时 30s-2min
   - 不能 HTTP 同步等待
   - 任务队列 + 通知

2. GPU 弹性:
   - 流量峰谷差异大 (白天高, 夜间零)
   - Spot 实例降本
   - 快速扩缩容

3. 多分辨率:
   - 1K/2K/4K
   - 不同分辨率资源差异大
   - batch 优化

4. Discord 集成:
   - 通过 Bot 推送结果
   - 限制: Discord API 速率
```

### 4.3 架构推测

```

└─────────────────┬───────────────────────────┘
                  │ /imagine prompt
                  ▼
┌─────────────────────────────────────────────┐
│         Discord Bot / API                   │
│  - 接收指令                                  │
│  - 返回任务 ID                               │
└─────────────────┬───────────────────────────┘
                  │
                  ▼
┌─────────────────────────────────────────────┐
│         Job Queue (Redis/SQS)               │
```

### 4.4 关键技术

```
1. 异步任务队列
   - Redis / SQS
   - 优先级队列 (付费/免费)
   - 失败重试 + 死信队列
   - 任务超时 (5min)

2. GPU 弹性
   - K8s + HPA (按 queue 长度)
   - KEDA (自定义指标)
   - Spot 实例 (夜间, 成本 1/3)
   - 扩缩容: 1-100 GPU

3. 推理优化
   - 多分辨率 batch
   - 模型量化 (FP16/FP8)
   - xFormers 优化
   - CUDA Graph

4. 结果存储
   - S3 对象存储
   - CDN 分发
   - 短链 (临时访问)

5. Discord 集成
   - Bot API
   - 速率限制 (per channel)
   - 富文本消息 (图像 + 元数据)
```

### 4.5 性能基准

| 指标 | 数值 |
|------|------|
| 日活 | 500万+ |
| 日均生成 | 1000万+ |
| 平均生成时间 | 60s |
| GPU 利用率 | 60% |
| Spot 比例 | 70% (夜间) |
| 成本 | $0.04/张 (4K) |

### 4.6 可借鉴经验

1. **异步模式**: 长任务必须
2. **Spot 实例**: 大幅降本
3. **CDN 分发**: 结果访问优化
4. **优先级队列**: 付费体验

## 五、Suno 多模态音乐生成架构

### 5.1 背景

Suno 是 AI 音乐生成平台, 输入 prompt 生成完整歌曲 (歌词+演唱+编曲)。

### 5.2 核心挑战

```
1. 多模态:
   - 文字 (歌词) + 音频 (演唱)
   - 跨模态注意力
   - 长序列 (3min 歌曲 = 数千 token)

2. 流式输出:
   - 用户期望边生成边听
   - 分段生成 + 流式播放
   - 缓冲管理

3. 长任务:
   - 完整歌曲 1-3min
   - 异步 + 流式结合
   - 进度通知

4. 多模型协同:
   - 歌词模型
   - 演唱模型
   - 编曲模型
   - 混音模型
```

### 5.3 架构推测

```
                  │ prompt
```

```
3. 多模态 LLM
   - 文字 → 音频 (Bark/MusicGen)
   - 跨模态 attention
   - 长序列优化

4. WebSocket 推送
   - 实时分片
   - 进度更新
   - 错误处理
```

### 5.5 可借鉴经验

1. **工作流编排**: 多步骤任务必须
2. **流式分片**: 长任务体验
3. **多模型协同**: 复杂生成 pipeline
4. **WebSocket**: 实时推送

## 六、Cursor 端云协同代码补全架构

### 6.1 背景

Cursor 是 AI 代码编辑器 (VSCode fork), 代码补全 + 聊天, 体验极低延迟。

### 6.2 核心挑战

```
1. 低延迟:
   - 代码补全要求 < 200ms
   - 用户键入即触发
   - 不能等云端推理

2. 端云协同:
   - 端侧小模型 (快速补全)
   - 云端大模型 (复杂任务)
   - 智能切换

3. 上下文:
   - 当前文件 + 项目代码库
   - 长上下文管理
   - RAG 检索

4. 隐私:
   - 代码不上传 (端侧处理)
   - 仅必要信息发云端

```

```
   - 50-100 tokens/s
   - 隐私: 代码不出本地

2. 智能路由
   - 简单补全: 端侧 (< 100ms)
   - 复杂任务: 云端 (Claude/GPT-4o)
   - 用户选择: 隐私模式强制端侧

3. 上下文管理
   - 当前文件 + 光标位置
   - 项目代码库 RAG 检索
   - 长上下文压缩

4. 流式输出
   - SSE 流式
   - 边生成边显示
   - 用户可中断

5. 隐私模式
   - 代码不离开本地
   - 仅元数据 (语言/框架) 上传
   - 端侧完整推理
```

### 8.3 共同架构模式

```
1. API Gateway
   - 鉴权

2. 任务/请求队列
   - 异步任务 (Midjourney/Suno)

   - 多模型 (大/小/多模态)
   - 弹性扩缩
   - 多地域

4. 流式输出
   - SSE/WebSocket
   - 增量推送

5. 缓存层
   - KV Cache (长对话)
   - 结果缓存 (相同 prompt)
   - CDN (静态资源)
```

### 9.1 端云协同普及

```
趋势:
  - 端侧小模型 (1-7B INT4)
  - 云端大模型 (70B+)

  - Apple Intelligence
  - Google Gemini Nano
  - Cursor (代码补全)
  - 微软 Copilot+PC
  - 字节豆包 Lite

价值:
  - 隐私: 数据不出本地
  - 延迟: 端侧 < 100ms
  - 成本: 端侧分流, 云端省 50%+
```

```
挑战:
  - 沙箱 (Firecracker/WASM)
  - 状态持久化
  - 故障恢复

  - Cursor Agent (代码任务)
```

## 十、面试速答

**Q1: Character.AI 长对话架构核心?**

A: 1) KV Cache 分层 (热内存/温CPU/冷SSD, LRU 淘汰); 2) 会话保持 (按 character_id+user_id 一致性哈希, 同一对话同实例); 3) 多模型路由 (热门角色大模型, 长尾小模型); 4) 流式 SSE; 5) Prefix cache (角色 prompt 共享)。

**Q2: Midjourney 异步架构核心?**

A: 1) 异步任务队列 (Redis/SQS, 优先级队列); 2) GPU 弹性 (K8s+HPA, 按 queue 长度扩缩, Spot 实例夜间); 3) Discord Bot 推送结果; 4) S3 + CDN 分发图像; 5) 任务超时 + 重试 + 死信队列。

**Q3: Cursor 端云协同怎么实现?**

A: 1) 端侧推理 (Llama.cpp + Qwen-Coder 1.5B/3B INT4, < 100ms); 2) 智能路由 (简单补全端侧, 复杂任务云端 Claude/GPT-4o); 3) RAG 代码库上下文; 4) 隐私模式 (代码不离开本地); 5) 流式输出 + 用户可中断。

**Q4: GitHub Copilot 的核心技术?**

A: 1) 上下文工程 (当前文件 + 邻近代码 + 同项目相关文件); 2) 增量补全 (用户键入即更新, 取消机制); 3) 多模型 (Codex 补全低延迟, GPT-4 聊天高质量); 4) 多 IDE 适配 (统一后端 API); 5) 企业版私有部署。

**Q5: AIGC 平台的共同架构?**

A: 1) API Gateway (鉴权/限流/路由); 2) 任务/请求队列 (异步任务必备); 3) 推理集群 (多模型/弹性/多地域); 4) 流式输出 (SSE/WebSocket); 5) 缓存层 (KV/结果/CDN); 6) 端云协同 (延迟+隐私); 7) 多模态融合。

## 十一、综合面试题

### 题 1（中级）：设计 AI 角色扮演平台

**答题要点**：

1. **挑战**:
   - 长对话 KV Cache (100K+ token)
   - 会话保持 (KV 连续性)
   - 流式输出
   - 多角色多模型

2. **架构**:
   - API Gateway + 鉴权
   - Conversation Router (按 character_id 路由)
   - Inference Pool (多模型, 按角色分组)
   - KV Cache 分层 (内存/CPU/SSD)

3. **关键**:
   - 会话保持: 一致性哈希 + 故障重建
   - KV 分层: 热内存, 冷 SSD, LRU 淘汰
   - Prefix cache: 角色 prompt 共享
   - 流式: WebSocket/SSE

4. **优化**:
   - PagedAttention
   - Continuous batching
   - INT8/FP8 量化
   - 多模型路由 (热门大模型, 长尾小模型)

5. **监控**:
   - TTFT/吞吐/错误率
   - KV Cache 命中率
   - GPU 利用率
   - 用户留存

### 题 2（高级）：设计 AIGC 全模态平台

**答题要点**：

1. **挑战**:
   - 多模态 (文字/图像/音频/视频)
   - 异步任务 + 流式
   - 多模型协同
   - 大流量 + 弹性

2. **架构**:
   ```
   API Gateway → Orchestrator → Multi-Model Pool
   ```

3. **核心组件**:
   - API Gateway: 鉴权/限流/路由
   - Orchestrator: 工作流编排 (多步骤 pipeline)
   - 模型池: LLM/VLM/Audio/Video
   - 任务队列: Redis/SQS, 优先级
   - 结果存储: S3 + CDN

4. **关键技术**:
   - 工作流: 多步骤依赖 (歌词→演唱→编曲→混音)
   - 流式分片: 长任务边生成边播放
   - 端云协同: 简单端侧, 复杂云端
   - 多模态 batch: 跨模态分组
   - Spot GPU: 异步任务用 Spot 降本

5. **可靠性**:
   - 任务重试 + 死信队列
   - 模型故障切换
   - 多地域部署
   - 混沌工程

6. **成本**:
   - 模型路由 (简单小模型, 复杂大模型)
   - Spot 实例 (夜间/异步)
   - KV Cache 复用
   - 端云协同 (端侧分流)
